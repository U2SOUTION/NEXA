# 모듈 — NEXA Deck (형제 컨트롤러)

고정된 판 위에 슬라이더 6, 레버 토글, 푸시락, 물리 숫자 키, 시작·정지를 둔 형제 컨트롤러다. 같은 상자 안에 적색 버섯 스위치가 있으나, 그 스위치는 안전 모듈이다. 형제 입력이 아니다.

이 모듈은 [모듈형 오픈 컨트롤러](모듈형%20오픈%20컨트롤러(Modular%20Open%20Controller).md) 의 형제다. 주소, 세션, Arm, 허용 목록, 표준 패킷 봉투는 그 문서를 따른다. 노브·원형 터치·4 방·마이크의 기구와 코어 필드 정의는 [NEXA Rotor](모듈형%20오픈%20컨트롤러%20NEXA%20Rotor.md) 와 같다. Deck 에도 그 입력을 둔다. 판 앞에 선 사람이 Rotor 를 집어 들지 않아도 되게 하려는 것이다. 슬라이더·레버 토글·푸시락은 종류마다 6개다. 숫자 키·시작·정지는 Deck 이 더하는 단일 조작이다.

예전에 형태 예시로만 있던 슬라이더형 B 와 스위치형 C 의 1 차 실체가 이 모듈 한 대다.

---

## 역할 분리

| 위치 | 담당 | 하지 않는 일 |
| :--- | :--- | :--- |
| **Deck 형제** | 키·슬라이더·레버·푸시락·시작·정지, 그리고 노브·원형 터치·4 방·마이크를 표준 패킷으로 보낸다. 암호/수치 LED 는 장비가 시킨 쪽을 켠다 | 숫자열을 암호로 판정, 설정값 적용, 액추에이터 구동, 비상 차단, 어느 컨트롤러를 쓸지 결정, 스위치로 부하 전류를 끊음 |
| **안전 모듈 (같은 상자)** | 적색 버섯을 전원 또는 액추에이터 릴레이에 하드와이어 직렬. 감시 접점은 `ESTOP_REQUEST` 알림 | 조작 패킷으로 차단을 대신함 |
| **장비** | 숫자열이 가동 암호인지 설정값인지 결정. 슬라이더·레버·푸시락·노브를 자기 축·모드로 맵. Rotor 와 Deck 이 같은 축을 건드릴 때의 정리. 틀린 암호 횟수 제한 | Deck 의 키 배치를 다시 정의 |

한 상자에 있어도 회로는 둘이다. Deck MCU 가 멈추거나 무선이 끊겨도 버섯은 구동을 끊는다.

## 넣는 것

축은 같은 종류가 반복되는 번호다. `0`~`5` 가 아닌 항목은 축이 없다. 키 번호는 패킷 절의 표가 가진다.

| 입력 | 수량 | 축 | 값 | 동작 | 뜻 |
| :--- | ---: | :--- | :--- | :--- | :--- |
| 적색 버섯 | 1 | — | — | 유지. 하드와이어 | 안전 모듈. 전 장비에서 같은 차단. 부하를 끊는 스위치는 이것뿐이다 |
| 시작 | 1 | — | 누름 `1`, 뗌 `0` | 순간 | 운전 요청. 전 장비에서 같은 요청 |
| 정지 | 1 | — | 누름 `1`, 뗌 `0` | 순간 | 정상 정지 요청. 전원을 끊지 않음 |
| 슬라이더 | 6 | `0`~`5` | `0`~`1` | 무스프링 직선. 놓아도 유지 | 절대 위치. 축 이름은 장비가 정함 |
| 레버 토글 SPST | 6 | `0`~`5` | `0` 열림, `1` 닫힘 | 유지. 2핀 | 트리거 접점 |
| 레버 토글 DPDT | 6 | `0`~`5` | `0` 접점 없음, `1`, `2` | 유지. 6핀. 중립이 있는 3단 | 트리거. `0` 의 동작은 장비 맵 |
| 푸시락 | 6 | `0`~`5` | `0` 해제, `1` 잠금 | 눌러 잠그고, 다시 눌러 해제 | 트리거 접점 |
| 숫자 키 | 12 | — | 키 `0`~`9`, 확인 `10`, 지우기 `11`. 누름 `1`, 뗌 `0` | 물리 키 | 키 번호만 송신. 한 벌이라 6개로 나누지 않음 |
| 노브 | 1 | — | 절대각, 증분 | Rotor 와 같은 코어 | 증분 조향. 판에 고정이면 몸체 회전 보정은 쓰지 않아도 된다 |
| 4 방 | 1조 | — | 방향 마스크 | Rotor 와 같은 마스크 | 방향의 의미는 장비 |
| 원형 터치 | 1 | — | 접촉각 | Rotor 와 같은 터치 필드 | 탭·스크롤 등은 장비가 읽음 |
| 마이크 | 1 | — | 키워드, 청취 | 본체 마이크. 절차는 Rotor 문서 | 단독·무선이면 키워드만. 다른 컨트롤러와 유선 클럭을 공유하면 스테레오 |

상태 표시는 화면 없이 LED 다.

| LED | 누가 켜는가 |
| :--- | :--- |
| Arm | 장비가 Arm 된 동안 |
| 링크 | Deck 이 하트비트를 주고받는 동안 |
| 고장 | `fault` 가 있을 때 |
| 암호 | 장비가 숫자열을 가동 암호로 받는 동안 |
| 수치 | 장비가 숫자열을 설정값으로 받는 동안 |

암호 LED 와 수치 LED 는 동시에 켜지 않는다. 확인을 누르기 전에는 장비도 값을 적용하지 않는다.

### 숫자 키

정전식 터치 키패드는 두지 않는다. 가죽·캔버스처럼 두꺼운 장갑에서 입력이 빠진다. 키는 돔이 있는 실리콘·멤브레인, 또는 캡이 크고 간격이 넓은 기계식이다. 캡은 12 mm 안팎으로 두고, 장갑으로 옆 키가 같이 눌리지 않게 간격을 둔다.

형제는 키 식별자와 눌림·뗌만 보낸다. 암호를 저장하지 않고, 이어 붙인 비밀번호 필드도 만들지 않는다. 전화기 UI 가 같은 키 식별자를 보내면, 장갑을 벗었을 때는 폰으로, 끼고 있을 때는 이 키로 같은 칸을 채운다.

가동 암호는 장비마다 둔다. 틀린 횟수가 쌓이면 잠시 입력을 거부하는 정책은 장비다. 세션·허용 목록·HMAC 은 패밀리 문서 그대로다. 암호는 그 위의 작업자 확인이다.

### 슬라이더

기본은 **6개**다. 축 번호는 `0`~`5` 로 고정한다. 다축 CNC 의 축, 오디오 채널 레벨처럼 장비 맵이 여섯 칸을 각자 쓰게 하려는 수다. 장비가 일부만 써도 여섯 개는 그대로 둔다. 안 쓰는 축은 장비가 무시한다.

7개 이상은 Deck 이 아니다. 슬라이더·SPST·DPDT·푸시락 모두 그렇다. 그 판은 스페셜 컨트롤러로 따로 둔다.

스프링으로 중앙에 돌아오는 슬라이더는 두지 않는다. 증분은 노브가 맡는다. Deck 슬라이더는 절대 위치만 낸다.

### 스위치

반복 수량은 슬라이더와 같이 **종류마다 6개**다. 번호는 `0`~`5` 다.

| 종류 | 핀 | 동작 |
| :--- | :--- | :--- |
| 레버 토글 SPST | 2 | 한 접점. 열림 또는 닫힘 |
| 레버 토글 DPDT | 6 | 두 극이 같이 움직인다. `0` 은 접점이 없는 중립, `1` 과 `2` 는 양쪽 |
| 푸시락 | — | 누르면 유지, 다시 누르면 해제 |

캡과 레버의 **크기는 접근성 때문에 달라도 된다.** 장갑·손 닿는 자리에 큰 것을 둔다. 전기적 역할은 전부 **트리거**다. MCU 입력으로만 읽고, 모터·히터·릴레이 전류를 이 접점으로 통과시키지 않는다. 부품의 정격 전류가 커도 회로에서는 신호로만 쓴다. 부하를 끊는 스위치는 적색 버섯뿐이다.

글자를 박지 않는다. 각 축의 의미는 장비가 정한다. DPDT 의 `0` 은 중립에서 두 극 모두 접점이 없는 상태다. 그 값에 일을 두는 장비는 자기 맵에서 처리한다.

### 마이크

Deck 에도 본체 마이크를 둔다. 평소는 키워드만 보낸다. Rotor 또는 다른 컨트롤러와 **유선으로 샘플 클럭을 공유**하면 두 본체 마이크가 스테레오로 동작한다. 플러그인 스테레오 `VOICE_EXT_MIC` 은 Deck 에도 꽂을 수 있고, 그때 클럭은 Deck 쪽이다. 오디오 샘플은 표준 패킷에 넣지 않는다.

---

## 넣지 않는 것

- 화면. 대시보드는 스마트폰 형제다. Deck 은 LED 만 둔다.
- 기능 이름이 인쇄된 추가 키. 시작·정지·비상만 어느 장비에서나 같은 뜻이다.
- 열쇠 스위치. 작업자 확인은 숫자 키가 맡는다.
- 발판 데드맨. 잭 자리만 나중을 위해 남길 수 있다. 1 차 구성에는 발판을 넣지 않는다.
- 슬라이더·SPST·DPDT·푸시락이 종류별로 7개 이상. 기본은 각 6개이고, 그 이상은 스페셜 컨트롤러다.
- 100 Hz 스트림에 키·슬라이더를 실음. 노브·접촉 중 터치는 Rotor 와 같이 `STREAM` 상한 100 Hz 를 쓸 수 있다.

---

## 패킷

봉투는 패밀리 표준 패킷이다. 슬라이더·숫자 키는 형제 타입이고, 노브·4 방·원형 터치·마이크는 Rotor 와 같은 코어 타입이다.

| 입력               | 타입                                                   | 보내는 때                                                      |
| :--------------- | :--------------------------------------------------- | :--------------------------------------------------------- |
| 형제 식별            | `0x30` `SIBLING_META`                                | 붙을 때, 스냅샷                                                  |
| 숫자·시작·정지         | `0x35` `SPECIAL_KEYPAD`                              | 가장자리                                                       |
| 레버 SPST·DPDT·푸시락 | `0x35` `SPECIAL_KEYPAD`                              | 레벨이 바뀔 때와 스냅샷. 축 `0`~`5`                                   |
| 노브·4 방·원형 터치·마이크 | Rotor 와 같은 `0x20` `0x21` `0x22` `0x26` `0x2B` `0x2E` | 노브·접촉 중 터치는 `STREAM`. 마이크는 청취 중 이벤트. 절차·영점은 Rotor 문서       |
| 슬라이더 6           | `0x36` `SPECIAL_ANALOG`                              | 바뀐 축만 `EVENT`. 스냅샷에는 `0`~`5` 전부. 매 하트비트와 `STREAM` 에는 넣지 않음 |
| 버섯 감시 접점         | `0x01` `ESTOP_REQUEST`                               | 접점이 열리거나 다시 닫힐 때 1 회. 차단은 하드와이어                            |

키 식별자 초안이다. 장비는 이 번호의 뜻을 바꾸지 않고, 숫자열을 어디에 쓸지만 정한다.

| ID | 키 |
| :--- | :--- |
| `0`~`9` | 숫자 |
| `10` | 확인 |
| `11` | 지우기 |
| `20` | 시작 |
| `21` | 정지 |
| `40`~`45` | 레버 SPST 축 `0`~`5`. 값 `0` 열림 / `1` 닫힘 |
| `50`~`55` | 레버 DPDT 축 `0`~`5`. 값 `0` 접점 없음 / `1` 한쪽 / `2` 반대쪽. `0` 의 동작은 장비 맵. 부하 전류 없음 |
| `60`~`65` | 푸시락 축 `0`~`5`. 값 `0` 해제 / `1` 잠금 |

슬라이더 값은 축마다 `0`~`1` 이고, 축 번호는 `0`~`5` 다. 한 축만 움직이면 그 축만 보낸다. 변화 문턱의 숫자는 슬라이더 기구가 정해진 뒤 패밀리 문서의 상수로 올린다. 그 전에 Deck 이 문턱을 따로 확정하지 않는다.

### 예제

숫자는 설명용이다. `controller_id` `0xD001`, `dest_id` `0xA010` 은 허용 목록이 아니다. 바이트 폭과 CRC 는 패밀리 문서의 테스트 벡터로 남긴다. 아래는 필드 구성이다.

헤더는 공통이다. `seq` 는 보낼 때마다 1 씩 올린다. `link` 는 CAN 또는 ESP-NOW 같은 물리 종류이고, 링크 품질이 아니다.

**숫자 `7` 을 누름.** 가장자리만 보낸다. 뗌은 같은 키에 `value` `0` 이다. 시작(`20`)·정지(`21`)·확인(`10`)·지우기(`11`)도 같다. 장비는 확인 전까지 숫자열을 적용하지 않는다.

```text
msg_type: EVENT (0x02)
data_type: 0x35 SPECIAL_KEYPAD
key_id: 7
value: 1
```

**SPST 축 2 가 닫힘.** 키 번호는 `42` 다. 열리면 `value` 는 `0` 이다.

```text
msg_type: EVENT (0x02)
data_type: 0x35 SPECIAL_KEYPAD
key_id: 42
value: 1
```

**DPDT 축 0 이 한쪽.** 키 번호는 `50` 이다. 6핀은 부품의 핀 수다. 두 극은 레버를 따라 같이 움직이므로 패킷에는 위치 하나만 보낸다. `0` 은 중립이라 두 극 모두 접점이 없고, `1` 과 `2` 는 양쪽이다. 접점이 없는 `0` 에 일을 시키는 장비는 그 맵을 자기가 가진다. 이 접점으로 부하 전류를 흘리지 않는다.

```text
msg_type: EVENT (0x02)
data_type: 0x35 SPECIAL_KEYPAD
key_id: 50
value: 1
```

**푸시락 축 0 이 잠김.** 키 번호는 `60` 이다. 다시 눌러 해제하면 `value` 는 `0` 이다.

```text
msg_type: EVENT (0x02)
data_type: 0x35 SPECIAL_KEYPAD
key_id: 60
value: 1
```

**슬라이더 축 3 만 `0.40`.** 안 움직인 축은 이 이벤트에 넣지 않는다.

```text
msg_type: EVENT (0x02)
data_type: 0x36 SPECIAL_ANALOG
axis: 3
value: 0.40
```

**페어링 직후 스냅샷.** 슬라이더 `0`~`5` 와 레버·푸시락의 현재 레벨을 한 번에 보낸다. 하트비트와 `STREAM` 에는 이 값을 넣지 않는다.

```text
msg_type: SNAPSHOT (0x03)
0x30 SIBLING_META   sibling_id: 1   role: specialized
0x36 SPECIAL_ANALOG axis: 0..5     value: 그 순간의 위치
0x35 key_id: 40..45 value: 0 열림 / 1 닫힘
0x35 key_id: 50..55 value: 0 접점 없음 / 1 / 2
0x35 key_id: 60..65 value: 0 해제 / 1 잠금
```

하트비트는 1~5 Hz 의 `HEARTBEAT` (`0x01`) 로 생존과 `0x2C` 만 알린다. 노브·4 방·원형 터치가 움직이면 Rotor 와 같은 `0x20` `0x21` `0x22` `0x26` 을 `STREAM` 으로 보낸다. 그 필드 예는 Rotor 문서의 `ControllerOutputPacket` 이다. 버섯을 누르면 `0x35` 가 아니라 `event_id` `0x01` `ESTOP_REQUEST` 한 번이고, 구동은 하드와이어가 끊는다.

잔량 모니터를 Deck 에 두면 패밀리 문서의 `0x2A` 규칙 (`POWER_STEP_PCT`, `POWER_LOW_PCT`, `POWER_REFRESH_S`) 을 그대로 쓴다. 셀을 둘지는 기구 항목으로 남긴다. 유선 도킹으로 장비 전원을 받는 구성이면 잔량 필드는 보내지 않는다.

## 장비와의 경계

Rotor 와 Deck 이 같은 축을 동시에 건드릴 수 있다. 경로 우선순위는 패밀리 기본을 따른다.

`안전정지 > 로컬 수동 직결 > 로컬 서버 중계 수동 > 외부 경유 원격 > 서버 자동`

같은 등급의 수동 입력이 겹치면 장비가 정리한다. 기본 정리는 다음 순서다.

1. 작업 위치에 **더 가까운** 컨트롤러의 입력.
2. 거리가 같거나 모르면, 그 축에 **먼저 입력이 들어온** 컨트롤러를 그 조작이 이어지는 동안 유지한다.
3. 장비는 이 정리를 자기 프로필에서 바꿀 수 있다. 합성하거나, 한쪽을 거절하거나, 축마다 컨트롤러를 나눌 수 있다.

열융착기 1 차 성공은 Rotor 만으로도 성립한다. Deck 은 그 증명 조건에 넣지 않는다.

## 아직 정하지 않은 것

- 슬라이더 행정, 캡 재질, 상자 치수
- MCU 와 링크 (CAN / ESP-NOW) 의 부품
- 본체 배터리 장착 여부
- 슬라이더 변화 문턱 상수
- 발판 잭을 1 차 기구에 구멍을 낼지
