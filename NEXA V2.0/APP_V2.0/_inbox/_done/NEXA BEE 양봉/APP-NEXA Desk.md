# APP — NEXA Desk

PC(또는 상시 전원 기기) 에서 돌아가는 **공용 런타임**이다. 침실 온수 매트의 음악·알람이 첫 응용이지만, **특정 장비 전용 프로그램이 아니라** 여러 NEXA 프로젝트·장비가 붙을 수 있는 기초를 둔다.

**역할 한 줄:** 포털·장비·컨트롤러를 PC 와 **연결**하는 거점이면서, PC 에서 **직접 컨트롤러**가 될 수 있고, 연결이 없어도 도는 **자체 기능**을 갖는다.

**이름·호칭:** 문서·교차 링크는 **NEXA Desk**. 대화에서 짧게 **Desk**만 써도 된다. 예전 가칭 Host/호스트는 쓰지 않는다 (USB 호스트·PC 와 혼동). 현장·양봉의 “스테이션”(U2 하이브, 공압 포트, 충전 거치 등) 및 **포털 (핵심 거점)** 과도 구분한다. NEXA Desk = PC 위 자리 — 어댑터·미디어·로컬 자동화·직접 조작 UI. 구현 언어는 이름에 넣지 않는다. 책상 옆 하드웨어 (ESP-NOW·HID·로컬 구동단) 는 **[NEXA Desk Driver](장비-NEXA%20Desk%20Driver.md)**(대화: **데스크 드라이버**) 이며 Desk 와 다른 제품이다.

로터 펌웨어에 장비별 분기를 넣지 않는 것과 같이, NEXA Desk 의 **장비 연동**도 표준 이벤트·슬롯 + **어댑터**로 해석한다. 자체 기능·NEXA Desk UI 는 어댑터/서비스로 둔다.

## 목표

- **연결:** 포털·장비 ESP·로터 (등 컨트롤러) ↔ PC 버스·이벤트.
- **직접 컨트롤러:** NEXA Desk UI·단축키·트레이 등으로 장비/미디어를 조작 가능 (로터와 병행, 로터 필수 아님).
- **입력:** 기본은 **키보드·마우스**. **로터 보유 시** 같은 기능을 로터로 **더 편하게** 쓰게 한다 (로터 = 가속, 필수 아님).
- **자체 기능:** 오프라인·무장비·무포털이어도 미디어·로컬 알람·로그·개발 도구 등 **단독 동작**.
- **공용 런타임:** 접속·인증·구독·로깅·설정은 한곳. 기능은 어댑터로 확장.
- **1 차 검증:** 매트 입면/기상 → 음악·알람. 이후 온풍·Path·GRC 등.
- **포털 중심 · 웹뷰 우선:** 내용은 포털 웹. **표시면 기본은 Desk 웹뷰**(외부 브라우저는 보조). Desk 네이티브는 **웹이 못 하는 구멍만**.

## 구현 단속 · 포털 중심 · OS 티어

밤샘 논의 반영. **중심은 포털.** Desk 는 포털·웹을 돌리며 시스템에만 손을 뻗는 런타임이다, 또 하나의 무거운 UI 앱이 되지 않게 단속한다.
**표시면은 웹뷰가 먼저** — 브라우저 크롬·창 정책으로는 어려운 **심플·상시상위·측면 펼침/숨김** 등을 Desk 창이 맡는다.

### 한 줄 원칙

**제품 UI 는 전부 웹 (포털) → Desk 웹뷰로 본다 (기본) · 외부 브라우저는 보조 → 시스템 접근은 백그라운드 (트레이/무 UI 로 숨김 가능).**

### UI vs 시스템 — 이원화

| 층 | 기술 | 보이는가 |
| :--- | :--- | :--- |
| **제품 UI** | 포털 HTML/CSS/JS (**브라우저 베이스** = 웹 스택). 웹뷰·외부 브라우저 어느 쪽이든 **같은 URL** | ✅ 사용자가 보는 전부 |
| **표시 셸** | Desk 웹뷰 창 (프레임리스·상시상위·측면 패널 등). **자체 화면·메뉴를 키우지 않음** — 포털만 담음 | 창 테두리·위치만 (내용 아님) |
| **시스템 접근** | 파이썬 등 백그라운드. 루프백·볼륨·장치·Driver·깨우기·localhost 브리지 | ❌ **숨김 가능**(트레이 아이콘만 / 완전 무 UI). 제품 UI 를 그리지 않음 |

OS 권한·장치 선택 등 **시스템이 띄우는 대화상자**는 예외 (숨길 수 없음). Desk 가 만든 설정·상태·아트 화면은 전부 포털 쪽.

### 입력 · 조작 (키보드·마우스 기본 · 로터 가속)

| | |
| :--- | :--- |
| **기본** | UI 조작은 **키보드 + 마우스**. 로터 없이도 포털·Desk 전 기능에 도달 가능해야 함 |
| **로터 보유** | [NEXA Rotor](모듈형%20오픈%20컨트롤러%20NEXA%20Rotor.md) 가 있으면 **자주 쓰는·현장에 맞는 조작**을 로터로 **더 편리하게** (노브·링·슬롯 → 볼륨·곡·모드·매트 등). Desk Driver HID/패킷 경로 |
| **방향** | 로터 = **필수 대체재가 아니라 가속 계층**. 새 Desk/포털 기능은 먼저 키·마우스로 되고, 로터 매핑은 “더 편하게”로 얹음 |
| **충돌** | Desk 수동 UI 와 로터 직결은 같은 **로컬 수동** 등급 (아래 세 갈래·패밀리 §0.2.2) |

### 단속 규칙

| # | 규칙 |
| :--- | :--- |
| 1 | **기본 구현면 = 포털 웹**(UI·설정·아트 페이지·상태). Desk 에 동일 UI 를 다시 만들지 않음 |
| 2 | 새 기능: **「포털 URL 만으로 되나?」** → Yes 면 포털만. No 면 백그라운드 **화이트리스트**에 한 줄 |
| 3 | 백그라운드 허용 예: 루프백·엔드포인트 볼륨/뮤트·장치 선택·Driver MQTT/`ampMaster`·깨우기 연동·localhost 브리지 |
| 4 | **웹 샌드박스 제약** 때문에만 네이티브/파이썬을 씀. UI·비즈니스 로직의 중심은 포털 |
| 5 | 웹뷰/브라우저 ↔ 백그라운드 = **localhost WebSocket / MQTT**(아트 확장과 동일 패턴) |
| 6 | **표시면 기본 = Desk 웹뷰.** 외부 브라우저는 공유·북마크·“그냥 웹”용 보조 |
| 7 | 백그라운드는 **제품 UI 없음**. 트레이·무 UI 허용. “설정 창”이 필요하면 **포털 페이지**로 |
| 8 | **입력 기본 = 키·마우스.** 로터는 가속 (보유 시 편의↑). 로터 없으면 막히는 UI 금지 |

### 표시면 — 웹뷰 우선 · 브라우저 보조

**내용은 항상 같은 포털 URL.** 아래는 **셸·접근면**만 나눈다 (제품 UI 를 복제하지 않음).

| 우선 | 선택 | 요지 |
| :--- | :--- | :--- |
| **1 (기본)** | **Desk 웹뷰 셸** | 프레임리스·창 정책·네이티브 브리지. 모드는 아래 「셸 모드」 |
| **2 (보조)** | **외부 브라우저** | 크롬 등으로 포털. 공유·북마크. Desk 는 백그라운드로 반응 |
| **3** | **Chrome 확장** | 탭 정밀·native messaging. 「포털·브라우저 세 갈래」 |

**왜 웹뷰가 먼저:** 일반 브라우저는 크롬·탭·창 계층이 고정에 가깝다. Desk 는 **얇고·작게·옆에 붙였다 접는** 형태가 맞다.

#### 셸 모드 · 접근면 후보 (1 차 묶음)

사용자가 고르거나 장면별로 전환. **안은 포털.**

| # | 접근면 | 요지 |
| :--- | :--- | :--- |
| 1 | **프레임리스 리사이즈 창** | 브라우저 프레임 (탭·주소창) 없음. 크기 조절 가능. 심플·상시상위 후보 |
| 2 | **모니터 사이드바** | 작업표시줄처럼 가장자리 도킹. **자동 숨김** 지원. 펼침/접힘 |
| 3 | **일반 브라우저** | 보조. “그냥 웹”·공유·북마크 |
| 4 | **트레이 (무 UI)** | 창 없음. 클릭·핫키로 1·2·5 등 호출. 백그라운드 숨김과 동일 계열 |
| 5 | **PIP / 플로팅 미니** | 아주 작은 항상 위 캡슐 (재생·상태). 기상·미디어·아트 |
| 6 | **전체화면 / 키오스크** | 아침 아트·알람 전면. Esc·로터·키로 탈출 |
| 7 | **Quake 식 드롭다운** | 핫키로 위에서 내려왔다 접힘. **가장자리 도킹**으로 사이드바 (2) 와 형제 — 구현은 **도킹 하나**로 묶고 변만 위/옆 |
| 8 | **투명 HUD 오버레이** | 투명·기본 클릭 관통. **기본은 일방 표시** · 조작은 선택 (아래). **셸 먼저 · 데이터는 나중에** |

**묶음 규칙:** 사이드바 ↔ Quake = **가장자리 도킹 패밀리**(택일·방향만). PIP·전체화면·HUD = **모드**(별도 앱이 아님).

##### 토스트 vs OSD — 태생은 다름 · UX 는 “겹치되 같지 않음”

| | **OSD** (On-Screen Display) | **토스트** (Toast / OS 알림) |
| :--- | :--- | :--- |
| **태생** | TV·모니터·앰프·볼륨 노브 — **방금 조작의 피드백** | 폰·OS 알림 — **앱/시스템이 건네는 메시지** |
| **느낌** | “내가 돌린 결과”가 화면에 비침 | “나한테 할 말 있음”이 뜸 |
| **수명** | 매우 짧음 · **알림 센터에 안 남음** | 짧거나 클릭 가능 · **알림 이력에 남을 수 있음** |
| **Desk 예** | 볼륨·`ampMaster`·모드·로터 한 칸 | “기상 5 분 전”·“PC 깨우는 중”·연결 끊김 |
| **구현** | Qt/웹 오버레이 한 줄기 (Desk 그림) | **winotify** 등 OS 토스트 API |
| **조작** | 불가 (일방) | 기본 불가 · dismiss 정도 |

**같은 점:** 짧게 · 모달 아님 · **일방 표시** · 조작 패널 아님.
**다른 점:** OSD = **조작 피드백**, 토스트 = **사건 알림**. UX 를 하나로 취급하면 볼륨이 알림함으로 들어가거나, 알람이 볼륨 바와 같은 톤이 되어 어색해진다.
→ Desk 에서는 **채널을 분리**한다 (라이브러리·시각 톤도 분리).

##### HUD vs OSD vs 토스트 — 조작 · 역할

| | **투명 HUD** | **OSD** | **토스트** |
| :--- | :--- | :--- | :--- |
| **역할** | 상시·슬롯 **상태판**(glance) | 순간 **조작 피드백** | 순간 **사건 메시지** |
| **기본** | 일방 · 클릭 관통 | 일방 · 곧바로 사라짐 | 일방 · OS 알림 규칙 |
| **직접 조작** | 기본 불가 · 히트존은 예외 | 불가 | 불가 (dismiss 후보) |
| **간접 조작** | 핫키·로터·사이드바/창 | 로터·키로 조작 → OSD 만 비춤 | — |
| **복잡한 UI** | ❌ → 사이드바·창·브라우저 | ❌ | ❌ |

요지: **셋 다 만지작거리는 패널이 아니다.** HUD=상태판, OSD=피드백, 토스트=알림.

##### 투명 HUD — 셸 먼저 · 데이터 나중

| 단계 | 내용 |
| :--- | :--- |
| **1 — 셸 (기본 구성)** | 투명 레이어·모니터 배치·**기본 클릭 관통**·상시상위·핫키/로터로 표시·숨김. 포털 HUD 페이지 (빈 슬롯) 만 로드 |
| **2 — 데이터 (필요 시)** | 성격별 위젯·구독만 켬. 예: `ampMaster`·재생 상태·매트 수면 단계·알람 카운트다운·아트 한 줄기. **안 쓰는 데이터는 안 올림** |
| **3 — 조작 (선택)** | 기본 = 표시만. 히트존·관통 off 는 **화이트리스트 액션만**(전체 설정 UI 금지) |
| **단속** | HUD 도 **포털 웹**. Desk 가 네이티브로 숫자 UI 를 그리지 않음. 브리지 = 상태 push(+ 선택적 히트) |
| **이슈 (실측)** | 포커스 훔침·히트테스트·게임 전체화면과의 겹침 — 셸 PoC 에서 확인 |

### OS 티어 (동일 UX ≠ 동일 시스템 능력)

“윈도우·리눅스·iOS·안드로이드에서 작동”은 **포털 UX**를 공통으로 두고, **Desk 풀 기능 (루프백·시스템 볼륨·HID·깨우기)** 은 PC 티어로 나눈다.

| 티어 | 대상 | 포털 웹 | Desk 백그라운드 |
| :--- | :--- | :--- | :--- |
| **A — PC** | Windows · Linux (1 차) | ✅ | ✅ 풀 (파이썬 등). Scarlett·L1·Driver |
| **B — 모바일** | Android · iOS | ✅ 중심 | ❌/얇음 (알림·원격 MQTT 정도). 루프백·Scarlett·깨우기 **비기대** |
| **비상 오디오** | 폰 → JAB5 BT | — | L1 우회. [Desk Driver 오디오 계층](장비-NEXA%20Desk%20Driver.md) |

macOS 는 PC 티어 후보 (실측 후). 모바일에서 “풀 Desk”를 약속하지 않는 것이 단속이다.

### 백그라운드 런타임 (파이썬 등)

| | |
| :--- | :--- |
| **하는 일** | OS·오디오·로컬 브로커 클라이언트·웹↔네이티브 브리지 |
| **안 하는 일** | 제품 UI·설정 화면·포털 대체. **숨김 (트레이/무 UI) 이 기본 후보** |
| **감싸기** | 웹뷰 셸 (Tauri/Electron 등) 이 있어도 **안은 포털 URL**. 셸 ≠ 두 번째 UI |

### 구현 스택 후보 (Python · 표시면/접근면)

단속 전제: **제품 UI = 포털 웹**. 파이썬은 **셸·백그라운드·브리지·OS 구멍**만. UI 프레임워크로 화면을 다시 그리지 않는다.
언어: **Python 3.11+**(3.12 후보). Windows 1 차 · Linux 동시 염두. 셸 트랙 **B(PySide6+WebEngine) 기본 후보**.

#### 트랙 선택

| 트랙 | 셸 | 언제 |
| :--- | :--- | :--- |
| **B — 기본 후보** | **PySide6 + Qt WebEngine**(`QWebEngineView`) | 프레임리스·사이드바·PIP·**투명 HUD·클릭 관통**·상시상위까지 한 툴킷으로 |
| **A — 가벼운 PoC** | **pywebview**(Win=WebView2) | URL 띄우기·단순 프레임리스·브리지 검증. HUD/도킹/리사이즈는 Win32 이슈 많음 → 본구현은 B 로 이전 가능 |
| **C — 이후 선택** | **Tauri / Electron 셸 + Python 사이드카** | 배포·웹뷰 성능 우선 시. 안은 동일 포털 URL · 파이썬은 OS/오디오만 |

**권장:** 표시면 요구 (1~8) 가 넓으니 **트랙 B**. A 로 버스·미디어만 먼저 검증해도 됨.

#### Chrome 확장 ↔ Desk (통신)

이미 「포털·브라우저 세 갈래」·[Desk Driver 표시면](장비-NEXA%20Desk%20Driver.md) 에 역할만 있었고, 기능 총괄에는 빠져 있었음 → 여기·총괄 #10b에 명시.

| | |
| :--- | :--- |
| **경로** | Chrome 확장 ⇄ **Native Messaging** ⇄ NEXA Desk(파이썬 host) ⇄ (필요 시) Driver MQTT/패킷 |
| **Desk 역할** | Native Messaging host. stdin/stdout **길이 +JSON**. 어댑터 `chrome_ext` |
| **확장 역할** | 백그라운드 service worker + 콘텐츠 스크립트. 탭 타깃·페이지 DOM/미디어 정밀 조작 |
| **쓰는 때** | 일반 브라우저에서 HID 만으로는 부족한 탭·사이트 제어. 포털 외 **허용 origin** 어댑터 |
| **안 쓰는 때** | 웹뷰 기본 경로·확장 미설치 — **HID + 웹뷰 브리지 + MQTT**만으로 최소 동작 |
| **우선순위** | HID·확장·패킷 겹치면 **확장/패킷 우선**(세부 미결) |
| **구현 메모** | 별도 pip 패키지 필수는 아님. host 실행 파일=Desk(또는 작은 sidecar). 스키마·권한은 미결 |

```text
[Chrome 탭] ← content script ← extension ←── Native Messaging (JSON) ──→ [Desk Python host]
                                                                              ↕ MQTT / 내부 버스
                                                                    [Driver · media · 웹뷰 브리지]
```

#### 백그라운드 · 브리지 · 오디오 · 버스

| 역할 | 라이브러리 | 메모 |
| :--- | :--- | :--- |
| localhost API · WS | **FastAPI** + **uvicorn** + **websockets** | 웹뷰↔파이썬. **확장 Native Messaging 과 별개** |
| Chrome Native Messaging | Desk 를 host 로 등록 · stdio JSON | 「Chrome 확장 ↔ Desk」. `chrome_ext` |
| MQTT | **paho-mqtt** 또는 **aiomqtt** | Driver·매트·포털 |
| 비동기 합치기 | **anyio** / Qt+`qasync`(트랙 B) | GUI 스레드와 버스 분리 |
| Windows 엔드포인트 볼륨 (L1) | **pycaw** + **comtypes** | Scarlett·기본 장치 |
| 재생 (로컬 파일 스모크) | **pygame** · **python-vlc** · 또는 OS 기본 | 브라우저 재생이 1 차면 최소만 |
| Desk Driver 시리얼 | **pyserial** | USB 시리얼 후보 |
| 설정·경로 | **pydantic** · **platformdirs** · (선택) **typer** CLI | |
| 패키징 | **PyInstaller** · **briefcase**(후보) | 트레이 + 웹엔진 용량 큼 — WebEngine 동봉 주의 |

#### 쓰지 않거나 뒤로

| 후보 | 이유 |
| :--- | :--- |
| **NiceGUI / Reflex / Streamlit / Flet** 등으로 Desk UI | 포털 대체·단속 위반. Flet=Flutter 위 Python UI |

#### 최소 PoC 조합 (제안)

```text
PySide6 + QtWebEngine  →  포털 URL (프레임리스 창 1개)
FastAPI localhost      →  bridge (볼륨·트레이 명령)
pystray                →  숨김/호출
paho-mqtt              →  Driver/매트 스텁
pycaw                  →  L1 스모크 (Windows)
```

HUD·사이드바는 같은 Qt 창 모드로 추가. 확정·버전 핀은 롤아웃 0→1 에서.

## 런타임 골격 (기초)

```text
[설정·자격]
    → 버스 접속 (MQTT 필수 후보 / 이후 ESP-NOW·로컬 소켓)
    → 코어 루프 (수신 · 디스패치 · 하트비트)
    → 어댑터 레지스트리 (장비·도메인별)
    → 공통 서비스 (미디어, 알림, 스케줄 훅, 로그)
```

| 층 | 내용 |
| :--- | :--- |
| **Core** | 프로세스 생존, 설정 로드, 버스 클라이언트, 이벤트 버스 (내부), 어댑터 로드 |
| **Bus** | 포털/로컬 브로커 MQTT. 구독·발행·nonce 정책은 장비 문서와 맞춤 (상시 명령 구독 남용 금지) |
| **Adapters** | `mat_sleep_audio`, (이후) `chrome_ext`, `heater_notify`, `path_preview`, `grc_alert` … |
| **Services** | `media`(재생·페이드·볼륨·**AI 안내 시 더킹**·루프백 분석), `notify`(OS/트레이), `clock`(NTP·알람 시각) |

코드 위치: **`NEXA-Desktop/NEXA-Desk/`** (PC 데스크톱 계열. Edge 펌은 `NEXA-Edeg/`). 패키지명 후보 `nexa-desk`. 이 문서는 **앱 스펙**(구현 전 기획 포함).

## 이벤트 모델 (초안)

장비·포털이 NEXA Desk 에 보내는 논리는 **작은 이벤트**로 통일한다. 토픽·페이로드 스키마는 아래와 같이 확정.

### 토픽 계층

```json
nexa/{identity_id}/{instance_id}/{capability_id}/{domain}/{type}
```

| 계층 | 의미 | 안정성 |
| :--- | :--- | :--- |
| `identity_id` | **근거/정체성** (영구). K(지식)·P(프로토콜)·F(기능) 접두 + NanoID 4 자 | 재부팅해도 변하지 않음 |
| `instance_id` | **누구** (실행 인스턴스, 일시적). 프로세스마다 새로 발급 | 프로세스마다 새로 발급 |
| `capability_id` | **무엇을** (기능 자격 ID, 예: `nexa.desk.media.play`) | 고정 |
| `domain` | 도메인 | `sleep` / `heat` / `path` / `security` … |
| `type` | 이벤트 유형 | `onset` / `wake_boost` / `sit_early_wake` / `alarm` / `telemetry` … |

**원칙:** 영구 정체성 (identity_id) 이 상위, 일시적 실행 인스턴스 (instance_id) 가 하위. 토픽 계층은 " 안정적인 것 → 변하는 것 " 순서.

### 페이로드

| 필드 | 역할 |
| :--- | :--- |
| `identity_id` | 이벤트의 근거가 되는 정체성 |
| `instance_id` | 이벤트를 보낸 실행 인스턴스 |
| `capability_id` | 호출되는 기능 자격 ID |
| `domain` | `sleep` / `heat` / `path` / `security` … |
| `type` | `onset` / `wake_boost` / `sit_early_wake` / `alarm` / `telemetry` … |
| `ts` | 시각 |
| `payload` | 도메인별 JSON |

### 1 차 단계 간소화

"1 차 단일 인스턴스 " 원칙에 따라, 1 차에서는 `instance_id` 를 단일 고정값으로 사용. 멀티 인스턴스가 필요한 2 차에서 `instance_id` 가 실제 분기 역할을 한다.

NEXA Desk → 장비는 기본적으로 **적게**. 재생은 로컬. 필요 시 포털에 상태만 올림 (`playing`, `track`, `volume`).

## 어댑터 — 1 차: 침실 매트 오디오

스펙: [장비-스마트 온수 매트 해킹 제어](장비-스마트%20온수%20매트%20해킹%20제어.md) 「기상 알람」·「음악」. 슬립 중 PC 는 아래 「전원·슬립 · 아침 기상」.

**역할:** 입면·기상·알람 **시각·트리거는 매트 전담**. Desk 는 알람을 포털에 **쓰지 않는다**. 트리거를 받으면 **재생만**.

| 입력 | 동작 (초안) |
| :--- | :--- |
| 입면 확정 | 입면 전 음악 페이드아웃·정지 또는 입면 플레이리스트 |
| 매트 기상 트리거 (포털 정기·캘린더 / 로터 일회「N 분 후」 / `WAKE_UP_BOOST`·앉음 앞당김) | PC 깨우기 (필요 시) → **Desk 웹뷰 (기본)** · Desk 미설치·웹뷰 미지원이면 **일반 브라우저** → 템플릿 URL 재생 |
| 앉음 (기상 창) | 기상 음악 **앞당김** |
| 깊은 잠 창 앉음 | 음악 시작 안 함 (문서) |
| 로터 PC 슬롯 노브 | 볼륨 |
| 로터 링 칸 | 다음/이전 곡 |

오디오 샘플은 매트·로터에 두지 않음.
**정기·템플릿·URL:** **포털 웹 (캘린더 내부 기능)** 이 원본·스키마 (JSON). 매트는 동일 JSON 을 **NVS 미러** — 포털 끊겨도 시각·템플릿 URL 로 트리거. **일회:** 로터→매트 (상대 시간만). 로터↔캘린더 충돌은 **나중 저장이 덮음**(매트 문서). Desk 는 목록을 고르지 않고 매트/포털이 가리킨 템플릿을 튼다.

## 오디오 · PC 전제 (설계 방향)

음악·영상은 **PC 를 통해 듣는 추세**를 1 차로 반영한다. Scarlett·앰프·브라우저·Desk 미디어가 그 경로다.

포털 TTS/안내는 **1 차**로 별도 AI 스피커 없이 Desk 가 처리·JAB5 로 낸다. **PC OFF 면 불가.**
**차후** 전용 AI 스피커는 **NEXA 닉시 (Nixie)** 가 담당할 계획 (상시·PC 비의존). Desk `media` 와의 분담은 닉시 쪽에서 정리.

| 기능 | NEXA Desk | NEXA Desk Driver |
| :--- | :--- | :--- |
| 재생·루프백 가로채기·분석 | **담당** | 안 함 |
| 포털 TTS · AI 안내 재생·더킹 | **`media` 가 담당** | 안 함 |
| 큰 음악 위 AI 음성 안내 시 **볼륨 더킹** | **`media` 가 담당** | 안 함 |
| 분석 결과를 조명에 반영 | 목표 `level`/씬 전달 | **디밍·릴레이 실행만** |
| 단순 LED VU | 루프백 요약 → `vuLevel` | **표시만**(1 와이어 등). [Driver 피드백](장비-NEXA%20Desk%20Driver.md) |
| PC 꺼진 동일 오디오 체험 | 해당 없음 (PC·Desk 필요) | 오디오 DSP 이양 **하지 않음**(과설계) |

조명 중 재실·씬·매트 연동 등 **비오디오**는 PC 오프·Driver 대기전원으로 남을 수 있다. 상세: [Desk Driver 「오디오 · PC 전제」](장비-NEXA%20Desk%20Driver.md).
앰프 전원·POT4 마스터: [Desk Driver 「WONDOM 앰프 (JAB5)」](장비-NEXA%20Desk%20Driver.md).
**아트 확장:** 웹 (p5 등) → MQTT/WS → Driver 조명. 구조·페이로드 초안: [Desk Driver 「아트 프로젝트 확장」](장비-NEXA%20Desk%20Driver.md).
**닉시 이관:** Desk TTS → 닉시 전용 스피커는 Driver 문서 트리거 초안 따름 (병행 후 조건 충족 시).

## 사운드 믹싱 · 채널 (기획)

PC 에서 여러 소리 소스를 **세션으로 섞는** 자리. 하드웨어 마스터 (JAB5 POT4) 와 층을 나눈다. 앰프·존 하드웨어: [Desk Driver 「WONDOM」](장비-NEXA%20Desk%20Driver.md).

### 계층

| 층 | 이름 | 역할 |
| :--- | :--- | :--- |
| L1 | **세션 버스** (`media` / `media_mix`) | 브라우저·TTS·(선택) 기타의 상대 볼륨·더킹 |
| L2 | **장치 라우팅** | 어떤 Windows/코어오디오 엔드포인트로 내보낼지 (1 차: 기본 장치 하나) |
| L3 | **ampMaster** | Desk Driver → JAB5 **POT4**. 스피커단 **볼륨 상한**(전체 음량의 최대치). 버스 믹서가 아님 |

```text
브라우저 재생 ──┐
AI TTS ─────────┼── L1 믹싱/더킹 ──► L2 엔드포인트 ──► Scarlett ──► JAB5 ──► 스피커
기타(선택) ─────┘         │                              │
                          └─ 상태 이벤트 ──► 조명 level   └── L3 ampMaster(선택·씬)
```

### 세션 버스 (1 차)

| 버스 id | 소스 | 평소 | AI TTS 안내 중 | 안내 종료 후 |
| :--- | :--- | :--- | :--- | :--- |
| `bus.media` | 브라우저·Desk 템플릿 URL·로컬 플레이리스트 | `userMediaGain` (사용자) | **더킹** → `userMediaGain × duckRatio` | `fadeIn` 으로 복귀 |
| `bus.tts` | AI TTS / 시스템 안내 음성 | 0(미재생) 또는 대기 | **`ttsGain`** (평소보다 ↑ 가능) | 페이드아웃 후 정지 |
| `bus.other` | OS·통화 등 | 손대지 않음 (기본) | 손대지 않음 또는 약 더킹 (미결) | — |

### 더킹 · 페이드 파라미터 (후보 기본값)

실측 전 **후보**. Desk 설정으로 덮어쓴다.

| 키 | 후보 기본 | 의미 |
| :--- | :--- | :--- |
| `duckRatio` | **0.25** (−12 dB 근처 체감) | TTS 중 `bus.media` 배수 |
| `duckFadeMs` | **150** | 더킹 진입 |
| `unduckFadeMs` | **400** | 복귀 |
| `ttsGain` | **1.0 ~ 1.2** | TTS 버스 게인 (클리핑 주의) |
| `ttsPreRollMs` | **80** | 더킹 안정 후 TTS 시작 |
| `ttsPriority` | **true** | TTS 가 `bus.media` 보다 우선. 동시 재생 허용 (더킹) 이지 완전 뮤트는 기본 아님 |
| `hardMuteMediaOnTts` | **false** | true 면 미디어 완전 묵음 (특수 씬) |

### TTS 트리거 (연동)

| 계기 | 동작 |
| :--- | :--- |
| 매트 기상 → Desk 재생 전 안내 | (선택) 짧은 TTS 후 템플릿 URL. 또는 URL 만 |
| 로터/Desk “안내” 명령 | `bus.tts` 재생 + 더킹 |
| 포털/자동화 알림 | 동일. 연속 TTS 는 큐 (한 줄기) |

재생 중 새 TTS: **큐에 이어붙이거나** 현재 TTS 중단 후 교체 — 기본 후보 **큐**.

### ampMaster 와 더킹

| 정책 | 요지 |
| :--- | :--- |
| **A. 분리 (1 차 확정)** | 더킹은 L1 만. POT4/`ampMaster` 는 사용자·씬만. JAB5 포트는 **10 kΩ AUX_ADC 분압**(WONDOM 볼륨 조절 저항기·AA-JA11117 실측≈10.27 kΩ) |
| B. 약연동 | 쓰지 않음 (보류). 필요 시 재검토 |

Scarlett 앞에서 미디어만 줄이고 TTS 는 유지·상승해 **명료도**를 확보. 하드웨어 마스터는 [WONDOM POT4](장비-NEXA%20Desk%20Driver.md).

### 감지 페이드 인 · 의도 뮤트 페이드 아웃

| 동작 | 방침 |
| :--- | :--- |
| 오디오 **감지** 시 | PC/세션 쪽 게인 **페이드 인**(L1). 임계·채터링 방지는 구현 때 |
| 사용자 **의도 뮤트** | 동일 층에서 **페이드 아웃** 후 유지 |
| **건드리지 않음** | JAB5 POT4 · `ampMaster` · digipot · 볼륨 저항기 |

의도 뮤트 중에는 감지 페이드 인을 **하지 않음**. 정책 A 와 동일 축.

### 출력 라우팅 · 존 (Desk 쪽)

| 단계 | Desk | 하드웨어 |
| :--- | :--- | :--- |
| **1 차** | 기본 재생 장치 **하나**. 더킹만으로 TTS 확보 | JAB5 ×1 |
| **2 차** | `bus.tts` → 장치 T, `bus.media` → 장치 M (가상 케이블·Scarlett 멀티아웃) | 라인에서 합쳐지거나 존별 JAB5 |
| **3 차** | `zone.desk` / `zone.room` 메타로 버스 바인딩 | [WONDOM 존 표](장비-NEXA%20Desk%20Driver.md) 구성 C/D |

TTS 만 근거리 존·음악은 전 존 — **3 차**에서 명시.

### `media_mix` / `desk_driver_amp` 이벤트 (초안)

| 방향 | 예 | 페이로드 요지 |
| :--- | :--- | :--- |
| 내부 | `tts.start` / `tts.end` | id, 길이 ms |
| 내부 | `mix.state` | `bus.media`·`bus.tts` 게인 |
| → Driver | `ampMaster.set` | 0…100, zone? |
| → Driver | `amp.seq` | 시퀀스 id (전원) |
| → Driver | `level.set` / `scene.set` | ch·level·씬 (조명·아트 공통) |
| → Driver | `vuLevel` | 0…100 |
| → Driver | `light.level` | 루프백 연동 (기존, `level.set` 과 정렬) |

스키마·토픽: [Driver 페이로드 초안](장비-NEXA%20Desk%20Driver.md). JSON 키는 구현 직전 확정.

### 믹스 상태머신 (초안)

```text
IDLE ──tts.start──► DUCKING ──(duckFadeMs)──► TTS_PLAY
                         ▲                         │
                         │                    tts.end / 큐 다음 없음
                         │                         ▼
                         └──────── UNDUCKING ◄── (unduckFadeMs) ── IDLE
```

| 상태 | `bus.media` | `bus.tts` |
| :--- | :--- | :--- |
| IDLE | `userMediaGain` | 0 |
| DUCKING | 보간 → ducked | 0 (pre-roll) |
| TTS_PLAY | ducked | `ttsGain` |
| UNDUCKING | 보간 → user | 0 |

- 큐에 TTS 가 남아 있으면 TTS_PLAY 에서 다음 항목으로 가고 UNDUCKING 을 생략 (또는 짧은 갭만).
- 사용자가 노브로 `userMediaGain` 을 바꾸면 IDLE·UNDUCKING 에만 즉시 반영. TTS_PLAY 중에는 **목표만 갱신**, 적용은 UNDUCK 후 (후보).

### Scarlett · 장치 이름 (운영)

| 항목 | 방침 |
| :--- | :--- |
| 기본 출력 | Desk 설정 `audio.out.default` = Scarlett 재생 장치 id/이름 |
| 1 차 | 모든 버스 → 이 장치 하나 |
| 2 차 | `audio.out.media` / `audio.out.tts` 분리 시 이름 두 개. 미설정이면 default 로 폴백 |
| 장치 사라짐 | 재생 중지 · 트레이 알림. 앰프 전원 시퀀스는 건드리지 않음 (기본) |

### 롤아웃 (Desk ↔ WONDOM 동기)

| 단계 | Desk | Driver/WONDOM |
| :--- | :--- | :--- |

## 설정·보안 (기초)

- 장비마다 자격. 공통 비밀번호·와일드카드 구독 지양 (패밀리 보안과 동일 취지).
- 로컬 브로커 우선, 없으면 포털 정책에 따름.

- NEXA Desk 는 **수신 포트 최소화**(필요 시 localhost 만).

### 데이터 저장소 (웹 기본 · 민감 로컬 · 선택)

| 층 | 어디에 | 예 | 정책 |
| :--- | :--- | :--- | :--- |
| **A — 기본** | **포털 (웹 서버)** | 계정·스케줄·Path·음악 템플릿·이력·원격 정책·대부분 설정 | **원본은 웹.** PC·장비는 캐시/미러 (NVS 등) |
| **B — 민감** | **로컬만** | MQTT/브로커 비밀번호·토큰·API 키·장비 페어링 비밀·로컬 시크릿 | **웹에 기본 올리지 않음.** env·`platformdirs` 시크릿. 로그 금지 |
| **C — 개인 선택** | 로컬 또는 웹 | Desk 셸 배치·로컬 플레이리스트 메타·“이 PC 만” 선호 항목·(선택) 일부 설정 미러 | 기본은 A 에 가깝게 두되, **사용자가 로컬만 / 웹 동기**를 고름 |

- **민감 (B) 을 웹에 두는 옵션**은 열더라도 **기본 off · 명시 opt-in**. 가능하면 B 는 동기화 대상에서 제외.
- Path 등 공용 테이프 원본은 이미 **포털 DB**(A) — [Path 기획](기획-NEXA%20Path%20템플릿%20—%20SVG%20키프레임·JSON·G방언.md).
- 오프라인: A 의 로컬 미러로 재생·실행. 비밀 (B) 없으면 원격만 제한.

## 포털·브라우저와의 관계 — 세 갈래

포털 UI 연동을 **셋으로** 나눈다. 백엔드 (계정·스케줄·AI) 는 같고, **표시·밀착도**만 다르다.
**내용은 포털 · 표시 기본은 Desk 웹뷰 · 외부 브라우저는 보조**(「구현 단속」).

| 방식 | 관계 | 요지 |
| :--- | :--- | :--- |
| **NEXA Desk 웹뷰** | **직접 (밀착) · 기본** | Desk 셸 안에 **같은 포털 URL**. 모드: 프레임리스 창·사이드바·PIP·전체화면 등 (「표시면 · 셸 모드」). 네이티브 브리지·“Desk 에서 재생” |
| **일반 브라우저** | **간접 · 보조** | 크롬 등으로 포털만. 공유·북마크·“그냥 웹”. Desk 는 MQTT·브리지로 백그라운드 반응 |
| **Chrome 확장** | **브라우저 정밀** | native messaging. 탭·패킷 정밀. 포털 외 허용 사이트 어댑터 가능 |

- 웹뷰·브라우저 모두 **포털을 그림**. Desk 전용 UI 를 따로 키우지 않음 (단속).
- **기본 경로 = 웹뷰 셸 + 포털 URL.** 외부 브라우저는 사용자가 열 때.
- 일반 브라우저만 쓸 때: Desk = **백그라운드**(파이썬 등) + 필요 시 트레이.
- Chrome 확장: Desk Driver·미디어·버스 + 확장 어댑터. HID·확장·페이지 겹치면 **확장/패킷 우선**(세부 미정).
- 셋 다 없어도 NEXA Desk **자체 기능**(로컬 미디어 등) 은 동작 가능.

```text
로터 ── ESP-NOW ── Desk Driver ──┬── USB HID ──────────► OS / 일반 브라우저 활성 창
                                 ├── 로컬 구동단 ─────► 책상 주변기·국소 조명 등
                                 └── 패킷 ─────────────► NEXA Desk
                                                           ├── 웹뷰 브리지 ──► Desk 안 포털
                                                           └── native msg ──► Chrome 확장 ──► 탭/콘텐츠 스크립트
```

## 로터·장비와의 관계

**조작 방향:** Desk/포털 UI 는 **키·마우스가 기본**. 로터를 갖고 있으면 같은 (및 현장용) 기능을 로터로 **더 편하게** 쓴다 — 「입력 · 조작」.

| 경로 | 용도 |
| :--- | :--- |
| 로터 → ESP-NOW → [Desk Driver](장비-NEXA%20Desk%20Driver.md) → NEXA Desk/HID/로컬 구동/(확장) | PC 슬롯·HID·패킷·로컬 구동단. **BT/Wi‑Fi HID 없음**(ESP-NOW 통일). Desk·확장 직접 제어는 병행 |
| 매트/장비 → MQTT → NEXA Desk | 도메인 이벤트 |
| NEXA Desk → 포털 | 재생 상태·이력 (선택). 웹뷰·간접·확장 공통 |
| NEXA Desk ↔ Chrome 확장 | native messaging. 탭 타깃·페이지 이벤트 |

매트 조작 피드백 LED 는 로터 (또는 NEXA Desk UI). NEXA Desk 의 주 매체는 **소리·화면**.

## 전원·슬립 · 아침 기상

PC 가 슬립하면 **NEXA Desk 도 기본은 같이 멈춘다.** 아침 재생은 **먼저 PC 를 깨우거나 켠 뒤** Desk **웹뷰**로 템플릿 URL 을 연다. Desk 미설치·웹뷰 미지원이면 **일반 브라우저**로 폴백. Desk Driver 만으로 깨우기·원격 전원 가능 (라우터 불필요). 상세·MQTT·WoL: [장비-NEXA Desk Driver](장비-NEXA%20Desk%20Driver.md) 「전원·깨우기」. 알람 지정 본문: [매트 「기상 알람」](장비-스마트%20온수%20매트%20해킹%20제어.md).

| 주체 | 역할 |
| :--- | :--- |
| **매트** | **입면·수면·기상·알람 전담.** 포털 JSON **미러 (NVS)** + 일회 (로터). 포털 OFF 여도 미러로 트리거. 샘플 재생 안 함 |
| **포털** | **기상 스케줄 = 캘린더 내부 기능**(웹). 절대 시각·**음악 스타일 템플릿**·URL·JSON 원본 |
| **로터** | 매트 5 번: 일회 **N 분 (시) 후**만. URL/템플릿 선택 없음. Wi‑Fi 안 염 |
| **NEXA Desk Driver** | 매트 (등) 요청 시 **깨우기·원격 전원**. 알람 시각을 포털에 쓰지 않음 |
| **NEXA Desk** | PC 재개 후 **재생만**. 알람을 포털에 대신 입력하지 않음 |
| **OS** | 슬립/절전. USB remote wake·WoL 허용 |

### 아침 기상 시퀀스 (기획)

```text
[지정]
  정기: 포털 캘린더(웹) → JSON 원본 → 매트 NVS에 JSON 미러 (끊김 대비)
  일회: 로터 5번 “N분 후” → 매트 RTC 절대·NVS → (가능 시) 포털 동기
  충돌: 로터 일회 ↔ 캘린더 정기 → 나중 저장이 덮음
[트리거] 매트가 미러/일회 시각·WAKE_UP_BOOST·앉음 앞당김 판정 (포털 없어도 미러로 가능)
    → 재생 시작 알림 (MQTT 등) + PC 슬립/꺼짐이면 Desk Driver 깨우기·전원
    → OS 재개 → NEXA Desk 기동
    → Desk 웹뷰(기본)로 템플릿 URL 재생
    → Desk 없음·웹뷰 미지원 → 일반 브라우저로 동일 URL (확장 불필요)
```

- 슬립이어도 **Desk Driver 대기전원 + 깨우기**면 재생까지 이어진다.
- Desk 는 로터 알람 지정의 **중계·포털 기록 경로가 아님.**
- **아침 재생 UI:** 웹뷰 기본 · 미설치/미지원 시 브라우저. Chrome 확장은 아침 재생 필수 아님.
- **스케줄 원본=포털 캘린더 · 실행 사본=매트 JSON(NVS).** JSON 필드 표는 포털/매트 스키마 문서에서 채움 (버전 핀).

## 아직 닫지 않은 것


- 로터→NEXA Desk: **Desk Driver 가 기본** — [장비-NEXA Desk Driver](장비-NEXA%20Desk%20Driver.md). NEXA Desk↔Desk Driver 양방향·시리얼 모드는 그 문서 미결
- 오디오 캡춰 루프백 분석 (밴드·주기)·AI 안내 더킹 깊이·복귀 곡선 · `desk_driver_lights` 페이로드
- `media_mix`/`desk_driver_amp` JSON · Scarlett 장치 id 프로비저닝 UI
- 기본 기능 (**NEXA Desk 가 켜지고, MQTT 를 받고, 음악을 틀 수 있는 최소 동작**) 롤아웃 1 완료 후 2·3 일정 · WONDOM `jabLayout` 과 zone 키 정렬

- HUD: 셸 PoC 범위 (클릭 관통·모니터) · 1 차로 올릴 데이터 슬롯 (볼륨/재생/매트 등) 화이트리스트
