# 레일캠 - 허니왜건 말벌 레이저 요격 전략

허니 왜건 (아파트형 8 칸 복합군) 소문 주변 **말벌 레이저 요격** 전략서다.
**니치아 M140(445nm 2W) 단펄스** 운용·안전·`FIRE_OK`·인터록이 본 문서의 중심이며, 비전·와이어 XY·ESP32↔RPi 는 그 조준·교전을 성립시키기 위한 수단이다.

플랫폼 (보안 LED·사이렌·520nm 라인·피에조·기상·IMU) 개요 → [`레일캠-GRC 외부 보안·생태 플랫폼.md`](레일캠-GRC%20외부%20보안·생태%20플랫폼.md).
**레이저 발사 정책·하드웨어·게이트의 단일 원본은 본 문서.**

소문 직근 **피듀셜 마커 (AprilTag/QR) 중심 설계는 폐기**한다. 대신 **외벽 물리적 그리드 + 단일 카메라 + 와이어 XY + 2 축 짐벌**로 조준하고, **복합군 방풍벽의 복합군 ID 피듀셜**(→ [`미아 벌 방지 및 교통 체증 극복 마스터 플랜.md`](미아%20벌%20방지%20및%20교통%20체증%20극복%20마스터%20플랜.md) · 불투명 벽·깊이 300mm) 은 **칸·절대 앵커**로 적극 활용한다.

**표적 범위:** 자유비행 추적·요격이 아니다. **소문에 달라붙거나 소문 앞을 저속 호버링하는 말벌**만 교전한다.
**컴퓨트:** 스캐너 구동부에 라즈베리 파이를 두지 않는다. **ESP32(약 2 대, ESP32-CAM 포함)** 가 촬상·이송·무장 로컬을 담당하고, **약 5m 떨어진 RPi**가 스틸컷을 받아 좌표·게이트를 계산한다.
**링크:** 기본 **ESP-NOW**. **평시** `patrol_wake_ms`=**10000**(≈**10 초**) 마다 상황 스틸 1 장 → RPi (UI·느린 순찰). **스캐너 ESP**는 로컬로 **의심만** 판정 (큰 물체·장면급변·말벌급 후보) → 의심 시 즉시 스틸 업로드. **말벌**은 수 초 지연 (≈5 초급) 도 허용. **확정·타격·정확도는 RPi**. Engage 시 빈도↑·RPi **크롭 ROI**·절대 ID 없으면 짐벌 **2 컷**. 해지 후 Sleep. 전력은 **와이어 급전**.

핵심 제어는 **정밀 단안 3D 거리 추정으로 레이저를 쏘는 것**이 아니라,

1. 말벌의 **대략적 XY(칸·소문 위치)** 로 스캐너·레이저 헤드를 이동하고
2. 카메라 **화면 중심 (0,0)** 에 말벌을 수렴시킨 뒤
3. **설치형 작업거리 \(D\_{work}\)**(설계 기본값 **500mm**, 현장 변경 가능) 에서 짐벌 2 축으로 미세 조준하여
4. 아군 (꿀벌) 이 **배제 반경 (5mm) 안**에 있으면 **XY 를 살짝 옮겨 시선 (조준각) 을 재계산**한 뒤
5. **`FIRE_OK` 를 만족할 때만 M140 2W 단펄스**를 발사하는 것이다.

**외벽·소문 ↔ 헤드 거리는 가동 중 실시간 추정하지 않는다.** 한 설치에서 기구적으로 고정된 \(D\_{work}\) 를 쓰고, 설치 환경에 맞게 설정값만 바꾼다.
동일하게, 아래 **환경 설정 변수**들은 비전으로 매 프레임 추정하지 않고 **설치·현장 config**로 둔다.

## 0. 레이저 운용 (M140 · FIRE_OK · 인터록)

본 절이 **445nm 고출력 레이저의 단일 운용 원본**이다. GRC 플랫폼 (`레일캠-GRC 외부 보안·생태 플랫폼.md`) 은 보안·생태 이펙터만 다루고, 여기서는 **말벌 단펄스 발사**만 정의한다.

### 0.1 최상위 원칙 (변경 불가)

1. **사람·사람 유사 객체 1 원칙**
   비전/센서상 **사람 (human)** 뿐 아니라 **사람처럼 보이는 것 (person-like / humanoid / 불확실 인형·실루엣)** 이 **한 프레임이라도** 잡히면 → **M140 즉시 중지·무장 해제**.
   “확정 사람”을 기다리지 않는다. **의심만으로도 Lockout.**

2. **말벌 전용 (Wasp-Only)**
   M140 은 **말벌 (등검은·장수 등, 정책상 wasp 클래스) 로 확정된 경우에만** 발사한다.
   **조수·침입·미확인·생태 알람·수동 “위협 제압”만으로는 절대 켜지지 않는다.**

3. **소문·외벽 지향만 (Entrance-Facing Only)**
   **카메라·레이저 광축이 허니 왜건 소문/외벽 쪽을 향할 때만** 발사한다.
   하늘·측면·후면·개방 공간·사람 접근로 등 **소문이 아닌 방향을 보면 발사 금지** (§0.4.3).

4. 우선순위
   **사람·사람유사 안전 ≫ 아군 (꿀벌) ≫ 소문 지향·빔 경로 ≫ 장비·법규 ≫ 보안 경고 (비레이저) ≫ 말벌 단펄스**

### 0.2 M140 발사 허용 로직 (`FIRE_OK`)

발사 (또는 충전·암드 유지) 는 아래를 **전부 만족 (AND)** 할 때만 허용한다. 하나라도 깨지면 **즉시 HOLD/ABORT + 전원 경로 차단**.

```text
FIRE_OK =
    target_class == WASP                    // 말벌만. 그 외 클래스 전부 거부
  ∧ wasp_conf >= wasp_conf_min              // 확정 신뢰도
  ∧ engage_* (소문 근접·저속 등)            // 비교전 비행 제외
  ∧ entrance_facing_ok                      // 카메라·레이저가 소문/외벽 지향 (§0.4.3)
  ∧ NOT person_like_any                     // 사람·사람유사·인형 실루엣 등 0건
  ∧ NOT human_sensor_trip                   // PIR 등
  ∧ ally_keepout Clear                      // 꿀벌 배제 (§6)
  ∧ weather 허용 ∧ imu_settle_ok
  ∧ laser_enable ∧ laser_master_sw_on ∧ NOT laser_temp_lockout
  ∧ NOT unknown_large_in_beam_roi           // 빔 근처 미확인 대형 거부
```

| 판정                                | M140                          | 대신 쓰는 것 (플랫폼)       |
| :---------------------------------- | :---------------------------- | :-------------------------- |
| **말벌 확정** + 위 AND              | 단펄스 허용                   | —                           |
| 조수                                | **금지**                      | LED·사이렌·피에조 초음파    |
| 사람 / **사람 유사** / 침입         | **금지**                      | LED·사이렌·520nm 라인       |
| 미확인                              | **금지**                      | 조명·위협 LED·재스틸        |
| 생태 알람만                         | **금지**                      | 알림·유도 TX(비레이저)      |
| **렌즈가 소문 반대·측면·상하 과각** | **금지**                      | 짐벌·이송으로 소문면 재정렬 |
| 수동 오버라이드 “조수에 레이저”     | **금지** (펌웨어에 경로 없음) | —                           |

**가동 중 중지:** 펄스 중이라도 `person_like_any`·비 -WASP·**`entrance_facing_ok` 깨짐**이면 **즉시 차단**.

### 0.3 광원별 역할 (레이저 vs 비레이저)

| 수단                               | 본 전략서                     | 플랫폼 (`레일캠-GRC …`)                |
| :--------------------------------- | :---------------------------- | :--------------------------------- |
| **M140 445nm**                     | **`FIRE_OK` 만** — 말벌 단펄스 | 채널 목록·에스컬레이션 S4 진입점만 |
| 520nm 라인 / LED / 사이렌 / 피에조 | 발사 대체·사전 유도만 언급    | **보안 주력** 상세                 |

**구 S4b(조수용 450nm PWM) 는 폐기한다.** 조수·침입에 고출력 블루 경로 없음.

### 0.4 인터록 · 물리 전원 스위치 · 빨간 점멸 · 소문 지향

| 계층                            | 내용                                                                          |
| :------------------------------ | :---------------------------------------------------------------------------- |
| **Person-like Lockout (1 원칙)** | `person_like` / human / humanoid → **M140 VCC·무장 즉시 OFF**                 |
| Pre-Launch                      | 위 조건 또는 비 -WASP 면 출격·암드 자체 거부                                    |
| E-Stop                          | 사람유사 진입 시 이송 정지, 짐벌 하향                                         |
| 하드 인터록                     | PIR 등 → **M140 전원 물리 차단**                                              |
| **레이저 마스터 물리 스위치**   | M140 공급 전단 **키/토글** — OFF 면 펌웨어와 무관하게 **전원 단절** (§0.4.1)   |
| **ARM 빨간 LED**                | 물리 SW **ON 즉시** 빨간 LED **점멸** (§0.4.2)                                |
| 아군 게이트                     | keepout 5mm (§6)                                                              |
| SW 무장                         | `laser_enable` ⊕ 하드 인터록 ⊕ **wasp-only** ⊕ **물리 SW ON** ⊕ **소문 지향** |
| 흔들림 Lockout                  | IMU 임계 초과 시 발사 금지                                                    |
| **소문 지향 게이트**            | 카메라·레이저가 **소문/외벽 쪽**이 아니면 발사 금지 (§0.4.3)                  |
| 빔 경로                         | 개방 시야·반사 최소화                                                         |

#### 0.4.1 레이저 전원 물리 스위치

M140 은 소프트웨어 `laser_enable` 만으로 켜지지 않는다. **마스터 물리 스위치**가 ON 이어야 드라이버까지 전원이 도달한다.

| 항목            | 권장                                                                                 |
| :-------------- | :----------------------------------------------------------------------------------- |
| **기능**        | M140(및 필요 시 LD 드라이버) **주전원 차단/투입**. OFF = 안전한 “비무장”             |
| **형태**        | 키 스위치 또는 명시적 토글 (오조작 방지 커버/가드 권장)                               |
| **배치 (우선)** | **홈 도킹·차체 조작 패널** 등 헤드가 아닌 **고정 거점**                              |
| **배치 (대안)** | 헤드 후면·비가시 측면, **렌즈·빔 방향과 반대쪽**                                     |
| **전기**        | 스위치는 **전원 양극 (또는 릴레이 코일 급전)** 직렬. MCU GPIO 가상 스위치로 대체 금지 |
| **상태 피드백** | SW 접점 → MCU 입력 `laser_master_sw`                                                 |
| **운용**        | 평시·운반·정비·사람 작업 시 **OFF**. 말벌 교전 세션 준비 시에만 ON                   |

물리 SW OFF 이면 `FIRE_OK` 와 무관하게 **발사 불가**. ON 만으로도 발사되지 않으며, wasp-only·지향·게이트를 통과해야 한다.

#### 0.4.2 빨간 LED 점멸 인디케이터

| 항목       | 권장                                                              |
| :--------- | :---------------------------------------------------------------- |
| **트리거** | 물리 마스터 SW **ON 되는 즉시** (가능하면 **하드웨어 직결 점멸**) |
| **표시**   | **적색 LED 점멸** (예: 1~2 Hz)                                    |
| **배치**   | 헤드 전면/상면, 주간 시인. 렌즈·빔 출구와 혼동 금지               |
| **의미**   | “M140 전원 ON / 암 가능” — 발사 중과 구분하려면 (선택) 별도 패턴  |
| **연동**   | SW OFF → LED **즉시 소등**                                        |
| **금지**   | 위협·조명 LED 와 **동일 채널 공유 금지**. ARM 전용                 |

권장: 마스터 SW 뒷단 **하드웨어 플래셔** — MCU 가 죽어도 SW 만 켜져 있으면 점멸.

#### 0.4.3 소문·외벽 지향 게이트 (`entrance_facing_ok`)

**카메라 렌즈와 레이저 출사 방향이 허니 왜건 소문 (외벽) 쪽을 향하지 않으면 M140 은 발사되지 않는다.**
보안 순찰·깃발·하늘을 보느라 짐벌이 돌아가 있어도, **발사 직전**에는 반드시 소문면 지향으로 돌아와야 한다.

| 검증 (권장 AND)           | 내용                                                                               |
| :------------------------ | :--------------------------------------------------------------------------------- |
| **A. 짐벌·자세 엔벨로프** | 팬/틸트가 **소문면 허용각** 안 (`gimbal_entrance_pan/tilt_min_max`)                |
| **B. 비전 FOV**           | 프레임에 **외벽 그리드·소문·소문 컬러** 특징이 충분 (`entrance_feat_score >= min`) |
| **C. 말벌 위치**          | 말벌 bbox 가 **소문 ROI / 교전 존** 안                                              |
| **D. (선택) IMU 자세**    | 헤드가 “벽 대향” 캘리브 자세와 일치                                                |
| **E. 동축·보어사이트**    | 보정 후 **레이저 예상 빔도 같은 소문면**                                           |

```text
entrance_facing_ok =
    gimbal_in_entrance_envelope
  ∧ wall_or_entrance_visible
  ∧ wasp_in_entrance_engage_roi
  ∧ (optional) imu_attitude_ok
```

| 상황                           | 결과                                    |
| :----------------------------- | :-------------------------------------- |
| 하늘·측면·후면·통로만 보임     | **발사 금지** — 소문면으로 재조준       |
| 깃발·기상 ROI 만 보고 있음      | **발사 금지** — 교전 시 소문 ROI 로 복귀 |
| 소문면 + 말벌 + FIRE_OK 나머지 | 허용                                    |

이송 XY 가 해당 칸 앞에 있어도 **짐벌만 빗나가면** 불허.

### 0.5 니치아 M140 · 단펄스 · 컴팩트 방열

| 항목      | 사양                                                                   |
| :-------- | :--------------------------------------------------------------------- |
| 선정 모듈 | **니치아 (Nichia) M140** 블루 **445nm**, **2W (2000mW)**                |
| 용도      | **말벌 핀포인트 단펄스 전용**                                          |

| 방열 요소               | 내용                                                |

- 발사 조건은 **`FIRE_OK` 만**.
- **물리 마스터 SW + 빨간 점멸 LED + 소문 지향** 필수.
- `laser_pulse_ms` / `laser_cooldown_ms` / IMU·기상·아군 게이트.

### 0.6 운용 요약

- M140 = **말벌 단펄스 전용**.
- 사람 유사 → **1 순위 중지**.
- **렌즈·빔이 소문/외벽 쪽이 아니면 발사 불가**.
- **물리 SW OFF = 비무장.** ON = 빨간 LED 점멸.
- 보안·조수는 **비레이저**(플랫폼) 만.

### 피듀셜 정책 (소문 직근 폐기 · 방풍 복합군 유지)

소문 앞에는 환기·보초 꿀벌이 밀집하고, 프로폴리스로 인쇄 패턴이 가려진다.
**소문 직근 피듀셜은 실전 가용성이 낮아 폐기**한다.

대신:

1. **외벽 프레임 격자** + 칸 치수 DB 로 대략 위치
2. **복합군 방풍벽 (불투명) ID 피듀셜** 로 복합군·절대 앵커 확정 (미아플랜 개정)
3. 화각에 마커가 안 들어오면 **짐벌 2 컷**으로 보완

투명 방풍 너머 벌 판독은 쓰지 않는다.

## 2. XY 이송 하드웨어 (스캐너·레이저 헤드)

헤드 (카메라 + 짐벌 + 2W 레이저) 를 허니 왜건 전면에서 옮기는 **와이어 기반 XY**다.

| 축         | 기구                        | 역할·주행                                                           |
| :--------- | :-------------------------- | :------------------------------------------------------------------ |
| **X**      | **2 줄 와이어 + 피더 롤러**  | 횡방향 이송. 피더가 와이어를 밀어/당겨 헤드 X 위치 결정             |
| **Y**      | **와이어 권취 드럼**        | 종방향 이송. 드럼 감김/풀림으로 헤드 Y 위치 결정. **주행 ≈ 1800mm** |
| (작업거리) | 전면 스탠드오프 / 설치 지그 | 외벽·소문면까지 **\(D\_{work}\)** (기본 500mm)                      |

### 제어 관점 함의

- **대이송 (칸·소문까지)** 과 **아군 회피용 소폭 재배치**는 모두 이 XY 가 담당한다.
- 와이어·피더·드럼은 **백래시·장력·정착 시간**이 있다. 재배치 후 **정착 (settle)** 이 끝난 뒤 짐벌 재서보·발사한다.
- **수 mm~수십 mm 급 회피**는 XY, **서브도급 미세 추적**은 짐벌로 나눈다. 아군 5mm 회피를 짐벌만으로 억지하면 시선 (LOS) 이 아군을 스칠 수 있어, **시점을 옮기는 XY 재조준**이 맞다.
- **전력은 와이어 급전**, 데이터는 무선 (ESP-NOW) 으로 분리해 헤드 질량·케이블 항력을 줄이고 **내풍·소형화**한다.

## 3. 스캐너 컴퓨트·통신 (ESP32 ↔ 라즈베리 파이)

### 3.1 역할 분담

| 위치                     | 하드웨어                                            | 역할                                                                      |
| :----------------------- | :-------------------------------------------------- | :------------------------------------------------------------------------ |
| **스캐너 구동부**        | **ESP32 ≈ 2 대** (예: **ESP32-CAM** + 모션/무장 ESP) | 스틸 촬상·전송, XY·짐벌 구동, settle, **레이저 하드 인터록·무장**         |
| **차량/기계실 등 (~5m)** | **라즈베리 파이**                                   | 그리드·YOLO·아군 게이트·회피 벡터 등 **좌표·정책 연산**, 디지털 트윈 보고 |
| **RPi 측 (권장)**        | **브리지 ESP32**                                    | ESP-NOW ↔ USB/UART 로 RPi 연결 (RPi 는 ESP-NOW 직접 수신 불가)              |

스캐너에 **라즈베리 파이를 탑재하지 않는다.** 연산·발열·질량을 헤드에서 제거하고, 바람의 영향을 줄이기 위한 경량 설계와 맞춘다.

### 3.2 표적 전제 (통신·지연과 정합)

| 교전                                                | 비교전                                     |
| :-------------------------------------------------- | :----------------------------------------- |
| 소문 **착지·밀착**                                  | 빠른 **통과·자유비행**                     |
| 소문 앞 **저속 호버** (속도·체류가 `engage_*` 이내) | 고속 기동으로 스틸–연산–이송 루프를 벗어남 |

자유비행 요격용 연속 추적 루프를 전제하지 않는다. **준정적 표적 + 스틸컷 + 원격 연산**이 성립하는 범위만 다룬다.

### 3.3 링크: ESP-NOW

- **기본 링크: ESP-NOW** (2.4GHz, 저오버헤드 P2P, 이벤트 버스트).
- 일반 Wi‑Fi TCP 상시 스트림·이더넷 헤드 직결과 **다른 방식**이다.
  - Wi‑Fi: RPi 직접 수신 가능하나 스택·듀티가 커질 수 있음.
  - 유선: RF 는 없으나 헤드 케이블이 **항력·꼬임·질량**을 키워 내풍 설계에 불리 → **시험·폴백**용.
- 업링크: **JPEG 스틸 분할 전송**(§3.5) + 상태 (엔코더, settle, 무장).
- 다운링크: XY 목표, 짐벌 목표, 회피 스텝, **FIRE / HOLD / ABORT**, 스틸 **ACK/NACK**.
- **연속 영상 스트림은 쓰지 않는다.** (`still_on_events`, `tx_min_interval_ms`)
- **평시 Light Sleep** (§3.4). 라디오를 상시 ON 으로 두지 않는다.
- ESP-NOW 페이로드 상한 **250 바이트/프레임** → 스틸은 반드시 **청크 분할**(§3.5.2).

### 3.4 Light Sleep · 주기 감시 (기본 10 초) · 로컬 의심 · Engage·크롭·2 컷

ESP-NOW 를 **항상 깨워 두지 않고**, 평시는 **Light Sleep**으로 RF·CPU 듀티를 낮춘다.
다만 **완전 무감시는 하지 않는다.**

#### 3.4.1 역할 분담 · 평시 10 초 · 로컬 의심

| 단 | 책임 |
| :--- | :--- |
| **스캐너 ESP** | **의심만** — 큰 물체·장면급변 (보안), 말벌급 후보 (부정확 허용). 의심 시 **즉시** 스틸 업로드 |
| **RPi** | **확정·정확도·타격** — YOLO·그리드·아군 게이트·FIRE. 평시 수신 스틸로 UI·느린 순찰 |

| 모드 | 주기 / 트리거 | 동작 |
| :--- | :--- | :--- |
| **평시 (Patrol)** | **`patrol_wake_ms` = 10000** (≈ **10 초**, 5~10 초 가능) | 상황 스틸 1 장 → RPi (기록·UI). 말벌만 보면 이 간격으로도 충분 (≈5 초 반응 허용) |
| **로컬 의심** | 이벤트 (큰 물체 등) | 10 초를 기다리지 **않음**. 즉시 업로드 → RPi 판정. **보안 속응은 ESP 의심이 담당** |
| **Engage / Alert** | **`engage_still_ms` = 250~400** (가드 ≥ **200**) | RPi 확정 후 각성 · 빈도↑ · ROI. **연속 스트림 금지** |

**전제:** 말벌 교전은 **수 초 (≈5 초) 뒤 반응이어도 운용상 충분**. 반면 **큰 물체 출현**은 5~10 초 주기만으로는 늦을 수 있어, ESP 로컬 의심 → 즉시 업로드가 역할 분담의 핵심이다.

Engage 빈도는 ESP-NOW·RPi 가 한 주기를 소화하는 선에서만. `engage_still_ms_max`(200ms) 미만으로 올리지 않는다.

#### 3.4.2 RPi → CAM 다음 크롭 ROI (전송 부하↓)

말벌 확정·추적 중 RPi 는 ACK/CMD 에 **다음 프레임 크롭 박스**를 실어 보낸다 (`roi_cmd_enable`).

| 항목 | 내용 |
| :--- | :--- |
| 방향 | RPi → 브리지 → ESP32-CAM (`CMD` / ROI 확장 필드) |
| 내용 | `roi_x,y,w,h` (센서 좌표) 또는 정규화 박스 + `still_profile` |
| 효과 | CAM 이 **전체 VGA 가 아니라 요청 ROI 만 JPEG** → 청크 수·RF 점유↓ |
| 폴백 | ROI 명령 없거나 타임아웃 → `engage`/`pre_fire` 기본 프로파일 (전체 또는 소문 ROI) |

평시 patrol 은 전면 상황용이라 **풀 (또는 QVGA)**. Engage 이후부터 크롭을 적극 사용한다.

#### 3.4.3 절대 ID 마커 미검출 → 짐벌 2 컷

카메라 **화각** 때문에 현재 프레임에 **절대 좌표용 고유 ID 마커**(복합군 방풍 피듀셜·그리드 영점 등) 가 안 보이면, XY 만으로 칸을 단정하지 않고:

1. 짐벌을 `dual_shot_pan_offset_deg`(또는 틸트) 만큼 **좌·우 (또는 상·하) 두 자세**로 나누고
2. 각 자세에서 스틸 1 장 + meta 에 **짐벌각·샷 인덱스 (0/1)** 를 실어 보내고
3. RPi 가 두 컷에서 마커/그리드를 합쳐 **절대 앵커·칸 ID**를 복원한다.

`dual_shot_on_no_abs_id=true` 일 때만. Engage 중에는 크롭·빈도와 시분할해 RF 를 넘기지 않는다.

#### 3.4.4 복합군 방풍 피듀셜 활용

소문 **직근** 피듀셜은 폐기 유지.
**복합군 방풍벽 (불투명·깊이 300mm)** 의 **복합군 ID 피듀셜**은:

- 칸/복합군 **절대 ID** 확정, 그리드 피팅 초기값·검증
- 2 컷 시 한 장에라도 잡히면 앵커로 사용
- 투명 벽 너머 벌 판독 대체 (미아플랜과 동일 취지)

#### 3.4.5 상태표 · 흐름

| 상태                   | 동작                                                                                                                 |
| :--------------------- | :------------------------------------------------------------------------------------------------------------------- |
| **Idle (Light Sleep)** | RF 상시 ON 없음. `patrol_wake_ms`(기본 **10000**) + **로컬 의심 감시**                                               |
| **Patrol wake**        | 깨어남 → 스틸 1 장 (`patrol`) + meta → ESP-NOW 분할 → RPi |
| **RPi 판정**           | 말벌 Engage / 보안 특이 / Clear. Engage 시 **ROI·engage_still_ms** 하향 명령 |
| **Clear**              | ACK 후 Light Sleep                                                                                                   |
| **Alert / Engage**     | 각성 유지 · `engage_still_ms` 주기 · ROI 크롭 · 필요 시 **2 컷** · 이송·게이트·타격 |
| **해지**               | Clear → `session_idle_ms` → Light Sleep                                                                              |

```text
[Light Sleep]
    │  매 patrol_wake_ms = 10000 (≈10초) · 의심 시 즉시
    ▼
[평시 10초 스틸 → RPi] ── UI·느린 순찰
    │
[로컬 의심?] ── 큰 물체·장면급변·말벌후보 ──► 즉시 스틸 → RPi
    │
    ├─ RPi Clear ──────────────────────► Light Sleep
    │
    └─ RPi 확정 (말벌/보안) ──► 각성 (Alert/Engage)
              │  engage_still_ms · ROI · 필요 시 2컷
              │  타격 허가는 RPi만
              └─ 해지 ──► session_idle_ms ──► Light Sleep
```

**주의 (구현)**

- 평시 **10 초**는 **단발 스틸 순찰**이지 상시 스트림이 아니다. 속응은 **로컬 의심 업로드**가 담당한다.
- Engage 빈도↑는 **링크·RPi 여유 안에서만**. 포화 시 `engage_still_ms` 를 늘리거나 ROI 를 더 조인다.
- Light Sleep 중 ESP-NOW **상시 수신**은 가정하지 않는다. ROI·빈도 명령은 **Patrol wake·Engage 각성**에서만.
- Alert/Engage 중 Sleep 금지 → **해지 전까지 RF·각성 유지**.
- `patrol_wake_ms`·`engage_still_ms` 는 config 로 수정 가능.

### 3.5 스틸 압축 전략 · ESP-NOW 분할 패킷

ESP32-CAM → (ESP-NOW) → 브리지 ESP → (UART/USB) → RPi 경로에서, **한 장의 JPEG 를 250B 한도 안에 넣지 못한다.**
압축은 **캡처 단계에서 끝내고**, 링크는 **고정 헤더 + 청크**로만 나눈다.

#### 3.5.1 압축 전략 (Capture-side only)

| 원칙 | 내용 |
| :--- | :--- |
| **코덱** | 센서/카메라 **HW JPEG 만** (`still_codec=jpeg`). 이미 압축된 JPEG 에 zlib·재인코드 루프를 돌리지 않음 |
| **스트림 금지** | MJPEG/H.264 연속 송신 없음. **이벤트·순찰 단발**만 |
| **용량 게이트** | 완성 버퍼 ≤ `still_max_bytes`(기본 **12 KiB**). 초과 시 **품질↓ 또는 해상도↓ 1 회 재촬상** 후 재시도, 그래도 초과면 **ABORT + 로그** |
| **색** | 기본 **컬러 JPEG** (소문 HSV·그리드 대비). 그레이는 실험 프로파일만 |
| **ROI** | Engage/`pre_fire`: RPi 가 보낸 **다음 크롭 ROI** 우선. 없으면 소문·말벌 bbox 주변 크롭 후 JPEG (전송량↓) |

**프로파일 (권장)**

| `still_profile` | 해상도 (안) | JPEG quality 방향 | `still_max_bytes` 목표 | 용도 |
| :--- | :--- | :--- | :--- | :--- |
| **`patrol`** | QVGA (320×240) 또는 HVGA | **고압축**(용량 우선) | 6~10 KiB | 주기 순찰·보안 UI |
| **`engage`** | VGA (640×480) 또는 ROI | 중압축 | 10~12 KiB | 칸·말벌 확인·이송 전 |
| **`pre_fire`** | ROI 크롭 우선 / VGA | **저압축**(디테일 우선) | ≤12 KiB | 아군 5mm·중심 수렴·발사 직전 |

```text
[캡처]
  framesize · quality ← still_profile
       │
       ▼
  HW JPEG buffer
       │
       ├─ len ≤ still_max_bytes ──► 분할 송신 (§3.5.2)
       │
       └─ len > still_max_bytes ──► quality↑압축 또는 framesize↓ 1회
                                      └─ 여전히 초과 → drop + 재시도 다음 주기
```

**예상 청크 수 (대략):** 12 KiB ÷ 200 B/청크 ≈ **60 청크/프레임**.
`still_chunk_gap_us` 를 두면 순찰 1 장 송신에 수십 ms 수준 — `patrol_wake_ms=10000` 과 정합. 연속 스트림으로 키우지 말 것.

#### 3.5.2 분할 전송 · 공통 헤더

ESP-IDF 기준 ESP-NOW 사용자 데이터 **최대 250 바이트**.
본 설계: **고정 헤더 16B 급 + 페이로드 ≤200B + CRC16** (여유 확보). `still_chunk_payload` 기본 **200**.

```text
오프셋  크기  필드
0       2     magic = 0x4E58 ('NX')
2       1     ver = 0x01
3       1     msg_type
4       2     frame_id          // 프레임 단위, 래핑 uint16
6       1     flags             // bit0=MORE, bit1=REQ_ACK, …
7       1     hdr_crc8          // 바이트0–6
8       …     type별 바디
…       2     pkt_crc16         // 헤더+바디 전체 (리틀엔디안)
```

| `msg_type` | 이름 | 방향 | 역할 |
| :--- | :--- | :--- | :--- |
| `0x01` | `STILL_META` | CAM→Br | 프레임 메타 + 총길이·청크수 (JPEG 바이트 없음) |
| `0x02` | `STILL_CHUNK` | CAM→Br | JPEG 조각 |
| `0x03` | `STILL_END` | CAM→Br | 전체 JPEG CRC32 · 송신 완료 |
| `0x10` | `STILL_ACK` | Br→CAM | 수신 OK / 결손 비트맵 |
| `0x11` | `STILL_NACK` | Br→CAM | 타임아웃·폐기 요청 |
| `0x20` | `CMD` | Br→CAM/모션 | move/gimbal/fire/hold · **`ROI_NEXT`**(다음 크롭) · `STILL_RATE`(engage_still_ms) |
| `0x21` | `STATUS` | CAM/모션→Br | 엔코더·settle·무장 · **abs_id_seen** · dual_shot 인덱스 |

#### 3.5.3 `STILL_META` (0x01) 바디

| 오프셋 (헤더 뒤) | 크기 | 필드 | 설명 |
| :--- | :--- | :--- | :--- |
| +0 | 4 | `jpeg_len` | 완성 JPEG 바이트 수 |
| +4 | 2 | `chunk_total` | 예상 청크 수 |
| +6 | 2 | `width` / +8 `height` | 픽셀 |
| +10 | 1 | `jpeg_q` | 센서 quality 값 |
| +11 | 1 | `profile` | 0=patrol, 1=engage, 2=pre_fire |
| +12 | 4 | `t_ms` | CAM 모노토닉 ms |
| +16 | 2 | `enc_x_mm` / +18 `enc_y_mm` | 엔코더 mm |
| +20 | 1 | `gimbal_pan` / +21 `gimbal_tilt` | 약식 각도 |
| +22 | 1 | `cell_hint` | 칸 0–7, 0xFF=미지 |
| +23 | 1 | `meta_flags` | settle_ok, armed, … |

메타 **먼저 1 패킷** → 이어서 `STILL_CHUNK` → 마지막 `STILL_END`.

#### 3.5.4 `STILL_CHUNK` (0x02) 바디

| 오프셋 | 크기 | 필드 |
| :--- | :--- | :--- |
| +0 | 2 | `chunk_idx` (0 … chunk_total−1) |
| +2 | 2 | `payload_len` (1…`still_chunk_payload`) |
| +4 | `payload_len` | JPEG 바이트 연속 구간 |

`flags.MORE=1` 이면 후속 청크 있음. **무결성은 `STILL_END` 의 CRC32**로 확정.

#### 3.5.5 `STILL_END` (0x03) · `STILL_ACK` (0x10)

**END:** `jpeg_crc32`(전체 JPEG) + `chunks_sent`.

**ACK** (브리지→CAM)

| 필드 | 설명 |
| :--- | :--- |
| `frame_id` | 대상 프레임 |
| `status` | 0=OK, 1=PARTIAL, 2=CRC_FAIL, 3=TIMEOUT |
| `missing_bitmap[]` | PARTIAL 일 때 결손 `chunk_idx` |

CAM 은 PARTIAL 이면 **결손 청크만** `still_retransmit_max` 까지 재전송. CRC_FAIL/TIMEOUT 이면 폐기 후 **재촬상**.

#### 3.5.6 송신·조립 시퀀스

```text
[ESP32-CAM]
  JPEG ready (≤ still_max_bytes)
    → STILL_META → STILL_CHUNK × N → STILL_END
    → STILL_ACK
         ├─ OK → 완료
         ├─ PARTIAL → 결손 청크 재송
         └─ FAIL → 재촬상 or 다음 patrol

[브리지 ESP]
  META로 버퍼 할당 → CHUNK 슬롯 채움 → END에서 CRC32
    → OK면 UART로 [magic|jpeg_len|jpeg_crc32|jpeg_bytes] 1회 전달
    → ACK 회신

[RPi]
  완성 JPEG decode → YOLO/그리드/보안
```

**브리지 권장:** RF 만 청크, **UART 는 재조립된 단일 JPEG** — RPi 는 분할을 몰라도 된다.
**단일 파이프라인:** Engage 중에도 **동시에 두 `frame_id` 를 보내지 않는다.**

#### 3.5.7 용량·시간 예산 (설계 가이드)

| 항목 | 값 (안) |
| :--- | :--- |
| ESP-NOW MTU | 250 B |
| 청크 페이로드 | 200 B |
| 순찰 JPEG | ~8 KiB → ~40 청크 |
| 교전 JPEG | ~12 KiB → ~60 청크 |
| 청크 간격 | 0.5~2 ms (`still_chunk_gap_us`) |
| 1 프레임 RF 점유 | roughly 40~120 ms (재전송 전) |
| 조립 타임아웃 | `still_assemble_timeout_ms` 200~500 |

#### 3.5.8 의도적으로 하지 않는 것 (링크)

- JPEG 위 **이중 압축**, raw RGB/YUV 업링크
- 청크 없는 “거대 단일 ESP-NOW 페이로드” 가정
- 패킷 CRC 생략
- 연속 MJPEG 를 ESP-NOW 에 태우기
- RPi 에서 청크 조립을 필수로 두기 (브리지에서 끝내는 쪽이 기본)

### 3.6 메시지 시퀀스 (요지)

```text
[Idle] Light Sleep  ← 매 patrol_wake_ms(기본 10000≈10초) · 로컬 의심 즉시 · Engage 시 빈도↑/ROI/2컷 (§3.4)
    │
    ▼
[ESP-CAM] 상황 스틸 1장 (patrol 프로파일 · §3.5)
    │  ESP-NOW META→CHUNK×N→END → ACK  ← 짧게 RF 활성
    ▼
[브리지 ESP] 재조립 ──UART/USB──► [RPi] 화면 갱신 + 말벌/보안 판정
    │
    ├─ Clear → Light Sleep
    │
    └─ 말벌/보안 특이 → 각성 유지 (Alert/Engage)
           │  ESP-NOW 명령 (move / gimbal / fire|hold)
           │  + 재스틸 (engage / pre_fire 프로파일)
           ▼
      [모션 ESP] XY·짐벌 → settle → …
           │
           ▼
      (요격 시) 하드 인터록·FIRE_OK 통과 후 M140
           │
           ▼
      상황 해지 → session_idle_ms → Light Sleep
```

- 대이송·회피 이동 **후** 조준·발사 직전 **재스틸**을 권장한다. 한 장으로 전 과정을 끝내지 않는다.
- 최종 발사 허가는 RPi 정책과 함께, 스캐너 ESP 의 **로컬 무장·인터록**을 통과해야 한다.

### 3.7 RF 와 꿀벌 생태

- 본 링크는 **단거리 (~5m)·저듀티**이며, 평시는 Light Sleep + **10 초당 스틸 1 장** + **로컬 의심 시 즉시 업로드**. 상시 스트림·상시 RF ON 과 급이 다르다.
- 동일 2.4GHz 대역의 주변 Wi‑Fi·휴대 단말과 비교해도, **스틸 버스트 + Sleep**이면 노출을 더 줄일 수 있다.
- “영향 제로”를 단정하지는 않되, 설계 원칙은 **전송 최소화·평시 Sleep·소문면 상시 비콘 금지·안테나 소문 밀집면 직부착 지양**이다.
- 경량·내풍 (무선 데이터 + 와이어 전력) 과 **저 RF 듀티**는 같은 방향이다.
- 압축·청크 (§3.5) 로 **프레임당 RF 점유를 짧게** 유지하는 것이 생태·보안 순찰 주기를 양립시키는 수단이다.

## 4. 설치형 작업거리 \(D\_{work}\)

허니 왜건 **외벽 (소문면) 과 스캐너·레이저 헤드 사이의 거리**는 비전으로 매 프레임 재지 않는다.

| 구분        | 내용                                                                              |
| :---------- | :-------------------------------------------------------------------------------- |
| 성격        | **설치 시 고정** — 한 현장·한 장착에서 가동 중 변하지 않음                        |
| 설계 기본값 | **500mm**                                                                         |
| 변경        | **설치 환경에 따라 설정 가능** (차체·레일·가드·공간 제약 등)                      |
| 저장        | 장비/현장 설정값 `D_work_mm` (예: config·NVM). 부팅 시 로드                       |
| 연동        | 렌즈 초점·레이저 스폿·**5mm↔픽셀 환산**·DoF 는 모두 현재 \(D\_{work}\) 기준 캘리브 |

### 규칙

- 가동 중 \(D\_{work}\) 를 단안 bbox 등으로 **추정·갱신하지 않는다.**
- \(D\_{work}\) 를 바꾸면 (재설치·이격 조정) **초점·스폿·mm↔px 캘리브를 다시** 맞춘다.
- XY 회피·대이송은 평면 이동이며, 외벽까지 거리는 설정 \(D\_{work}\) 를 유지한다.

## 6. 아군 회피 XY 재조준 (5mm 게이트)

### 6.1 의도

단순 HOLD 만 하면 소문 앞 밀집 시 **말벌이 아군과 겹쳐 영원히 못 쏜다.**
짐벌만 살짝 틀면 **같은 시점의 LOS**가 아군 5mm 존을 스칠 수 있다.
그래서 **헤드 XY 를 옮겨 시선 기하를 바꾼 뒤** 조준각을 다시 잡고 쏜다.

### 6.2 판정

- 말벌 중심 (이미지 또는 작업면 mm 환산) 기준 **배제 반경 = 5mm**.
- 그 안에 꿀벌 (아군) 검출점이 하나라도 있으면 **발사 금지 → 회피 분기**.

### 6.3 회피 벡터 (원칙)

1. 말벌 위치 \(P_w\), 가장 가까운 아군 \(P_a\) 를 구한다.
2. 회피 방향: 아군에서 **멀어지는 쪽**(대략 \(P_w - P_a\) 또는 아군이 없는 사분면).
3. XY 에 **소폭 스텝**(예: 10~30mm, 현장 튜닝) 만 가한다. 칸 전체를 다시 훑지 않는다.
4. 정착 후 짐벌로 \(P_w\) 를 다시 화면 중심에 수렴 (조준각 재계산).
5. 5mm 게이트 재검사.
6. **최대 N 회**(예: 2~3 회). 계속 막히면 HOLD/ABORT 후 보고. 무한 추적은 하지 않는다.

### 6.4 주의

| 리스크                      | 대응                                                    |
| :-------------------------- | :------------------------------------------------------ |
| 말벌이 회피 중 이탈         | 추적 타임아웃·재감지 후 대이송부터                      |
| 와이어 장력·정착 전 발사    | **settle 완료 플래그** 후 서보·발사                     |
| 과도한 XY 스텝              | 스텝 상한 + **\(D\_{work}\) 유지** (이격은 바꾸지 않음) |
| 아군이 말벌에 달라붙은 경우 | N 회 실패 시 강제 중단 (아군 우선)                       |
| 링크 지연 중 표적 이탈      | 재스틸·`engage_*` 재검증, 실패 시 ABORT                 |

## 7. 비전 기준점 (그리드 · 컬러 · 검출)

### 7.1 외벽 격자 → 칸·소문 XY 맵

- OpenCV 직선 검출 + **8 칸 토폴로지 제약 (RANSAC/격자 피팅)** 으로 교차점을 찾는다. (**RPi**에서 수행)
- 설계 mm 와 매핑해 **월드/칸 좌표**를 만든다. 와이어 엔코더 (ESP 보고) 와 교차 검증한다.
- 가림이 심하면 **이전 유효 그리드 + XY 엔코더**로 폴백한다.

### 7.2 소문 컬러박스 → 보조 레퍼런스

- 칸별 소문 컬러 HSV 중심은 **보조**(칸 ID·국소 힌트).
- Primary 는 그리드. 컬러만으로 영점을 잡지 않는다.

### 7.3 말벌·아군 검출

- RPi YOLO 등으로 말벌 / 꿀벌을 구분하거나, 말벌 확정 후 주변 소형 객체를 아군 후보로 둔다.
- **`engage_vmax_mm_s` / `engage_hold_ms`** 로 소문 근접·저속만 교전한다.
- 말벌 bbox 크기는 **거친 근접 힌트만**. 정밀 Z·포커스 입력으로 쓰지 않는다.
- 5mm 게이트는 **픽셀→작업면 mm** 환산 (\(D\_{work}\)·렌즈 FOV 캘리브) 또는 동등한 픽셀 반경으로 구현한다.

## 8. 하드웨어·작업거리 요약

| 항목                   | 사양 방향                                                                                  |
| :--------------------- | :----------------------------------------------------------------------------------------- |
| 스캐너 컴퓨트          | **ESP32 ≈ 2** (CAM + 모션/무장). **헤드에 RPi 없음**                                       |
| 원격 연산              | **RPi ~5m** + (권장) **ESP-NOW 브리지 ESP**                                                |
| 데이터 링크            | **ESP-NOW**, 평시 Light Sleep + **`patrol_wake_ms`=10000**(≈10 초) + 로컬 의심 즉시 업로드             |
| 전력                   | **와이어 급전** (경량·내풍)                                                                |
| 카메라                 | 짐벌 헤드 **단일**(ESP32-CAM 등), 레이저 동축/시야 보정                                    |
| X 이송                 | **2 줄 와이어 + 피더 롤러**                                                                 |
| Y 이송                 | **와이어 권취 드럼**, 주행 **≈1800mm**                                                     |
| 작업거리 \(D\_{work}\) | **설치 고정**, 설계 기본 **500mm**, **현장 설정 변경 가능**                                |
| 짐벌                   | 팬·틸트 2 축 (중심 수렴·재조준)                                                             |
| 레이저                 | **니치아 M140 445nm 2W** 단펄스, \(D\_{work}\) 초점·스폿, **§0 FIRE_OK·물리 SW·소문 지향** |
| 초점                   | \(D\_{work}\) 맞춤 고정초점 (DoF) 우선, 필요 시 AF                                          |

\(D\_{work}\) 는 비전 추정 Z 가 아니라 **설치·설정으로 고정하는 타격 거리**다. 기본값은 500mm 이고, 환경에 맞게 `D_work_mm` 만 바꾼다.

## 9. 소프트웨어 시퀀스 (상세)

1. **설정 로드** — `D_work_mm`, `link_mode`, `patrol_wake_ms`(기본 **10000**, 사용자 변경 가능), `engage_*`, 캘리브 (RPi·ESP 동기).
2. **순찰 루프** — Light Sleep ↔ 10 초 순찰 스틸 + **로컬 의심 시 즉시 업로드** → RPi 확정. Clear 면 Sleep.
3. **Alert/Engage** — 특이 시 각성 유지. 그리드·엔코더 동기, `engage_*` 만족 시 요격 시퀀스.
4. **XY 대이송** — RPi 명령 → 모션 ESP. 중심 근접 + **\(D\_{work}\) 유지**.
5. **재스틸·짐벌 미세 조준** — settle 후 (Δu, Δv) → 0.
6. **5mm 아군 게이트**
   - Clear → 7.
   - Occupied → **아군 회피 XY 재조준**(§6) 후 5~6 반복, N 회 실패 시 ABORT.
7. **M140 발사·보고** — `FIRE_OK`(§0) 전부 만족 시에만 RPi FIRE + ESP 하드 인터록·물리 SW.
   `entrance_facing_ok`·person-like·아군·IMU 중 하나라도 깨지면 ABORT.
8. **해지** — 상황 Clear → `session_idle_ms` → Light Sleep·순찰 재개.

## 10. 의도적으로 하지 않는 것

- 소문 직근 피듀셜을 절대좌표 **필수** 앵커로 두지 않음.
- bbox 만으로 **mm 급 Z**를 뽑아 조준·초점에 쓰지 않음.
- 가동 중 \(D\_{work}\) 를 비전으로 **실시간 추정·변경**하지 않음 (설치·설정으로만 변경).
- **자유비행 말벌**을 연속 영상·고속 서보로 요격하려 하지 않음.
- 스캐너 헤드에 **RPi 를 올려** 질량·발열·상시 Wi‑Fi 를 키우지 않음.
- ESP–RPi **연속 스트림**·상시 비콘·**평시 RF 상시 ON**으로 듀티를 키우지 않음 (Light Sleep 기본).
- 아군 5mm 침범 시 **무조건 발사**하거나, **무한 XY 추격**하지 않음.
- 회피용 대행정 (칸 단위 재스캔) 을 기본값으로 두지 않음 — **소폭 스텝 + 재조준**만.
- **비 -WASP**(조수·침입·미확인) 에 M140 경로를 두지 않음.
- 렌즈·빔이 **소문/외벽이 아닌 방향**일 때 발사하지 않음.
- 물리 마스터 SW 없이 SW `laser_enable` 만으로 무장하지 않음.

## 12. 한 줄 요약

**M140 은 말벌 확정·소문 (외벽) 지향·아군 Clear·물리 SW ON·`FIRE_OK` 일 때만 단펄스한다.**
소문 근접·저속 표적만, ESP32 가 평시 **10 초**마다 상황 스틸을 보내고, **로컬 의심 (큰 물체 등) 시 즉시** 업로드한다. 말벌은 ≈5 초급 반응으로도 충분. **확정·타격은 RPi**, 이후 XY→중심→짐벌→5mm 회피·요격.
\(D\_{work}\) 는 설치 고정 (기본 500mm). 정밀 3D 측량·자유비행 요격·비 -WASP 레이저는 쓰지 않는다.
