# 기획 — NEXA Path 템플릿 — SVG 키프레임·JSON·G 방언

NEXA Path 는 **저장된 자세 (키프레임) 를 순서대로 실행하는 공용 테이프**다. 추적 모드의 Path 한 갈래로 온풍기에 먼저 얹지만, 형식 자체는 단축·다축 장비에 공통이다.

이 문서는 브라우저에서 템플릿을 만들고 (JSON), 장비 실행열 (**NEXA G 방언**) 로 컴파일하는 기획이다. **1 차 구현·시험은 단축 온풍 (원호)** 이고, 설계 목표는 **복합축으로 축만 늘려도 같은 스키마·같은 테이프**를 쓰는 것이다.

## 목표

- **공용:** 이동 (축) 과 장면 (이펙터·스킵) 을 분리한 Path 모델.
- **편집:** 키프레임을 만들고, 점마다 머무름·이펙터·스킵을 둔다. **1 축은 도형 클릭으로 충분**, **2 축 이상은 티칭이 기본**, 도면이 있으면 **벡터 가져오기**를 쓸 수 있다.
- **비트맵 → 벡터** 는 Path 가 아니라 **그래픽 (벡터화) 모듈**이다. Path 는 **확정된 SVG·폴리라인만** 가져온다.
- **원본 = JSON**, **실행 = G 방언** — 단축 → 다축 업그레이드가 “축 문자 추가”로 끝나게. 작성 방법과 무관하게 저장 포맷은 같다.
- **로터:** Path **템플릿 선택**만 (실행). 티칭 중에는 Manual·“키프레임 찍기”에 쓸 수 있다. 링 2 번 장비 프리셋 ≠ Path 템플릿.
- **1 차 적용:** 온풍 조준 원호 (도형 작성). 검증 후 다축·티칭·벡터 입력·동일 방언 확장.

## 적용 범위 (양봉·공용)

| 단계 | 장비·맥락 | 축 (안) | Path 가 하는 일 |
| :--- | :--- | :--- | :--- |
| **1 차 (시험)** | 칸탈·필름 온풍 / ThermoFlux 조준 | `A` (원호 1 자유도) | 구간 순회 + 점별 온·풍 + `scene` 스킵 |
| 이후 | 가드 레일캠 (GRC)·순찰각 | 레일·헤드 각 등 | 웨이포인트 순회, 사람 있으면 장면/경고 |
| 이후 | 리프팅·이송 | `Z` / 수평축 | 들어 올리기·내리기·경유점 |
| 이후 | 하이브리드 챔버 | 회전·뚜껑 등 | 공정 구간 순회 + 온도 장면 |
| 이후 | 열융착·작업대 | 작업 각·보조축 | 작업자 구역 Path |

벌 개체 추적이 아니다. mmWave·재실은 **사람·안전·장면 조건**에 쓴다.

## 핵심 모델

Path 한 줄의 의미는 항상 같다.

```text
자세(pose: 하나 이상 축) → (선택) 장면 스킵 평가 → 이펙터(온도·풍·I/O…) → 머무름 → 다음 자세
```

| 층 | 내용 | G 방언 |
| :--- | :--- | :--- |
| **운동** | 축 목표. 단축 `A`, 다축 `A+Y+…` | `G0` / `G1` |
| **시간** | 머무름 | `G4 P…` |
| **이펙터** | 장비별 출력 (온풍이면 온도·풍) | `M104`·`M106`·기타 M |
| **스킵** | `scene` / `travel` + 조건 | `M900 …` |

온·풍은 “온풍 전용 필드”가 아니라 **이 장비의 이펙터 채널**이다. 챔버면 같은 자리에 공정 온도·RPM 등이 올 수 있다.

## 축·기구 프로파일

템플릿은 장비의 **축 프로파일**을 참조한다.

| 항목 | 역할 |
| :--- | :--- |
| `axis[]` | 사용 축 문자. 1 차 `["A"]` |
| 축별 단위 | deg, mm, pulse 환산 |
| 축별 한계 | min/max. 초과 시 `LIMIT` |
| `reversible` | 정역 가능 여부. false 면 키프레임 순서·방향 제약 |
| 기하 (선택) | 원호이면 `arcRadiusMm` / `arcRadiusMaxMm`. 직선 레일이면 길이 |

에디터·작성 UI:

- **호스팅:** Path 에디터는 **포털 웹**. NEXA Desk·Chrome 확장에 에디터 UI를 두지 않는다(포털 단속). Desk 웹뷰는 **같은 포털 Path URL**. Desk는 미리보기·컴파일 헬퍼·실행 요청만([APP-NEXA Desk](APP-NEXA%20Desk.md)).
- **1 축 원호:** SVG 원호 클릭 (온풍 1 차) — 주력
- **1 축 직선:** 선분 위 클릭
- **2 축 이상:** **티칭이 주력**. 평면·직교 뷰·**벡터 가져오기**는 편집·미리보기·도면 입력
- **비트맵 처리:** Path UI 에 넣지 않음 → 「그래픽 (벡터화)」 모듈

## Path 작성 방법

저장 결과는 모두 같은 JSON(`pose` + dwell + effectors + skip). 차이는 **점을 어떻게 만드는지**다.

| 방법 | 요지 | 적합한 때 |
| :--- | :--- | :--- |
| **도형 편집** | 축 UI/SVG 에서 경로를 클릭·드래그해 키프레임 | **1 축.** 각·위치가 화면과 1:1 |
| **티칭 찍기** | Manual·관절 프리로 자세를 두고 “키프레임 생성” | **2 축 이상 기본.** 편리·기구적으로 정확 |
| **티칭 녹화** | 궤적을 주기/Δ마다 샘플 | 우회·곡선 재현 → (선택) 단순화 |
| **벡터 가져오기** | **이미 벡터인** SVG·폴리라인을 축 공간에 올려 Path 편집 | **2 축 도면·평면도.** 티칭과 보완 |

**비트맵은 Path 작성 방법이 아니다.** 비트맵 → 벡터 추출은 아래 「그래픽 (벡터화) — Path 와 분리」에서 한다. Path 는 그 결과 SVG 만 받는다.

### 언제 어떤 방법인가

| 축·상황 | 권장 작성 | 이유 |
| :--- | :--- | :--- |
| **단축 (온풍 원호 등)** | **도형 편집으로 충분** | 자유도 1. 임의 그림 업로드 이득이 작음 (호에 투영·클램프 필요) |
| **2 축 이상** | **티칭 찍기를 기본** | 공간 자세·리밋은 기구에 맞추는 편이 정확 |
| **2 축 + 도면 있음** | **벡터 가져오기** 후 편집·(필요 시) 티칭으로 pose 보정 | 대략 경로는 도면, 정확 자세는 티칭 |
| 다축 + 복잡한 우회 | 티칭 녹화 → (선택) 단순화 | 전 경로 재현 |

### 그래픽 (벡터화) — Path 와 분리

비트맵에서 선을 뽑는 일과 Path 테이프를 만드는 일은 목적·품질 기준이 다르다. **한 화면에 섞지 않는다.**

| 단계 | 모듈 | 하는 일 | 성공 기준 |
| :--- | :--- | :--- | :--- |
| 1 | **그래픽 (벡터화)** | 비트맵 업로드 → 이진화·외곽선·노이즈 제거·단순화 → **SVG/폴리라인 확정** | 깨끗한 도면 곡선 |
| 2 | **Path 편집** | 확정 벡터를 가져와 스케일·투영·키프레임·이펙터·스킵 | 장비 실행 테이프 |

```text
비트맵 업로드
  → [그래픽] 벡터 추출·수정 → SVG(또는 폴리라인) 확정
  → [Path] 벡터 가져오기 → 작업 영역 맞춤 → 키프레임 편집 → JSON / G방언
```

- **SVG 를 직접** 갖고 있으면 그래픽 단계를 건너뛰고 Path 「벡터 가져오기」만 한다.
- 그래픽 모듈은 Path 전용이 아니다. 도면·맵·로고 등 **공용 벡터화**로 두고 Path 가 소비만 해도 된다.
- Path 에디터는 **비트맵 업로드·선 따기 옵션을 두지 않는다** (축 리밋·스킵·이펙터와 섞이지 않게).

### 벡터 가져오기 → Path (Path 쪽)

1. SVG/폴리라인 선택 (그래픽에서 확정했거나 외부 SVG).
2. 장비 작업 영역 (원호·직사각 등) 에 **맞춤·스케일·회전**. 상한 밖은 클램프·`LIMIT`.
3. path 를 샘플해 키프레임 후보 생성 (간격·단순화).
4. 사용자가 점 추가·삭제·순서, 머무름·이펙터·스킵.
5. (다축) 필요 시 **티칭으로 개별 pose 덮어쓰기**.
6. JSON → G 방언.

1 축 원호에 임의 SVG 를 넣을 때는 호 위로 **투영**한다. 온풍 1 차 우선순위는 낮다.

### 티칭 흐름

1. Path 편집에서 **티칭 모드**를 연다 (또는 장비 Manual).
2. **관절을 부드럽게**(토크 완화·프리) 손으로 밀거나, **로터 등으로 수동 조작**해 자세를 맞춘다.
3. “키프레임 생성”(로터 확정 칸 / 브라우저 버튼) → 그 순간의 **축 피드백 `pose`** 를 샘플한다.
4. 필요하면 다음 자세로 옮겨 반복. 순서 = 찍은 순서.
5. 점마다 머무름·이펙터·스킵은 티칭 직후 또는 에디터에서 채운다.
6. JSON 저장 → G 방언 컴파일. 미리보기로 확인.

**pose 출처:** 엔코더·리밋 기준 누적 등이 있는 축에서 티칭 정확도가 높다. 온풍 1 차처럼 인코더가 약하면 티칭은 보조에 두고 **도형 편집을 주력**으로 한다.

### 티칭 결과의 해석 (최단 vs 전 경로)

| 해석 | 의미 | 결과 |
| :--- | :--- | :--- |
| **최단형 (경유 압축)** | 사용자가 **찍은 점만** 키프레임. 점과 점 사이는 `G0`/`G1` 최소 이동 | 점이 적고 빠름. 티칭 **찍기**의 기본 |
| **전 경로 추적** | 티칭 **녹화**로 궤적 전체를 샘플 | 밀어 준 곡선·우회 재현. 파일·점 수 큼 |
| **녹화 후 단순화** | 전 경로 샘플을 줄여 최단형에 가깝게 | 다축에서 녹화와 운용 속도의 절충 |

1 축·2 축 티칭 찍기의 기본 해석은 **최단형**이다. 전 경로 녹화는 엔코더 있는 다축 단계에서 연다.

## 사용자 흐름

### A. 도형 편집 (1 축·온풍 1 차)

1. 장비·축 프로파일을 고른다 (온풍 원호 + 반경).
2. 가능 구간이 보이는 **경로 도형**(SVG) 을 본다. 상한 초과 시 클램프·`LIMIT`.
3. 경로를 **클릭**해 키프레임을 만든다. 드래그로 미세 이동, 번호로 순서.
4. 점마다 **머무름**, (선택) **이펙터**, (선택) **스킵**을 넣는다.
5. JSON 저장 → G 방언 컴파일 → 미리보기.

### B. 티칭 (2 축 + 기본)

1. 프로파일 선택 후 티칭 모드.
2. Manual/프리조인트로 자세 맞춤 → 키프레임 찍기 반복 (최단형).
3. 에디터에서 머무름·이펙터·스킵 보완, 미리보기.
4. JSON → G 방언.

### C. 벡터 가져오기 (도면·2 축 보완)

1. (비트맵이면 먼저) **그래픽 모듈**에서 벡터 확정.
2. Path 에서 SVG/폴리라인 가져오기 → 영역 맞춤·샘플.
3. 키프레임 편집·이펙터·스킵. 필요 시 티칭으로 보정.
4. JSON → G 방언.

단방향 (`reversible: false`) 에서는 경로상 **한쪽 순서**만 허용. 되돌림 키프레임은 경고·차단.

## 키프레임 필드

### 공용

| 필드 | 필수 | 역할 |
| :--- | :--- | :--- |
| `pose` | 예 | 축별 목표. 단축 예: `{ "A": -20 }`. UI 가 `angleDeg` 만 받아도 저장 시 `pose` 로 정규화 |
| `dwellMs` | 예 | 머무름. 0 이면 통과만 (`scene` 스킵과 다름) |
| `effectors` | 아니오 | 이펙터 맵. 온풍 예: `{ "setTempC": 28, "fanLevel": 2 }` |
| `skipEnabled` | 아니오 | 스킵 사용 |
| `skipMode` | 아니오 | `scene`(기본) 또는 `travel` |
| `skipWhen` | 아니오 | 조건 (AND, 1 차) |

하위 호환: 온풍 JSON 초안에 `angleDeg`·`setTempC`·`fanLevel` 평탄 필드를 써도 되고, 컴파일 전에 `pose` / `effectors` 로 올린다.

### 스킵 시점 (scene / travel)

| 모드 | 평가 시점 | 동작 | 단축 원호 (온풍) | 다축·정역 |
| :--- | :--- | :--- | :--- | :--- |
| **`scene`** (기본) | **이동 후** | 머무름·이펙터만 생략. 그 자세까지는 감 (또는 통과) | **1 차 권장.** 호상 그 각은 어차피 지남 | 경유는 하되 작업만 생략 |
| **`travel`** | **이동 전** | 그 점으로의 이동 자체를 생략 | 단방향에선 이득 작음 | **의미가 큼.** 우회·불필요 경유 제거 |

온풍 1 차: **`scene` 만** 구현. `travel` 은 정역·다축에서 연다. `scene` 스킵이어도 **다음 점으로의 이동은 수행**한다 (단방향 순서 유지).

### 스킵 조건 (1 차, AND)

| 조건 | 예 | 용도 |
| :--- | :--- | :--- |
| 재실 | 없음 / 있음 | 빈 구간 장면 생략, 또는 사람 있을 때만 경유 (`travel`) |
| mmWave 근접 | 자세 근처 클러스터 | 사람 있는 칸만 이펙터 |
| 온도·센서 | 목표 이상이면 스킵 | 이미 충분하면 머무름 생략 |
| 플래그 | 내검, `HEAT_HOLD`, 홀트, ARM | 안전·작업 |
| 수동 끔 | 점만 비활성 | 현장 |

### 이펙터 적용 시점

## NEXA G 방언 (실행)

표준 CNC 에 드롭인하지 않는다. **NEXA 장비 공통 실행 테이프**다. 단축에서 검증한 문을 다축이 그대로 쓴다.

### 계층

```text
축 프로파일 + SVG/축 UI → JSON 템플릿 → 컴파일 → G방언 → 장비 인터프리터
```

### 최소 코드 (초안)

| 코드 | 역할 |
| :--- | :--- |
| `G0` / `G1` | 축 이동. `G0 A-20` / `G0 X400 A10` |
| `G4 P…` | 머무름 (ms) |
| `M104 S…` | 온도 목표 (온풍·챔버 등 열 이펙터) |
| `M106 S…` | 풍량 단 (온풍). 다른 장비는 별 M 또는 동일 S 의미 재정의는 프로파일에 |
| `M900 …` | 스킵. `scene`=이동 후 장면 스킵, `travel`=이동 전 |
| `M902 …` | Path 메타 (profileId, 반경 등) — 선택 |

### 단축 → 복합축

- 운동 = **축 문자만**. `pulseMs` 단독 스키마에 의존하지 않는다.
- 이펙터·스킵 = **M 코드** (축과 분리).
- 축 추가 = 테이프에 문자 추가 + 인터프리터 축 테이블 확장. Path JSON 버전을 깨지 않는다.

## 저장·식별·동기 (온풍 1 차 기준, 공용 원칙)

| 항목 | 결정 |
| :--- | :--- |
| **원본 저장소** | **포털 DB**가 기본. 템플릿은 DB 화한다. |
| **장비 NVS** | 용량이 **작으면** NVS 에 배치. **커도** 장비 메모리가 허용하면 NVS 에 두어 **인터넷 없이 반복 실행** 가능하게 한다. |
| **전송** | 큰 템플릿은 **분할 전송**. 작은 것은 일괄. |
| **식별** | DB **`id`**(안정 키) + 사람이 읽는 **번호 (슬롯·표시 번호)** — **둘 다 편집 가능**. 로터 노브는 표시 번호와 매핑. |
| **그 외 동작** | 1 회/루프, 중단·재개, Path 종료 후 이펙터·모드 복귀, 속도 등은 **옵션**(프로파일·템플릿·장비 설정). 초안에 필드로만 열어 둔다. |

## 실행·우선순위·안전

우선권은 **한 스위치 (수동 vs Path) 로 끝내지 않는다.**
사람이 미처 못 보는 순간은 **센서 가드**가 막고, 의도적 조작은 **수동**, 스케줄은 **Path/자동**이다. 장비마다 2↔3 기본만 바꾸면 된다.

### 우선 층 (높을수록 강함)

```text
0 하드 안전  >  1 센서 가드  >  2 의도적 수동  >  3 Path / 추적 자동
```

| 층 | 이름 | 주체 | 역할 | Path·수동과의 관계 |
| :--- | :--- | :--- | :--- | :--- |
| **0** | **하드 안전** | E-stop, 기구 리밋, 과열 차단 등 | 소프트웨어 논의 밖. 전원·구동 차단 | **항상 최우선** |
| **1** | **센서 가드** (소프트 안전) | mmWave 근접·재실, `HEAT_HOLD`, 과전류·충돌 추정, ARM 해제 등 | 사람이 상황 판단이 안 될 때 **위험 방향으로의 동작·가열을 막거나 감속** | Path **와** 수동 **모두** 막을 수 있음. **1 ≠ 2** — “SW 우선”이 필요한 곳은 대개 여기 |
| **2** | **의도적 수동** | 로터 Manual, 홀드, 조그, 티칭 프리조인트 | 현장 개입·미세 조정 | **3(Path) 과의 경쟁**만 옵션으로 조정 |
| **3** | **Path / 추적 자동** | Path, Focus, Scan, Centroid… | 저장된 테이프·추적 루프 | 가장 낮은 자동화 층 |

**섞지 말 것:** “소프트웨어가 사람보다 위”를 층 2 에 두면 현장이 답답해지고, “항상 사람 우선”만 두면 층 1 이 비어 사고가 난다.

### 층 1 — 센서 가드 (상세)

| 항목 | 초안 |
| :--- | :--- |
| **입력** | 재실/부재, mmWave 클러스터·근접, 온도 상한, `HEAT_HOLD`·홀트·ARM, (이후) 도어·하중·전류 |
| **동작 등급** | `ignore` → `slow`/`derate`(감속·출력 제한) → `hold`(정지·유지) → `inhibit`(해당 축·이펙터 금지) → `estop_request`(층 0 에 요청) |
| **애매한 센서** | 클러스터 깜빡·저신뢰 → 즉시 풀 차단보다 **`slow`/`hold`**. 확정·지속되면 `inhibit` 이상으로 |
| **해제** | 조건 해제 + (필요 시) 수동 확인. 가드가 풀어져도 **자동으로 Path 를 강제 재개하지 않음**(옵션). 재개는 수동 또는 “재개 명령” |
| **Path 스킵과의 구분** | `scene`/`travel` 스킵 = **테이프 논리**. 센서 가드 = **안전**. 스킵으로 가드를 대체하지 않음 |

온풍 층 1 최소셋·효율·거리는 아래. 히터 본문 「출구 근접·효율·최적 거리」, 코드 문서는 **안내만**.

### 온풍 근접·최적 거리·다축 (요약)

- **효율:** 사람 가까이 온풍 (방 공기 낭비↓). **안전 바닥 `D_opt` 안으로는 안 들어감.**
- **가드:** 최근접 Y·급접근 → 경고 (derate) / 컷 (**열 0 + 후풍 강 + 축 hold**, 래치·명령 재개). 모든 추적 모드·수동 위험 방향 포함. 스킵과 별층.
- **`D_brake`:** 제동거리 = (레이더 확정 + 제어 + 액추에이터 정지/후퇴)×접근속도. E-stop 과 다른 기호.
- **`D_opt`:** `D_brake` + 열 마진 + 충돌 마진. 추종 `D_track` ≈ `D_opt` 바로 밖.
- **단열:** 손실↓·표면 여유↑(기계). 출구 온풍·충돌을 대체하지 않음.
- **다축·상시 추종:** 충돌 비중↑ → 조준 레이더 + **공간용 센서**, 스탠드오프. 축 수=레이더 수가 아니라 **사각 메우기**.

### 층 2 vs 3 — 수동과 Path (옵션)

| 필드 (안) | 의미 | 온풍 1 차 기본 |
| :--- | :--- | :--- |
| `manualOverPath` | `true` 면 Path 중 수동 입력이 Path 를 **양보**(일시정지·중단). `false` 면 Path 유지, 수동은 홀드·비상만 | **`true`** |
| `pathResume` | 수동·가드 해제 후 `manual` / `command` / `auto` | **`command`**(복귀·재개 명령 있을 때만) |
| `trackingOverPath` | Focus 등 추적이 Path 를 가로챌지 | 옵션. 1 차는 Path 확정 중엔 Path 유지 권장 |

### 장비 프로파일별 기본 성향

| 장비 성격 | 층 1 (센서 가드) | 층 2 vs 3 기본 | 비고 |
| :--- | :--- | :--- | :--- |
| **온풍·열** | **매우 강함** — 컷 시 열 0·후풍 강·축 hold. `D_brake`/`D_opt`·단열·(다축) 공간 센서 | **수동 ≥ Path** | 밀착 효율 + 스탠드오프 |
| **리프팅·이송** | **매우 강함** — 사람 있으면 이동 `inhibit` | 수동 ≥ Path | 다칠 수 있는 축 |
| **레일캠 순찰 (GRC)** | 중간 — 사람 있으면 장면/경고 또는 일시정지 | Path 가 길게 돌아도 됨. 수동 개입 시 양보 권장 | 스킵 (`travel`) 과 가드를 역할 분리 |
| **챔버 공정** | 도어·과열 등만 강하게 | **Path(공정) 유지**가 나을 수 있음 (`manualOverPath: false` + 비상만 수동) | 공정 중단 비용 큼 |

프로파일에 `priority: { manualOverPath, sensorGuard: { level, actions[] }, pathResume }` 자리를 둔다. **전 장비 단일 디폴트는 두지 않는다.**

### 판단 규칙 (실무)

1. **다치거나 탈 수 있으면 → 층 1 이 Path·수동보다 위** (수동도 위험 방향은 막거나 감속).
2. **의도적 미세 조작 → 층 2 가 Path(3) 보다 위** — 온풍·티칭 기본.
3. **센서 애매 → derate/hold 먼저**, 확정 후 inhibit.
4. **가드 ≠ 스킵.** 빈 구간 장면 생략은 `scene`; 사람 보호는 센서 가드.
5. **기본은 프로파일, 현장은 옵션**으로만 완화 (강화는 슈퍼관리자·안전 정책).

### 그 외 안전·UX (기본 + 옵션)

| 항목 | 기본 | 옵션 |
| :--- | :--- | :--- |
| **`scene` 스킵 시 온도** | **안전 기본값** — 절전·추적에 맞게. 이전 점 온도 무작정 유지 금지 | 유지 / 기본값 / off |
| **단방향 (`reversible: false`)** | **저장 시 검증** — 순서·방향 어긋나면 저장 거부·경고 | — |
| **리밋·클램프** | 편집 시 경고 + 저장 시 거부 가능. 실행 중 `LIMIT` 면 hold | 클램프만 하고 계속 |
| **E-stop·홀트 후** | 층 0/1 해제 후에도 **자동 Path 재개 없음**. 재개 명령 또는 수동 | `pathResume: auto` |
| **Path 완료 UX** | **알림** + **복귀 명령이 있을 때만** 이전 모드 복귀 | 알림만 |
| **템플릿 권한** | **현장 수정 가능** | 슈퍼관리자 **읽기 전용 배포** |

스키마 초안에는 `priority`·`sensorGuard`·`pathResume`·스킵 시 이펙터 정책 필드만 열어 두고, 수치·토큰은 방언·장비 맵에서 채운다.

## 스키마

지금 단계의 목적은 **초안을 고정해 가는 것**이다. `schemaVersion`, 프로파일 스냅샷 여부, 키프레임 `id`, `G0`/`G1` 의 F 등은 **아직 닫지 않은 것**에 두고, JSON·G 방언 예시는 위 정규 형태를 기준으로 키운다.

## 티칭·벡터 — 롤아웃 3–4 전 우선 결정 (초안)

구현 전에 아래를 **이 순서로** 확정한다. (세부 수치·알고리즘은 이후.)

| 우선 | 항목 | 초안 결정 |
| :--- | :--- | :--- |
| **1** | **좌표계·원점** | 장비 **홈/리밋 기준 pose**. 작업 원점이 있으면 프로파일에 `origin` 오프셋. Path JSON 의 `pose` 는 항상 장비 축 단위. |
| **2** | **티칭 중 이펙터** | 티칭 모드 진입 시 **열·풍 등 위험 이펙터는 안전 기본 (off/최저)** 강제. 찍기만 하고 장면은 에디터에서. |
| **3** | **SVG 단위·원점** | 가져오기 시 **mm**, 장비 작업 영역 원점에 맞춤. 화면 Y-down 이면 가져올 때 **축 공간으로 한 번 변환**. Path 는 변환 결과만 저장. |
| **4** | **샘플 간격 기본** | **거리 (mm) 우선**, 원호 1 축은 **각도 (°)** 로 환산 가능. 기본 후보는 선형 ~10–20 mm / 원호 ~5–10° — 프로파일에서 조정. |

녹화 주기·단순화 알고리즘 수치는 롤아웃 4 에서 채운다.

## 에디터 요구 (요약)

### Path 에디터

- **위치: 포털 웹**(원본·DB와 동일 거점). Desk 네이티브/확장 Path UI 없음
- 축 프로파일 선택 (1 차: 온풍 원호 + 반경 상한)
- **작성 모드:** 도형 편집 | 티칭 찍기 | 벡터 가져오기 | (이후) 티칭 녹화
- 도형: 키프레임 클릭/드래그/번호 (1 축 주력)
- 티칭: Manual/프리조인트, “키프레임 생성”, 최단형 기본
- **벡터 가져오기:** SVG·확정 폴리라인만. 비트맵 업로드 없음
- 점 패널: 머무름·이펙터·스킵 (`scene`/`travel`)
- 스킵 배지, 미리보기, JSON·G 방언 내보내기
- 2 축 +: 티칭 우선, 2D·벡터는 보조

| **3** | `pose`/`effectors` 정규화. **2 축 + 티칭 찍기 (최단형)**. `travel`·다축 `G0` |
| **4** | **벡터 가져오기** + (별도) **그래픽 벡터화** 모듈. 티칭 녹화·단순화. GRC·리프팅·챔버 |

온풍 추적 펌웨어 (`setPathPreset`) 와의 연결 상세는 `코드-온풍 조준 — mmWave 추적 코드` 를 수정한다. 이 문서는 **공용 스키마·방언·작성 방법·에디터**가 주인이다. 그래픽 벡터화의 상세 스펙은 별도 기획으로 빼도 된다.
