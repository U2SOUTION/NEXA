# 개념기반\_ 동적라우팅\_ 및\_ 보안전략
큰 그림을 그리시는 단계에서 나중에 실제 코딩이나 아키텍처 설계를 하실 때 키워드 검색이 가능하도록, 오늘 나눈 핵심 개념들을 기술 표준 용어 중심으로 일목요연하게 정리해 드리겠습니다.

나중에 구글링하시거나 기술 문서를 보실 때 이 용어들을 사용하시면 원하는 정보를 정확하게 찾으실 수 있습니다.

---

## 🏛️ 1. 아키텍처 및 라우팅 관련 용어

- 도메인 주도 설계 (Domain-Driven Design, DDD): 기술적인 파일 경로가 아닌, `motor` 나 `nexa` 같은 비즈니스 개념 (용어) 을 중심으로 시스템 구조를 설계하는 방법론입니다.
- 동적 라우팅 (Dynamic Routing): 소스 코드에 주소를 고정하지 않고, 데이터베이스나 캐시의 데이터에 따라 실시간으로 주소 (길) 를 바꾸는 기법입니다.
- API 게이트웨이 (API Gateway): 외부의 모든 요청을 단 하나의 출입구 (개념 주소) 로만 받고, 내부의 실제 주소로 안전하게 연결해 주는 중계 서버입니다.
- URL 리라이팅 (URL Rewriting): 사용자가 보는 주소창의 주소는 그대로 둔 채, 서버 내부적으로 실제 주소로 몰래 바꾸어 처리하는 기술입니다.

---

## 🔒 2. 보안 관련 용어

- 무빙 타겟 디펜스 (Moving Target Defense, MTD): 공격자가 취약점을 분석할 시간을 주지 않도록, 실제 시스템 주소나 환경을 정기적으로 수시로 바꾸어 방어하는 고도화된 보안 전략입니다.
- 보안 난독화 (Security Obfuscation): 내부 실제 파일 경로, 디바이스 ID, 물리 주소를 외부인이 예측할 수 없도록 복잡한 해시값이나 무작위 경로로 숨기는 기법입니다.
- 캡슐화 (Encapsulation) / 정보 은닉 (Information Hiding): 내부의 구체적인 구현이나 물리적 구조를 외부에 노출하지 않고, 추상적인 인터페이스 (용어) 만 제공하는 설계 원칙입니다.

---

## ⚡ 3. 성능 및 비용 절감 (캐싱) 관련 용어

- 하이브리드 캐싱 (Hybrid Caching): 메모리 비용을 아끼기 위해 자주 쓰는 데이터는 메모리 (Redis) 에, 가끔 쓰는 데이터는 디스크 (RDB) 에 나누어 저장하는 전략입니다.
- Cache-Aside (Lazy Loading): 요청이 들어왔을 때 캐시를 먼저 보고, 데이터가 없으면 그때서야 DB 에서 쿼리해 온 뒤 캐시에 동적으로 올리는 캐싱 패턴입니다.
- LRU (Least Recently Used) 알고리즘: Redis 의 메모리가 부족해지면, 가장 오랫동안 사용되지 않은 옛날 데이터를 자동으로 지워 메모리를 최적화하는 내장 정책입니다.
- TTL (Time To Live): 캐시에 저장된 데이터가 무한정 메모리를 차지하지 않도록, 일정 시간 (예: 1 시간) 이 지나면 자동으로 소멸하게 만드는 만료 시간 설정입니다. [1, 2]

## 🚫 남발하면 안 되는 이유 (트레이드오프)

- 디버깅 지옥: 로그에 찍힌 주소가 실시간으로 바뀌기 때문에, 에러가 발생했을 때 사용자가 정확히 어떤 기능을 쓰다가 터진 것인지 추적하기가 까다로워집니다.
- 관리 포인트 증가: 주소가 바뀔 때마다 용어집 (DB/Redis) 의 정합성을 계속 맞춰줘야 하므로 관리 비용이 듭니다.

## ⚖️ 필터링을 위한 3 단계 자가 진단 기준 (체크리스트)

개념을 적용할지 말지 고민될 때 다음 3 가지 질문을 던져보세요. 2 개 이상 해당할 때만 이 기법을 적용하시는 것을 추천합니다.

1. " 이 주소 (기능) 가 해커에게 노출되었을 때 치명적인 타격이 있는가?" (보안성)
    
    - `O` ➡️ 결제, 핵심 제어, 회원 정보 처리 등 (적용 대상)
    - `X` ➡️ 일반 공지사항 조회, 단순 회사 소개 페이지 (일반 라우팅 적용)
    
2. " 비즈니스 환경이나 인프라 구조 변경에 따라 주소가 바뀔 가능성이 높은가?" (유연성)
    
    - `O` ➡️ 자주 교체되는 외부 연동 API, IoT 장비 주소 (적용 대상)
    - `X` ➡️ 로그인창, 마이페이지 등 거의 변하지 않는 표준 고정 메뉴 (일반 라우팅 적용)
    
3. " 모든 개발자와 기획자가 공통으로 부르는 핵심 비즈니스 키워드인가?" (인지성)
    
    - `O` ➡️ 우리 핵심 서비스명, 특정 장비 카테고리 (`motor`, `nexa`) (적용 대상)
    - `X` ➡️ 하위 세부 기능 단어 (`upload-image`, `check-status`) (일반 라우팅 적용)
