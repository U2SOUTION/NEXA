# 멀티윈도우 · Document PiP 통합 규격 및 선택 가이드

**한 줄:** NEXIA 탭·워크플로를 **멀티윈도우(병렬 생산성)** 와 **Document PiP(상시 보조)** 중에서 선택·혼합한다. 본 문서는 **선택 매트릭스**, **멀티윈도우 아키텍처**, **PiP 운영 규격**을 한곳에 정의한다.

> **병합 출처:** `08 멀티윈도우 아키텍처 규격` · `10 멀티윈도우 vs Document PiP 선택 가이드` · `09 Document PiP 운영 규격` (확인 후 원본 삭제 가능)

---

## 1. 목적과 범위

- NEXIA 탭 프로파일(기본 7개 포함)을 **멀티 모니터·멀티 창** 환경에서 안정 운영하기 위한 **아키텍처·운영 기준**을 정의한다.
- 기능 설계 시 **멀티윈도우 vs Document PiP** 선택 **매트릭스·체크리스트**를 제공한다.
- Document PiP의 **상태·동기화·UI·생명주기·장애** 운영 규격을 포함한다.
- STT/TTS 엔진 동작·음성 루프 상세는 [`07 음성 인풋…`](<../../../../NEXA-Platform/docs/Nexia/07 음성 인풋 자동화 및 확장 로직 (Voice Input Automation & Expansion).md>) · UI 포용성은 `04`가 우선한다.

---

## 2. 한 줄 정의

| 방식             | 정의                              | UX 성격                        |
| ---------------- | --------------------------------- | ------------------------------ |
| **멀티윈도우**   | 작업 공간 **분할·병렬 처리**      | 전문가형 (Deep Work)           |
| **Document PiP** | **항상 위** 보조 제어·상태 가시성 | 앰비언트형 (Ambient Assistant) |

PiP는 메인 창을 **대체하지 않고** `보조 제어 / 상태 가시성`만 제공한다.

---

## 3. 비교 매트릭스

| 기준             | 멀티윈도우                 | Document PiP        |
| ---------------- | -------------------------- | ------------------- |
| 주 목적          | 작업 공간 분할 / 병렬 처리 | 항상 위 보조 제어   |
| 복잡 편집        | **강함**                   | 약함 (메인 창 위임) |
| 지속성           | 작업 **세션** 중심         | **메인 탭 종속**    |
| 제어권 충돌 위험 | 중간~높음                  | 중간                |
| 구현 난이도      | 높음                       | 중간                |
| 멀티 모니터      | **핵심 이점**              | 단일 보조 창        |
| 레이아웃 복원    | **필수 KPI**               | 해당 없음           |

## 4. 선택 규칙

### 4.1 멀티윈도우를 선택할 때

- 탭 **2개 이상** 동시 편집이 필요할 때
- 대형 캔버스·코드·그래프를 **병렬**로 봐야 할 때
- 레이아웃 복원·**멀티 모니터** 활용이 핵심일 때
- 예: Synapse와 Glos 분리 병렬 · Cockpit 모니터링 + Physis 결과 동시 확인 · 장시간 집중 작업 레이아웃 복원

### 4.2 Document PiP를 선택할 때

- 핵심 **상태 표시**와 **짧은 명령**만 필요할 때
- 타 애플리케이션 작업 중 **보조 비서**가 필요할 때
- 음성 **대기·빠른 인터럽트**가 핵심일 때
- 예: 다른 앱 작업 중 STT 대기 · 마이크/AI 처리 상태 모니터링 · 장시간 보조 UI

### 4.3 혼합 전략 (권장)

| 정책       | 내용                                                |
| ---------- | --------------------------------------------------- |
| **기본**   | **작업 = 멀티윈도우**, **상시 제어 = PiP**          |
| **제어권** | 한 시점 **한 STT 엔진** (§8)                        |
| **승인**   | 고위험 작업(배포·IoT)은 항상 **Cockpit** 경유       |
| **모드**   | Deep Work → MW · Ambient → PiP · Hybrid → **둘 다** |

### 4.4 모드별 권장안

| 모드              | 권장               | 설명                         |
| ----------------- | ------------------ | ---------------------------- |
| Deep Work         | 멀티윈도우         | Synapse / Glos / Physis 병렬 |
| Ambient Assistant | PiP                | 상시 대기 · 빠른 전송 · 중단 |
| Hybrid Control    | **둘 다**          | 메인 작업 + 보조 음성        |
| Mobile Light      | PiP 유사 경량 패널 | 모니터링·승인 중심           |

## 6. 멀티윈도우 아키텍처

### 6.1 설계 원칙

- **단일 로직 인스턴스:** 핵심 실행 컨텍스트는 중앙 오케스트레이터로 단일화
- **창 독립성:** UI는 분리하되 **상태 소스는 분산되지 않음**
- **충돌 방지:** 한 시점 **한 제어권** (음성/STT/고위험 실행)
- **복구 우선:** 비정상 종료 후 레이아웃·세션 자동 복원

### 6.2 탭 가변 구조

- 멀티윈도우는 **고정 탭 수를 전제하지 않음**
- 창 생성은 **탭 레지스트리** 기반 동적 수행
- 신규 탭: `route`, `riskLevel`, `defaultWindowPolicy` **필수 등록**

**탭 증감 판단 (책임 경계)**

| 늘릴 때                                        | 줄일 때                          |
| ---------------------------------------------- | -------------------------------- |
| 독립 워크플로·책임이 기존 탭과 **명확히 분리** | 기능 중복으로 **인지 부하** 증가 |
| 별도 KPI·**owner** 정의                        | 사용 빈도·성과 **임계치 이하**   |
| 보안·장애 정책이 **독립** 성립                 | 기존 탭에 **흡수 가능**          |

원칙: **「탭 수 고정」이 아니라 「책임 경계 명확화」** 우선.

### 6.3 구성 요소

| 구성                | 기술                              | 책임                      |
| ------------------- | --------------------------------- | ------------------------- |
| Window Manager      | `window.open`, Screen Details API | 창 생성·배치·복원         |
| Sync Bus            | `BroadcastChannel`                | 창 간 이벤트 전파         |
| Shared Runtime      | `SharedWorker`                    | 공통 실행 컨텍스트        |
| Collaboration State | `Yjs`                             | 문서·그래프 실시간 동기화 |
| UI State            | `Pinia`                           | 탭·드로어·선택 상태       |

**PiP와의 관계:** MW 채널 `nexia.window.sync.v1` · PiP 채널 `nexia.pip.sync.v1` (§7.4) — **채널 분리**, 제어권은 §8에서 통합.

### 6.4 상태 동기화 (멀티윈도우)

- 채널: **`nexia.window.sync.v1`**
- 필수 필드: `requestId`, `sourceWindowId`, `target`, `timestamp`
- **우선순위:** (1) 보안/긴급 정지 → (2) 실행 제어 → (3) UI/레이아웃

### 6.5 레이아웃 복원

| 항목 | 정책                                     |
| ---- | ---------------------------------------- |
| 저장 | 창 위치·크기·탭 매핑·포커스 순서         |
| 주기 | 사용자 변경 후 **debounce 500ms**        |
| 복원 | 로그인 완료 후 **1회** 자동              |
| 실패 | 안전 레이아웃 — **단일 창 Cockpit** 폴백 |

### 6.6 장애 대응 (멀티윈도우)

- **창 비정상 종료:** 세션 잠금 없이 해당 창 작업만 격리
- **Sync 버스 지연:** 로컬 임시 큐 → 재전송
- **SharedWorker 재시작:** 런타임 재결합 → 미완료 작업 재동기화

## 7. Document PiP 운영 규격

### 7.1 핵심 특성

- **메인 문서 종속:** 메인 탭 종료 시 PiP도 종료
- **항상 위:** 짧은 명령·상태 확인에 최적
- **경량 상호작용:** 복잡 편집은 **메인 창**에서만

### 7.2 상태 및 제어권 모델

| 상태           | 메인 창 | PiP 창  | 설명                   |
| -------------- | ------- | ------- | ---------------------- |
| MainMaster     | Active  | Passive | 메인이 제어권 보유     |
| PiPMaster      | Passive | Active  | PiP가 음성 제어권 보유 |
| ProcessingLock | Locked  | Locked  | LLM 처리 중 입력 잠금  |
| PrivacyMute    | Muted   | Muted   | 전역 음성 차단         |

- 공통 레이어 키: `activeLayer` (`GlobalFlow` | `Crew` | `Solo`)
- 전환 이벤트: `PIP_OPEN`, `PIP_CLOSE`, `MASTER_SWITCH`, `LAYER_SWITCHED`, `PRIVACY_MUTE`, `RESUME`

### 7.3 PiP 운영 규칙

- PiP가 Master일 때 메인 음성 루프는 **Pause**
- PiP **닫힘** 시 제어권 **즉시 메인** 반환
- 응답 생성 중 **ProcessingLock** 강제
- STT/TTS 동작: **07** 문서 규격
- `activeLayer=GlobalFlow` → **읽기 전용** 원칙

### 7.4 동기화 채널

- 채널: `BroadcastChannel('nexia.pip.sync.v1')`
- 필수 메시지: `type`, `source`, `target`, `requestId`, `timestamp`, `payload`
- 중복 방지: `requestId` 기반 **idempotency**

**공통 이벤트 (07 / 11 정합)**

| 이벤트                        | 목적                          |
| ----------------------------- | ----------------------------- |
| `LAYER_SWITCHED`              | GlobalFlow / Crew / Solo 전환 |
| `MASTER_SWITCH`               | 음성 제어권(PiP/메인) 이양    |
| `SOLO_LIST_UPDATED`           | Solo 채팅 리스트 변경         |
| `CROSS_DOMAIN_CHAT_ACTIVATED` | 타 도메인 채팅 시작           |
| `PRIVACY_MUTE`                | 전역 음성 차단                |
| `RESUME`                      | 음성 루프 재개                |

### 7.5 UI · 프라이버시

- 필수 표시: `Listening`, `Muted`, `Processing`
- 권장 색상: Listening(적색), Muted(회색), Processing(청색)
- 파형은 **수집 상태만** — 원시 오디오 **저장하지 않음**
- 메인·PiP **마이크 상태 동일** 표시
- UI 상세: `04` · 음성 엔진: `07`

### 7.6 생명주기 · 폴백

| 이벤트              | 동작                         |
| ------------------- | ---------------------------- |
| PiP 닫힘            | 제어권 즉시 메인 반환        |
| 메인 탭 닫힘        | PiP 종료 (선택: 사용자 경고) |
| PiP 미지원 브라우저 | 플로팅 모달 / 미니 패널 폴백 |

### 7.7 장애 대응 (PiP)

- **채널 단절:** PrivacyMute → 재연결 시도
- **마이크 권한 박탈:** 즉시 Muted + 재권한 요청
- **제어권 충돌:** 마지막 **유효 승인 이벤트** 기준 단일화

## 8. 제어권(Handover) — 멀티윈도우 · PiP 공통

| 규칙               | 내용                                               |
| ------------------ | -------------------------------------------------- |
| STT/마이크         | **단일 창**만 Master (§7.2)                        |
| 충돌 시 우선       | **Cockpit**                                        |
| 고위험 실행        | MW/PiP에서 직접 실행 ❌ → Cockpit 승인             |
| MW + PiP 동시      | Hybrid 시 **한 STT 엔진** — `MASTER_SWITCH`로 이양 |
| PiP ProcessingLock | MW 창 음성 입력도 **잠금**                         |

## 9. KPI

### 9.1 멀티윈도우

| 항목                     | 기준               |
| ------------------------ | ------------------ |
| 창 간 상태 전파 지연     | 평균 **50ms** 이하 |
| 레이아웃 복원 성공률     | **99%** 이상       |
| 제어권 충돌 자동 해결률  | **95%** 이상       |
| 창 비정상 종료 복구 시간 | **3초** 이하 목표  |

### 9.2 Document PiP

| 항목                     | 기준                |
| ------------------------ | ------------------- |
| 제어권 전환 지연         | 평균 **100ms** 이하 |
| 상태 불일치율 (메인/PiP) | **0.5%** 이하       |
| 음성 루프 재개 성공률    | **99%** 이상        |
| 오인식 명령률            | **2%** 이하 목표    |
