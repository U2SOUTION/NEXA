# NEXNAP · 시스템 인터페이스 표준 규약

HEXAGON Protocol(5W1H 토큰)과 의미 매트릭스를 탭 간 릴레이·AI 협업의 **기술적 인터페이스 규약**으로 고정한다. (`_프로토콜.md` 후속 SSOT)

## 1. 개요 및 목적

- 목적: 탭(Domain) 간 데이터 릴레이 시 발생하는 기술적 혼선을 방지하고, AI가 인간의 의도(WILL)와 정책(Ethos)에 따라 일관되게 행동하도록 강제함.
- 핵심 원칙: 모든 데이터 전송은 HEXAGON 헤더를 포함하며, 모든 행위 결정은 의미 매트릭스를 통과해야 함.

## 2. HEXAGON Protocol: 통신 헤더 규약 (Message Header)

모든 탭 간의 메시지(gRPC/WebSocket) 최상단에 위치하는 공통 구조체입니다.

| 레이어 | 기술적 데이터 타입 (Enum) | AI 처리 로직 |
| ------ | ------------------------- | ------------ | ------ | ------------------------------------------------------ | --------------------------------------------------------- |
| Where  | SELF                      | FIELD        | DOMAIN | 권한(Scope) 검사 및 접근 제어 결정                     |
| When   | MOMENT                    | DURATION     | ERA    | 데이터의 보존 기간 및 긴급도 결정                      |
| Who    | WILL                      | ECHO         | TICK   | ASK                                                    | [중요] 실행 동력원 식별. ASK일 경우 반드시 콕핏 승인 필요 |
| What   | FACT                      | LINK         | RULE   | 데이터 처리 방식 결정 (단순 저장 vs 연결 vs 로직 실행) |
| How    | FLOW                      | STUCK        | VOID   | 프로세스 큐(Queue) 관리 및 상태 시각화 방식 결정       |
| Why    | CAUSE                     | LOGIC        | TARGET | AI가 답변 시 반드시 포함해야 할 근거와 목표 명시       |

## 3. 의미 매트릭스: 에토스 판정 엔진 (Decision Engine)

에토스(Ethos) 탭에서 가드레일로 작동하며, 특정 데이터가 유입되었을 때 실행 여부를 결정하는 4x4 상태 머신입니다.

## [판정 프로세스]

1.  Input: HEXAGON 헤더를 포함한 메시지 유입.
2.  Mapping: 헤더의 토큰값을 의미 매트릭스의 축(Axis)과 레이어(Layer)에 매칭.
3.  Check:

- A3(판정) x L1(의도): 이 작업이 시스템 규범상 승인(Go)인가 거부(Stop)인가?
  - A2(위력) x L4(가설): 실패 시 파급 강도가 어느 정도이며 위험 요소가 있는가?

4.  Output: Authorized(실행) / Blocked(차단) / Pending(콕핏 승인 대기).

## 4. 인공지능 협업을 위한 3대 인터페이스 전략## 전략 1: "No Token, No Action" (토큰 강제)

- 모든 API 호출 시 HEXAGON 토큰이 비어있으면 시스템은 즉시 VOID 상태를 반환하고 거부합니다.
- 클로드 코드가 새로운 기능을 개발할 때, 반드시 이 토큰들을 먼저 정의하도록 시스템 프롬프트에 고정합니다.

## 전략 2: "State-Based UI" (상태 기반 시각화)

- How(State) 레이어의 값이 STUCK으로 변하면, 콕핏(Cockpit)의 상태 가시성 인터페이스에 즉시 경고 알림을 띄우고 비상 정지 진입점을 활성화합니다.

## 전략 3: "Cross-Tab Relay" (탭 간 연계 표준)

- Navis → Sense → Synapse로 이어지는 데이터 흐름에서, 데이터 알맹이(Payload)는 변하더라도 HEXAGON 헤더는 유지(Pass-through)되거나 누적되어 인과관계(Why)를 보존합니다.

## 5. 클로드 코드 및 시덴스 2.0에 내릴 지시 사항 (Prompt)

"NEXNAP 프로젝트의 모든 코딩은 위 HEXAGON Protocol과 의미 매트릭스를 최상위 인터페이스 규약으로 따른다. 모든 함수와 클래스 설계 시, 이 토큰들을 메타데이터로 수용할 수 있는 구조를 먼저 짜고, 에토스 가드레일이 이 매트릭스를 기반으로 모든 실행 권한을 제어하도록 인터셉터를 구현하라."
