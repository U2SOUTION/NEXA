# 마크다운 파싱 주의사항 체크리스트

## 📋 개요

`MERMAID_STYLE_CUSTOMIZATION_PLAN.md` 문서에서 발생했던 파싱 오류 해결 과정을 기록하고, 향후 유사한 문제를 방지하기 위한 체크리스트입니다.

## 🔍 발생한 문제

### 증상

- 코드 블록이 일반 텍스트로 표시됨
- 체크박스(`- [ ]`)가 파싱되지 않고 원본 그대로 표시됨
- 다른 문서는 정상적으로 렌더링됨

### 해결

- 중첩된 코드 블록 제거
- 헤딩 구조 정리
- 불필요한 강조 문법 제거

## ✅ 마크다운 작성 체크리스트

### 1. 코드 블록 처리

#### ✅ 올바른 형식

**설명**:

```css
/* 코드 내용 */
```

다음 내용...

**주의사항**:

- 코드 블록 전후에 빈 줄 필수
- 코드 블록 내부에는 유효한 코드만 포함
- 코드 블록 내부의 들여쓰기는 실제 코드로 인식됨

#### ❌ 피해야 할 형식

````markdown
##### 제목

- 항목
  ```css
  코드
  ```
````

````

**문제점**: 리스트 항목 내부에 코드 블록 중첩 시 파서가 혼란을 겪을 수 있음

```markdown
**UI**:
````

┌────┐
│ │
└────┘

```

```

**문제점**: 들여쓰기가 있는 코드 블록은 인덴트가 코드로 인식됨

### 2. 체크박스 처리

#### ✅ 올바른 형식

```markdown
##### Phase 3-1: 제목

- [ ] 체크박스 항목 1
- [ ] 체크박스 항목 2
- [x] 완료된 항목
```

**주의사항**:

- 체크박스는 리스트 항목으로 시작해야 함 (`- [ ]` 형식)
- 코드 블록 내부의 체크박스는 파싱되지 않음 (의도된 동작)
- 코드 블록 전후의 빈 줄로 충분한 분리 필요

#### ❌ 피해야 할 형식

````markdown
##### 제목

```css
코드
```
````

- [ ] 항목 <!-- 코드 블록 직후 체크박스 -->

````

**문제점**: 코드 블록과 체크박스 사이에 충분한 간격이 없으면 파서가 혼란을 겪을 수 있음

### 3. 헤딩 구조

#### ✅ 올바른 형식

```markdown
### 대제목 (H3)

#### 중제목 (H4)

##### 소제목 (H5)

#### 또 다른 중제목 (H4)
````

**주의사항**:

- 헤딩 레벨은 순차적으로 증가/감소할 필요 없음
- 하지만 계층 구조를 명확히 유지하는 것이 가독성에 좋음
- 헤딩 사이에 빈 줄 필수

#### ⚠️ 주의해야 할 형식

```markdown
### 제목

#### 하위 제목

##### 더 하위 제목

#### 또 다른 하위 제목 <!-- H4로 다시 올라감 - 가능하지만 혼란스러울 수 있음 -->
```

**권장**: 가능하면 계층 구조를 명확하게 유지

### 4. 강조 및 스타일링

#### ✅ 올바른 형식

```markdown
- **볼드 텍스트**: 설명
- _이탤릭 텍스트_: 설명
- `인라인 코드`: 설명
```

#### ❌ 피해야 할 형식

````markdown
- **UI**: <!-- 불필요한 강조 -->
  ```css
  코드
  ```
````

````

**문제점**: 과도한 강조는 가독성을 해치고 파싱에 혼란을 줄 수 있음

### 5. 리스트 항목

#### ✅ 올바른 형식

```markdown
#### 기능 목록

##### 1. 기능 1

- 항목 1
- 항목 2

##### 2. 기능 2

- 항목 1
````

**주의사항**:

- 리스트 항목 사이에 빈 줄 권장 (가독성)
- 코드 블록 내부의 리스트는 코드로 처리됨

## 🔧 파서 동작 원리

### 처리 순서

1. **코드 블록 처리** (최우선)

   - 패턴: ` ```(\w+)?\s*\n([\s\S]*?)\n``` `
   - 언어 지정자(`\w+`)는 선택적 (`?`)
   - 줄바꿈(`\n`)으로 구분하여 인라인 코드와 차별화
   - 비탐욕적 매칭(`*?`)으로 가장 가까운 닫는 ``` 찾기
   - 코드 블록을 플레이스홀더(`__CODE_BLOCK_N__`, `__MERMAID_BLOCK_N__`)로 치환
   - 이후 파싱 단계에서 제외 (다른 마크다운 파싱이 코드 블록 내부를 건드리지 않음)

2. **체크박스 처리**

   - 패턴: `^(\s*)- \[([ x])\] (.+)$`
   - 코드 블록 플레이스홀더가 포함된 라인은 건너뜀
   - 체크박스를 플레이스홀더(`__CHECKBOX_N__`)로 치환

3. **제목 처리**

   - 패턴: `^(#{1,6})\s+(.+)$`
   - 코드 블록 내부 제외
   - ID 자동 생성

4. **기타 처리**
   - 테이블, 강조, 단락 등

### 플레이스홀더 시스템

파서는 특수 요소를 플레이스홀더로 치환하여 다른 파싱 과정에서 보호합니다:

- `__CODE_BLOCK_N__`: 일반 코드 블록
- `__MERMAID_BLOCK_N__`: Mermaid 다이어그램
- `__CHECKBOX_N__`: 체크박스
- `__TABLE_MARKER_N__`: 테이블

- [ ] 항목

````
코드
````

````
코드
````

```
## 📝 작성 시 권장 사항

1. ✅ 모든 코드 블록 전후에 빈 줄 추가
2. ✅ 코드 블록 내부 들여쓰기는 실제 코드의 일부로만 사용
3. ✅ 체크박스와 다른 요소 사이에 충분한 간격 유지
4. ✅ 헤딩 구조를 명확하게 유지
5. ✅ 불필요한 강조 제거
6. ✅ UI 예시는 텍스트 아트로 표현하거나 이미지 사용 고려

## 🧪 테스트 방법

문서 작성 후 다음을 확인:

1. ✅ 코드 블록이 올바르게 렌더링되는가?
2. ✅ 체크박스가 클릭 가능한 상태로 표시되는가?
3. ✅ 헤딩이 올바른 스타일로 표시되는가?
4. ✅ 리스트 항목이 올바르게 들여쓰기되는가?
5. ✅ 테이블이 올바르게 렌더링되는가?
```
