# AI 도메인 — 3영역 스플릿 레이아웃 기획

현재 **탭 기반**인 AI 도메인 중앙(content) 영역만 **Quasar Splitter로 3개 영역**으로 나누고, 각 영역의 **내용 조정**과 **표시/숨김**을 지원하기 위한 기획 문서다.

---

## 0. 적용 범위 (의도)

- **기존 드로어(좌/우)는 그대로 둔다.**  
  프레임의 **left**(채널·메모·미디어), **right**(에이전트·설정) 레이아웃과 동작은 변경하지 않는다.
- **라우팅은 수정하지 않는다.**  
  경로·라우트 설정은 그대로 두고, **같은 경로·같은 슬롯**에 어떤 컴포넌트를 넣을지만 바꾼다.
- **컨텐츠 영역만** 변경한다.  
  프레임이 할당하는 **content** 슬롯 안에서, 지금의 “단일 탭 그룹”을 **Quasar 스플릿으로 3개 영역(좌·중앙·우)** 으로 구성한다.

즉, **드로어·라우팅은 유지하고, content 한 블록만 스플릿 레이아웃으로 교체**하는 것이 목표다.

---

## 1. 배경

### 1.1 현재 구조의 특징과 한계

| 항목 | 현재 | 한계 |
|------|------|------|
| **레이아웃** | 프레임: left(채널/메모/미디어) · **content(탭)** · right(에이전트/설정) | content가 **단일 탭 그룹**이라 한 번에 하나의 화면만 노출 |
| **content 내부** | 채팅 / 에디터 / 코드 / 이미지 / 음원 / 영상 / 탐색기 **탭 전환** | 넓은 영역을 쓰는 장점은 있으나, **채팅과 에디터·탐색기를 동시에 보기 어려움** |
| **사용 시나리오** | 채팅 ↔ 에디터 ↔ 탐색기 전환 반복 | 대화 보면서 편집·파일 선택을 하려면 탭을 자주 바꿔야 함 |

### 1.2 목표

- **3영역 스플릿**: 좌(채팅) · 중앙(에디터 등) · 우(탐색기)를 **동시에** 배치.
- **영역별 표시/숨김**: 각 영역을 보이거나 가려서, 필요에 따라 1~3개 영역만 사용.
- **영역 내용 조정**: 각 슬롯에 어떤 패널(채팅, 에디터, 코드, 탐색기 등)을 넣을지 **사용자가 선택**할 수 있도록 (기본 배치는 좌=채팅, 중앙=에디터류, 우=탐색기).

## 2. 목표 레이아웃

### 2.1 전체 구조 (드로어 유지 + content만 스플릿)

```
┌──────────────┬─────────────────────────────────────────────┬──────────────┐
│  [드로어 좌]   │              [ content 영역 ]                │  [드로어 우]   │
│  그대로 유지   │  ┌─────────────────────────────────────┐   │  그대로 유지   │
│  채널/메모/   │  │ 타이틀(도메인 정체성) │ 파일 편집 보기 실행 │   │  에이전트/     │
│  미디어       │  ├──────┬──────────────┬──────┤         │  설정         │
│              │  │ 영역1 │    영역2     │ 영역3│  스플릿 │              │
│              │  │ 탭…   │ 탭…          │ 탭…  │         │              │
│              │  └──────┴──────────────┴──────┘         │              │
└──────────────┴─────────────────────────────────────────────┴──────────────┘
```

- **프레임 left / right**: 기존 그대로. **변경 없음.**
- **프레임 content**: **상단 헤더** + **q-splitter로 나눈 3영역** 하나의 블록으로 구성.

### 2.2 content 상단 헤더

- **목적**: **도메인 정체성**을 보여 주는 타이틀과, AI 채팅뿐 아니라 **편집기**로서의 기본 메뉴(파일·편집·보기·실행 등)를 제공한다. 영역 구성·표시/숨김 등 **액션도 한곳에서** 접근할 수 있도록 한다.
- **배치**: content 영역 **맨 위**에 고정. 스플릿 3영역보다 위에 **한 줄(또는 메뉴 + 툴바)** 로 둔다.

#### 헤더 구성 (좌 → 우)

| 구역 | 내용 | 비고 |
|------|------|------|
| **타이틀** | 도메인 정체성을 나타내는 **타이틀** (예: "NEXA AI", "AI 스튜디오"). 로고·아이콘 + 텍스트 조합 가능. | 사용자가 “지금 AI 도메인”임을 바로 인지. |
| **메뉴 바** | 편집기형 **기본 메뉴** (우선 **가상**으로 배치). | 채팅만이 아니라 문서·코드 편집 도구라는 정체성. |

**메뉴 항목 (가상 · 우선 플레이스홀더)**

| 메뉴 | 예시 항목 (가상) | 용도 |
|------|------------------|------|
| **파일** | 새 채팅, 새 문서, 열기, 저장, 내보내기… | 채팅·문서·코드 파일 단위 작업. |
| **편집** | 실행 취소, 다시 실행, 잘라내기, 복사, 붙여넣기, 찾기, 바꾸기… | 에디터·코드 공통 편집 액션. |
| **보기** | 영역 표시/숨김, 레이아웃 프리셋, 전체 화면, 줌… | 화면 구성·가시성. |
| **실행** | 실행, 디버그, 중단… | 코드 실행·실험 (추후 연동). |
| **(기타)** | 도움말, 설정 바로가기… | 필요 시 확장. |

- 위 메뉴는 **1단계에서 가상(플레이스홀더)** 으로만 두고, 실제 동작은 단계적으로 연결한다. “보기” 메뉴는 영역 표시/숨김·프리셋과 먼저 연동하기 좋다.

#### 헤더 액션 (레이아웃·구성)

| 액션 | 설명 |
|------|------|
| **영역 표시/숨김** | 좌·중앙·우 각각 “패널 보이기/숨기기” 토글. (보기 메뉴 또는 툴바) |
| **영역별 패널·탭** | 해당 영역에 넣은 패널 목록·탭 전환, “패널 추가” 드롭다운. |
| **레이아웃 프리셋** | “기본”, “코드 중심” 등. (보기 메뉴) |
| **비율 초기화** | 스플릿 비율 기본값 복원. |

- 구현 시 **1단계**: **타이틀** + **메뉴 바(파일·편집·보기·실행 등 가상)** 노출 + 영역 표시/숨김·탭 전환 동작 우선 확보.

### 2.3 content 내부 3영역 구성 (기본)

- **영역1 (content 내 좌)**: 채팅 등 — **여러 패널 허용**, 영역 내 **탭**으로 전환.
- **영역2 (content 내 중앙)**: 에디터·코드·이미지·음원·영상 등 — **여러 패널 허용**, 영역 내 **탭**으로 전환.
- **영역3 (content 내 우)**: 탐색기 등 — **여러 패널 허용**, 영역 내 **탭**으로 전환.

각 영역은 **하나가 아닌 여러 개 기능(내용)** 을 가질 수 있고, **탭으로 전환**한다. 드래그 앤 드롭 배치는 **나중에 구현 고려**.

### 2.4 Quasar Splitter 사용 (content 내부만)

- **구성**: `q-splitter` 2단 중첩으로 3영역 구현.
  - 1차: `#before` = 영역1(좌), `#after` = 2차 splitter.
  - 2차: `#before` = 영역2(중앙), `#after` = 영역3(우).
- **단위**: `unit="px"` 또는 `unit="%"` (기본 비율 유지 시 % 권장).
- **비율(기본 제안)**: 좌 28% · 중앙 44% · 우 28% (또는 25/50/25). 사용자 드래그로 변경 가능.
- **최소/최대**: `limits`로 각 패널 최소·최대 폭 지정 (예: [200, 600] px).

## 3. 영역 표시/숨김 (보이기·가리기)

### 3.1 요구사항

- 각 영역(좌·중앙·우)을 **개별적으로** 보이거나 숨길 수 있다.
- 숨기면: 해당 구역이 0 폭(또는 최소화)이 되고, 스플릿 구분선도 사라지는 형태가 자연스럽다.
- 다시 보이면: 이전 비율 또는 기본 비율로 복원 (선택 사항: 직전 비율 저장).

### 3.2 구현 방향

| 방식 | 설명 |
|------|------|
| **A. 0 폭 + 스플릿터 제거** | 영역이 “숨김”일 때 해당 pane 크기를 0으로 두고, 스플릿터에서 해당 구역을 렌더링하지 않음. 2영역·1영역 레이아웃으로 전환. |
| **B. 토글 버튼** | 각 영역 헤더(또는 상단 툴바)에 “패널 접기/펼치기” 아이콘. 클릭 시 해당 영역만 0 폭 ↔ 복원. |
| **C. 상태 저장** | `leftVisible`, `centerVisible`, `rightVisible` 같은 ref + localStorage 등에 저장해 세션/재접속 시 유지. |

### 3.3 기본 동작 제안

- **content 상단 헤더**에 좌·중앙·우 각각 “영역 보이기/숨기기” 토글 버튼 배치 (액션 접근 용이).
- 좌/중앙/우 각각 “숨기기” 시 해당 영역만 0 폭으로 줄이고, 나머지 두 영역이 남은 공간을 나눠 가짐.
- “보이기” 시 기본 비율(또는 저장된 비율)로 복원.

## 4. 각 영역의 내용 조정

### 4.1 요구사항

- 각 **영역(좌·중앙·우)** 에 **여러 개 기능(패널)** 을 넣을 수 있다.
- 한 영역 안에서는 **탭**으로 패널을 전환한다.
- 사용자가 영역별로 “어떤 패널들을 넣을지” 구성할 수 있도록 한다. (헤더 등에서 액션 접근.)

### 4.2 “내용” 후보 (패널 풀)

| 패널 ID | 컴포넌트 | 설명 |
|---------|----------|------|
| chat | AiChatPanel | 채팅 대화·입력 |
| editor | AiEditorPanel (Tiptap) | 문서 에디터 |
| code | AiCodeEditorPanel (Monaco) | 코드 에디터 |
| image | AiImageEditorPanel | 이미지 편집 |
| audio | AiAudioEditorPanel | 음원 편집 |
| video | AiVideoEditorPanel | 영상 편집 |
| explorer | AiExplorerPanel | 파일/리소스 탐색 |

### 4.3 영역별 여러 패널 + 탭 전환

- **한 영역**에 패널을 **여러 개** 등록할 수 있다 (예: 좌 = [채팅, 메모 미리보기], 중앙 = [에디터, 코드, 이미지, 음원, 영상], 우 = [탐색기]).
- 해당 영역 내에서는 **q-tabs / q-tab-panels** (또는 동등한 탭 UI)로 전환. 한 번에 하나의 패널만 표시.
- **헤더**(content 상단 또는 영역별 작은 헤더)에서 “이 영역에 패널 추가”·“탭 선택” 등 액션 제공.

### 4.4 조정 방식 · 드래그 앤 드롭

| 방식 | 설명 |
|------|------|
| **탭 전환** | 각 영역 내 여러 패널을 **탭**으로 전환. **1단계에서 구현.** |
| **헤더에서 패널 추가/제거** | 상단 헤더 또는 영역 헤더의 드롭다운/버튼으로 “이 영역에 표시할 패널” 추가·제거. |
| **드래그 앤 드롭** | 패널을 슬롯·탭 순서로 끌어다 놓아 배치. **나중에 구현 고려.** |

## 5. 제안 파일·구조

### 5.1 레이아웃 담당

- **위치**: `domains/ai/views/` 또는 `domains/ai/views/content/`.
- **이름 후보**: `AiSplitLayout.vue` (또는 기존 `AiContent.vue`를 스플릿 구조로 대체).

```
domains/ai/
├── views/
│   ├── content/
│   │   ├── AiContent.vue          # (현재) 탭 기반 → 단계적으로 AiSplitLayout으로 이전
│   │   └── AiSplitLayout.vue      # [신규] 3영역 q-splitter + 영역별 패널·표시 토글
│   ├── left/
│   │   └── AiLeftNav.vue           # 기존 유지 (채널/메모/미디어)
│   └── right/
│       └── AiRightPanel.vue        # 기존 유지 (에이전트/설정)
```

### 5.2 상태·설정

- **composable 또는 store** (도메인 로컬):
  - `useAiSplitLayout.ts` (가칭)
  - 상태: 각 영역별 **패널 ID 목록** (여러 개) + **현재 선택된 탭 인덱스**.
  - 상태: `leftVisible`, `centerVisible`, `rightVisible` (boolean).
  - 상태: `leftSize`, `centerSize`, `rightSize` (비율 또는 px, 스플릿 v-model과 동기화).

### 5.3 설정 저장 정책

- **우선: localStorage.**  
  스플릿 비율, 영역 표시/숨김, 영역별 패널 구성·탭 순서 등 **레이아웃/구성 설정**은 **localStorage**에 저장한다. (기존 useAiSettings·채널 저장 등과 키 구분만 하면 됨.)
- **추후: 웹서버·DB 연동 시 서버화.**  
  채팅 내용, 편집 저장, 메모 등과 함께 **레이아웃/구성 설정도 웹서버·DB로 이전**할 예정이다. 당장은 localStorage로 구현해 두고, API·스키마가 정리되면 동일 설정 항목을 서버에서 불러오기·저장하도록 전환한다.

### 5.4 컴포넌트 매핑

- `panelId` → 컴포넌트 매핑은 **한 곳**에서 관리 (예: `AiSplitLayout.vue` 내부 객체 또는 `config/aiPanelRegistry.ts`).
- 각 영역은 `<component :is="currentComponent(leftPanelId)" />` 형태로 렌더링하면, 패널 ID만 바꿔도 내용 전환 가능.

## 6. 라우팅·프레임과의 관계

- **라우팅은 수정하지 않는다.**  
  경로·라우트 설정은 **현재와 동일**하게 유지한다. 일관성을 위해 라우터 정의나 라우트 구성을 바꾸지 않고, **같은 경로에서 같은 슬롯에 무엇을 렌더할지만** 바꾼다.
- **드로어(left/right)**: 레이아웃·라우팅 모두 **현재와 동일**하게 유지.
- **content**: AI 도메인에서 content 슬롯에 지금 보여 주는 “탭 1블록”(AiContent.vue)을 **AiSplitLayout 한 개**로 교체한다. 즉 **라우트는 그대로 두고**, 해당 슬롯에 렌더되는 **컴포넌트만** AiContent → AiSplitLayout으로 바꾼다. content **안만** 탭 1개 → 스플릿 3영역으로 바뀌고, 프레임의 left / content / right 구분은 그대로다.

## 7. 정리

| 항목 | 내용 |
|------|------|
| **상단 헤더** | content 맨 위에 고정. 영역 표시/숨김, 영역별 패널·탭 조정, 프리셋 등 **액션 버튼**을 한곳에서 접근. |
| **레이아웃** | Quasar `q-splitter` 2단 중첩으로 content 내 좌·중앙·우 3영역. |
| **영역별 구성** | 각 영역에 **여러 패널** 허용, 영역 내 **탭**으로 전환. 헤더에서 패널 추가/제거 등 조정. |
| **드래그 앤 드롭** | 패널·탭 순서 배치는 **나중에 구현 고려.** |
| **표시/숨김** | 영역별 토글(헤더에 배치)로 해당 영역만 0 폭 ↔ 복원. |
| **설정 저장** | **우선 localStorage.** 추후 채팅·편집 저장 등 웹서버·DB 연동 시 **레이아웃 설정까지 웹서버화.** |
| **파일** | `AiSplitLayout.vue` 신규(헤더 + 스플릿 + 영역별 탭) + 레이아웃 상태용 composable, 기존 패널 컴포넌트 재사용. |
| **라우팅** | **수정하지 않는다.** 경로·라우트 설정 유지, content 슬롯에 렌더하는 컴포넌트만 교체. |

이 기획이 확정된 뒤, 단계적으로 **헤더 + AiSplitLayout 도입 → 영역별 탭·표시/숨김 → 설정 localStorage 저장** 순으로 구현하면 된다. **라우터 코드는 건드리지 않는다.**
