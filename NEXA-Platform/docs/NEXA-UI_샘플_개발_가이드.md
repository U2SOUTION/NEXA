# SampleSection 전체 샘플 추가 체크리스트

## 📋 개요

SampleSection 컴포넌트에 추가할 수 있는 모든 샘플 유형을 체크리스트로 정리합니다.

**목적**:

1. **테스트 및 검증**: 사이드바에서 다양한 UI 요소들이 올바르게 작동하는지 확인
2. **문제 발견**: 긴 라벨/텍스트로 인한 가로 확장, 잘림, 레이아웃 깨짐 등의 문제를 사전에 발견
3. **일관성 확보**: 모든 폼 요소가 동일한 스타일과 동작을 하는지 확인
4. **반응형 테스트**: 사이드바 가로폭 변경 시 자동으로 조정되는지 확인
5. **전역 스타일 검증**: 전역 CSS가 올바르게 적용되는지 확인
6. **Quasar와 NEXA의 조화**: Quasar 프레임워크의 기본 기능을 유지하면서 NEXA 테마의 특별함을 적용한 적절한 타협점과 조화점을 찾는 것

**핵심 원칙**:

- 샘플 파일은 **테스트 도구**이므로 컴포넌트별 스타일을 넣지 않음
- 모든 스타일은 **전역 CSS**로 해결해야 함 (`src/css/nexa-system/_form.scss` 등)
- 샘플은 문제를 발견하고 전역 해결책을 검증하는 용도
- 샘플 파일에 스타일을 추가하면 전역 스타일 검증이 어려워짐
- **Quasar의 기본 동작을 최대한 활용**하면서 **NEXA 테마의 일관성**을 유지하는 것이 목표

**SCSS 아키텍처 레벨 5 정책 (NEXA 시스템)**:

- **위치**: `src/css/nexa-system/` 디렉토리
- **역할**: NEXA 프로젝트 특화 전역 스타일 정의 (브랜딩 컬러, 시스템 공통 UI, 특수 클래스)
- **허용**: NEXA 특화 스타일, 레이아웃, 애니메이션, 특수 클래스
- **제한**:
  - 색상 값 직접 정의 금지 (레벨 4 테마 변수 사용: `var(--nexa-primary)` 등)
  - 특정 모듈에 종속된 스타일 금지
  - CSS 변수 참조 사용 (`var(--nexa-*)`)
- **파일 구조**:
  - `nexa-system.scss` (메인 파일)
  - `_form.scss`, `_item.scss`, `_card.scss`, `_table.scss`, `_list.scss`, `_chart.scss` (부분 파일)

**참조 문서**:

- [NEXA-SCSS_ARCHITECTURE.md](./NEXA-SCSS_ARCHITECTURE.md) - SCSS 아키텍처 및 정책 상세 가이드

### 각 샘플 추가 시 확인 사항

- [ ] 가로 확장 시 아코디언 화살표가 가려지지 않는지 확인
- [ ] 긴 라벨/텍스트가 ellipsis로 처리되는지 확인
- [ ] 반응형 레이아웃이 올바르게 작동하는지 확인
- [ ] 다크 모드에서도 정상 작동하는지 확인
- [ ] 스타일이 프로젝트 표준과 일치하는지 확인
