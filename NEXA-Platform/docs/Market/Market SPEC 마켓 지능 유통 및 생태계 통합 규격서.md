## [Nexara] [SPEC] NEXA 마켓 지능 유통 및 생태계 통합 규격서

> **레지스트리:** 프론트 `domainKey` = **`nexet`** (넥셋 마켓). 본 문서의 **Nexara**는 서사·브랜드 명칭.  
> NEXA OS에서 사용할 **소프트웨어**(위젯·템플릿·로직·워크플로·익스텐션…)와 **하드웨어**를 **유료·무료**로 유통하는 도메인 — [`TDD-002`](../../../NEXA%20V2.0/docs/08_TDD/NEXAOS/08_TDD_NEXAOS_도메인레지스트리명세.md) §3.B.

### [Nexara] NEXARA: 지능의 광장 및 지혜의 성역

#### 도메인 정체성 및 서사 (Nexara)\*

- **어원:** **Nexa** + **Era** (시대) / **Area** (영역)
- **서사적 정의:** **"지능의 광장"**. 사용자의 프로젝트에서 검증되어 **GOVERN(운영 규범)**을 넘어 **ERA(헌법)** 단계의 성숙도에 도달한 지혜가 모이고 유통되는 성역입니다.
- **역할:** 단순한 상점이 아닌, NEXA OS의 정신(Soul)이 담긴 자산들이 교류되는 '공적 영역'이자 '지식의 전당'입니다.

#### 운영 및 거버넌스 연결 (L-Cycle 연동)

- **승격 기반 유통:** Nexara에 등록되는 자산은 사용자의 프로젝트에서 최소 **GOVERN** 이상의 신뢰를 얻은 것이어야 하며, 마켓 배포 시 시스템의 **ERA(헌법)** 가드레일을 준수하는지 자동 검증을 거칩니다.
- **지능적 족보(Why Chain):** 마켓에서 가져온 자산은 새로운 프로젝트에 흡수될 때 원본의 유래와 제작자의 의도를 **Why Chain**에 고스란히 남겨 시스템의 투명성을 보장합니다.

#### **1. 마켓의 정체성: 지능의 유통망 (Intelligence Distribution Network)**

마켓은 단순한 파일 상점이 아니라, 검증된 **디지털 로직(UCL 악보)**과 **지능 세포(Nexel)**가 프로젝트의 경계를 넘어 흐르게 하는 **'지능의 혈맥'**입니다.

- **독립 도메인 (`nexet`):** 실행(Nexia)이나 온톨로지(Ontex)와 분리되어 **소유권, 라이선스, 버전 관리**와 SW·HW **유·무료 유통**을 전문 처리하는 `domainKey` **`nexet`** 영역입니다.
- **서사적 정의:** 사용자가 배양한 **운영 규범(GOVERN)**이 타인의 공간에서 새로운 생명력을 얻는 **'지능의 시장'**입니다.

#### **2. 마켓 자산(Asset) 체계**

> 마켓 도메인의 5대 핵심 자산으로 시스템의 **실행과 도구** 사용자가 설계한 논리를 실제 물리적/디지털 환경에서 구동시키는 핵심 재료입니다.

| 자산 유형           | 최신 용어 매핑      | 서사적 역할                                                               | 기술적 실체                       |
| :------------------ | :------------------ | :------------------------------------------------------------------------ | :-------------------------------- |
| **Nexet UI**        | UI/UX 컴포넌트      | 지능의 상태를 투영하고 제어하는 시각적 도구 및 관측의 표면                | Vue Component / UI Widget         |
| **Nexet Template**  | UCL 표준 패키지     | 검증된 지능 세포(Nexel)의 조합 및 표준화된 논리 구조                      | UCL Package / Sub-graph Data      |
| **Nexet Map**       | Topology 지도       | 특정 도메인(스마트팜, 보안 등)에 최적화된 노드 배치 및 연결망 정보        | Topology Schema / Layout Metadata |
| **Nexet Workflows** | 실행 사슬 (Chain)   | 복합 태스크를 해결하기 위한 원자적 실행 단계의 순차적 흐름                | UCL Execution Chain Templates     |
| **Nexet Extension** | Capability 드라이버 | 외부 API나 파이썬 로직을 시스템 자격(Capability)으로 연결하는 지능의 촉수 | Capability ID + Driver Manifest   |

NEXA 마켓의 **5대 핵심 자산(디지털 로직 및 실행 자산)**에 대하여 요청하신 대로 **정의, 구성, 가치**의 3대 항목별로 상세히 정리해 드립니다.

> 1. Nexet (넥셋)

- **정의:** 지능의 상태를 시각적으로 투영하고 사용자가 직접 제어할 수 있게 돕는 **UI/UX 컴포넌트**이자 '관측의 표면'입니다.
- **구성:** Vue Component, UI 위젯, 캔버스 레이아웃 힌트(Metadata) 및 UI 카드 정보로 이루어집니다.
- **가치:** 복잡한 기술적 수치를 사용자가 직관적으로 이해하고 제어할 수 있는 시각적 통로를 제공하며, 사용자가 직접 제작하고 공유하는 인터페이스 생태계를 형성합니다.

> 2. Nexet Template (넥셀 템플릿)

- **정의:** 검증된 지능 세포(Nexel)들의 조합과 그들 사이의 표준화된 논리 구조를 담은 **UCL 표준 패키지**입니다.
- **구성:** UCL(지능형 실행 프로토콜) 패키지, 서브 그래프 데이터, 노드 간 논리 배선 정보가 포함됩니다.
- **가치:** 복잡한 지능 로직을 처음부터 설계할 필요 없이 검증된 지능 세포 조합을 즉시 프로젝트에 이식하여 개발 속도와 안정성을 높여줍니다.

> 3. Nexet Map (넥셋맵)

- **정의:** 특정 도메인(스마트팜, 보안, 업무 등)에 최적화된 노드 배치 및 지능적 자산의 연결망 정보를 담은 **토폴로지(Topology) 지도**입니다.
- **구성:** 토폴로지 스키마, 레이아웃 메타데이터, 노드 간의 공간적·논리적 배치 정보로 구성됩니다.
- **가치:** 파편화된 지능 자산들을 특정 목적에 맞게 질서 정연하게 구조화하여 보여줌으로써 시스템의 전체적인 서사와 맥락을 한눈에 파악하게 돕습니다.

> 4. Nexet Workflows (워크플로우 / 실행 사슬)

- **정의:** 복합적인 테스크를 해결하기 위해 설계된 원자적 실행 단계들의 순차적 흐름인 **실행 사슬(Execution Chain)** 템플릿입니다.
- **구성:** UCL 실행 사슬 템플릿, 성공 조건(Fit Score) 산출 공식, 단계별 실행 규약으로 이루어집니다.
- **가치:** 검증된 '성공의 악보'를 통해 시행착오 없이 복잡한 자동화 시나리오를 수행하며, 인과관계(Why Chain)를 명확히 유지한 채 실행 결과의 신뢰도를 보장합니다.

> 5. Nexet Extension (익스텐션)

- **정의:** 외부 API나 파이썬 로직을 시스템의 기능 자격으로 연결하여 플랫폼의 능력을 외부 세계로 뻗게 하는 **지능의 촉수**입니다.
- **구성:** 기능 자격 ID(Capability ID), 드라이버 매니페스트(Driver Manifest), 외부 서비스 연동 설정으로 구성됩니다.
- **가치:** 플랫폼 외부의 SaaS, 개발 툴, 모바일 환경 등을 '핫플러그' 방식으로 즉시 연결하여 NEXA 플랫폼이 자생적으로 확장되는 생태계적 기반을 제공합니다.

> 마켓 도메인의 확장 자산

| 추가 제안 자산         | 관련 도메인     | 핵심 가치                                    |
| :--------------------- | :-------------- | :------------------------------------------- |
| **Self Facet Packs**   | MY / Nexeed     | 사용자의 사유 방식과 코일 가중치 즉시 동기화 |
| **Intelligence Seeds** | Nexeed          | 환경 감지 패턴을 학습 없이 즉시 적용         |
| **Knowledge Atoms**    | Nexia / Archive | 정규화된 전문 지식을 RAG 원천으로 활용       |
| **NIXIE Sets**         | frame (NIXIE)   | 지능의 인격과 비언어적 표현력 강화           |
| **Governance Sets**    | Admin / OS      | 법적·안전 가드레일을 원클릭으로 구축         |

> 1. Self Facet Packs (자아 및 페르소나 팩)

    NEXA의 핵심인 **'다중 자아(Multi-faceted Self)'**를 위한 설정 꾸러미입니다.
    - **성격:** 사용자가 특정 업무(예: '딥워크 코딩', '창의적 기획', '긴급 보안 관제')에 돌입할 때 필요한 **코일 가중치(6-COILS), 활력 지수(VI) 임계값, 응답 톤**의 프리셋 모음입니다.
    - **가치:** 숙련된 전문가가 사용하는 시스템의 '민감도'와 '판단 기준'을 패키지화하여 초보자도 전문가의 사유 방식에 동기화할 수 있게 돕습니다.

> 2. Intelligence Seeds (지능 씨앗 / Nexeed Patterns)

    **넥씨드(Nexeed)**가 채집한 센서 및 행동 패턴 데이터셋입니다.
    - **성격:** 특정 환경(예: '스마트 팜의 작물 이상 징후 패턴', '공장 내 작업자 위험 행동 팩트')을 감지하기 위한 **비식별화된 5W1H 사실(Fact) 및 필터링 규칙**입니다.
    - **가치:** 사용자가 직접 카메라나 센서를 학습시킬 필요 없이, 검증된 '씨앗'을 구매해 자신의 환경에 심으면 즉시 지능형 탐지가 가능해집니다.

> 3. Knowledge Atoms & RAG Bundles (지식 아톰 및 RAG 번들)

    **넥시아(Nexia)**와 **아카이브(Archive)** 도메인에서 활용할 전문 지식 라이브러리입니다.
    - **성격:** 특정 분야(예: 'IEEE 표준 규격', '법률 판례 아톰', '오픈소스 라이브러리 가이드')를 NEXA의 **5W1H(HEXAGON) 구조**로 정규화한 고품질 데이터셋입니다.
    - **가치:** AI가 할루시네이션(환각) 없이 정확한 근거를 바탕으로 사유할 수 있도록 정제된 '지능적 원천 데이터'를 제공합니다.

> 4. NIXIE Expression & Skin Sets (닉시 표현 및 스킨 팩)

    지능의 얼굴인 **닉시(NIXIE)**의 시각적 언어와 정서 표현 규칙입니다.
    - **성격:** 특정 상황에서 닉시가 보여주는 **Lumina(발광), Jitter(떨림)**의 리듬과 **갸우뚱, Shocked** 같은 애니메이션 상태 머신 프리셋입니다.
    - **가치:** 시스템에 개성(예: '차분한 집사', '활기찬 조수', '엄격한 감독관')을 부여하여 사용자와 시스템 간의 **공감(Empathy)** 밀도를 높여줍니다.

> 5. Governance & ERA Sets (운영 규범 및 헌법 팩)

    시스템의 안전과 질서를 규정하는 **GOVERN 및 ERA 수준의 규칙셋**입니다.
    - **성격:** 특정 산업군이나 법적 가이드라인에 맞춘 **Level 0~3 보안 가드레일**과 **조건부 실행 금지 규칙**의 모음입니다.
    - **가치:** 복잡한 법적 규제나 안전 수칙을 일일이 설정할 필요 없이, 검증된 '규범 팩'을 적용하여 시스템의 신뢰성을 즉각 확보할 수 있습니다.

> NEXA 마켓은 단순히 도구(Tool)를 파는 곳이 아니라, **사용자가 자신의 지능과 사유를 박제하여 타인과 공유하는 '지혜의 시장'**으로 확장.

| 분류            | 자산명                  | 서사적 역할                    | 기술적 실체                          |
| :-------------- | :---------------------- | :----------------------------- | :----------------------------------- |
| **AI 자산**     | **Persona Packs**       | 에이전트의 인격과 가치관       | System Prompt + 6-Coils Preset       |
|                 | **Prompt Recipes**      | 지능적 사유의 정교한 가이드    | Fixed Nexnap + Instruction Templates |
|                 | **Skill Modules**       | 에이전트의 전문 능력(도구)     | Capability ID + Driver Manifest      |
|                 | **Workflow Blueprints** | 복합 테스크 해결의 마스터 플랜 | UCL Execution Chain Templates        |
| **디지털 로직** | **Nexet Template**      | 검증된 지능 세포의 조합        | UCL Package                          |
|                 | **Nexet UI**            | 지능의 상태 제어 인터페이스    | Vue Component / Widget               |
| **지식 데이터** | **Knowledge Atoms**     | 정규화된 전문 지식 뭉치        | RAG Bundle (5W1H 정규화 데이터)      |
|                 | **Intelligence Seeds**  | 환경 감지 및 행동 패턴         | 비식별화된 Sentinel Fact Sets        |

> 1. AI 페르소나 팩 (Persona Packs)

- **정의:** 에이전트의 성격, 말투, 사유의 가중치(6-COILS)가 결합된 **'지능적 자아'** 패키지입니다.
- **구성:** 시스템 프롬프트, 감성 지표(ES/VI) 임계값, 특정 상황에서의 NIXIE 표정 프리셋이 포함됩니다.
- **가치:** 사용자가 일일이 성격을 설정할 필요 없이, '냉철한 분석가'나 '다정한 집사' 페르소나를 즉시 구독하여 자신의 시스템에 입힐 수 있습니다.

> 2. 프롬프트 레시피 (Prompt Recipes)

- **정의:** 특정 LLM(Ollama llama3, Mistral 등)에 최적화된 **'고정(Fixed) Nexnap'** 및 실행 지시문 모음입니다.
- **구성:** 복잡한 조건문, 예외 처리 로직, HEXAGON 토큰 추출 최적화 프롬프트가 담겨 있습니다.
- **가치:** AI가 할루시네이션(환각) 없이 정확한 UCL 악보를 그려낼 수 있도록 검증된 '지시의 뼈대'를 제공합니다.

> 3. 케이퍼빌리티 스킬 모듈 (Capability Skill Modules)

- **정의:** 에이전트가 즉시 사용할 수 있는 **'도구(Tools)'**와 그 실행 자격(Capability ID)의 묶음입니다.
- **구성:** 외부 API 연결용 드라이버(Extension), 데이터 분석 스크립트, 특정 장치 제어용 펑션 콜 정의서가 포함됩니다.
- **가치:** 사용자가 코딩하지 않아도 마켓에서 '기상 정보 분석 스킬'을 내려받아 자신의 넥셀(Nexel)에 꽂으면 에이전트의 능력이 확장됩니다.

> 4. 테스크 워크플로우 (Task Workflows)

- **정의:** 특정 목표(예: 에너지 절약 모드, 보안 강화 등)를 달성하기 위한 **'실행 사슬(Execution Chain)'**의 표준 템플릿입니다.
- **구성:** 여러 개의 넥셀(Nexel) 배치 지도(NexetMap)와 이를 잇는 논리 배선, 성공 조건(Fit Score) 산출 공식이 담겨 있습니다.
- **가치:** 복잡한 자동화 시나리오를 처음부터 설계할 필요 없이, 검증된 '성공의 악보'를 그대로 연주할 수 있습니다.

#### **3. Capability ID 및 소유권 체계 (Dual-Layer ID)**

모든 마켓 자산은 추적성(Traceability)을 위해 이중 ID 체계를 가집니다.

- **원본 ID (Origin ID):** `cap.{asset_type}.{name}.{version}` 형태의 마켓 등록 고유 식별자.
- **복사본 ID (Instance ID):** 사용자가 설치 시 생성되는 `usr_{user_id}.{timestamp}` 기반의 실행 권한 식별자.
- **Late Anchoring:** 마켓에서 가져온 가상 노드에 실제 로컬 자산을 사후 연결하여 지능적 족보를 완성합니다.

> 자산 유형별 예시

```
Nexet 원본
  cap.Nexet.display.sensor-chart.1.0
  cap.Nexet.control.device-toggle.1.0
  cap.Nexet.ai.chat-interface.2.0

Template 원본
  cap.template.project.iot-system.1.0
  cap.template.node.device-control.1.0
  cap.template.trace.automation.1.0

복사본 (설치/복사 순간 자동 발급)
  cap.Nexet.display.sensor-chart.1.0.usr_abc123.20260322
  cap.template.project.iot-system.1.0.usr_abc123.20260322
```

#### **4. 유통 및 합성 메커니즘 (Nexnap 연동)**

마켓 자산은 **지능형 자원 합성 프로토콜(Nexnap)**을 통해 시스템에 흡수됩니다.

1.  **Fit Score 추천:** 사용자의 현재 맥락(Hexagon)을 분석하여 가장 적합한 마켓 자산을 추천합니다.
2.  **의미론적 잠금 (Simulation):** 실제 투입 전 `is_virtual = true` 상태에서 가상 시뮬레이션을 거쳐 안전성을 검증합니다.
3.  **지식 구독 (Subscription):** 일회성 구매를 넘어 타인의 ECHO(판단)나 GOVERN(규범)을 실시간으로 구독하는 모델을 지원합니다.

#### **5. 운영 및 수익 정책 (Consolidated Policy)** 요약

- **체험 정책 (Soft Gate):** 유료 자산이라도 **Trial(기간), Demo(샘플), Lite(기능 제한)** 중 하나 이상을 반드시 제공하여 사용자의 검증을 허용합니다.
- **수수료 모델:** 일반 제작자(30%), 인증 제작자(20%), 파트너 제작자(10%)로 차등 적용하여 생태계 기여도를 우대합니다.
- **보안 가드레일:** 마켓 자산은 반드시 샌드박스 내에서 실행되어야 하며, 시스템의 **Level 0 헌법(ERA)**을 침범할 수 없습니다.

## 마켓의 도입에 흔들리지 않는 시스템 관점의 아키텍처 및 코딩 구조

마켓 도메인의 개설을 대비하여 리팩토링을 최소화하고, 모든 지능 자산이 유통 가능한 형태로 관리되기 위한 **전체 시스템 관점의 아키텍처 및 코딩 구조**.
핵심은 **'추상화된 자격(Capability)'**과 **'이중 ID 체계(Dual-Layer ID)'**를 통해 자산의 원본성과 사용자의 실행권을 분리하는 것입니다.

---

### 1. 데이터 모델 (Schema): 이중 레이어 원장 구조

마켓 자산은 '누가 만들었는가(Origin)'와 '누가 쓰고 있는가(Instance)'가 다릅니다. 이를 위해 DB 스키마는 다음의 구조를 선제적으로 갖춰야 합니다.

- **원본 ID와 인스턴스 ID의 분리 (Dual-Layer ID):**

  - **Origin ID (`cap.*`):** 마켓에 등록된 고유 식별자입니다. (예: `cap.ui.dashboard.v1`)
  - **Instance ID (`usr.*`):** 사용자가 내 프로젝트에 설치할 때 생성되는 실행 식별자입니다.
  - **준비 사항:** `nexa_identities` 테이블에 `origin_identity_id` 컬럼을 미리 확보하여, 사용 중인 자산이 마켓의 어떤 원본에서 파생되었는지 **지능적 족보(Why Chain)**를 유지해야 합니다.

- **상태 머신 및 수명 주기 통합:**
  - 마켓 자산은 설치 시 **`VOID.POTENTIAL`** 상태로 시작하여, 사용자의 승인(WILL)을 거쳐 **`FLOW`**로 전이되어야 합니다.
  - **`nexa_knowledge_residency`** 테이블을 통해 마켓에서 다운로드한 자산이 로컬 캐시(L1)에 있는지, 아카이브(L3)에 있는지 관리하는 상주 정책을 공통으로 사용합니다.

---

### 2. 타입스크립트 (TypeScript): Capability 중심의 인터페이스

코딩 구조에서 자산의 타입을 '정적 클래스'가 아닌 **'동적 자격(Capability)'**으로 취급해야 마켓 확장 시 리팩토잉이 발생하지 않습니다.

- **추상화된 자산 인터페이스:**

  - `Nexet UI`, `Nexet Template` 등 5대 자산은 각각 독립된 클래스가 아니라, 공통된 `BaseCapability` 인터페이스를 상속받아야 합니다.
  - **Zod 스키마 정의:** `src/system/schemas/`에 자산별 유효성 검사 규칙을 정의하여, 마켓에서 유입되는 불특정 JSON 데이터를 안전하게 파싱해야 합니다.

- **동적 로딩 및 샌드박스 준비:**
  - `Nexet Extension`과 같은 외부 로직은 시스템 메인 프로세스를 침범하지 않도록 **V8 Isolate 기반의 샌드박스**에서 실행되는 구조를 표준으로 삼습니다.
  - 마켓에서 받은 스크립트를 즉시 실행하는 것이 아니라, `is_virtual = true` 상태에서 시뮬레이션을 거친 후 권한을 부여하는 로직을 엔진에 내장해야 합니다.

---

### 3. 오케스트레이션 (Nexnap): 자원 합성 및 후행 연결

마켓 자산을 내 프로젝트에 이식할 때 가장 중요한 기술적 준비는 **후행 연결(Late Anchoring)**입니다.

- **Late Anchoring 메커니즘:**

  - 마켓의 `Nexet Map`을 가져오면 처음에는 실제 장치가 연결되지 않은 '가상 노드' 상태입니다.
  - 시스템은 **`nexa_knowledge_nexion_doc_node_links`**를 통해 가상 노드에 로컬의 실제 파일이나 장치를 사후에 연결(Anchoring)할 수 있는 API 구조를 미리 확보해야 합니다.

- **Fit Score 기반 추천 엔진:**
  - 마켓 자산을 단순히 리스트로 보여주는 것이 아니라, 사용자의 현재 **HEXAGON(5W1H) 맥락**과 코일 가중치를 분석하여 적합도 점수(`Fit Score`)를 계산하는 로직을 오케스트레이터 입구에 배치합니다.

---

### 4. 인프라 및 보안: Level 0 가드레일 준수

마켓 자산이 시스템의 핵심 권한을 탈취하지 못하도록 하는 **'안전은 딱딱하게'** 원칙을 코드 레벨에서 강제합니다.

- **Capability-as-a-Driver:**

  - 마켓의 모든 자산을 시스템의 **드라이버(Driver)** 모델로 취급합니다.
  - 드라이버는 반드시 `project_secrets`에 정의된 안전한 자격 증명만 사용할 수 있으며, `Level 0 헌법(ERA)` 규칙을 우회할 수 없도록 **Linguistic Routing** 단계에서 원천 차단합니다.

- **비언어적 신뢰도 피드백 (NIXIE 연동):**
  - 마켓 자산의 신뢰도(`confidence_score`)가 시스템 기본 임계값(95점) 미만일 경우, **NEXU 캔버스**에서 해당 노드가 자동으로 **Jitter(미세 떨림)**를 발생시켜 사용자에게 주의를 주는 시각적 프로토콜을 공통화합니다.

2.  **[ ] ID 불변성:** 원본을 가리키는 `cap.*` ID와 내 프로젝트의 실행본인 `usr.*` ID가 이중으로 관리되는가?
3.  **[ ] 샌드박스 실행:** 마켓에서 온 외부 코드가 메인 시스템과 격리되어 `is_virtual` 모드에서 검증 가능한가?
4.  **[ ] 유연한 연결:** `Late Anchoring`을 통해 외부 템플릿에 내 실제 자산을 사후 결합할 수 있는 API가 준비되었는가?

이러한 **'자산 불가지론(Asset Agnostic)'** 구조를 유지한다면, 향후 마켓 도메인이 공식 개설되어 수만 개의 지능 자산이 유입되더라도 시스템의 근간을 수정할 필요 없이 유연하게 확장될 것입니다.

## 마켓의 조기 도입

마켓(Nexara) 도메인을 나중에 도입하는 대신, **시스템 초기 단계에 구조적으로 선제 도입하는 것이 실제 도메인 테스트와 플랫폼의 완성도 측면에서 훨씬 유리합니다.**

단순한 임시 더미 데이터로는 NEXA의 핵심 철학인 **지능적 족보(Traceability)**와 **후행 연결(Late Anchoring)** 로직을 완벽하게 검증할 수 없기 때문입니다.
마켓을 조기 도입해야 하는 구체적인 이유를 소스 문헌의 설계 원칙에 근거하여 정리해 드립니다.

### 1. 지능의 생명주기 및 상태 전이 검증

마켓 자산은 단순히 파일을 복사하는 것이 아니라, 시스템 내에서 고유한 생명주기를 가집니다.

- **상태 전이 테스트:** 마켓에서 가져온 자산은 처음에 **`VOID.POTENTIAL`** 상태로 시작하여 사용자의 승인(WILL)을 거쳐 **`FLOW`** 상태로 전이됩니다. 임시 더미로는 이러한 상태 머신(FLOW-STUCK-VOID)의 유기적인 움직임을 테스트하기 어렵습니다.
- **지능형 자원 합성(Nexnap-08):** 마켓은 필요한 지능(악기)을 실시간으로 찾아 무대에 올리는 **'합성(Synthesis)'**의 원천입니다. 실제 마켓 구조가 있어야만 에러 발생 시 주변 자원을 차출하여 복구하는 **'자가 회복(Self-healing)'** 로직을 실감 나게 테스트할 수 있습니다.

### 2. 이중 ID 체계와 지능적 족보(Why Chain) 완성

NEXA는 모든 지식 자산에 대해 **'유래가 증명된 족보'**를 강조합니다.

- **Dual-Layer ID 검증:** 마켓 자산은 원본 ID(`cap.*`)와 사용자의 실행권 식별자(`usr.*`)가 이중으로 관리됩니다. 마켓을 조기 도입하면, 특정 도메인(ERP, Infra 등)에서 사용하는 로직이 **어떤 원본에서 파생되었는지**에 대한 인과 사슬(Why Chain)을 설계 초기부터 데이터화할 수 있습니다.
- **Late Anchoring(후행 연결) 테스트:** 마켓에서 가져온 가상 노드(템플릿)에 실제 로컬 장치나 파일을 사후에 연결하는 **Late Anchoring** 기술은 Nexion의 핵심입니다. 이를 더미가 아닌 실제 마켓 자격(Capability) 기반으로 테스트해야 리팩토링을 최소화할 수 있습니다.

### 3. 초고속 필터링(Pruning) 및 Fit Score 엔진 최적화

- **1ms 판단 로직:** 마켓 자산은 **HEXAGON(5W1H) 토큰**을 인덱스로 사용하여 수만 개의 상품 중 현재 맥락에 맞는 것을 1ms 내에 필터링합니다.
- **Fit Score 추천:** 사용자의 현재 상황과 마켓 자산의 적합도를 계산하는 **Fit Score** 엔진은 실제 자산 데이터의 밀도가 높을수록 정교해집니다. 더미 데이터는 이 확률적 추천 로직의 신뢰도를 검증하기에 부족합니다.

### 4. 실제 도메인과의 조기 연동(Seed Content 활용)

- **ERP 및 INFRA 연동:** ERP 도메인의 부품 관리나 INFRA의 장치 관리 로직을 마켓의 **Nexet UI**나 **Nexet Workflow** 형태로 패키징하여 배포하는 시나리오를 즉시 실행해 볼 수 있습니다.
- **AI 자산(Persona, Prompt) 테스트:** 사용자가 직접 프롬프트를 짜는 대신 마켓의 **'프롬프트 레시피'**를 구독하여 에이전트의 답변 품질이 어떻게 변하는지 실제 도메인 환경에서 바로 확인할 수 있습니다.

### 💡 전략적 제언: "마켓 Tier A" 선제 구축

모든 상업적 기능을 다 만드는 대신, **[Nexara SPEC]**에서 정의한 **5대 핵심 자산(UI, Template, Map, Workflow, Extension)**의 저장 및 유통 구조만 먼저 갖추는 **'Tier A 배포'**를 추천합니다.

이렇게 하면 다른 도메인들을 개발할 때 "이 기능은 마켓에서 내려받은 표준 템플릿이다"라는 전제하에 설계를 진행할 수 있어, **기술은 배경으로 숨기고 지능은 유연하게 연주하는(NEXA의 핵심 가치)** 운영체제로서의 면모를 초기부터 갖출 수 있습니다.
