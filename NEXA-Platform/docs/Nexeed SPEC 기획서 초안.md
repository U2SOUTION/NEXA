# NEXA Nexeed SPEC (기획 초안)

> **용어 연동:** [`@ GLOSSARY NEXA-OS 용어집 .md`](@ GLOSSARY%20NEXA-OS%20용어집%20.md) — **Nexeed**는 리브랜딩 후보 표에서 **Trace → Nexeed**에 대응하는 **‘행동 기록·자동화 배양’** 층의 명칭으로 본 문서에서 사용한다. **Nexel · Nexet** 정의는 동 용어집과 맞춘다. 표기 **넥시드(발음)** / 영문 **Nexeed**.

---

## NEXA Nexeed는 무엇인가?

**Nexeed(넥시드)**는 NEXA 플랫폼 철학 **「반복은 AI에게, 창조는 사람에게」(Liberation)** 을 가장 실천적으로 담는 도메인이다.

Nexeed는 사용자가 시스템을 가르치는 **교육의 장**이며, 여기서 쌓인 데이터는 NEXA OS가 단순 도구를 넘어 **사용자의 의지를 닮은 유기체**로 성장하게 하는 핵심 연료가 된다.

**「Nexet에서의 행동 감시·녹화 → Nexel 변환 → 논리 재구성 및 자동화」** 흐름을, 현재 확정된 NEXA 기술 스택 및 지능 위계 아키텍처와 맞물리게 설계한다.

### Nexeed의 정의

> **Nexeed는 사용자의 노련한 경험(UI 행동)을 낚아채어 지능 세포(Nexel)로 배양하는 ‘자동화의 인큐베이터’다. 기록된 사실(Fact)을 논리(Logic)로 치환함으로써, 단순 반복을 시스템의 규범(GOVERN)으로 성장시킨다.**

사용자는 복잡한 코딩이나 논리 설계 없이, 평소처럼 **Nexet**을 조작하는 것만으로 자신만의 **지능형 자동화 생태계**를 구축할 수 있다. 본 SPEC은 단순 매크로 녹화가 아니라, 숙련 경험이 **운영 규범(GOVERN)** 으로 진화하는 **지능 진화론**에 초점을 둔다.

## 차별점: Nexeed가 ‘녹화기’를 넘어서야 할 것

Nexeed는 다음 지능형 기능을 **일관된 제품 요구**로 둔다. (파이프라인 단계와도 대응한다.)

### 의도 중력(Intent Gravity)

녹화 중 사용자가 **특정 입력값에 오래 머무르거나 같은 구간을 반복 수정**한 흔적을 포착해, 해당 **Nexel**에 높은 **긴박도(Urgency)** 또는 **중요도** 가중치를 자동 부여한다. **Dwell Time**·반복 횟수 등을 측정해, “여기서 사용자가 머뭇거렸다”는 신호를 논리 단위에 녹인다.

### 가상 시뮬레이션(Dry-run)

녹화된 로직을 실제 실행(또는 실제 장치 적용) 전에 **`is_virtual = true`** 상태에서 가상으로 돌려본다. **가스 밸브 잠금과 창문 열기** 같은 **규칙 충돌(Rule Conflict)** 을 미리 알려 검증 가능하게 한다.

### 비언어적 피드백(Jitter)

재구성된 논리 사슬의 신뢰도(**`confidence_score`**)가 낮을 때(예: 95점 미만), **NIXIE(닉시)** 가 미세한 **Jitter** 로 “검토가 필요함”을 비언어적으로 알린다.

### 지능적 유래 추적(Traceability)

자동화가 실행될 때 **NEXU 캔버스**에서 “이 자동화가 과거 어느 **Nexeed** 녹화에서 유래했는지”를 **역방향으로 추적**해 확인할 수 있어야 한다.

## 1. Nexeed 지능형 서사 파이프라인: 「씨앗에서 숲으로」

**Nexet(시각적 창)** 에서의 동작은 Nexeed 내부에서 아래 단계를 거친다.

### ① 씨앗 채집(Contextual Recording)

| 측면         | 내용                                                                                             |
| ------------ | ------------------------------------------------------------------------------------------------ |
| **작업**     | `UI_EVENT`(클릭, 입력 변경, 드래그 앤 드롭 등), `SENSOR_FACT`(영상·음성 등) 수집                 |
| **기술**     | 좌표만이 아니라 해당 Nexet과 결합된 **Capability ID**·**5W1H 사실(Fact)** 로 낚아챔              |
| **데이터화** | `input_channel = UI_EVENT`, `who_pulse = WILL` 등으로 기록, **영문 IR(중간 표현)** 으로 1차 요약 |

### ② 세포 분화(Nexel Atomic Conversion)

| 측면     | 내용                                                                                                                       |
| -------- | -------------------------------------------------------------------------------------------------------------------------- |
| **작업** | 녹화 종료 시 연속 행동 덩어리를 최소 단위 **Nexel(세포)** 로 분해                                                          |
| **기술** | **역방향 분해(Reverse Decomposition)** — 예: 「온도 슬라이더 + 저장」→ `[Logic Nexel: 값 비교] + [Action Nexel: API 호출]` |
| **결과** | 각 동작은 독립 실행 자격을 갖춘 **식별·메타데이터(Identity 계층과 연계 가능)** 를 갖고 시스템 세포로 박제                  |

### ③ 악보 직조(UCL Orchestration)

| 측면     | 내용                                                                                         |
| -------- | -------------------------------------------------------------------------------------------- |
| **작업** | 분화된 Nexel을 **Nexion(사고의 칠판)** 위에서 **실행 사슬(Execution Chain)** 로 연결         |
| **기술** | 점선(ECHO·제안)을 실선(WILL·확정)으로 바꾸며 논리를 완성하는 과정 자체가 **UCL 악보**가 된다 |

### ④ 규범 승격(Promotion to GOVERN / ERA)

| 측면     | 내용                                                                                           |
| -------- | ---------------------------------------------------------------------------------------------- |
| **작업** | 저장된 자동화가 반복적으로 성공하고 사용자 승인을 얻으면 **운영 규범** 으로 격상               |
| **진화** | 최종적으로 **ERA** 단계로 진화해, 사용자 개입 없이도 판단·실행이 가능한 **지능적 습관**이 된다 |

## 3. 시각적 교감(NIXIE · Jitter) 연동

Nexeed가 자동화 로직을 만들 때 **NIXIE(닉시)** 는 예를 들어 다음과 같이 비언어 피드백을 준다.

- **녹화 중:** 도트가 **호박색(Amber)** 으로 부드럽게 맥동(Pulse)하며 **경청 중** 을 암시
- **변환 불확실:** Nexel 변환 과정에서 **`confidence_score`** 가 낮으면 **Jitter** 로 보정 요청
- **자동화 실행:** 배양된 씨앗이 돌 때 **Lumina(발광)** 과 함께 캔버스 위에 해당 사슬 유래를 실선 하이라이트

## 4. 멀티모달 센티널과 Nexeed 확장

**Nexeed** 의 「씨앗 채집」에 카메라 등 외부 센서를 붙이는 것은 **기술적으로 가능**할 뿐 아니라, **센티널(Sentinel) 아키텍처** 를 완성하는 핵심 방향이다. 마우스·키보드가 **디지털 공간의 의지** 를 채집한다면, 카메라는 **물리 공간의 맥락** 을 채집해 생활 패턴 학습으로 이어질 수 있다.

### 4.1 기술적 적용 가능성: 멀티모달 센티널

NEXA는 **마이크로 센티널(Micro Sentinel)** 을 통해 영상·음성 처리 구조를 갖출 수 있다.

- **비식별화·패턴 추출:** 원시 영상을 서버로 그대로 보내기보다 엣지(라즈베리 파이 등)에서 **YOLOv10**·**VideoLLaMA** 등으로 「누가(Who) 어디서(Where) 무엇을(What)」 같은 **5W1H 사실(Fact)** 으로 변환
- **패턴의 아톰화:** 물리 행동 패턴에 `input_channel = VIDEO` 등 태그를 달고 Nexeed로 유입, 기존 UI 이벤트와 동일한 **영문 IR** 로 정규화

### 4.2 센서 기반 패턴 습득 흐름(확장안)

1. **관측(Observation):** 반복 물리 행동(예: 매일 저녁 커튼·독서등 패턴) 관측
2. **사실 채집(TICK):** 사용자가 버튼을 누르지 않아도 센티널이 **TICK** 펄스로 인식해 Nexeed 임시 저장소에 씨앗 적재
3. **의도 추론·제안(ECHO):** 반복 패턴의 **`confidence_score`** 가 높으면 NIXIE가 발광하며 「자동화 Nexel로 변환할까요?」 같은 **ASK** 카드 제시
4. **세포화:** 사용자 **WILL** 승인 시 물리 패턴이 장치 제어 **Nexel** 로 전환되어 실행 사슬에 등록

### 4.3 기대 효과

- **Zero-UI 자동화:** 매크로를 일부러 녹화하지 않아도 생활만으로 **지능의 씨앗** 을 시스템이 발견
- **물리·디지털 통합 족보:** NEXU 캔버스에서 「며칠 전 거실 카메라 포착 행동에서 유래」 같은 **Traceability** 를 시각 증명
- **보안:** 영상 분석은 로컬 엣지 위주, 전송은 **비식별화된 텍스트 사실** 위주로 개인정보 노출 리스크 완화

## 5. `SENSOR_FACT`의 확장

**Nexeed(넥시드)**의 「씨앗 채집」에서 **`SENSOR_FACT`** 범위를 넓힌다는 것은, 시청각 데이터만이 아니라 사용자·환경의 **총체적 맥락**을 지능 자산으로 옮기는 일을 뜻한다.
**센티널(Sentinel)** 아키텍처와 **지능 위계** 위에서, `SENSOR_FACT`에 얹을 수 있는 데이터 범위를 아래 **네 계층**으로 나눈다.

### 5.1 생체·정서 계층 (Empathy & Vitality Facts)

사용자의 신체 상태와 정서 리듬을 감지해, 시스템 반응 속도·인지 부하를 조절하는 근거가 되는 씨앗이다.

- **활력 지수(VI, Vitality Index):** 피로·몰입도를 분석한다. VI가 낮을 때의 조작 패턴은 **Low-Entropy(인지 에너지 절약)** 모드 전환 근거가 된다.
- **공감 지수(ES, Empathy Score):** 정서적 만족·불만 신호를 포착한다.
- **공감 편차(Empathy Gap):** 말로 드러난 의도(INTENT)와 실제 정서(VI/ES) 사이 괴리를 사실로 남긴다.

### 5.2 행동 역학 계층 (Behavioral Dynamics Facts)

조작 뒤에 깔린 **의지의 무게**를 수치화하는 씨앗이다.

- **의도 중력(Intent Gravity):** 특정 **Nexet**에 머무는 시간(Dwell Time), 클릭 빈도, 망설임 패턴을 포착한다. 해당 노드의 중요도·긴박도 자동 설정의 근거가 된다.
- **진화 델타(Evolutionary Delta):** 과거에 성공한 자동화 패턴과 지금의 새 행동 차이를 계산해, 시스템 진화 방향을 정하는 씨앗이 된다.
- **휴리스틱 지름길(Heuristic Shortcuts):** 긴 논리 없이 반복되는 **직관적 판단** 패턴을 사실로 모은다.

### 5.3 물리·논리 위상 계층 (Topological Facts)

물리 공간과 논리 기능을 묶어 **환경적 맥락**을 완성하는 씨앗이다.

- **공간 위상(Knowledge Topology):** 장치의 물리 위치(GPS)와 논리 기능(**Capability ID**) 관계망 변화를 감지한다. 예: 「안방 조명」이 「독서 모드」라는 논리 위치로 옮겨지는 위상차를 기록한다.
- **준거 지수(Compliance Index):** 물리 사실(SNT)이 **ERA** 등 절대 원칙에 얼마나 맞는지 수치화한다. 안전 한계를 벗어나는 징후는 **Safety Reflex(인터럽트)** 발동의 씨앗이 된다.

### 5.4 시스템·인프라 헬스 계층 (Health & Infrastructure Facts)

시스템이 느끼는 **압박**과 **신뢰도**를 서사로 바꿀 수 있게 하는 씨앗이다.

- **신뢰도 지터(Confidence Jitter):** 정합성·근거 불확실 시 생기는 미세 노이즈를 시스템이 사실로 기록한다.
- **큐 압박(Queue Pressure):** 승인·실행 큐 적체를 **시스템의 숨가쁨**으로 인지해, 쓰로틀링(Throttling) 정책 근거로 쓴다.
- **블랙스완 징후(Anomaly Pattern):** 과거에 없던 이상·예외를 잡아 잠재 위험 씨앗으로 분류한다.

### 5.5 요약

`SENSOR_FACT`를 이와 같이 넓히면 **Nexeed**는 「불을 켰다」 수준을 넘어, **「피곤한 상태(VI)에서 평소보다 강한 의지(Gravity)로 보안(Compliance)을 당기려 한다」** 같은 **다차원 서사**를 씨앗으로 채집할 수 있다.

이 데이터는 **마이크로 센티널** 단에서 **비식별 요약**된 뒤 **영문 IR**로 넘어가, 서버 부하를 키우지 않으면서도 지능 밀도를 높이는 데 쓰인다.

## 6. Nexeed 보안 가드레일

Nexeed 도메인의 지능 자산 채집 및 자동화 배양 과정에서 발생할 수 있는 프라이버시 침해와 물리적 안전 사고를 방지하기 위해 다음의 **보안 가드레일(Security Guardrail)** 규약을 정의한다. 모든 구현체는 아래 기술된 단언적 원칙을 준수해야 한다.

#### **1. 데이터 주권 및 엣지 로컬 비식별화**

- **원시 데이터 유출 금지:** 카메라 및 오디오 센서로부터 수집된 모든 날것의 데이터(Raw Data)는 엣지(Micro Sentinel) 단을 절대 벗어나지 않는다.
- **비식별 사실 추출:** 센티널은 로컬에서 즉시 비식별화를 수행하여 '사용자 이름' 대신 'Who: Worker', '얼굴' 대신 'What: Tool/Action'과 같은 **5W1H 사실(Fact)**로만 변환하여 전송한다.
- **파일 즉시 파기:** 분석에 사용된 원본 멀티모달 파일은 영문 IR 요약본 생성 즉시 로컬 메모리에서 파기하거나, 인가된 별도 보안 저장소 외의 플랫폼 유입을 원천 차단한다.

#### **2. 업무 맥락 기반의 논리적 통제**

- **공간 위상 제한(Geofencing):** `Where(Scope)` 레이어를 적용하여, 사전에 정의된 물리적 **워크스테이션(FIELD)** 좌표 범위를 벗어난 구역에서의 패턴 채집을 금지한다.
- **도메인 종속 활성화:** 센서 기반의 `TICK` 펄스는 특정 업무용 **Nexet(넥셋)**이 활성화되어 있거나, `project_id`의 성격이 '업무/기획' 도메인일 때만 제한적으로 작동한다.

#### **3. 명시적 의지(WILL) 및 승인 게이트**

- **기록 주도권:** 시스템에 의한 상시 감시를 불허한다. 모든 패턴 습득은 사용자가 Nexeed 인터페이스에서 직접 기록 버튼을 누르는 **WILL(의지)** 펄스 발생 시에만 시작된다.
- **최종 승인(ASK) 의무:** AI가 제안한 자동화 Nexel 사슬은 즉시 실행되지 않는다. 반드시 사용자에게 **ASK(승인 대기)** 카드를 제시하고, 사용자의 명시적 승인을 얻어야만 시스템 규범(GOVERN)으로 등록된다.

#### **4. 실행 샌드박스 및 가상 검증**

- **격리 실행:** 센서 데이터 분석 및 사용자 스크립트 실행은 메인 시스템과 격리된 **V8 Isolate 기반 샌드박스** 내에서만 수행한다.
- **의미론적 잠금(Meaning Lock):** 배양된 자동화 사슬을 실물 장치에 투입하기 전, `is_virtual = true` 상태의 **가상 시뮬레이션**을 필수로 거쳐야 하며, 이를 통해 물리적 충돌 및 안전 수칙 위반 여부를 사전 검증한다.

#### **5. 긴급 인터럽트 및 안전 반사(Safety Reflex)**

- **Level 0 즉시 차단:** 센서 분석 결과가 시스템 생존과 직결된 **안전 규범(Level 0)**을 위반할 경우, 의사결정 매트릭스를 거치지 않고 **Safety Reflex(로컬 선조치)**를 즉각 발동하여 실행권을 차단한다.
- **Safety VOID 강제:** 위험 상황 감지 시 진행 중인 모든 자동화 사슬을 무효화하고 안전 기본값(Safe Default)으로 강제 복귀(Rollback) 시킨다.

### **[정리] 업무 중심 Nexeed 센서 제한 규약**

| 구분            | 제한 내용                                           | 기대 효과                                   |
| :-------------- | :-------------------------------------------------- | :------------------------------------------ |
| **데이터 형태** | 영상 유기 및 **영문 5W1H 텍스트**로만 전송          | 개인정보 유출 리스크 원천 차단              |
| **활성 조건**   | 특정 **Capability ID** 호출 시에만 작동             | 사생활 구역에서의 불필요한 감시 방지        |
| **결정 권한**   | AI의 제안(ECHO) 후 사용자의 **WILL(승인)** 필수     | 의도하지 않은 자동화 방지 및 주도권 확보    |
| **분석 초점**   | 인간의 특징이 아닌 **업무 도구와 환경 변화**에 집중 | '감시'가 아닌 '생산성 보조'로의 정체성 확립 |

이와 같이 **「기술은 배경으로 숨기고(비식별), 지능은 업무 지원에만 유연하게(맥락 제한)」** 하는 방향으로 Nexeed의 `SENSOR_FACT` 범위를 고정하면, 보안 우려를 줄이면서도 지능형 업무 환경을 구축할 수 있다.
이 가드레일은 물리적·논리적으로 보장하는 최종 방어선으로 작동한다.
