## 🛠️ 1. 최종 결정 기술 스택 (React 중심 풀스택)

AI 에이전트(안티그래비티, 클로드 등)가 전 세계에서 가장 버그 없이 정교하게 코드를 짜내는 글로벌 표준 TypeScript 생태계로 확정했습니다.

- 프론트엔드: Next.js (App Router, TypeScript)
- 이유: 강력한 SEO, 뛰어난 로딩 속도, AI 생성 툴(v0.dev 등)과의 압도적인 궁합.
- 스타일링: Tailwind CSS + Shadcn UI
- 이유: 기존 무거운 퀘이사(Quasar)를 패기하고, AI가 원자 단위로 코드를 읽고 조작하기 가장 쉬운 Utility-first 스타일 채택. 화면 최적화 극대화.
- 실시간 동기화: Yjs + Hocuspocus (Node.js 기반)
- 이유: 충돌 없는 실시간 문서 편집 및 데이터 중계를 위한 완벽한 인프라 셋업 제공.
- 메인 백엔드: NestJS (TypeScript)
- 이유: 기존 Express를 패기하고 대규모 아키텍처와 객체지향적 안정성 확보. 프론트엔드(Next.js)와 완벽한 데이터 타입(DTO) 공유 가능.

## 🔄 2. Yjs 와 React 스토어(Zustand 등)의 역할 분리

둘은 대립 관계가 아니라, 데이터 완충(Yjs)과 화면 송출(스토어)로 철저히 협력합니다.

- Yjs (네트워크 동기화 엔진):
- 브라우저 화면(UI)은 신경 쓰지 않고 오직 메모리 위의 데이터(Y.Doc)만 관리.
  - Tiptap 에디터의 실시간 동시 편집, 사용자 커서 위치 공유(Awareness), 동시 수정 시 충돌 방지(CRDT) 전담.
- React 스토어 (브라우저 화면 제어 엔진):
- Yjs 데이터가 변경되었다는 이벤트가 오면, 최종 정제된 데이터만 가로채서 화면의 특정 컴포넌트(차트, 위젯 등)만 콕 집어서 선택적 재렌더링(Re-render) 유발.
  - 네트워크 동기화가 필요 없는 로컬 UI 상태(다크모드 여부, 사이드바 개폐 등) 관리.
  - 초당 수백 개씩 밀려오는 IoT 실시간 데이터 소켓이 화면을 얼려버리지 않도록 방어하는 버퍼(Buffer) 역할.

## 🛡️ 3. 하이브리드 망 분리 및 제어 명령 등급 보안 전략

금융권 수준의 물리적 안전성을 확보하면서도, 웹 기반 관제 편의성을 놓치지 않기 위해 명령의 위험도에 따라 망과 인증 단계를 분리합니다.

- 🟢 1등급 (일반 설정/조회) ➡️ 외부 인터넷망 자유 허용
- 대상: 대시보드 레이아웃 편집, 단순 텍스트/태그 수정, 데이터 모니터링.
  - 보안: 일반 웹 로그인 세션 + Hocuspocus의 ReadOnly 스코프 분리로 불법 변조 원천 차단.
- 🟡 2등급 (소프트 제어) ➡️ 외부 인터넷망 + 2차 인증(MFA)
- 대상: 소프트웨어 원격 재부팅, 알림 임계치 수정, 비위험 보조 장비 가동.
  - 보안: 명령 수행 시 OTP/생체 인증 강제, NestJS 메인 서버에 위변조 불가능한 감사 로그(Audit Log) 즉시 기록.
- 🔴 3등급 (하드 제어) ➡️ 내부 현장 폐쇄망 전용 (인터넷 원천 차단)
- 대상: 공장 메인 전원 차단, 물리 모터/밸브 조작, 하드웨어 펌웨어 업데이트.
  - 보안: 외부망(Yjs)을 통한 다이렉트 명령 전달 통로를 물리적으로 없앰. 오직 현장 내부 네트워크 및 VPN 환경의 서버(Edge)를 통해서만 실제 디바이스 제어 명령(MQTT 등) 전송.

## 2. 핵심 아키텍처 및 역할 분리 지침

### [프론트엔드: Yjs와 Zustand의 역할 분리]

- **Yjs**: Tiptap 에디터 및 대시보드 커스텀 컴포넌트의 실시간 동시 편집 데이터(`Y.Doc`) 동기화 및 사용자 커서 상태(`Awareness`) 제어에만 집중합니다.
- **Zustand**: Yjs의 데이터 변경 이벤트(`ydoc.observe`)를 구독하여 최종 정제된 값만 가로챈 뒤, 화면의 특정 컴포넌트만 선택적 재렌더링(Selective Re-render)을 유발하는 구조로 설계하세요. 초당 수백 개의 데이터가 몰려도 화면이 얼지 않도록 버퍼 역할을 해야 합니다. 네트워크와 무관한 로컬 UI 상태도 여기서 관리합니다.

### [백엔드 & 보안: 3단계 제어 명령 등급 대응]

코드 베이스 내에 다음 3가지 등급의 제어 파이프라인 구조를 고려해 방어벽을 세우세요.

1. **🟢 1등급 (일반 설정/조회)**: Tiptap 문서 편집, 레이아웃 변경. Hocuspocus의 `onAuthenticate`에서 JWT 토큰 스코프를 검증하여 권한이 없는 유저는 강제로 `ReadOnly` 커넥션으로 고정하는 보안 훅을 구현하세요.2. **🟡 2등급 (소프트 제어)**: 장비 원격 재부팅, 알림 조건 수정 등. 외부망에서 실행되나, 명령을 내릴 때 2차 인증(MFA 프레임워크 자리)을 거쳐야 하며, NestJS 메인 서버에 감사 로그(Audit Log)를 강제로 남기는 인터셉터/미들웨어 뼈대를 만드세요.3. **🔴 3등급 (하드 제어)**: 메인 전원 차단, 물리 밸브 제어 등. 외부 인터넷망(Yjs/웹소켓)을 통한 직접 명령 하달이 구조적으로 불가능하도록 차단하고, 내부 폐쇄망 장비(Edge)가 안전한 명령 큐(Queue)에서 '가져오는(Pull)' 방식의 API 엔드포인트 뼈대만 NestJS에 마련하세요.
   ---## 3. 요청하는 결과물 구조AI 에이전트는 다음 사항을 순차적으로 수행하거나 올바른 파일들을 생성해야 합니다.

1. **전체 모노레포(또는 멀티 프로젝트) 폴더 구조 제안** (`/apps/frontend`, `/apps/backend` 등 구조적 시너지를 낼 수 있는 형태)
1. **Hocuspocus 서버 초기화 소스 코드** (`onAuthenticate` 보안 검증 및 XSS 차단을 위한 `onStoreDocument` 훅의 뼈대 포함)
1. **프론트엔드 Zustand 스토어와 Yjs Provider가 결합되는 예시 컴포넌트 코드** (`useDeviceStore.ts` 및 실시간 이벤트를 바인딩하는 컨텍스트/이펙트 구조)4. **NestJS 메인 서버에서 1/2/3등급 명령을 분기 처리하기 위한 Guard/Interceptor 구조 설계**

TypeScript 타입 안전성(Type-safety)을 극대화할 수 있도록 앞뒤 프로젝트의 인터페이스 공유 레이아웃을 신경 써서 작성해 주세요. 준비가 되었다면 구현 계획(Implementation Plan)을 먼저 보여준 뒤 코딩을 시작해 주세요.
