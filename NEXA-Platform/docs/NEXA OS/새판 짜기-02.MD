## 질문자님께서 퀘이사(Quasar)의 무거운 오버라이드 지옥에서 벗어나, 내 주도권 하에 완벽하게 통제되는 가볍고 직관적인 IoT 플랫폼을 만들기 위한 최종 기술 스택과 각 기술의 핵심 활용 전략을 정리해 드립니다.

## 🛠️ 최종 기술 스택 (Tech Stack)

- Frontend Framework: Vue 3 (Vite 기반, Composition API / Setup Script)
- CSS Architecture: Tailwind CSS v4 + Scoped CSS (@apply 방식)
- Backend Framework: NestJS (TypeScript 기반 정밀 아키텍처)

---

## 📐 기술 스택별 핵심 활용 전략## 1. Vue 3 : 원자 단위의 철저한 컴포넌트화

IoT 대시보드의 일관성을 지키기 위해 스타일을 HTML에 직접 적지 않고, 독립적인 커스텀 컴포넌트 내부로 격리시킵니다.

- 원천 분리 (Single Source of Truth): BaseButton.vue, SensorCard.vue, ToggleSwitch.vue 같은 공통 제어 컴포넌트를 바닥부터 직접 빌드합니다.
- 데이터 주도형 상태 제어: 장비 상태(정상/경고/에러/오프라인)를 Vue의 props로 받아 내부에서 스타일을 유연하게 스위칭합니다.
- 동적 리사이징 제어: CSS 반응형만으로 해결 안 되는 실시간 차트나 SVG 도면 영역은 Vue 3의 ResizeObserver나 computed를 활용해 자바스크립트 레벨에서 실시간 픽셀 계산을 병행합니다.

## 2. Tailwind CSS : 캡슐화된 반응형 및 테마 엔진

HTML 코드를 더럽히지 않고, Vue의 <style scoped> 내부에서 @apply 문법을 사용하여 오직 도구로서만 소비합니다.

- 반응형의 마이크로 컨트롤: 복잡한 미디어 쿼리(@media) 연발 대신 @apply block md:flex lg:grid 스타일의 한 줄 호흡으로 다양한 디스플레이(현장 패블릿, 모바일, 모니터)에 대응합니다.
- 컨테이너 쿼리 적극 도입: 사이드바 메뉴가 열려 메인 대시보드 영역이 찌그러질 때 브라우저 창 크기가 아닌 '부모 박스 너비'에 반응하도록 @container 및 @md: 접두사 규칙을 표준화합니다.
- 테마 파일 분리 구조: main.css 하나에 모든 테마를 밀어 넣지 않고 themes/light.css, themes/dark.css 등으로 파일을 완전히 쪼갠 뒤 메인에서 @import 조합하여 유지보수성을 극대화합니다.

## 3. NestJS : 견고하고 신뢰성 있는 IoT 데이터 백엔드

실시간으로 쏟아지는 센서 데이터와 장비 제어 명령(RPC)을 안전하게 처리할 수 있는 구조를 잡습니다.

- 모듈형 아키텍처: 장비 관리(Devices), 데이터 로그(Telemetry), 알림(Alerts) 등을 독립된 모듈로 나누어 프론트엔드의 컴포넌트 구조와 1:1 매핑이 잘 되도록 설계합니다.
- 실시간 데이터 스트리밍: 센서 데이터의 실시간 대시보드 반영을 위해 REST API에만 의존하지 않고, NestJS의 WebSocket 게이트웨이 또는 SSE(Server-Sent Events) 모듈을 적극 활용하여 Vue 3와 양방향 통신을 연결합니다.
- DTO 및 유효성 검사: 하드웨어 장비나 프론트엔드 제어 요청 시 들어오는 날것의 데이터를 class-validator를 통해 철저히 검증하여 플랫폼의 안정성을 확보합니다.

## 📁 추천 프로젝트 구조 (Directory Blueprint)

자체 컴포넌트 제작과 테마/반응형 분리를 위해 프론트엔드는 아래와 같은 구조로 시작하시는 것을 추천합니다.

src/
├── assets/
│ ├── css/
│ │ ├── themes/
│ │ │ ├── light.css # 라이트 테마 변수 정의
│ │ │ └── dark.css # 다크 테마 변수 정의
│ │ └── components/
│ │ └── global.css # 전역 공통 리셋 및 베이스 스타일
│ └── main.css # 테일윈드 로드 및 위 CSS 파일들 @import 통합
├── components/
│ ├── common/
│ │ ├── BaseButton.vue # 테일윈드 @apply가 격리된 공통 버튼
│ │ └── ToggleSwitch.vue # 터치 타겟이 최적화된 IoT 스위치
│ └── dashboard/
│ ├── SensorCard.vue # 컨테이너 쿼리가 내장된 실시간 센서 카드
│ └── RealtimeChart.vue # ResizeObserver와 CSS 비율이 결합된 차트
└── views/
└── DashboardView.vue # 깨끗한 HTML로 조립된 최종 대시보드 화면

이 구조는 질문자님께서 모든 코드의 동작 원리를 100% 통제할 수 있으면서도, 개발 속도와 화면 안정성을 동시에 챙길 수 있는 가장 이상적인 IoT 대시보드 아키텍처입니다.
