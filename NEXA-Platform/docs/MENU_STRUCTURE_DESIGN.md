# 상단 메뉴 트리 구조

**작성일**: 2024년  
**목적**: NEXA Platform의 상단 메뉴 트리 구조 정의

---

## 개념 정리

### 핵심 시스템

- **NEXA BOARD**: IoT 디바이스 관리 및 대시보드 (핵심)
- **EQUIPMENT**: 제작 장비 등록 및 관리
- **SYSTEM**: 디바이스 등록 및 시스템 상태 모니터링, AGW System 관리
- **네트워크**: 네트워크 구성 및 관리

### ERP 시스템 (부가 기능)

**유연한 관계형 구조:**

- **프로젝트**: 중심 엔티티로 등록 및 관리
- **업무 프로세스, 업무 일정, 업무 요구사항, 참고자료 등**: 독립적으로 등록 가능하며, 필요시 프로젝트와 선택적 연결
  - 각 항목은 프로젝트와 관계를 가질 수도, 가지지 않을 수도 있음
  - 독립 항목으로 관리하거나 특정 프로젝트에 속하도록 연결 가능
  - 프로젝트 패널을 통해 NEXA BOARD에 통합
  - 특정 장비 개발 프로젝트의 경우 부품관리 DB 활용
- **부품관리**: 부품 재고 관리 및 입출고
  - 프로젝트에서 활용 (특정 장비 개발 프로젝트 등)

**확장 가능성:**

- ERP 아래에는 현재 명시된 항목 외에도 다양한 항목들이 추가될 수 있음
- 각 항목은 독립적으로 등록 가능하며, 필요시 프로젝트와 연결 가능한 구조

### 확장 시스템 (Extended NEXA Systems)

- **SOLUTIONS**: NEXA Platform 기반 확장 솔루션
  - Industrial Systems (산업 시스템)
  - Living Solutions (생활 솔루션)
  - Media & Interaction (미디어/인터랙션)
  - Media Art (미디어 아트)

## 메뉴 구조 복잡도 분석 및 개선 방안

### 현재 상황

**최상위 메뉴 개수:** 12개

- MY, HOME, NEXA BOARD, NEXA PANNEL, AUTOMATION, EQUIPMENT, ERP, SYSTEM, NETWORK, SOLUTIONS, SETTINGS, HELP

**문제점:**

1. 메뉴가 너무 많아서 초기 접근 시 혼란스러움
2. 용어가 아직 확정되지 않음
3. 앞으로 더 추가될 가능성이 많음
4. 일부 메뉴는 관리자만 보여야 함
5. 일반 사용자와 관리자의 사용 패턴이 다를 수 있음

### 개선 방안 제안

#### 방안 1: 권한별 메뉴 표시 (권장)

**일반 사용자에게 표시:**

- MY | HOME | NEXA BOARD | AUTOMATION | HELP (5개)

**관리자에게 추가 표시:**

- NEXA PANNEL | EQUIPMENT | ERP | SYSTEM | NETWORK | SOLUTIONS | SETTINGS (7개 추가)

**장점:**

- 일반 사용자는 핵심 기능만 보여서 혼란 감소
- 관리자는 모든 기능 접근 가능
- 확장 시에도 일반 사용자 경험에 영향 최소화

#### 방안 2: 그룹화 및 접근 빈도 기반 구조

**1차 메뉴 (자주 사용하는 핵심 기능):**

- MY | HOME | NEXA BOARD | AUTOMATION

**2차 메뉴 (설정 및 관리 - 드롭다운 또는 하위 메뉴):**

- SYSTEM (디바이스 등록, 시스템 상태 포함)
- ADMIN (SYSTEM, NETWORK, NEXA PANNEL 통합 - 관리자만)
- TOOLS (ERP, EQUIPMENT 통합)
- SOLUTIONS (확장 기능)

**3차 메뉴 (보조 기능):**

- SETTINGS | HELP

#### 방안 3: 단계적 확장 구조

**현재 단계 (초기):**

- MY | HOME | NEXA BOARD | SYSTEM | SETTINGS | HELP (6개)

**확장 시 추가:**

- AUTOMATION, NEXA PANNEL, EQUIPMENT, ERP 등은 필요할 때 추가

**장점:**

- 점진적 복잡도 증가
- 사용자가 익숙해질 시간 제공

### 권장 접근

**1단계: 권한별 필터링 구현**

- 사용자 역할(일반/관리자)에 따라 메뉴 표시/숨김

**2단계: 용어 확정 및 통일**

- 각 메뉴의 명확한 역할 정의
- 일관된 네이밍 컨벤션 적용

**3단계: 그룹화 검토**

- 기능적으로 연관된 메뉴들을 논리적으로 그룹화
- 사용 빈도에 따른 우선순위 조정

**4단계: 확장성 고려**

- 새로운 메뉴 추가 시 기존 구조에 미치는 영향 최소화
- 관리자 전용 vs 일반 사용자용 명확히 구분

## UI 구조 - 사이드바 제어

### 사이드바 구성

- **왼쪽 사이드바**: 메뉴 트리 구조 표시
- **오른쪽 사이드바**: 컨텍스트 정보 및 상세 설정
- **상단 헤더**: 메인 메뉴 탭 및 제어 아이콘

### 상단 헤더 제어 아이콘

**필수 제어 아이콘:**

1. **설정 아이콘**

   - 시스템 설정 메뉴로 이동
   - SETTINGS 메뉴 접근

2. **왼쪽 사이드바 토글 아이콘**

   - 왼쪽 사이드바 열기/닫기
   - 메뉴 트리 구조 표시/숨김

3. **오른쪽 사이드바 토글 아이콘**
   - 오른쪽 사이드바 열기/닫기
   - 컨텍스트 정보 및 상세 설정 표시/숨김

**배치 위치:**

- 상단 헤더의 오른쪽 영역에 배치
- 아이콘들은 가로로 나란히 배치

**상태 표시:**

- 사이드바가 열려있을 때와 닫혀있을 때 아이콘 상태를 다르게 표시
- 활성화된 상태와 비활성화된 상태를 시각적으로 구분

## 연동 관계

### MY 메뉴 기능 설명

**MY 메뉴의 목적:**

- 사용자 계정 관리 및 로그인/로그아웃
- 사용자가 등록한 기기 정보 조회 및 관리

**주요 기능:**

1. **로그인/로그아웃**

   - 사용자 인증 및 세션 관리

2. **내 정보**

   - 사용자 프로필 관리
   - 계정 설정

3. **내 등록 기기**
   - 등록한 디바이스 목록 조회
   - 등록한 제작 장비 목록 조회
   - 내 기기 설정 관리

### MY ↔ SYSTEM / EQUIPMENT

- MY에서 사용자가 등록한 기기 정보를 조회
- SYSTEM 또는 EQUIPMENT에서 등록한 기기들의 개인 뷰 제공

### NEXA PANNEL ↔ NEXA BOARD

- 패널 카탈로그에 등록된 패널을 NEXA BOARD에서 선택하여 사용
- 보드에 패널 추가 시 패널 카탈로그에서 선택

### SYSTEM ↔ NEXA BOARD

- SYSTEM: 디바이스 등록 → NEXA BOARD: 디바이스 적용
  - SYSTEM에서 디바이스를 등록 (시스템에 디바이스 추가)
  - NEXA BOARD에서 등록된 디바이스를 보드에 적용 (보드-디바이스 연결)

### ERP 내부 항목 간 관계

**핵심 개념: 유연한 관계형 구조**

- **프로젝트**: 중심 엔티티로 등록 가능
- **업무 프로세스, 업무 일정, 업무 요구사항, 참고자료 등**: 독립적으로 등록 가능하지만 프로젝트와 선택적 연결(relation) 가능
  - 각 항목을 등록할 때 특정 프로젝트와 연결할지 선택 가능
  - 연결하지 않으면 독립적인 항목으로 관리
  - 연결하면 해당 프로젝트에 속한 항목으로 관리

**확장 가능성:**

- ERP 아래에는 현재 명시된 항목 외에도 다양한 항목들이 추가될 수 있음
- 각 항목은 독립적으로 등록 가능하며, 필요시 프로젝트와 연결 가능한 구조

### ERP 내부 항목 간 관계

**핵심 개념: 유연한 관계형 구조**

- **프로젝트**: 중심 엔티티로 등록 가능
- **업무 프로세스, 업무 일정, 업무 요구사항, 참고자료 등**: 독립적으로 등록 가능하지만 프로젝트와 선택적 연결(relation) 가능
  - 각 항목을 등록할 때 특정 프로젝트와 연결할지 선택 가능
  - 연결하지 않으면 독립적인 항목으로 관리
  - 연결하면 해당 프로젝트에 속한 항목으로 관리
  - 예: 업무 프로세스 등록 시 → 프로젝트 선택 (선택사항)
  - 예: 업무 일정 등록 시 → 프로젝트 선택 (선택사항)

**확장 가능성:**

- ERP 아래에는 현재 명시된 항목(프로젝트, 업무 프로세스, 업무 일정, 업무 요구사항, 참고자료, 부품관리) 외에도 다양한 항목들이 추가될 수 있음
- 각 항목은 독립적으로 등록 가능하며, 필요시 프로젝트와 연결 가능한 구조

### 프로젝트 ↔ 부품관리

- 특정 장비 개발 프로젝트의 경우 부품관리 DB 활용
- 프로젝트 내에서 필요한 부품 연결/관리

### 프로젝트 ↔ NEXA PANNEL

- 프로젝트 문서를 **프로젝트 패널**로 패널 카탈로그에 등록
- 패널 카탈로그를 통해 NEXA BOARD에 통합

### AUTOMATION ↔ NEXA BOARD

- 여러 기기와 패널을 연동한 자동화 규칙 생성
- 시간 기반 또는 이벤트 기반 시퀀스 실행

### AUTOMATION ↔ SYSTEM

- 디바이스 간 연결 및 조건 설정
- 트리거 조건에 따른 디바이스 제어

### EQUIPMENT 기능 설명

**EQUIPMENT 메뉴의 목적:**

- 제작된 장비를 등록하고 관리
- 사용자들이 제작 장비 목록을 조회하고 상태를 확인할 수 있도록 함

**주요 기능:**

1. **제작 장비 등록**

   - 제작 장비 정보 등록
   - 제작 장비 사양 및 설정 정보 입력

2. **제작 장비 목록**

   - 등록된 제작 장비 목록 조회
   - 제작 장비 검색 및 필터링

3. **제작 장비 상태**

   - 제작 장비 실시간 상태 확인
   - 제작 장비 동작 현황 모니터링

4. **제작 장비 관리**
   - 제작 장비 정보 수정 및 삭제
   - 제작 장비 설정 관리

**용어 구분:**

- **제작 장비 (EQUIPMENT)**: 맞춤 제작된 장비/설비 (소규모 프로젝트용)
- **디바이스 (DEVICES)**: IoT 디바이스, 사용자가 시스템에 등록하는 개인 기기

### EQUIPMENT ↔ NEXA BOARD

- 등록된 제작 장비 정보를 NEXA BOARD에서 패널로 표시 가능
- 제작 장비 상태 모니터링 패널 통합

### NETWORK 기능 설명

**NETWORK 메뉴의 목적:**

- 플랫폼과 디바이스 간의 네트워크 인프라 관리
- 통신 프로토콜 설정 및 모니터링
- 네트워크 상태 추적 및 문제 진단

**주요 기능:**

1. **WiFi 네트워크 관리**

   - 라우터 설정 (SSID, 비밀번호, 채널 등)
   - 디바이스별 WiFi 연결 상태 확인
   - 네트워크 토폴로지 시각화 (어떤 디바이스가 어떤 라우터에 연결되어 있는지)
   - 연결 품질 분석 (신호 강도, 속도 등)

2. **켄통신 관리** (근거리 네트워크)

   - BUS 구성 (켄통신 네트워크 구조 설정)
   - 노드 등록 및 관리 (켄통신에 연결된 기기들)
   - 통신 상태 모니터링 (연결 상태, 통신 오류 등)
   - 통신 로그 분석 (메시지 전송/수신 기록)

3. **Socket 연결 관리**

   - WebSocket 연결 상태 모니터링
   - 클라이언트 목록 및 연결 정보
   - 실시간 통신 로그

4. **MQTT 관리**

   - MQTT 브로커 설정 및 상태
   - 토픽 구조 관리 및 권한 설정
   - 구독/발행 현황 모니터링
   - 통신 로그 및 메시지 추적

5. **네트워크 모니터링**
   - 전체 네트워크 트래픽 분석
   - 연결 통계 (연결 수, 평균 응답 시간 등)
   - 오류 감지 및 알림
   - 성능 분석 및 최적화 제안

**SYSTEM 메뉴의 역할:**

- **SYSTEM**: 디바이스 등록, 시스템 전반의 상태 모니터링, AGW System 관리, 실시간 모니터링
- **NETWORK**: 디바이스 간 연결, 통신 프로토콜, 네트워크 인프라 관리
- **NEXA BOARD**: 디바이스 적용 (등록된 디바이스를 보드에 연결)

## SYSTEM 메뉴 기능 설명

### SYSTEM 메뉴의 목적

디바이스를 등록하고 관리하며, 전체 시스템의 상태를 한눈에 파악하고, AGW System을 관리하며, 실시간으로 시스템을 모니터링

### 주요 기능

#### 1. 디바이스 등록

- 시스템에 디바이스를 등록하는 기능
- 디바이스 기본 정보 입력 (모델 번호, API 키 발급 등)
- 등록된 디바이스 목록 조회 및 관리

#### 2. 시스템 상태

- 전체 시스템 건강도 (시스템 전반의 상태 요약)
- 디바이스 상태 모니터링 (등록된 모든 디바이스의 상태 확인)
- 네트워크 상태 요약 (네트워크 전반의 상태)
- 성능 지표 (시스템 성능 메트릭)

#### 3. AGW System

- TOWER, BACKUP, 켄통신 MARSER 등 AGW System 구성 요소 관리
- 각 시스템의 상태 및 설정 확인

#### 4. 실시간 모니터링

- 디바이스 활동 (실시간 디바이스 활동 추적)
- 통신 로그 (시스템 전반의 통신 로그)
- 오류 추적 (오류 발생 추적 및 분석)

### DEVICES → SYSTEM 변경 이유

**이전 (DEVICES):**

- 디바이스 등록/적용 기능이 포함되어 있어 혼란
- 역할이 불명확

**현재 (SYSTEM):**

- 디바이스 등록 및 시스템 전반의 모니터링 역할이 명확
- 디바이스 등록은 SYSTEM, 적용은 NEXA BOARD로 분리
- AGW System 관리와 모니터링 기능에 집중

## 디바이스 등록 vs 디바이스 적용

### 개념 구분

**디바이스 등록 (SYSTEM)**

- 시스템에 디바이스를 처음 등록하는 과정
- 디바이스 기본 정보 입력 (모델 번호, API 키 발급 등)
- `devices_iot` 테이블에 디바이스 정보 저장
- 등록 후 시스템 전역에서 사용 가능한 디바이스가 됨

**디바이스 적용 (NEXA BOARD)**

- 등록된 디바이스를 특정 보드에 연결/적용하는 과정
- 보드에서 사용할 디바이스를 선택하여 연결
- `board_devices` 테이블에 보드-디바이스 연결 정보 저장
- 하나의 디바이스를 여러 보드에 적용 가능 (N-N 관계)

### 워크플로우

```
1. 디바이스 등록 (SYSTEM)
   ↓
   디바이스가 시스템에 등록됨
   ↓
2. 디바이스 적용 (NEXA BOARD)
   ↓
   등록된 디바이스를 보드에 연결
   ↓
3. 패널 추가 (NEXA BOARD)
   ↓
   연결된 디바이스의 센서 데이터를 표시하는 패널 추가
```

### 메뉴 위치

- **디바이스 등록**: SYSTEM → 디바이스 등록
- **디바이스 적용**: NEXA BOARD → 보드 → 디바이스 적용
