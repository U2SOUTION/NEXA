> **7 → 6**

- 7️⃣ *사람이 어떻게 느끼고 개입하는가*를 먼저 고정
- 6️⃣ 그 태도를 전역 Core로 끌어올림

이렇게 가야 **AI·도메인·자동화가 바뀌어도 Core가 흔들리지 않습니다.**

---

## 7️⃣ Buffer / Escalation / Policy 를 UI 개념으로 재정의

여기서 중요한 전제부터 정리할게요.

### ❌ 우리가 만들지 않는 것

- 설정 화면 (체크박스, 토글, 슬라이더 나열)
- "자동 분류 ON/OFF"
- "AI 사용 여부"

### ⭕ 우리가 만드는 것

- **행동 성향 조절기**
- **시스템의 태도**
- **개입의 밀도와 압력**

---

## 7-1. 설정의 3대 축 (UI 이전의 개념 모델)

### 🔹 ① Buffer — _판단을 어디에 머물게 할 것인가_

**질문**

> 이 판단을 지금 실행할까,
> 잠시 보류할까,
> 사람에게 보여줄까?

#### Buffer가 다루는 것

- 시간 지연
- 확신도 누적
- 중복 판단 압축
- 감정/집중 보호

📦 개념 모델

```
[Signal 발생]
      ↓
[Buffer Zone]
      ↓
(시간 / 신뢰 / 반복 / 사용자 성향)
      ↓
[Escalation or Release]
```

➡️ UI로 표현되면:

- "즉시 개입형"
- "조용히 모으는 중"
- "필요할 때만 알림"

---

### 🔹 ② Escalation — _언제 사람을 부를 것인가_

**질문**

> 이 상황은 자동으로 처리해도 되는가?
> 아니면 인간의 주의가 필요한가?

#### Escalation의 핵심

- 실패 감지 ❌
- **책임 전환 조건 정의 ⭕**

📌 예시

- 같은 판단 3회 반복
- 사용자 패턴과 충돌
- AI 신뢰도 하락
- 중요 문서 / 중요 장비 / 실시간 제어

➡️ Escalation은 경고가 아니라

> **"지금은 사람이 더 잘한다"는 신호**

---

### 🔹 ③ Policy — _결과를 어떻게 대우할 것인가_

**질문**

> 이 판단 결과를
> 실행할까?
> 보관할까?
> 제안할까?
> 요약만 남길까?

#### Policy는 판단하지 않는다

- Policy는 **처리 태도**다

📌 같은 결과라도:

- 자동 실행
- 소프트 제안
- 기록만
- 무시 가능 알림

➡️ 그래서 Policy는
Rule/Ai 위에 있어야 한다

---

## 7-2. UI는 "컨트롤 패널"이 아니라 "성향 다이얼"

이제 UI 개념으로 번역해보겠습니다.

### 🎛 1) 시스템 성향 다이얼 (Global Attitude)

- 보수적 ←───●───→ 공격적
- 기록 중심 ←───●───→ 실행 중심
- 자동 신뢰 낮음 ←───●───→ 자동 신뢰 높음

👉 이 값들이

- Buffer 길이
- Escalation 임계치
- Policy 강도에 **동시에 영향**

---

### 🧭 2) 도메인별 편차 허용 (Domain Bias)

- Archive: 보수적 / 기록 우선
- IoT: 즉각성 / 안정성 우선
- CNC: 절대 엄격 / 자동 제한
- Art Generator: 실험적 / 자유

➡️ UI에서는 "세부 설정"이 아니라

> **도메인 성향 프로필 선택**

---

### 🧭 3) 지금 이 작업에만 적용 (Context Override)

- "이번엔 그냥 두자"
- "이번엔 엄격하게"
- "이번 세션은 자동 금지"

➡️ 이건 설정 저장 ❌
➡️ **일시적 중력 변화**

---

## 7-3. settings/ 폴더의 의미 재정의 (중요)

이제 파일들의 **철학적 위치**가 명확해집니다.

### settings/ = ❌ 설정 폴더

### settings/ = ⭕ 태도 정의 영역

| 파일                   | 진짜 역할                   |
| ---------------------- | --------------------------- |
| SentinelSettingsSchema | 세계관 합성기               |
| BufferPolicy           | 판단 완충 메커니즘          |
| EscalationPolicy       | 책임 전환 규칙              |
| ClassificationSettings | 분류 결과를 어떻게 대우할지 |
| DiscardSettings        | 폐기 판단의 예의            |
| JudgmentSettings       | 개입의 예절                 |
| FlowSettings           | 리듬에 대한 배려            |

---

## 7-4. 지금 단계에서 "코드로 건드리면 좋은 것"

아길이님이 바로 손대기 좋은 순서입니다.

1️⃣ `BufferPolicy.ts`
→ **판단을 바로 실행하지 않는 구조 확정**

2️⃣ `EscalationPolicy.ts`
→ **사람을 부르는 조건의 선언**

3️⃣ `SentinelSettingsSchema.ts`
→ 위 둘을 *합성*하는 구조

(아직 UI ❌, 아직 AI ❌)
