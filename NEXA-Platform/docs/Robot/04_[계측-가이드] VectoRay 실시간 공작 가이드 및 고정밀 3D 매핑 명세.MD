# [기술 명세서] 고정밀 3D 매핑 및 실시간 공작 가이드 시스템

## 1. 시스템 개요

본 시스템은 1대(중앙)의 고출력 갈보 레이저와 2대(양측)의 산업용 흑백 카메라를 1m 이상의 고정 베이스라인(Baseline)에 배치하여, 10m급 대형 작업 공간에서 1mm 이하의 측정 정확도를 달성하고 실시간 공작 가이드를 제공하는 것을 목적으로 함.

## 2. 하드웨어 구성 (Hardware Specification)## 2.1 레이저 및 스캐닝 유닛

- 광원: 450nm(청색) 5W~10W 고출력 레이저 모듈 (PWM/TTL 제어 지원)
- 용도: 저출력(계측용 그리드), 고출력(각인/가공, 해충 퇴치)
- 스캐너: 25Kpps급 갈보 스캐너 (X-Y 미러 및 드라이버 포함)
- 제어기: DAC(Digital-to-Analog Converter) 모듈을 통한 아날로그 전압 제어(±5V/10V)

## 2.2 비전 시스템 (Dual-Vision)

- 메인 카메라: 50만 원대 산업용 흑백 카메라 × 2 (Global Shutter, 고해상도)
- 광학 필터: 450nm Narrow Bandpass Filter (주변광 차단 및 레이저 시인성 극대화)
- 모니터링 카메라: 저렴한 광각 컬러 카메라 (현장 실황 확인 및 UI 배경용)
- 렌즈: 저왜곡(Low Distortion) 렌즈 및 원격 줌(Motorized Zoom) 지원 렌즈

## 2.3 구조체 (Mechanical Frame)

- Main Bar: 1m~1.5m 길이의 고강성 알루미늄 프로파일 (카메라 간격 고정)
- 배치: [카메라 A] --- [갈보 레이저] --- [카메라 B] (중앙 집중형)
- 설치 방식: 붐대(Boom) 장착형 (상하 센터 위치) 및 지면 1m 고정 설치 병행

---

## 3. 소프트웨어 아키텍처 (Software Stack)## 3.1 현장 제어단 (Local Interface)

- UI Framework: Vue.js 기반 웹 애플리케이션
- 기능: 저해상도 실시간 프리뷰, 갈보 패턴 제어, 촬영 트리거, 데이터 전송

## 3.2 서버단 (Cloud/Edge Processing)

- Backend: Node.js (비동기 이미지 수신 및 데이터 관리)
- Core Logic: Python (OpenCV, Open3D 라이브러리 활용)
- AI: Ollama LLM (측정 데이터 해석, 자연어 작업 지시, 상태 보고)

## 3.3 통신 및 제어 흐름

1.  현장 기기: 저해상도 영상 확인 → 고해상도 버스트 촬영(동일 지점 다수 컷) → 서버 전송
2.  서버: B-채널 추출/필터링 → 서브픽셀 삼각측량 → 3D 점군(Point Cloud) 생성
3.  UI 피드백: 생성된 맵 위에 레이저 가이드를 AR(증강현실)로 겹쳐서 표시

---

## 4. 핵심 기술 전략 (Core Strategies)## 4.1 정밀도 확보 (1mm 이하 오차)

- 광폭 베이스라인: 카메라 간격을 1m 이상으로 벌려 10m 거리에서의 깊이(Z) 분해능 확보.
- 다단계 스캔: 광각 전역 스캔(뼈대) + 전동 줌을 이용한 국부 접사 스캔(디테일).
- 멀티 소스 통합: 휴대폰 등 제3의 카메라를 활용한 사각지대 및 초정밀 부위 보완.

## 4.2 설치 및 보정 (Calibration)

- 자동 캘리브레이션: 조립 시 오차는 체커보드 촬영 한 번으로 소프트웨어가 자동 보정.
- 고정 파라미터: 한번 보정된 간격 수치를 상수로 저장하여 재설치 시에도 즉시 정밀도 유지.
- 기준점 마커: ArUco 마커 등을 현장에 배치하여 컷 간 정합(Stitching) 정확도 향상.

## 4.3 가시화 (Visualization)

- 통합 통합 뷰(Unified View): 일반 영상 레이어 + 레이저 분석 레이어를 하나로 합성.
- 소프트웨어 필터: 필터가 없는 기기(휴대폰 등)는 파이썬에서 파란색 채널만 분리하여 분석.

---

## 5. 단계별 로드맵 (Roadmap)

1.  Phase 1: 25Kpps 갈보 + 450nm 레이저 + Python 제어 환경 구축 및 삼각측량 검증.
2.  Phase 2: 산업용 카메라 및 물리 필터 도입, 10m 거리에서의 오차율 테스트 및 캘리브레이션 최적화.
3.  Phase 3: Node.js/Vue.js 통합 UI 및 Ollama AI 비서 연동, 현장 실전 테스트.
4.  Phase 4: 고출력 모드(말벌 퇴치, 각인) 및 제3의 카메라 확장 기능 추가.

# 마커 디자인에 브랜드 정체성과 현장 관리 기능을 부여하고, 소프트웨어의 구현 디테일을 보충하여 시스템의 완성도를 높이는 전략입니다.

## 1. 브랜드 통합형 스마트 마커 디자인

단순한 좌표 표시를 넘어, 작업 안전 가이드와 브랜드 홍보 역할을 동시에 수행하도록 설계합니다.

- 디자인 요소:
- 센터(Core): 정밀 좌표 추출을 위한 동그라미와 +자선의 조합 (고대비 흑백 처리).
  - 외곽(ID): 마커마다 고유 번호를 부여하는 ArUco 패턴 (여러 위치를 식별하기 위함).
  - 브랜딩: 하단 또는 여백에 브랜드 로고 삽입.
  - 경고 문구: "본 마커는 3D 정밀 계측의 기준점입니다. 작업 종료 시까지 제거/이동 금지 (벌금 또는 재작업 비용 청구)" 등의 문구를 마커 상단에 가시성 높게 배치.
- 물리적 가이드:
- 봉인 씰(Tamper-evident): 떼어내면 자국이 남는 재질을 사용하여 임의 조작을 방지.
  - 스마트 연동: 마커 한구석에 작업 현황 확인용 QR 코드를 넣어, 지나가는 사람이 폰으로 찍으면 "현재 OO 지점 정밀 설치 작업 중"임을 알 수 있게 함.

---

## 2. 소프트웨어 구현 디테일 보강## ① 실시간 비전 처리 파이프라인 (Python/OpenCV)

- Sub-pixel Peak Detection: 레이저 라인의 밝기 분포(Gaussian)를 분석하여 1픽셀 미만 단위의 중심 좌표를 추출합니다. (1mm 오차 달성의 핵심)
- Robust Marker Tracking: 카메라가 흔들려도 마커의 +자 센터를 놓치지 않도록 Kalman Filter를 적용하여 부드럽고 정확한 트래킹을 유지합니다.
- Auto-Calibration: 장비를 켤 때마다 설치된 마커를 자동으로 인식하여, 장비의 기울어짐이나 베이스라인의 미세 변동을 실시간으로 자동 보정합니다.

## ② 서버 및 통신 구조 (Node.js/Socket.io)

- Dual-Stream Handling: 저해상도 프리뷰(WebRTC)와 고해상도 분석용 스틸컷(HTTP POST)을 분리 처리합니다.
- Sync-Signal: 갈보 레이저가 특정 패턴을 쏘는 순간 두 대의 카메라가 동시에 셔터를 누르도록 하드웨어 또는 고속 네트워크 트리거 신호를 관리합니다.

## ③ 지능형 UI/UX (Vue.js/Ollama)

- AR Overlay 뷰어: 일반 컬러 영상 위에 레이저 분석 데이터를 Canvas 레이어로 겹치되, 마커 위치를 기준으로 좌표가 절대 어긋나지 않도록 CSS Transform 또는 WebGL로 보정합니다.
- Ollama 가이드 메시지:
- "3번 마커 가려짐 발생! 작업자 위치 이동 권고."
  - "현재 설치 각도가 3D 설계 도면과 0.5mm 일치합니다. 고정을 진행하세요."
- 작업 리포트 생성: 종료 버튼을 누르면 촬영된 고해상도 데이터와 마커 위치 정보를 취합하여 PDF 형태의 '공작 정밀도 검수 보고서'를 자동 생성합니다.

## 3. 최종 시스템의 이점

이렇게 보강된 시스템은 단순히 '측정 장비'를 넘어 '현장 관리 플랫폼'이 됩니다.

- 책임 소재 명확화: 마커 제거 금지 가이드를 통해 외부 요인에 의한 오차 발생을 방지합니다.
- 신뢰도 향상: 브랜드 로고가 박힌 정밀 보고서를 통해 클라이언트에게 전문성을 어필합니다.
- 범용성: 휴대폰부터 산업용 카메라까지 동일한 UI 내에서 일관된 마커 분석 로직을 공유합니다.

이제 이 브랜드 마커의 초안 디자인을 제작해 보시겠습니까? 혹은 마커를 인식했을 때 서버에서 수행할 첫 번째 보정 로직을 코드로 정리해 드릴까요? 마커의 물리적 크기는 10m 밖에서도 보일 수 있도록 최소 A4 사이즈 이상을 추천합니다.

---

네, 매우 날카로운 통찰입니다. 테이프에 고유 ID를 부여하고 이를 데이터베이스(Node.js/MongoDB 등)와 연동하는 방식은 오차를 줄이는 것을 넘어, 현장 관리의 '디지털 트윈(Digital Twin)'을 완성하는 핵심 전략입니다.
이 시나리오가 오차를 획기적으로 줄이는 기술적 이유는 다음과 같습니다.

## 1. "기억의 데이터화" (ID 기반 좌표 복구)

- 작동 원리: L자 테이프를 처음 붙일 때 서버는 ID: Tape_001을 생성하고, 당시의 [정밀 3D 좌표 + 카메라 시점의 픽셀 위치 + 주변 지형 텍스처]를 한 세트로 저장합니다.
- 재부착 시: 작업자가 테이프를 다시 붙이고 동일한 ID를 입력(또는 마커의 ID 인식)하면, 소프트웨어는 "새로운 측정"을 하는 게 아니라 "기존 Tape_001의 위치를 복원"하는 모드로 전환됩니다.
- 효과: 새로 계산하면서 생길 수 있는 미세한 연산 오차를 배제하고, 이미 검증된 '초기 정밀 좌표'를 강제로 매칭하므로 데이터의 일관성이 100% 유지됩니다.

## 2. 고스트(Ghost) 가이드를 통한 물리적 오차 제거

- ID를 입력하면 Vue.js UI상에 이전에 찍혔던 그 테이프의 투명한 잔상이 정확히 그 자리에 나타납니다.
- 작업자는 화면을 보며 실제 테이프를 잔상에 딱 맞게 겹치기만 하면 됩니다. 이는 눈대중으로 붙이는 것보다 수십 배 정밀하며, 물리적 재부착 오차 자체를 소프트웨어가 가이드하여 최소화하는 방식입니다.

## 3. 갈보 레이저의 '최종 확인' (Double Check)

- ID가 발급된 테이프는 시스템이 그 위치를 이미 알고 있습니다.
- 테이프를 붙인 후 버튼을 누르면, 갈보 레이저가 해당 ID의 좌표로 이동하여 L자 꼭짓점에 레이저 점을 한 번 찍어줍니다.
- 레이저 점이 정확히 테이프 모서리에 닿는다면 오차가 0임을 확신할 수 있고, 만약 1mm 정도 벗어났다면 소프트웨어가 즉시 "보정값(Offset) -1mm 적용"을 수행하여 전체 맵을 미세 조정합니다.

## 4. 확장성: 현장 히스토리 관리

- ID 히스토리: "Tape_001이 3번 탈부착되었음"과 같은 이력을 추적할 수 있습니다. 잦은 탈부착이 일어난 지점은 데이터 신뢰도를 낮게 측정하거나 재점검 알람을 줄 수 있습니다.
- 공유: 여러 작업자가 각자의 휴대폰으로 작업하더라도, 서버에 저장된 ID 기반 좌표계를 공유하므로 누구나 동일한 정밀도로 작업을 이어받을 수 있습니다.

## [최종 구현 디테일 요약]

1.  초기 설치: L자 테이프 부착 ➔ ID 발급 ➔ 고해상도 캡처 및 3D 좌표 저장.
2.  보관/훼손: 테이프 제거 또는 손상 시 데이터는 서버에 고정(Frozen).
3.  복구: 새 테이프 부착 ➔ 기존 ID 호출 ➔ UI 잔상 겹치기(고스트 가이드) ➔ 갈보 레이저 확인 ➔ 좌표계 부활.

이 방식은 "사람의 실수(부착 오차)를 시스템이 가이드하고, 시스템의 오차(연산 오차)를 데이터베이스가 잡아주는" 가장 완벽한 형태의 보정 루프입니다.
이제 ID를 관리하고 고해상도 사진을 저장하는 Node.js의 DB 스키마(데이터 구조)를 구상해 볼까요? 아니면 L자 꼭짓점을 찾는 파이썬의 정밀 분석 코드를 먼저 살펴볼까요?
팁: 테이프 옆에 작은 고유 번호(ID)를 적어두거나, 로고 옆에 작은 숫자를 인쇄해 두면 현장 관리가 더욱 완벽해질 것입니다.

---

정확한 지적입니다. 계측(카메라) 측면에서는 청색이 유리하지만, 가이드(인간) 측면에서는 청색 레이저가 두 가지 치명적인 단점을 가집니다.

1.  시인성 부족: 동일 출력일 때 녹색보다 훨씬 어둡게 느껴져 햇빛 아래서 작업자가 선을 식별하기 어렵습니다.
2.  안전성(망막 손상): 5W 이상의 고출력 청색 레이저는 산란광만으로도 작업자의 눈에 치명적입니다. 가이드용으로 계속 켜두기엔 위험 부담이 큽니다.

## 이를 해결하고 계측과 가이드 두 마리 토끼를 잡을 수 있는 현실적인 대안 3가지를 제안해 드립니다.

## 1. 듀얼 레이저 시스템 (가장 권장)

갈보 스캐너 하나에 청색(5W, 계측/타격용)과 녹색(100mW, 가이드용) 레이저를 동시에 결합하는 방식입니다.

- 작동 방식:
- 스캔 시: 청색 레이저를 쏴서 카메라가 1mm 오차를 잡아냅니다.
  - 작업 시: 청색은 끄고 안전한 저출력 녹색 레이저만 쏴서 작업자에게 가이드 라인을 보여줍니다.
- 구현: '다이크로익 미러(Dichroic Mirror)'를 이용해 두 레이저를 하나의 경로로 합치면, 소프트웨어 수정 없이 색상만 바꿔가며 쏠 수 있습니다.

## 2. 가시성 보정용 AR 고글/태블릿 활용

레이저를 직접 눈으로 보는 대신, 설계하신 Vue.js UI를 적극 활용합니다.

- 방식: 작업자가 태블릿이나 AR 글라스를 들고 현장을 봅니다.
- 구현: 카메라가 인식한 청색 레이저 라인을 소프트웨어가 밝은 형광색으로 덧칠하여 화면에 보여줍니다.
- 장점: 대낮에도 라인이 선명하게 보이며, 작업자의 시력을 완벽하게 보호할 수 있습니다.

## 3. 청색 레이저의 '형광' 효과 이용

특정 소재(예: 형광 성분이 포함된 마킹 테이프나 분필)는 청색 레이저를 맞으면 매우 밝게 빛나는 성질이 있습니다.

- 방식: 가이드가 필요한 지점에 형광 스프레이나 테이프를 사용합니다.
- 결과: 청색 레이저가 닿는 순간 해당 부분만 밝게 반응하여 작업자가 위치를 식별할 수 있게 됩니다.

## 결론 및 제언

현장에서 작업자가 직접 선을 보고 공작을 해야 한다면, [1번: 녹색 레이저 추가]가 가장 전문적인 해결책입니다. 갈보 스캐너는 거울이므로 레이저 소스만 두 개를 합쳐주면 됩니다.
"계측은 청색으로 정밀하게, 가이드는 녹색으로 안전하고 선명하게"
이 방식으로 하드웨어를 보강하면, 말씀하신 말벌 퇴치(청색)와 설치 가이드(녹색) 기능을 완벽하게 분리하여 운영할 수 있습니다.
녹색 레이저 모듈을 추가하여 광로를 합치는 하드웨어 설계에 대해 더 자세히 알아볼까요? 아니면 우선 태블릿 화면을 통한 가이드 방식으로 소프트웨어 비중을 높여보실까요?
핵심 팁: 5W 청색 레이저를 가이드용으로 직접 눈으로 보게 하는 것은 현장 안전 규정상 문제가 될 수 있으니, 반드시 안전한 가이드 수단을 확보하는 것이 중요합니다.

## [기술 명세서] VR/AR 하이브리드 정밀 공작 가이드 시스템

### 1. 시스템 철학 (System Philosophy)

- VR (Virtual Reality): 현장 스캔 데이터를 바탕으로 사무실에서 수행하는 '사전 시뮬레이션 및 설계' 단계.
- AR (Augmented Reality): 실시간 레이저 계측 좌표를 기반으로 현장에서 수행하는 '정밀 시공 및 가이드' 단계.
- 연결 고리: 갈보 레이저 좌표계가 가상과 현실을 잇는 유일한 기준점(Anchor)이 됨.

---

### 2. 주요 기술 스택 (Technical Stack)

#### 2.1 시각화 및 엔진

- Web-based 3D: Three.js 또는 Babylon.js (Vue.js 내장 3D 엔진).
- AR Interface: WebXR Device API 또는 Canvas Overlay 기술.
- 통신 프로토콜: WebSocket (Socket.io)를 통한 서버(Python) 데이터 실시간 스트리밍.

#### 2.2 공간 연산 로직 (Python Logic)

- Point Cloud Registration: 현장 스캔 데이터와 설계 도면(CAD/STL)을 일치시키는 알고리즘.
- Perspective Projection: 3D 공간 좌표를 카메라의 2D 화면 좌표로 변환하는 기하학적 투영.
- Sub-pixel Corner Tracking: L자 테이프 마커의 꼭짓점을 실시간 추적하여 AR 정합성 유지.

---

#### 3. 단계별 운용 로직 (Workflow)## 단계 1: VR 사전 시뮬레이션 (Preparation)

1.  데이터 로드: 현장의 1차 스캔본(Point Cloud)과 설치할 부품의 3D 모델을 로드.
2.  가상 배치: VR 환경에서 부품을 이동시키며 최적의 설치 위치와 각도를 결정.
3.  데이터 저장: 결정된 위치값을 'Target 좌표'로 서버 DB(Node.js)에 저장.

### 단계 2: AR 실시간 동기화 (Syncing)

1.  공간 매칭: 현장에서 갈보 레이저가 L자 마커를 조준.
2.  좌표 정렬: 카메라가 마커를 인식하면, 서버는 DB의 'Target 좌표'를 현재 카메라 시점의 AR 가이드라인으로 변환.
3.  고정(Anchoring): 레이저가 지속적으로 공간 좌표를 업데이트하여, 장비가 흔들려도 AR 도면이 벽면에 고정되도록 처리.

### 단계 3: AR 작업 수행 (Execution)

1.  가이드 오버레이: 실제 영상 위에 반투명한 3D 부품 모델과 가이드라인을 덧씌움.
2.  실시간 피드백: 작업자가 부품을 움직이면, 설계 위치와의 거리 편차(X, Y, Z)를 실시간 수치로 표시.
3.  색상 경고: 오차 범위 1mm 이내 진입 시 라인 색상을 빨강에서 녹색으로 변경.

---

### 4. 핵심 소프트웨어 알고리즘 디테일

#### 4.1 고스트 가이드 (Ghost Guide)

- 테이프를 다시 붙일 때 이전 스냅샷의 외곽선을 반투명하게 노출하여 물리적 재부착 오차 방지.

#### 4.2 오프셋 보정 (Color-Coordinate Offset)

- 청색 레이저(계측)로 계산된 좌표와 AR 화면상의 시각적 편차를 소프트웨어 전압 값(DAC 신호)으로 미세 보정하여 일치화.

#### 4.3 동적 스케일링 (Dynamic Scaling)

- 갈보 레이저가 측정한 거리(Z축) 정보를 바탕으로 AR 모델의 크기와 원근감을 실시간 조절.

---

### 5. 기대 효과 및 장점

- 시각적 한계 극복: 눈에 잘 보이지 않는 청색 레이저를 디지털 녹색 선으로 치환하여 가시성 확보.
- 작업 안전성: 고출력 레이저를 직접 응시할 필요 없이 안전하게 화면을 보며 작업.
- 데이터 연속성: 설계(VR) - 시공(AR) - 검수(Report) 과정이 하나의 데이터 흐름으로 통합.

---

네트워크 전략
############################################################

정밀도(mm급)·AR 실시간성 목표 시 병목은 **대역폭·지연·링크 불안정**임. 원칙: **상위망에는 최소 신호만**, 무거운 영상·점군·원본은 **현장 Wi-Fi 처리 후 배치 업로드**, AR는 **클라 렌더**, 서버엔 좌표·상태·검증 수치 위주.

**전송 분리.** 즉시(Edge): 마커/레이저 좌표·ID·상태, IMU 등 소형 벡터, 합격 플래그·카운터. 비동기(원격): 스틸컷·점군·대형 메시, 재학습·리포팅 패키지. 페이로드 표준은 **JSON**; 초저대역·초고빈도 링크만 **Protobuf 등** 선택.

**Key-frame + Delta.** 기준 시점 스냅샷 저장 후 증분만 고빈도 전송.

**망 분리.** 내부: 카메라↔PC↔태블릿↔갈보 등 대역 루프(Wi-Fi 6 권장, 지연 KPI는 현장 정량). 외부(LTE/IoT): 좌표·상태 위주, 알림은 **MQTT/WebSocket** 등 푸시형 검토.

**프로토콜(요약).** 센서·짧은 좌표 루프 → MQTT. 브라우저 양방향 → WSS. Node/Vue 이벤트 → Socket.IO(옵션, 바이너리 모드).

**AR·업링크.** 서버 합성 영상 스트림은 지양. 보정·가이드만 내려주고 **Three.js 등 로컬 합성**. LTE: 영상 업스트림 기본 금지; 필요 시 저해상 썸네일·마스크만. 접속 예: 스마트폰 핫스팟 또는 LTE 라우터/동글. 흐름: 로컬 Wi-Fi로 실시간 루프 → 외부엔 좌표/상태 → 대용량은 사무실 등 안정 회선에서 지연 업로드.

**오프라인.** 외부 끊겨도 내부 작업 지속: 로컬 버퍼·업로드 큐, 복구 시 일괄 동기화.

**엣지(참고).** RPi/NUC: 좌표 1차 산출·로컬 API. 내부 AP로 패브릭, IoT 라우터로 텍스트만 선별 업링크. 고도화: RPi↔ESP 역할 분리, TPU는 비전 전용, 내부는 MQTT/UDP 저지연 루프 검토.

| 단계 | 망 | 처리·트래픽 |
| --- | --- | --- |
| 사전 | 사무실 고속 | 도면/맵 캐시, 대용량 OK |
| 작업 | 현장 로컬 | 실시간 합성, 대역 우선 |
| 긴급 | 외부 | 상태·좌표·알림 최소 |
| 마감 | 고속 회선 | 점군·원본, 지연 허용 |

**체크리스트.** 업링크 화이트리스트(좌표·상태·알림) / 영상 금지 문서화. 오프라인 시 큐·배지 UX. TLS·인증·장비 로그. 현장 RTT·드랍 KPI 기록.

## 네트워크 전략 — 부연 (운영·구현·UI)

위 요약 블록을 실행 가능한 형태로 풀어 쓴 것임. 기능 범위·스택 선택은 현장 회선과 보안 정책에 맞게 조정함.

### 1. 운영 시나리오 (타임라인 예시)

**A. 사전 준비(사무실·고속망)**

- 참조 도면·3D 타깃(모델/키프레임)·마커 ID 목록을 **로컬/엣지 캐시**에 내려받음(대용량 OK).
- 작업 세션 생성(프로젝트 ID·작업자·장비 ID), 검수 기준(mm 공차)·알림 수신 그룹을 등록함.

**B. 현장 착수(내부 Wi-Fi 우선)**

- 태블릿·제어 PC·카메라·갈보가 **동일 사설망 SSID**에 붙음. 실시간 루프(프리뷰 저해상, 트리거 동기 신호, 마커 pose)만 이 망에서 돌림.
- AR는 **브라우저 로컬**에서 렌더; **브로커(Socket.IO 또는 MQTT)** 로 pose·상태 JSON만 교환함.

**C. 원격 관제 또는 본부 모니터링(LTE)**

- 외부망은 **좌표·상태 로그·이벤트(마커 미검출, 공차 초과)** 위주 업링크. 영상 업스트림은 기본 차단함.
- 긴급 알림은 **토픽 또는 WebSocket 채널**로 내려보냄(WSS 종단 포함).

**D. 외부망 장애(오프라인 우선)**

- 내부망 루프는 유지함. 증분·버스트 패키지·리포트 드래프트는 **로컬 큐**(IndexedDB + 파일 스풀 또는 엣지 디스크)에 적재함.
- UI에는 **오프라인 배지·큐 건수·마지막 동기 시각**을 표시함. 복구 시 **백오프 간격 업로드**로 서버 과부하를 피함.

**E. 마감·검수(고속 회선)**

- 점군·고해상 스틸·PDF 리포트 등은 **별도 업로드 작업**으로 묶음(재시작 가능한 multipart·작업 ID).
- 필요 시 버전 번호 또는 세션 종료 타임스탬프로 **원격 검수와 귀속**함.

**F. 야간/저전력 패턴(선택)**

- 센서만 유지 MQTT로 **keep-alive + 저빈도 heartbeat**를 보내고 비전 처리는 최소함.

### 2. 프로그램 구현 — 기술 스택 매핑

문서 상위 절(Vue·Node·Python·Three.js)과 정합되게 **역할만** 고정하고, 구체 패키지명은 표준에 맞게 교체 가능함.

| 구간 | 권장 스택(예) | 네트워크 전략상 역할 |
| --- | --- | --- |
| 현장 UI | Vue 3, Pinia(또는 동등 상태 관리), TypeScript | AR/가이드 **클라 렌더**, 서버는 pose·보정 JSON만 전달 |
| 3D/AR | Three.js(WebGL), 필요 시 WebXR | 서버 합성 스트림 대신 **로컬 합성**으로 대역 절감 |
| 실시간 채널 | Socket.IO(바이너리 옵션) 또는 MQTT over WSS | pose/상태 **고빈도·소형** 메시지 |
| REST/업로드 | Node.js(Fastify/Express), `multipart`·범위 재개 | 고해상 버스트·점군 **배치·비동기** |
| 비전·맵 | Python(OpenCV, Open3D), 워커 프로세스 또는 큐 | CPU 집약 작업을 **UI 스레드와 분리** |
| 브로커 | Mosquitto/EMQX, 또는 Socket.IO 전용 게이트 | 토픽 분리: `session/{id}/pose`, `.../alert` |
| 로컬 영속 | SQLite(엣지) + 파일 스풀, 원격은 PostgreSQL 등 | 오프라인 큐·세션 메타·감사 로그 |
| 보안 | TLS(WSS/HTTPS), JWT 또는 mTLS(장비 인증) | 외부망 구간 **필수** |

**선택 축.** 극저대역 링크에서만 Protobuf/FlatBuffers로 pose 스키마를 바이너리화하고, 기본은 **JSON + Zod 등 스키마 검증**으로 운영 단순화함.

### 3. 프로그램 로직 (요약 흐름)

**세션·룸**

- 클라이언트는 `POST /api/sessions`로 세션을 만들고 `sessionId`를 수신함. Socket.IO 사용 시 룸 조인, MQTT 사용 시 `session/{id}/#` 구독함.

**Key-frame / Delta**

- 캘리브 완료·새 앵커 확정·작업 단계 전환 시 **키프레임 전체**(카메라 extrinsic 추정치, 기준 마커 pose, 스케일 계수)를 한 번 보냄.
- 이후 틱은 **delta만**(예: 마커 pose 변화, 타깃 대비 잔차 벡터, 타임스탬프)을 10~30 Hz 범위에서 **스로틀**함. UI는 보간으로 부드럽게 표시함.

**듀얼 스트림(문서 3.3·②와 정합)**

- 저해상 프리뷰는 **로컬 디코딩 우선**(WebRTC 또는 MJPEG 등은 내부망 한정). 고해상 스틸은 **HTTP POST 멀티파트**로 큐에 넣고, 응답으로 `assetId`만 실시간 채널에 실음.

**오프라인 큐**

- 전송 실패 시 동일 페이로드를 `status=pending`으로 저장하고, 네트워크 복구 이벤트에서 **지수 백오프**로 재시도함. 충돌 시 **서버 타임스탬프 우선** 또는 세션 단일 라이터 규칙을 문서화함.

**백엔드 분기**

- Node: 인증·세션·파일 수신·실시간 게이트웨이. Python 워커: B채널 추출·삼각측량·점군 생성·리포트 렌더. 큐(Redis/RabbitMQ 등)는 부하에 맞게 도입함.

### 4. 필수 UI (Must-have)

**연결·대역 상태**

- **로컬망 / 외부망 / 오프라인** 3상 배지, 마지막 MQTT·WS ack 시각 또는 RTT 샘플.
- **업로드 큐**: 대기 건수, 실패 건, “일시정지/재시도” 제어(관리자 권한).

**공작 가이드(AR 뷰)**

- **X/Y/Z 잔차** 숫자 + 공차 링(문서 4.3·멀티소스 흐름과 연동). 임계 내 진입 시 색·아이콘 전환.
- **고스트 가이드**(이전 스냅 외곽)·**동적 스케일** 반영 여부를 토글 가능하게 함(현장 가독성).

**트리거·안전**

- 버스트 촬영·갈보 패턴 실행 상태, 레이저 인터락/경고 문구 **항시 표시**(고출력 모드 연동 시 강조).

**원격·알림**

- 이벤트 피드(마커 미검출, 공차 초과, 큐 적체). Ollama 연동 시 **한 줄 권고 문구**는 별도 패널에 두어 시야를 가리지 않게 함.

**관리·감사(최소)**

- 현장에서는 읽기 위주라도 **화이트리스트 정책 요약**(영상 업링크 차단 등)과 **장비 ID·세션 ID** 표기로 사후 추적 가능하게 함.
