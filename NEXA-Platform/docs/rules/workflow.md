# NEXA 워크플로우 하네스 (Workflow & Feedback Loop)

> AI가 코드를 작성한 후 스스로 검증하게 만드는 고삐(Harness).

---

## 1. 코드 생성 전 체크리스트 (BEFORE)

1. **문서 참조**: 관련 기획 문서(`docs/`)를 먼저 확인했는가?
2. **도메인 확인**: 변경 대상이 어떤 도메인(nexion, admin, ais 등)에 속하는가?
3. **래퍼 체크**: 불필요한 wrapper div가 생기지 않는가?
4. **아키텍처 정합**: `nexa_identities`의 불변성 원칙을 위반하지 않는가?
5. **기존 코드 읽기**: 수정 대상 파일을 반드시 먼저 읽고 구조를 파악했는가?

---

## 2. 코드 생성 후 검증 (AFTER)

1. **린트 확인**: 편집한 파일에 linter 에러가 없는지 확인
2. **타입 체크**: TypeScript 에러(Red squiggles)가 있다면 즉시 수정
3. **임포트 확인**: 누락된 import, 사용하지 않는 import 정리
4. **네이밍 확인**: `coding-style.md` §1 네이밍 규칙 준수 여부 확인
5. **CSS 확인**: `--nexa-*` 변수만 사용했는가, Quasar 기본 색상을 쓰지 않았는가

---

## 3. 복잡한 변경 시 (COMPLEX)

- 3개 이상의 파일에 영향을 주는 변경 → **작업 계획을 먼저 제시**하고 승인 후 진행
- DB 스키마 변경 → **DDL SSOT 문서**와 정합 여부 확인 필수
- 새로운 도메인/모듈 생성 → 기존 도메인 구조를 참조하여 동일 패턴 적용

---

## 4. Definition of Done (완료 조건)

- [ ] Linter 에러 없음
- [ ] TypeScript 타입 체크 통과
- [ ] `--nexa-*` CSS 변수만 사용
- [ ] 불필요한 래퍼 div 없음
- [ ] 관련 기획 문서와 정합성 확인

---

## 5. 커밋 규칙

- **메시지 형식**: `type: 간결한 설명` (한글 허용)
- **type 종류**: `feat`, `fix`, `refactor`, `docs`, `style`, `test`, `chore`
- **예시**: `feat: Nexion 캔버스 3패널 레이아웃 구현`, `fix: N-PATH 인덱스 동기화 오류 수정`
- 커밋 전 반드시 `git diff`로 변경 범위 확인
