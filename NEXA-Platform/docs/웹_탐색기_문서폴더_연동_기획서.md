# 웹 탐색기 ↔ 문서 폴더 연동 기획서

AI 채널 Ollama 연동 시 AI가 접근할 수 있는 **문서 폴더(NEXA-Documentation, NEXA-Platform/docs)**를 웹 탐색기에서 직접 선택 가능하게 하고, DB에 미반영된 문서도 **DB에 반영**으로 등록할 수 있게 한다.

---

## 1. 개요 및 배경

### 1.1 두 가지 소스

| 소스 | 경로/위치 | 데이터 출처 | DB 반영 |
|------|-------------|-----------|---------|
| **업로드 폴더** | `uploads/{domain}/...` (파일 업로드) | `files` 테이블 | 기본적으로 `files` + `file_references` 등록 |
| **문서 폴더** | NEXA-Documentation, NEXA-Platform/docs (물리 경로) | `/api/docs/` API (폴더 스캔, 메타데이터, 파일) | 없음 |

- **웹 탐색기**(AI 채널 `AiExplorerPanel`, `GlobalFileExplorer`)는 **`GET /api/files/explorer/tree`**, **`GET /api/files/explorer`** 만 사용한다.
- 위 API는 **`files` 테이블**만 `file_path`(예: `uploads/{domain}/...`) 기준으로 반환한다.
- 따라서 **문서 폴더(nexa-docs, platform-docs)**는 DB에 없어서 현재 표시되지 않는다.

### 1.2 목표

1. **탐색기에 문서 폴더 노드 추가**: DB에 없는 문서 폴더(nexa-docs 등)를 트리에 병합 표시하고, 클릭 시 목록을 로드한다.
2. **일관된 표시**: 업로드 폴더와 문서 폴더 모두 동일한 UI에서 선택·미리보기·채팅 주입이 가능해야 한다.
3. **DB 반영(선택)**: 사용자가 원하는 문서만 선택한 뒤(예: ai) "디비에 반영"을 실행하면, 해당 문서가 `file_references`에 등록되고 이후 "미디어 추가" 등에 사용 가능해진다.

## 2. 기술적 배경

### 2.1 현재 탐색기 동작 구조

```
GlobalFileExplorer
  → useGlobalFileExplorer()
    → loadTree()     → GET /api/files/explorer/tree  → files 기반 file_path 로 domain 트리 구축
    → loadItems()   → GET /api/files/explorer        → files 기반 목록 (domain, path, q, limit, offset)
  트리 노드 선택 시 selectedNode = { domain, path }
  목록에 items (id, file_path, original_name, file_type, category, url, ...)
```

- 트리: `files`에서 `file_path LIKE 'uploads/%'`로 domain 목록을 구축해 `domains[]` 노드로 표시한다.
- 목록: `files` 테이블만 조회하므로 **문서 폴더 내용은 아예 표시되지 않는다.**

### 2.2 문서 폴더 API

| API | 역할 |
|-----|------|
| `GET /api/docs/config/folders` | 문서 폴더 목록 (id, label, pathPrefix, displayPathPrefix) |
| `GET /api/docs/metadata` | 문서 폴더 내 파일 목록 (relativePath, displayPath, folderId, modifiedDate 등) |
| `GET /api/docs/f/{prefixedPath}` | 파일 내용 (예: nexa-docs/Platform/01-기획/문서.md) |

- 경로 형식: **`{folderId}/{relativePath}`** (예: nexa-docs/Platform/01-기획/문서.md).
- `files` / `file_references` 와는 별개로 운영된다.

### 2.3 DB 구조 차이

- 업로드 파일 = **files 테이블**에 등록되어 있고, `file_references`로 도메인 연결.
- 문서 폴더 = 파일만 존재하고 DB에는 미반영. 따라서 **파일 경로·ID 등 DB 정보가 없으므로**, DB 등록 전에는 "미디어 추가"를 하려면 먼저 DB 반영이 필요하다.
- 즉, **문서 폴더 파일을 DB에 "등록"하는** 별도 흐름이 필요하다.

---

## 3. 사용자 시나리오

1. 사용자가 AI 채널(예: Ollama 연동)을 연다.
2. 왼쪽 **문서 탐색 패널**(ai, parts 등)에서 **문서 폴더**(예: NEXA-Documentation, NEXA-Platform/docs) 트리를 볼 수 있다.
3. 문서 폴더 노드를 선택하면, 해당 폴더 내 파일 목록이 표시된다.
4. 사용자는 필요 시 **미리보기 / 채팅 주입 / 선택** 등 기존 API와 동일하게 동작한다 (DB 반영).
5. **"디비에 반영"** 시나리오:
   - 문서 폴더에서 선택한 파일을 도메인(예: ai)에 "디비에 반영"하면,
   - 해당 파일이 `file_references`에 등록되고, 이후 미디어 추가 등에서 사용 가능해진다.

---

## 4. 설계 방향

### 4.0 탐색기 필터 용어: internal / external

DB 반영 여부에 따라 자산을 구분하는 **탐색기 필터**용 용어를 다음과 같이 정의한다.

| 구분 | 영문 (코드) | 한글 | 의미 |
|------|-------------|------|------|
| DB에 있음 | **internal** | 내부 | `files` + `file_references`에 등록된 자산. 미디어 추가·참조 등 즉시 활용 가능. |
| DB에 없음 | **external** | 외부 | 파일만 존재하고 DB에는 미반영된 자산. 뷰어·채팅 주입은 가능, 미디어 추가는 "디비에 반영" 후 가능. |

- **필터 UI**: `전체 | 내부 | 외부` (또는 `전체 | internal | external`) 버튼/탭으로 사용자 선택.
- **트리/목록**: 선택한 필터에 따라 internal 소스(files 기반 도메인), external 소스(문서 폴더 등)를 포함·제외하여 표시.

### 4.1 트리: 소스 통합

- **트리**: 트리 = `files` 기반 도메인 트리 + 문서 폴더 노드.
- **방식**: 클라이언트에서 병합. 기존 `GET /api/files/explorer/tree` + `GET /api/docs/config/folders` 호출 후, 두 결과를 하나의 트리로 병합한다. (files API 수정 없음.)
- **노드 구분**: `source: 'db'`(기존 도메인) / `source: 'docs'`, `folderId`, `label`(문서 폴더). 선택 시 목록 API를 소스별로 분기한다.

### 4.2 목록: 소스별 분기

- **선택 노드 `source === 'db'`** (기존 도메인 트리):
  - `GET /api/files/explorer?domain=...&path=...` 호출.
- **선택 노드 `source === 'docs'`** (문서 폴더):
  - `GET /api/docs/metadata` 호출 후, 결과에서 `folderId`가 일치하는 항목만 사용한다.
  - 각 항목은 **DB id가 없음**이므로 `id`는 임시 id(예: `doc:${folderId}:${relativePath}`) 또는 `null`/빈 문자열을 사용하고, `docPath`, `folderId`, `relativePath`, `displayPath` 등을 함께 전달한다.

목록 항목은 `files` 형식과 호환되게 구성한다.

- 필수: `id`, `file_path`, `original_name`, `file_type`, `category`, `url`, `created_at` 등
- 문서 폴더: `id` = 임시 id 또는 DB 반영 시 id, `file_path` = displayPath 또는 prefixedPath, `original_name` = 파일명, `file_type`/`category` = documents, `url` = 미리보기용 URL(예: `/api/docs/f/...`) 또는 fetch용 경로.

뷰어·채팅 주입 시 `docPath`(또는 prefixedPath)를 `/api/docs/f/{path}` 형식으로 변환해 fetch하면 된다.

### 4.3 "디비에 반영" 흐름 (확정)

- **방식**: `files` 테이블에 직접 삽입 후 `file_references` 등록.
- `files`에 행 추가: `file_path = 'docs/{folderId}/{relativePath}'`, `source = 'docs'`, `original_name`, `file_type = 'document'`, `category = 'documents'`. 실제 파일 서빙은 `file_path`가 `docs/`로 시작할 때 `/api/docs/f/...`와 매핑하는 프록시/리다이렉트로 처리.
- `file_references`에 `(file_id, domain)` 등록. 기존 "미디어 추가"(`POST /api/files/:id/reference`) 그대로 사용.

## 5. 구현 방안

### 5.1 트리 구성

- **useGlobalFileExplorer** (또는 GlobalFileExplorer 진입점):
  - 트리 로드 시 `loadTree()` 에서 `GET /api/docs/config/folders` 호출.
  - 문서 폴더별 노드 추가 예시:  
    `{ id: 'docs-' + folder.id, label: folder.label, icon: 'folder', source: 'docs', folderId: folder.id }`  
    (기존 도메인 노드와 구분하기 위해 `source`, `folderId` 필드 사용.)
  - 최종 `treeNodes` = `buildFileTreeFromApiResponse(treeApi)` 결과와 문서 폴더 노드를 병합해 하나의 트리로 렌더링한다.
- 노드 구분:
  - DB 도메인: `source` 없음 또는 `source: 'db'`, `domain`, `path` 등.
  - 문서 폴더: `source: 'docs'`, `folderId` 등.

### 5.2 목록 로드 분기

- **selectNode(node)** 시:
  - `node.source === 'docs'` 이면:
    - `GET /api/docs/metadata` 호출 후 `files` 형식과 유사하게 `folderId === node.folderId` 인 항목만 변환한다.
    - 변환 예시:  
      `{ id: 'doc:' + f.relativePath, file_path: f.displayPath, original_name: f.fileName, file_type: 'document', category: 'documents', docPath: f.relativePath, folderId: f.folderId, displayPath: f.displayPath }`  
      (단 `url`은 미리보기 URL을 만들거나, fetch 시 `getDocFileUrl(prefixedPath)`로 경로를 조합해 사용한다.)
  - 그 외(기존):
    - `GET /api/files/explorer?domain=...&path=...` 로 `items` 를 가져온다.

### 5.3 뷰어 및 채팅 주입 (미리보기/채팅/선택)

- 문서 폴더 항목은 `folderId`/`docPath`(또는 prefixedPath)를 사용해 "미리보기"를 요청한다.
- **미리보기 / 채팅 주입**:  
  `getDocFileUrl(prefixedPath)`로 fetch URL을 만들고 text fetch 후 파싱/표시한다.
- **선택**:  
  기존과 동일하게 항목 클릭 시 상세 정보를 표시하고, `/api/docs/f/...` 경로로 fetch하면 된다.

### 5.4 "디비에 반영" 흐름

- **조건/UI**: 문서 폴더에서 선택한 항목에 "디비에 반영" 버튼(또는 "미디어 추가"와 유사한 액션으로 "파일 등록"을 먼저 수행).
- **API**:
  - `POST /api/files/register-document` (또는 `/api/docs/register`)  
    - body: `{ folderId, relativePath, domain }` (예: ai).
  - 처리:
    - `files`에 행 생성:  
      `file_path = 'docs/' + folderId + '/' + relativePath`,  
      `source = 'docs'`,  
      `original_name` = 파일명,  
      `file_type = 'document'`,  
      `category = 'documents'`,  
      `content_hash` = null 또는 선택적 계산 (나중 확장).
    - `file_references`에 `(file_id, domain)` 등록.
  - 응답: `{ id, file_path, ... }` (새 file id).
- **서빙 매핑**: 이후 해당 `file_path`가 `docs/`로 시작하면,  
  `documentConfig.resolvePrefixedPath(folderId + '/' + relativePath)`로 실제 경로를 찾아 서빙하거나 302로 `/api/docs/f/...` 리다이렉트한다.
- **미디어 추가**: 이후에는 `id`가 `file` id이므로, 기존 "미디어 추가"와 동일하게 `POST /api/files/:id/reference`를 호출한다.

### 5.5 DB 스키마

- **files** 테이블: 컬럼 `source` (varchar, nullable) 추가 — `'upload'`(기본), `'docs'`.
- 문서 반영 시: `file_path = docs/{folderId}/{relativePath}`, `source = 'docs'`. 그 외 필드는 기존 규칙·5.4 로직에 맞춰 등록.

## 7. 뷰어 ↔ 마크다운 파서 연동 (md 표시 통합)

탐색기와 문서 폴더 연동 시 일관된 미리보기 UX를 위해, **모든 .md 파일**이 동일한 파서·스타일로 렌더되도록 한다.

### 7.1 현황

#### 7.1.1 UniversalViewer (다목적 뷰어)

| 파일 유형 | 현재 처리 | 비고 |
|-----------|-----------|------|
| image | `<img :src="previewUrl">` | getUploadDisplayUrl(file_path) |
| video | `<video :src="previewUrl">` | 동일 |
| audio | `<audio :src="previewUrl">` | 동일 |
| pdf | `<iframe :src="previewUrl">` | 동일 |
| **md/문서** | **"미지원" placeholder** | 미구현 |

- `previewUrl` = `getUploadDisplayUrl(file_path)` 또는 `file.url` (경로에 따라).
- md는 **바로 미리보기**가 불가능하므로 URL로 iframe 보여주는 방식이 적합하지 않고, **fetch 후 파싱·렌더**가 필요하다.

#### 7.1.2 마크다운 파서 (`src/system/utils/markdown`)

| 파일 | 역할 |
|------|------|
| `markdownParser.ts` | `parseMarkdown(content, fileKey, fileCheckboxStates)` → HTML 문자열 |
| `index.ts` | export `parseMarkdown`, `escapeHtml` |

**지원 기능**: 제목(h1~h6), 테이블, Mermaid 차트, 코드 블록, 리스트(ul/ol), 체크박스, 링크(**외부** 제한), 이미지 등

#### 7.1.3 기존 마크다운 사용처 (참고)

| 파일 | 용도 |
|------|------|
| `DocumentManagerContent.vue` | 문서 관리자: `documentStore.fileContents` + `parseMarkdown` → `.markdown-content` v-html |
| `documentManagerStore.ts` | `parsedContent` computed (파싱 결과 캐시) |
| `useMermaid` | `.mermaid-block` 선택 후 Mermaid 렌더링 |
| `_markdown.scss` | `.markdown-content` 스타일 정의 (제목, 테이블, 코드, mermaid 등) |
| `AiChatPanel.vue` | AI 채팅 내 마크다운 렌더링 |
| `ErrorTrackingContent.vue` | 에러 메시지 마크다운 표시 |

#### 7.1.4 요약

- **UniversalViewer**: md를 별도 분기로 처리해야 한다.
- **텍스트 fetch**: 업로드 파일은 `file_path` → URL로 fetch text; 문서 폴더는 `getDocFileUrl(prefixedPath)`로 fetch text.
- **렌더링 공통화**: 기존과 동일하게 `parseMarkdown` + `.markdown-content` + `useMermaid`를 재사용해 일관된 표시를 유지한다.

### 7.2 목표

- **모든 .md 파일**이 UniversalViewer에서 동일하게 렌더링된다.
- 문서 관리자, AI 채널, 뷰어 등 서로 다른 진입점에서도 md 표시가 **동일한 스타일**을 따른다.

### 7.3 설계

#### 7.3.1 md 감지

- `file_type`/`category`가 `document`/`documents` 이거나
- `original_name`/`file_path`가 `.md`로 끝나면 `md`로 간주한다.

```ts
const isMarkdown = computed(() => {
  const t = (file?.file_type || file?.category || '').toLowerCase()
  const name = (file?.original_name || file?.file_path || '').toLowerCase()
  return t === 'document' || t === 'documents' || name.endsWith('.md')
})
```

#### 7.3.2 URL별 fetch

| 소스 | 식별자 | fetch URL |
|------|------|------------|
| **문서 폴더** | `folderId` + `relativePath` (또는 `docPath`) | `getDocFileUrl(folderId + '/' + relativePath)` 로 fetch text |
| **업로드 파일** | `file_path` (uploads/... 등) | `getUploadDisplayUrl(file_path)` 또는 `file.url` 로 fetch text |

- 둘 다 `fetch(url).then(r => r.text())`로 본문을 가져온다.

#### 7.3.3 파싱·스타일·Mermaid 통합

1. **parseMarkdown**  
   - 문서 관리자와 동일하게 기본 옵션을 사용하고, 체크박스는 없으면 `fileCheckboxStates = {}`로 넘긴다.  
   - `fileKey`는 `file.original_name` 또는 `file.file_path`로 설정.

2. **스타일**  
   - 렌더 결과를 `.markdown-content` 클래스로 감싸고 `_markdown.scss` 스타일이 적용되도록 한다.

3. **useMermaid**  
   - 렌더된 HTML에서 `.mermaid-block`을 찾아 `useMermaid(containerRef, filePathGetter)`로 Mermaid 차트를 렌더링한다.

#### 7.3.4 UniversalViewer 변경 포인트

```vue
<!-- UniversalViewer.vue 내부 -->
<template v-else-if="isMarkdown">
  <div class="universal-viewer-markdown markdown-content" ref="markdownContainerRef"
       v-html="markdownHtml"></div>
</template>
<template v-else>
  <!-- 기존 "미지원" placeholder -->
</template>
```

- `markdownHtml`: fetch로 가져온 `parseMarkdown(content, fileKey, {})` 결과.
- `markdownContainerRef`: `useMermaid`의 `containerRef`로 전달.
- 로딩/에러: fetch 실패 시 에러 메시지를 표시한다.

#### 7.3.5 소스별 URL 구성

문서 폴더와 업로드 폴더 모두 동일한 로직으로 처리하려면 fetch URL만 소스에 따라 분기한다.

- `folderId`, `relativePath` (또는 `docPath` = `folderId/relativePath`)  
  → `getDocFileUrl(docPath)` 로 fetch.

업로드 파일의 경우 `file_path`를 `getUploadDisplayUrl`로 변환해 fetch한다. (단 URL이 `fetch`로 접근 가능해야 한다.)

## 9. 요약

- **문제**: 문서 폴더(nexa-docs, platform-docs)가 DB에 없어 탐색기에 보이지 않는다. md 파일은 "미지원"으로 표시된다.
- **목표**: (1) 탐색기 트리/목록에 문서 폴더를 통합해 DB 없이도 접근 가능하게 하고, (2) "디비에 반영"으로 `files`에 등록해 참조·미디어 추가를 지원하며, (3) **모든 md 파일**이 UniversalViewer에서 parseMarkdown + useMermaid + .markdown-content로 일관되게 렌더링된다.
- **확정 설계**: 트리 = 클라이언트 병합(Option B). 디비 반영 = `files` + `file_references` (방안 1). 목록·뷰어·서빙은 위 4~5장대로 구현.
