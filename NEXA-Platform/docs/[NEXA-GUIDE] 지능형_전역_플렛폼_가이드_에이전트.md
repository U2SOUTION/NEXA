# [NEXA-SMART-GUIDE] 지능형 전역 플랫폼 가이드 에이전트

**개요**: 플랫폼 전역에서 동작하는 **스마트 가이드 에이전트** 설계. "매뉴얼의 디지털화"가 아니라 **AI와의 정서적 교감·비언어적 커뮤니케이션**과 **맥락에 따른 절제(말할 때만 말하기)** 를 목표로 한다.

**캐릭터 네이밍 후보**: NEXU, ATO, OPSI, MIR, SAGE (추후 확정)
넥슈, 옵시, 세가, 미르, 아토

---

## 1. 핵심 원칙

### 1.1 잔소리 배제: Contextual Silence (맥락적 침묵)

- 사용자가 능숙히 조작할 때는 가이드가 **비활성** 상태 유지. 필요할 때만 부를 수 있음을 인지시키는 수준.
- **Shadow Mode**: 화면 구석에서 캐릭터가 책 읽기·꾸벅꾸벅 자기 등.
- **Minimalist Hint**: 말풍선 대신, 다음 액션 버튼에 **Breathing 효과** 등 시각적 암시만.

### 1.2 적기 개입: Active Transition (무언 → 적극)

- **감지**: 커서가 특정 구역 3회 이상 왕복, 클릭 후 즉시 Undo 반복 등 "헤매는" 패턴 감지 시에만 개입.
- **단계 1 (무언)**: 캐릭터가 커서를 눈동자로 추적 → 사용자 인지.
- **단계 2 (적극)**: 기침·손 흔들기 등으로 주의 유도 후, 짧고 명확한 해결 제시.

### 1.3 표정 일치: Emotional Synchronization (감정 동기화)

- **상태별 표정**: 정상 작업(은은한 미소), 중요/경고(진지·긴장), 성공(환호·엄지), 오류(당황·사과).
- **Lip-Sync & Expression**: 텍스트 **Sentiment Analysis** 결과로 눈썹·입모양 실시간 연동.

## 3. 기술 구현 요점

### 3.1 "무언의 메시지": 시선 처리(Eye Tracking)

- 캐릭터 눈동자가 **마우스 커서** 추적.
- 커서가 버튼 등 오브젝트 위에 있으면 캐릭터도 해당 오브젝트를 주시.
- → "말하지 않아도 보고 있다"는 신뢰 확보, 개입 시 메시지 수용도 상승.

### 3.2 AI–애니메이션 동기화

| 요소                        | 내용                                                                                                  |
| --------------------------- | ----------------------------------------------------------------------------------------------------- |
| **스트리밍 기반 사전 판단** | 답변 전체 완료를 기다리지 않고, **첫 토큰** 단계에서 감정 판단 → 표정 애니메이션과 동시 시작.         |
| **상태 매핑 테이블**        | 감정(예: 분노)·강도 → 애니메이션 파일·프레임·재생 속도 매핑. (예: 분노·강 → 화남 애니메이션 2배속)    |
| **경량 추론 모델(SLM)**     | 감정 분류만 담당하는 소형 모델을 앞단에 배치, **0.1초 내** 표정 명령 생성. LLM 전체로 하면 지연 발생. |

### 3.3 시나리오 예시 (Context → Intent → Command)

| 상황              | AI 판단   | 애니메이션 명령어                              |
| ----------------- | --------- | ---------------------------------------------- |
| 사용자 욕설       | 경고/불쾌 | `STOP → REVERSE(to 1, speed 2x) → PLAY(angry)` |
| 복잡 연산 수행 중 | 집중/생각 | `PLAY(thinking, loop=true, speed 0.5x)`        |
| 마이그레이션 성공 | 축하/기쁨 | `PLAY(happy, once) → RETURN(idle)`             |

### 3.4 도메인별 시나리오 기초자료

플랫폼 **도메인 경로**별 캐릭터 역할(비유)·실효 시나리오·Rive 표정/동작 예시. 페르소나·명령 매핑 설계 시 참고.

| 도메인 경로   | 캐릭터의 역할 (비유) | 실효적 시나리오 (Action)                                                                                             | Rive 표정/동작 예시                |
| ------------- | -------------------- | -------------------------------------------------------------------------------------------------------------------- | ---------------------------------- |
| `/nexa-node`  | 꼼꼼한 엔지니어      | 노드 연결 중 논리적 오류(Loop 등) 감지 시, 캐릭터가 고개를 갸우뚱하며 해당 노드를 가리킴.                            | Thinking → Confused (갸우뚱)       |
| `/nexa-trace` | 감독 (Director)      | 녹화 시작 시 슬레이트를 치는 동작. 녹화 중 사용자가 실수로 되돌리기를 하면 "컷!" 하는 표정.                          | Excited (시작) → Serious (녹화중)  |
| `/infra`      | 시설 관리자          | 신규 사용자가 진입하면 지도(Blueprint)를 펼치는 모션. 오프라인 장비 발견 시 해당 방향을 보며 걱정스러운 표정.        | Welcoming → Worry (장비 점검)      |
| `/nexa-ai`    | 연구 파트너          | AI가 긴 답변을 생성할 때 함께 턱을 괴고 생각함. 답변이 만족스러우면(좋아요 클릭 시) 함께 환호.                       | Deep_Thinking → Clap (성공)        |
| `/nexa-panel` | 마켓 큐레이터        | 위젯 위에 커서를 올리면 캐릭터가 그 위젯을 보며 엄지를 척 올리거나(추천), 세부 정보를 읽는 흉내.                     | Curious → Thumbs_Up                |
| `/dev`        | 조용한 조력자        | Contextual Silence 극대화. 코딩 중엔 구석에서 졸거나 책을 봄. API 에러(400/500) 발생 시에만 소스코드 쪽을 보며 당황. | Sleeping (평소) → Shocked (에러)   |
| `/my`         | 집사 (Butler)        | 사용자의 접속 기록이나 등급을 확인하며 정중하게 인사. 멤버십 혜택을 확인할 때 보물상자를 가리키는 동작.              | Polite_Bow (인사) → Sparkling_Eyes |

### 3.5 NEXA 연동 ([NEXA-AUTH-01])

- **Tier/이름**에 따라 캐릭터 동작 차등: 예) STANDARD 로그인 시 환영 애니메이션 더 활기차게.
- **에러 시**: 당황 표정 + `is_active: false` 디바이스를 가리키는 포즈 명령.
- 위 **도메인별 시나리오**(§3.4)와 조합해, 경로별 페르소나·표정 세트를 적용.

## 4. 애니메이션 엔진: Rive 권장

- **Lottie**: JSON 기반, 특정 프레임 재생 위주. 역재생·동적 보간은 코드 부담.
- **Rive**: **상태 머신**으로 JSON 입력값(감정·강도 등)에 따라 실시간 보간. `.riv` 바이너리로 Lottie 대비 10~15배 경량. **상태값만** PostgreSQL `jsonB`에 저장하면 됨.

**데이터 흐름**: Ollama(감정 JSON) → Node.js(전송 + jsonB 저장) → Vue + Rive(상태 머신 입력값 변경 → 표정/동작 출력).

- **Vue**: Rive 공식 Vue 런타임 지원, 반응형 데이터와 상태 연동 용이.
- **리소스**: GPU 가속, 화면 비가시/유휴 시 계산 중단으로 절전.

### 4.1 리소스 분산 전략 (프론트 vs 백엔드 AI)

역할을 나누어 **프론트엔드**는 표시·애니메이션, **백엔드**는 AI 추론만 담당하도록 한다.

| 구분           | 담당                | 역할                                                                                                                        | 비고                                    |
| -------------- | ------------------- | --------------------------------------------------------------------------------------------------------------------------- | --------------------------------------- |
| **프론트엔드** | Rive 엔진 + Vue     | **대화 내용** 렌더링(말풍선·텍스트), **간단한 애니메이션 명령** 해석·실행(PLAY/STOP/REVERSE 등), 시선 추적·입력 이벤트 수집 | 클라이언트 가벼움. 서버 왕복 없이 반응. |
| **백엔드**     | AI(LLM/SLM)·Node.js | **감정 분석**, **의도 판단**, **맥락 해석**, 애니메이션 **명령어 생성**(JSON). 대화 로그·상태 jsonB 저장                    | 무거운 추론은 서버에서만 수행.          |

- **프론트**: 백엔드가 내려준 **명령 JSON**(예: `{"emotion":"happy","intensity":80}`)과 **간단한 명령 시퀀스**(예: `PLAY(idle)` → `PLAY(thinking, loop)` )만 받아 Rive 상태 머신에 넣고, **대화 텍스트**는 그대로 표시. 추가 추론 없음.
- **백엔드**: 사용자 입력·시스템 이벤트를 받아 **AI로 감정/의도** 판단 후, **애니메이션 명령 JSON**만 스트리밍 또는 한 번에 전송. Rive/렌더링 로직은 모름.
- **효과**: 브라우저는 렌더링·이벤트·경량 로직만, 서버는 AI·저장만 담당해 **연산·대역폭 분산** 및 **지연 최소화**.

## 5. 페르소나·스킬·태스크 템플릿 및 회원 간 공유 (확장 비전)

DB의 **device_members**가 사용자–디바이스 관계를 연결하고 **디바이스 공유** 개념을 가능하게 하듯, 캐릭터의 **페르소나**를 **템플릿**으로 관리해 **회원 간 공유**로 확장할 수 있다.

| 개념                | 설명                                                                                                                                                         |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **페르소나 템플릿** | 페르소나(말투, 성격, System Prompt, 표정 세트)를 **템플릿**으로 저장. 사용자는 **캐릭터에 도메인별 페르소나**를 할당·조합할 수 있음.                         |
| **회원 간 공유**    | 사용자 A가 만든 페르소나(템플릿)를 다른 회원이 가져다 쓸 수 있도록 **공유** 기능. 스킬(Tools)·에이전트/태스크(워크플로우)도 동일하게 **템플릿화·공유** 가능. |
| **오픈 마켓 확장**  | 공유를 **무료** / **유료**로 확장하면, 플랫폼 내 **오픈 마켓** 형태로 전환 가능. 전문가가 만든 페르소나·스킬·태스크를 유로 배포하는 등.                      |

- **제공 방식**: 플랫폼이 **기본(디폴트)** 페르소나·스킬·태스크를 제공하고, 사용자는 **직접 추가**할 수 있음. 사용자 추가분이 플랫폼 기본을 **완전 오버라이드**할지, **추가만** 허용할지는 실제 사용 경험을 보며 결정.
- **참고**: [NEXA-AUTH-01]의 **device_members**는 “사용자–디바이스” 매핑과 디바이스 공유의 기반. 이와 같은 **user–persona**, **user–skill**, **user–agent_template** 매핑 및 공유 테이블 설계 시 위 비전을 반영할 수 있음. 관리자 도메인([NEXA-ADMIN-01] §4.6 AI 협력)의 페르소나 빌더·스킬 라이브러리·에이전트 설계와 연계.

---

**결론**: 스마트 가이드 완성도는 **맥락 파악 속도**와 **애니메이션 명령 변환의 실시간성**에 달려 있음. Rive 상태 머신 + 경량 감정 SLM + 스트리밍 감정 판단으로 실시간 정서 동기화 구현 권장.

## NEXU (가칭) 의 특징

NEXA + Issue (이슈)
NEXA + Sure (슈어)

원칙 1 (침묵): 넥슈는 평소에 대시보드 구석에 아주 작은 **'빛의 구체'**나 '차분한 눈동자' 형태로 머물며 존재감을 최소화합니다.

원칙 2 (개입): 사용자가 버튼 위에서 1.5초 이상 망설이면, 넥슈의 눈동자가 살짝 커지며 **"도움이 필요한가요?"**라는 무언의 표정 신호를 보냅니다.

원칙 3 (표정):
안심: 데이터 동기화 성공 시, 눈을 가늘게 뜨며 편안하게 웃는 표정.
주의: 잘못된 설정 입력 시, 눈썹(혹은 상단 라인)을 시옷(ㅅ)자로 만들며 걱정스러운 표정.
응원: 복잡한 작업을 완료했을 때, 윙크를 하거나 반짝이는 효과.

넥슈(NEXU)의 시선 처리 알고리즘: '관조와 집중'

1. 의도적 지연 (Damping & Ease-out)
   작동: 마우스가 움직일 때 넥슈의 눈동자가 즉시 반응하는 것이 아니라, 약간의 무게감이 느껴지도록 부드럽게 뒤따라오는(Following) 방식.

효과: 물리적인 질감이 느껴지며, AI가 기계적으로 반응하는 것이 아니라 '생각하며 지켜보고 있다'는 인상.

2. 관심 영역(Region of Interest) 고정
   작동: 마우스가 빈 배경을 돌아다닐 때는 넥슈가 멍하니 중심을 보거나 아주 천천히 눈을 깜빡입니다.

집중: 마우스가 [배포 시작], [삭제], [Tier 변경] 같은 중요 오브젝트(Critical UI) 위에 올라갔을 때만 넥슈가 그 버튼을 정확히 쳐다봄.

효과: 사용자는 "아, 넥슈가 내가 지금 중요한 결정을 하려는 걸 알고 있구나"라는 무언의 신호를 받게 됨

3. 시선 외면 (User Privacy Space)

작동: 사용자가 텍스트를 입력(Typing)하거나 복잡한 표를 분석 중일 때는 넥슈가 시선을 아래로 내리거나 다른 곳을 보며 **'방해하지 않는 상태'**가 됨.

NEXU 컨셉: 짙은 네이비 배경에 떠 있는 반투명한 유리 구체(Glassmorphism). 구체 내부에는 부드럽게 일렁이는 빛의 핵이 있고, 표면에는 감정을 표현하는 두 개의 디지털 수평선(눈)이 있습니다.
