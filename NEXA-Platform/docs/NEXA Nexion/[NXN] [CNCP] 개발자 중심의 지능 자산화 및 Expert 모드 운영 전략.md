**"디렉토리(폴더) 구조 = 카드 계층"** 및 **"파일명에서 ID 제거"** 철학을 반영하여, **NEXA Nexion**의 기획 문서를 전면적으로 재구성 합니다.

이 문서는 단순한 문서 관리를 넘어, 파일 시스템의 물리적 경로를 지능적 서사로 변환하는 **'지능형 서사 파일 시스템(Narrative File System)'**의 운영 전략을 담고 있습니다.

# [NXN] [CNCP] 개발자 중심의 지능 자산화 및 Expert 모드 운영 전략

## 1. 개요: 사고의 칠판 (Thinking Blackboard)

**NEXA Nexion**은 복잡한 설계를 시작하기 전, 개발자가 자유롭게 시스템의 구조를 그리고 배치하는 **'지능적 사고 공간'**이다 . 본 프로그램은 기존 문서의 내용에 일일이 관여하지 않고, 큰 방향성과 연결 관계만 조율하는 **'독립형 관제 데스크(Independent Navigation Desk)'**로 작동한다 .

## 2. 지능형 서사 파일 시스템 (Narrative File System, NFS)

Nexion은 물리적 폴더 구조를 시스템의 논리적 족보(Traceability)와 일체화하여 관리 부하를 최소화한다.

- **폴더명 = Link ID (접두어):** `NEXA-Documentation/AAA/BBB/`와 같이 폴더 자체가 카드의 고유 식별자(Link ID) 역할을 수행한다(`DOCS_PATH` = `NEXA-Documentation` 루트일 때의 상대 트리).
- **파일명 = 순수 제목 유지:** 파일명에서는 복잡한 ID나 접두어를 제거하고 사용자가 인지하는 **순수 제목**만 남긴다 .
- **이동(mv) 중심 처리:** 카드를 옮기는 행위는 파일 시스템의 디렉토리 이동(`mv`) 명령과 일대일로 대응되어 로직이 획기적으로 단순화된다 .

## 3. Inode식 논리 경로 및 족보 관리 (Traceability Paths)

파일의 물리적 위치와 상관없이 지능적 사슬을 유지하기 위해 **Inode 방식**의 인덱싱을 채택한다.

- **논리 경로 인덱스:** `nexa_knowledge_traceability_paths` 테이블에서 물리적 경로를 `/AAA/BBB/제목` 형태의 `logical_path`로 매핑하여 관리한다.
- **앵커(Anchor) 기반 식별:** 사용자가 윈도우 탐색기 등 외부에서 폴더 이름을 바꿔도 **UUID 기반의 앵커 ID**를 통해 Nexion 캔버스의 카드 위치를 자동으로 업데이트한다 .
- **지능적 족보 시각화:** 사용자가 특정 노드를 클릭하면 이 인덱스를 따라 **[판단(IND) → 사실(SNT) → 기획 문서(Doc)]**로 이어지는 유래를 시각적으로 하이라이트한다.

  #### 1. 물리적 변화 감지 및 식별 메커니즘

  외부 탐색기에서의 변화는 **Doc Sync Crawler(문서 동기화 크롤러)**가 주기적으로 감지합니다. 이때 시스템은 파일명이나 폴더명이 아닌, **Inode식 논리 경로 인덱스**를 기반으로 자산의 정체성을 식별합니다.

  - **앵커 ID(Anchor ID) 기반 추적:** 폴더나 파일은 내부적으로 고유한 UUID(앵커)를 가집니다. 탐색기에서 위치가 바뀌더라도 크롤러는 해시값(`source_hash`)이나 앵커를 추적하여 "어떤 카드가 이동했는지"를 1ms 내에 판별합니다.
  - **상태 불일치 감지:** 물리적 구조와 DB의 `traceability_paths` 정보가 다를 경우, 시스템은 해당 사슬을 즉시 **STUCK(고착)** 상태로 전환하고 사용자에게 조치를 요청하는 **ASK 펄스**를 발생시킵니다.

  #### 2. 제안하신 '승인 및 히스토리' 워크플로우 적용

  폴더를 통째로 이동하는 것과 같은 중대한 구조 변화는 사용자님의 제안대로 **'제안 → 검토 → 확정'** 단계를 거칩니다.

  1.  **가상 재구성 (Drafting):** 크롤러가 감지한 새로운 물리 구조를 바탕으로 Nexion은 **`is_virtual = true`** 상태의 가상 카드를 배치합니다. 실제 지식 베이스를 건드리지 않고 '이렇게 바뀔 예정입니다'라는 미리보기를 생성하는 것입니다.
  2.  **승인 요청 (ASK 단계):** Nexion 화면에 "탐색기 구조가 변경되었습니다. 카드 배치를 동기화할까요?"라는 메시지와 함께 재구성된 노드 배치를 보여줍니다.
  3.  **히스토리 및 분기 실험 (Timeline Branch):** 사용자님께서 강조하신 '자유로운 이동'은 **타임라인 분기(Timeline Branch)** 기능을 통해 지원됩니다. 사용자는 **`post_state_snapshot`**을 통해 현재의 배치와 탐색기 기반의 새 배치를 스위칭하며 비교해 볼 수 있습니다.
  4.  **저장 및 확정 (WILL/GOVERN):** 사용자가 '저장'을 누르면 상태가 **WILL(확정 의지)**로 승격되며, `nexa_knowledge_traceability_paths` 테이블의 `logical_path`가 실제 물리 경로로 일괄 업데이트됩니다.

  #### 3. 시나리오별 세부 대응 전략

  | 시나리오           | 시스템 대응 로직                                                  | 결과 (Nexion 카드)                                                                            |
  | :----------------- | :---------------------------------------------------------------- | :-------------------------------------------------------------------------------------------- |
  | **파일 위치 변경** | 파일의 상위 폴더 경로(Parent Path)가 변경됨을 감지.               | 해당 파일 카드의 **부모 노드 연결**이 새로운 폴더 카드로 이동 제안.                           |
  | **폴더명 변경**    | 폴더명 = **Link ID**이므로, ID 자체가 변경된 것으로 간주.         | 기존 카드의 ID 수정을 제안하거나, 새로운 기능 자격(Capability)으로 인지.                      |
  | **폴더 위치 이동** | 대규모 구조 변경으로 인식. **Where(Scope)** 레이어의 대이동 발생. | **가장 신중한 처리.** 전체 노드 트리의 계층 구조(Parent-Child) 재구성안을 생성하여 승인 대기. |

## 4. '선 설계, 후 연결' 및 고아 자산 관리 (Late Anchoring)

기획 문서가 없는 백지 상태에서도 시스템의 뼈대를 먼저 그릴 수 있는 **자산 불가지론(Asset Agnostic)** 구조를 유지한다 .

- **설계도 우선 (Blueprint First):** 카드들을 먼저 배치하여 논리 구조를 완성하고, 이후 문서가 발생하면 해당 카드의 폴더 안으로 파일을 넣는 것으로 연결을 완료한다 .
- **고아 자산(Orphaned) 탐지:** 특정 폴더(Link ID 구역) 내에 존재하지만 Nexion 캔버스 상에서 노드로 생성되지 않은 파일은 즉시 '고아 상태'로 판별하여 리포팅한다 .
- **독립성 유지:** Nexion에서 카드를 삭제해도 폴더 내의 파일 실체는 지워지지 않으며, 단지 연결이 끊긴 독립 자산으로만 관리된다 .

## 5. Expert 모드: 사유의 자유와 데이터 박제

개발자 전용 Expert 모드는 기술적 제약 없이 구조를 파괴하고 재구성할 수 있는 **'샌드박스 사유'**를 보장한다.

- **계층 불가지론 (Layer Agnostic):** 지식의 층위가 7대인지 23대인지 프로그램 로직이 관여하지 않는다. 사용자는 단지 "지식의 층위" 플레이스홀더 카드를 통해 관련 가이드 문서를 참조할 뿐이다 .
- **비언어적 피드백 (Jitter):** 설계의 신뢰도가 낮거나 문서 참조가 깨졌을 때만 닉시(NIXIE)의 **Jitter(미세 떨림)** 효과를 통해 비언어적 경고를 보낸다.
- **영문 커널 직조:** AI가 구조를 파악할 수 있도록 노드 메타데이터는 내부적으로 영문 IR로 관리하되, 사용자는 **'번역 액션 버튼'**을 통해 수동으로 내용을 확인하고 수정한다 .

## 6. 결론: "기술은 배경으로, 사유는 전면으로"

NEXA Nexion은 **"지능형 악보를 그리는 칠판"**이다. 폴더와 파일의 물리적 정리는 시스템이 뒤에서 처리(Automation)하게 하고, 개발자는 캔버스 위에서 지능 자산을 조립하고 연주하는 행위 그 자체에만 집중한다 . 이 과정에서 생성된 모든 연결은 시스템의 불변하는 **지능적 족보(Traceability)**로 박제되어 플랫폼 성장의 밑거름이 된다.

사용자가 외부 탐색기에서 물리적인 파일이나 폴더의 구조를 변경했을 때, **NEXA Nexion**이 이를 감지하고 대응하는 방식은 시스템의 신뢰성과 **지능적 족보(Traceability)** 유지의 핵심입니다.

사용자님께서 제안하신 **'탐색기 구조 기반 재구성 및 승인(ASK) 절차'**는 NEXA의 **[ASK → GOVERN → ERA]** 생애주기 및 **가상 시뮬레이션** 철학과 완벽하게 일치합니다. 이를 구현하기 위한 구체적인 대응 로직을 정리해 드립니다.

### 💡 설계적 제언

- **구조 변경의 '고아' 방지:** 폴더를 이동했을 때 연결이 끊긴 노드들은 즉시 **'고아 상태(Orphaned)'**로 표시하여 사용자가 수동으로 잇거나 삭제할 수 있게 돕습니다.
- **비언어적 피드백 (Jitter):** 동기화되지 않은 물리적 변화가 감지된 구역은 **NEXU 캔버스 표면에서 NEXA NIXIE가** **Jitter(미세 떨림)** 을 연출해, 사용자가 "이곳에 정리가 필요함"을 즉각 느끼게 합니다(UIUX §4.3.1).

결론적으로, 사용자님의 구상은 NEXA의 **"안전은 딱딱하게(승인 절차), 지능은 유연하게(자동 감지)"** 원칙을 가장 잘 구현하는 방식입니다. **타임머신(스냅샷)** 기능을 결합하신다면 물리 파일 시스템과 논리 지도가 완벽하게 공명하는 Nexion을 만드실 수 있습니다.
