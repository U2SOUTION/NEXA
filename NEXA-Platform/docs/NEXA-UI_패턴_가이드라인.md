# UI 패턴 가이드라인 - 모달 vs 사이드바

## 현재 프로젝트 사용 현황

### 모달창 (q-dialog) 사용 사례

1. **추가/수정 다이얼로그** (`PartClassesView.vue`)

   - 부품 분류 추가/수정 폼
   - 전체 화면 모달 (no-backdrop)
   - 복잡한 폼 입력

2. **삭제 확인 다이얼로그** (`PartClassesView.vue`)

   - 삭제 확인 및 상세 정보 표시
   - Persistent 모달 (확인 전 닫기 불가)

3. **관리 모달** (`PartsManagementSidebar.vue`)
   - 부품함 모델 관리 모달 (`BinModelManagementModal`)
   - 부품함 배치 공간 관리 모달 (`SpaceManagementModal`)

### 사이드바 사용 사례

1. **정보 표시** (`PartsManagementSidebar.vue`)

   - 호버 뷰 (빠른 미리보기)
   - 상세 뷰 (단일 항목 상세 정보)
   - 멀티 셀렉션 뷰 (선택된 항목 목록)

2. **네비게이션**
   - 물리 공간 트리 네비게이션
   - 부품 데이터 관리 메뉴

## 모달창 vs 사이드바 비교

### 모달창 (q-dialog)

#### 장점

1. **집중도**: 사용자의 주의를 완전히 집중시킴
2. **모바일 친화적**: 전체 화면 모달로 모바일에서도 사용하기 좋음
3. **명확한 작업 완료**: 확인/취소 버튼으로 작업의 시작과 끝이 명확
4. **폼 입력에 적합**: 복잡한 폼 입력 시 적합
5. **확인 다이얼로그**: 중요한 작업 전 확인에 적합

#### 단점

1. **기존 컨텍스트 차단**: 배경 작업을 볼 수 없음
2. **작업 흐름 중단**: 모달을 닫아야 다른 작업 불가
3. **데스크톱에서 공간 활용**: 사이드바보다 공간 활용이 제한적일 수 있음

#### 적합한 사용 사례

- ✅ **폼 입력**: 추가/수정 폼
- ✅ **확인 다이얼로그**: 삭제 확인, 중요 작업 확인
- ✅ **단일 작업**: 한 가지 작업에 집중해야 할 때
- ✅ **모바일 우선**: 모바일에서 주로 사용되는 기능

---

### 사이드바

#### 장점

1. **컨텍스트 유지**: 메인 화면을 보면서 작업 가능
2. **작업 흐름 연속성**: 사이드바를 열어둔 채 다른 작업 가능
3. **정보 표시**: 상세 정보, 목록 등을 표시하기에 적합
4. **데스크톱 최적화**: 넓은 화면에서 효율적
5. **비동기 작업**: 여러 작업을 동시에 볼 수 있음

#### 단점

1. **모바일 제약**: 작은 화면에서 공간 부족
2. **집중도 낮음**: 배경 작업에 주의가 분산될 수 있음
3. **명확성 부족**: 작업의 시작과 끝이 모호할 수 있음

#### 적합한 사용 사례

- ✅ **정보 표시**: 상세 정보, 목록, 통계 등
- ✅ **빠른 탐색**: 호버 뷰, 미리보기
- ✅ **비동기 작업**: 여러 항목 비교, 참조
- ✅ **데스크톱 우선**: 넓은 화면에서 주로 사용

## 권장 가이드라인

### 모달창을 사용해야 하는 경우

1. **폼 입력 작업**

   - 추가/수정 폼
   - 복잡한 설정 입력
   - 다단계 입력 프로세스

2. **확인/경고 다이얼로그**

   - 삭제 확인
   - 중요 작업 확인
   - 경고 메시지

3. **단일 작업 집중**

   - 한 가지 작업에 완전히 집중해야 할 때
   - 작업 완료 전 다른 작업을 막아야 할 때

4. **모바일 우선 기능**
   - 모바일에서 주로 사용되는 기능
   - 터치 인터페이스에 적합한 작업

### 사이드바를 사용해야 하는 경우

1. **정보 표시**

   - 상세 정보 표시
   - 목록 표시
   - 통계/요약 정보

2. **빠른 탐색/미리보기**

   - 호버 뷰
   - 빠른 정보 확인
   - 비교 작업

3. **비동기 작업**

   - 여러 항목을 동시에 참조
   - 작업 흐름을 중단하지 않고 정보 확인

4. **데스크톱 우선 기능**
   - 넓은 화면에서 효율적인 작업
   - 메인 화면과 함께 사용

## 관리작업 메뉴 기능별 권장 패턴

### 모달창 권장 기능

1. **편집** → 모달창

   - 복잡한 폼 입력
   - 현재 이미 모달창 사용 중 ✅

2. **복제** → 모달창 (구현 시)

   - 폼 입력과 유사한 작업
   - 확인 후 생성

3. **위치 정보 관리** → 모달창

   - 폼 입력 작업
   - 설정 변경

4. **위치 이동** → 모달창 또는 사이드바

   - 목적지 선택이 필요하면 모달창
   - 단순 이동이면 사이드바

5. **부품함 템플릿 생성** → 모달창

   - 폼 입력 작업

6. **일괄 작업** → 모달창
   - 복잡한 설정 입력

### 사이드바 권장 기능

1. **빠른 미리보기 (호버 뷰)** → 사이드바

   - 현재 이미 사이드바 사용 중 ✅
   - 간단한 정보 표시에 적합
   - 마우스 호버 시 빠른 정보 확인

2. **변경 이력** → 사이드바

   - 정보 표시
   - 목록 표시

3. **관련 부품 보기** → 사이드바

   - 목록 표시
   - 비교 작업

4. **부품함 목록 보기** → 사이드바

   - 목록 표시

5. **부품함 이력** → 사이드바

   - 목록 표시

6. **부품함 통계** → 사이드바
   - 통계/요약 정보 표시

### 모달창 또는 사이드바 모두 가능 (상황에 따라)

1. **내보내기** → 모달창 권장

   - 옵션 선택이 필요할 수 있음
   - 확인 후 실행

2. **인쇄** → 모달창 권장

   - 옵션 선택이 필요할 수 있음
   - 확인 후 실행

3. **활성화/비활성화** → 모달창 권장 (필터 결과 전체 적용 시)

   - 확인 다이얼로그 필요
   - 선택 항목만이면 사이드바에서 처리 가능

4. **즐겨찾기** → 사이드바 또는 즉시 실행

   - 단순 토글 작업
   - 확인 불필요

5. **상태 변경** → 모달창 권장
   - 상태 선택이 필요할 수 있음

## 모바일 대응 전략 (필수)

### 하이브리드 접근

1. **데스크톱**: 사이드바 사용 가능

   - 넓은 화면 활용
   - 컨텍스트 유지
   - 정보 표시, 빠른 탐색 등에 활용

2. **모바일**: **무조건 모달창**

   - 전체 화면 모달
   - 집중도 향상
   - 모든 기능을 모달창으로 통일

3. **반응형 전환 (필수)**
   - 화면 크기에 따라 자동 전환
   - 같은 기능이라도 디바이스에 따라 다른 UI
   - 데스크톱에서 사이드바로 표시되던 것도 모바일에서는 모달창으로 전환

### 구현 예시

```vue
<!-- 데스크톱: 사이드바 (컨텍스트 유지가 중요한 경우) -->
<q-drawer v-if="!isMobile && useSidebar" ...>
  <!-- 사이드바 내용 -->
</q-drawer>

<!-- 모바일: 무조건 모달창 -->
<q-dialog v-if="isMobile" v-model="showDialog" full-width full-height>
  <!-- 모달 내용 (전체 화면) -->
</q-dialog>

<!-- 데스크톱: 모달창 (관리 작업 기본) -->
<q-dialog v-if="!isMobile && !useSidebar" v-model="showDialog">
  <!-- 모달 내용 -->
</q-dialog>
```

### 관리 작업 메뉴 적용

- **기본**: 모달창 (데스크톱/모바일 모두)
- **예외**: 컨텍스트 파악이 중요한 경우만 사이드바 (데스크톱만)
  - 예: 변경 이력, 관련 부품 보기 등
  - 모바일에서는 동일 기능도 모달창으로 표시

### 특별 모달: 상세보기

- **상세보기** → **전체 화면 모달** (데스크톱/모바일 모두)
  - 사이드바 크기 제한으로 인해 상세 정보 표시에 부적합
  - 컨텐츠가 많거나 복잡한 정보 표시에 적합
  - 거의 전체 화면을 차지하는 모달 (`full-width`, `full-height`)
  - 집중도가 높은 정보 탐색에 최적화

2. **일관성 우선**: 기존 패턴과 일관성 유지
3. **예외 처리**: 특별한 이유가 있을 때만 다른 패턴 사용

## 최종 권장사항

### 1. 기본 원칙

**관리 작업 메뉴:**

- **기본**: 모달창 사용
- **필요 시**: 사이드바 사용 (컨텍스트 파악이 중요한 경우)

**데스크톱 vs 모바일:**

- **데스크톱**: 사이드바를 사용하여 컨텍스트 파악이 좋도록 일부 기능 할당
- **모바일**: **무조건 모달창** 사용

### 2. 일관성 유지

- 현재 사용 중인 패턴 우선 유지
- 새로운 기능은 유사한 기존 기능과 동일한 패턴 사용

### 3. 모바일 대응 (필수)

- **데스크톱**: 사이드바 사용 가능 (컨텍스트 유지)
- **모바일**: **무조건 모달창** (전체 화면 모달)
- 반응형으로 자동 전환 필수

### 4. 관리 작업 메뉴 패턴

- **대부분 모달창이 기본**
- **필요하면 사이드바 사용** (정보 표시, 컨텍스트 유지가 중요한 경우)

## Quasar 버튼 스타일링 규칙

### 문제 상황

Quasar의 `q-btn` 컴포넌트에서 커스텀 스타일을 적용할 때, 특히 `flat` 속성과 `color="primary"` 속성을 함께 사용하면 버튼 내부 텍스트 색상이 제대로 적용되지 않는 문제가 발생할 수 있습니다.

### 해결 방법

#### 1. 속성 제거

**사용하지 말 것:**

- `flat` 속성 제거
- `color="primary"` 속성 제거

**이유:** Quasar의 기본 스타일이 커스텀 CSS와 충돌하여 텍스트 색상이 적용되지 않음

#### 2. CSS로 처리 (권장)

**인라인 스타일 사용 금지:**

- `style="color: white"` 같은 인라인 스타일 사용하지 않음
- 모든 스타일은 CSS 클래스로 처리

**CSS 패턴:**

```css
.custom-confirm-btn {
  background-color: var(--q-primary);

  /* Quasar 내부 요소에 직접 스타일 적용 */
  :deep(.q-btn__content),
  :deep(.q-btn__content span) {
    color: white;
  }

  /* 추가 보장 */
  color: white;
}

.custom-confirm-btn:hover {
  background-color: var(--q-primary);
  opacity: 0.9;
  border-color: var(--q-primary);

  :deep(.q-btn__content),
  :deep(.q-btn__content span) {
    color: white;
  }

  color: white;
}
```

#### 3. 템플릿 예시

```vue
<q-btn
  :label="buttonLabel"
  @click="handleClick"
  class="custom-confirm-btn"
  :loading="isLoading"
  :disable="isDisabled"
/>
```

### 적용 대상

- 모든 확인 버튼 (내보내기, 인쇄, 활성화/비활성화 등)
- 커스텀 배경색과 텍스트 색상이 필요한 모든 버튼

### 핵심 규칙

1. ✅ **CSS 클래스로만 스타일 처리**
2. ✅ **`:deep()` 사용하여 Quasar 내부 요소 스타일 적용**
3. ✅ **`flat` 및 `color` 속성 사용 금지**
4. ✅ **인라인 스타일 사용 금지**
