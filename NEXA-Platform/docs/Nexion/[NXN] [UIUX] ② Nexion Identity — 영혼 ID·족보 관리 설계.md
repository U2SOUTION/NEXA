## 1. 5대 정렬

| 5대 SSOT 요약 | 본 문서의 초점 |
| :--- | :--- |
| **역할** | **Identity ID(영혼 ID)** 발급·족보. 원장: `nexa_identities`. |
| **핵심 기능 — 설계·일반** | 6자 발급, AI 분류, `domain_tags` 등 메타, 족보 조회. |
| **핵심 기능 — 운영자** | `superseded_by_id`·`replaced_by_id` → Re-pointing → `domain_tags` 재매핑 → (조건부) 구 행 DELETE. **ASK → WILL**. |
| **비유** | 이름·신분증·유래. 정제는 호적·합가·주소 갱신. |

---

## 2. 일반 모드 vs 운영자(정제)

| 모드 | 사용자 | 설명 |
| :--- | :--- | :--- |
| **일반** | 설계자·운영 | 발급·조회·허용된 메타 편집. |
| **운영자(✦운영자✦)** | 슈퍼 관리자 등 | **지능 자산 정제 툴** — 병합 수렴·참조 이전·도메인 태그 배치·감사·선택적 DELETE. **별도 제품 타일(6대)로 두지 않고** Identity 화면 **탭·권한**으로 분리. |

---

## 3. UI 골격(예시)

- **목록·검색·필터:** `identity_id`, 접두·테넌트·상태·`domain_tags`.
- **상세·족보:** 별칭, 승계 포인터, 감사 링크.
- **정제(운영자):** 미리보기, 영향 참조 건수, **WILL** 게이트 — 전제·순서는 `__NEXA Identity ID 발급 및 처리 설계 v3.1.md` 「✦운영자✦」.

---

## 4. 정제 툴 흐름(요약)

**정본·승계 체인 확정 → 참조 Re-pointing → `domain_tags` 재매핑 → (전제 충족 시) 구 행 DELETE.**  
세부·금지 사항·스냅샷은 **Identity v3.1** 이 단정한다. 본 문서는 **어느 화면에 어떤 단계가 노출되는지** 만 안내한다.
