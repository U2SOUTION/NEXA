## 1. 5대 정렬 및 적용 범위

### 1.1 Nexion Narrative에서 다루는 것

| 5대 SSOT 요약 | 본 문서의 초점                                              |
| :------------ | :---------------------------------------------------------- |
| **역할**      | 지능형 서사 파일 시스템(NFS) — 물리 폴더를 **논리 지도**로. |
| **핵심 기능** | Inode식 앵커링, Doc Sync Crawler, 고아(Orphaned) 자산.      |
| **비유**      | 영혼의 **주소지·거주 구역**.                                |

### 1.2 적용 범위와 UI 골격

- **1차 무대는 중앙 콘텐츠 영역.** Nexion **도메인**의 **Vue Flow 캔버스**(노드·엣지·레이어·평면 확장)가 주 무대이며, 아래 **물리/논리 이원화·논리 계층** 규칙은 이 영역의 **행동·표현 모델**을 정의한다.
- **좌·우 드로어**는 중앙을 보조한다. **좌:** 탐색·계층·목록(물리 트리·리소스). **우:** 선택 항목 상세·메타·검수. “무엇을 지도 위에 둘 것인가”는 **중앙 규약 우선**, 좌·우는 **같은 상태의 보조면**.
- **전역 재사용:** 드로어 내부 UI는 플랫폼 **공통 슬롯**으로 뽑을 수 있게 하고, **Nexion 전용 규칙**(Link ID, Why Chain 등)은 **`domains/nexion`** 모듈에만 둔다.

## 2. 핵심 철학: 물리와 논리의 이원화

- **물리(Storage)** 와 **논리(Context)** 를 **일치시키려 하지 않는다.** 파일이 저장된 위치(물리)와, 파일 **사이의 관계**(논리)는 별개다. 물리는 **거처**, 논리는 **흐름**이다.
- **원칙:** 데이터의 **크기·위치(물리)** 는 압축·고정할 수 있으되, 데이터 **사이의 방향성(의미 관계)** 은 보존하여 지능적으로 관리한다.

---

## 3. 물리 계층 (Physical Layer): 정보의 거처

물리 구조는 단순 ‘파일 정리’를 넘어 **다중 상태**로 분화한다.

| 상태                         | 설명                                                                       |
| :--------------------------- | :------------------------------------------------------------------------- |
| **현재 물리 (As-Is)**        | 실제 저장소의 폴더 구조. 작업 기준점.                                      |
| **수정/가상 물리 (To-Be)**   | 사용자가 구상한 미래 구조. 실제 이동 **전** 가상 배치.                     |
| **추천 물리 (AI Suggested)** | 의미 분석 기반 제안 폴더 구조.                                             |
| **동기화(Commit)**           | 가상·추천이 **확정될 때만** 실제 디렉터리를 재구성해 인지적 연속성을 유지. |

---

## 4. 논리 계층 (Logical Layer): 사고의 연결

논리는 물리 제약 없이 확장한다.

- **평면적 확장 (Flat Expansion):** 노드 클릭으로 하위를 펼치거나 접는(Accordion) 방식으로 **공간 기억** 유지(프랙탈 줌 대안으로의 선택지).
- **다중 관계 라인 (Multi-Type Edges):**
  - **물리 라인:** 실제 폴더 소속 관계.
  - **의미 라인:** 사용자가 직접 잇는 데이터 흐름·영감·전원 계통 등.
- **의지적 압축 (Manual Aggregation):** 체득이 끝난 덩어리를 **슈퍼 노드**로 압축해 시각 노이즈 감소.

## 5. 구현·운용 전략 (Vue Flow + AI)

**중앙(캔버스)** 과 **좌·우(드로어)** 역할을 구분한다.

| 전략                           | 내용                                                                                                                                      |
| :----------------------------- | :---------------------------------------------------------------------------------------------------------------------------------------- |
| **직접 조율 (Manual Mapping)** | AI에 전부 맡기지 않고 **중앙**에서 좌표·관계를 직접 설정해 설계자가 시스템을 **체득**하게 함.                                             |
| **레이어 토글 (Layer Toggle)** | **중앙**에서 물리 뷰·논리 뷰·특정 성격 라인만 선택 렌더링. 토글 **컨트롤 배치**는 UI 셸 규약, **의미(무엇을 가릴지)** 는 본 절·§4와 정합. |
| **AI 역할**                    | 구조 모순 검사·문서 간 맥락 리마인드 등 **검수·보조** → **우측 패널** 알림·요약. 반복 패턴은 **검수/인사이트 블록**으로 분해해 재사용.    |

## 6. 식별자·용어·Capability (횡단 정리)

Nexion에서 **추론 입력 단위**를 AI에 넘길 때 **식별자가 흔들리면** 벡터·요약·족보가 **통째로 불안정**해진다. UI(중앙·좌·우)와 별도로 **불변 키**만 압축한다. _(상세 SSOT: Glossary·Capability·스키마 문서.)_

### 6.1 경로·가변 논리를 ID 본문에 넣지 않는다

| 대상                 | 이유                                                                                                     |
| :------------------- | :------------------------------------------------------------------------------------------------------- |
| **물리 경로·파일명** | 이동·리네임으로 변함 → **불변 ID 본문**으로 쓰면 파이프라인·인덱스가 끊김.                               |
| **캔버스 논리 계층** | 부모·자식·슈퍼 노드·Why Chain 상 위치 등은 편집으로 **가변** → 불변 논리 슬롯이 아니면 ID에 넣지 않는다. |
| **문서 단위 추적**   | **`anchor_id`(UUID 등) 불변 앵커** 를 축으로 하고, 경로·논리 위치는 **메타데이터**로 갱신.               |

### 6.2 용어 단위 발급 + 의미는 메타

- **용어**를 AI·지식의 최소 엔티티로 두고 **불변 `term_id`(UUID 등)** 를 발급한다. 라벨·정의·동의어·출처·버전·해시 등은 **전부 메타**.
- **표기 문자열을 ID로 쓰지 않는다.** 다국어·동음이의는 **엔티티 분리**와 메타로 처리.
- **플랫폼 Capability ID** (`nexa.*`, Tier·메뉴)와 **추론 자산 스코프**는 역할이 다르다. 앵커·용어 축과 정렬하고, 전역 규약은 `__NEXA Capability ID 체계와 발급 및 Tier 접근 권한.md`, `[NXN] [SCHM] …` 등과 **네임스페이스·테이블** 수준에서 맞춘다.
