## [NXN-SPEC] 심플 닉시 GSAP 적용 UI 구현 v0.1

**문서 성격:** 온라인 미니 닉시의 **시각 연출·UI·GSAP** 상세. 학습·정리용으로 수치·우선순위는 구현 단계에서 확정할 수 있다.
**구현 우선순위:** **본 문서를 1차 진행의 기준(SSOT)** 으로 둔다. Nexion·실 API·스트림 연동보다 앞서, 아래 **「액션 버튼 시뮬레이션」** 으로 지능형 표현과 GSAP 파이프라인을 검증한다.
**필수 선행(데이터·계약):** `docs/Nexion/[NXN] [SPEC] 심플 닉시(Simple NIXIE) 테스트 버전 구현 명세.md` — **N-MAP Pinia 스냅샷·파일 구조·스냅샷 기본값**. 해당 명세에서는 **CSS 키프레임 기반 연출을 쓰지 않으며**, 본 문서에서 **GSAP**으로 구현한다.
**의존성:** `NEXA-Platform/package.json`에 **`gsap`** 추가(버전은 도입 시 팀과 합의).
**관련 설계:** `docs/NIXIE ARCH 닉시 설계도.md` 등.

### 1차 진행 계획: 지능형 표현 요소 → 임시 액션 버튼 시뮬레이션

**원칙:** 아래 **지능형 표현 요소(기초 9 + 시스템 8)** 는 처음부터 실데이터·N-MAP 스트림에 묶지 않고, **`NixieDevControls.vue`** 의 **임시 액션 버튼(또는 소수의 조합 버튼)** 으로 **원하는 요소만 골라 시뮬레이션**할 수 있게 만든다.

| 단계          | 내용                                                                                                                                                                                                       |
| :------------ | :--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **버튼 역할** | 각 버튼(또는 버튼 그룹)은 특정 표현 요소를 가리킨다. 클릭 시 `useNmapSnapshotStore`의 **action** 호출, 또는 해당 요소 전용 **GSAP 트리거 함수** 호출(스토어 필드와 1:1이 아닐 수 있는 요소는 헬퍼로 분리). |
| **목적**      | 연출이 의도대로 보이는지·프레임·타임라인 순서를 **수동으로 재현**해 디자인·기획 합의를 먼저 얻는다.                                                                                                        |
| **범위**      | 17개를 **한 번에** 다 넣을 필요는 없다. 우선 **Lumina·Jitter·갸우뚱·Reddish·맥박** 등 핵심부터 버튼을 붙이고, 나머지는 이터레이션으로 추가한다.                                                            |
| **배치**      | **`NixieDevControls.vue`** — **NexionRightPanel** 아코디언(위 **「개발용 컨트롤」**).                                                                                                                        |

**정리:** 실서비스 입력이 오기 전까지, **지능형 표현 요소 = 액션 버튼으로 시뮬레이션**하는 것을 **본 v0.1 구현의 기본 진행 방식**으로 명시한다.

### 시뮬레이션 우선: N-MAP 스토어(Pinia) 강제 변경

프로토타입은 **실시간 스트림·Nexion 생산자 없이** 먼저 돌려볼 수 있게 구성한다. 핵심은 **`useNmapSnapshotStore`(N-MAP Pinia)의 상태값을 개발용 UI에서 강제로 바꿔** 닉시 반응(GSAP·도트)을 즉시 확인하는 것이다. 버튼·슬라이더·토글은 모두 **스토어 `actions`를 경유**해 스냅샷을 갱신하고, `NixieOnlineCharacter`는 **구독만** 하여 연출한다.

아래는 **우선 시뮬레이션해 볼 시나리오**를 문서에 고정한다. 스냅샷 필드명(`ui_entropy_mode`, `is_virtual`, `source_shell_id`, `user_defined_threshold` 등)은 구현 시 타입 정의에 맞추되, **의미는 본 절과 동일**하게 유지한다.

#### 로우-엔트로피 제동 (Low-Entropy Throttling)

| 구분 | 내용 |
| :--- | :--- |
| **동작** | `ui_entropy_mode`를 **`minimal`** 또는 **`static`** 으로 전환하는 버튼(또는 모드 선택). |
| **검증** | 복잡한 GSAP 애니메이션·Jitter 연산이 **억제**되고, 인지 부하를 줄이는 **정적인 도트 패턴**으로 **즉시** 전환되는지 확인한다. |

#### 가상 실행 고스트 레이어 (Virtual Ghosting)

| 구분 | 내용 |
| :--- | :--- |
| **동작** | `is_virtual = true` 를 활성화하는 버튼(토글). |
| **검증** | 도트 **투명도 감소** 또는 **점선 형태의 잔상(Ghosting)** 등으로, 현재 동작이 **실제 기기 제어가 아닌 가상 시뮬레이션**임을 시각적으로 구분할 수 있는지 확인한다. |

#### 쉘 컨텍스트 및 외부 자원 유입 (Nebula Influx)

| 구분 | 내용 |
| :--- | :--- |
| **동작** | `source_shell_id`를 **현재 쉘과 다른 외부 기기**로 가정한 값으로 바꾼 패킷 유입을 시뮬레이션하는 버튼(또는 프리셋). |
| **검증** | 캔버스 **외곽(VOID 영역)**에서 새 도트 클러스터가 날아와 정착하는 **성운 유입** 연출이 자연스럽게 실행되는지 확인한다. |

#### 사용자 정의 임계값 가변성 (Threshold Sensitivity)

| 구분 | 내용 |
| :--- | :--- |
| **동작** | `user_defined_threshold`를 **실시간 조절**하는 슬라이더 또는 단계 버튼(예: 95 → 98). |
| **검증** | **동일한 `confidence_score`**에서도 임계값이 올라가면 닉시가 즉시 **Jitter(미세 떨림)**를 일으키며 **ASK(승인 대기)** 신호를 보내는지 테스트한다. |

### 구현 방향 요약

- **연출:** Lumina·Jitter·갸우뚱·Reddish 등은 **GSAP** (Timeline / Tween). **순수 CSS `@keyframes`로 대체하지 않는 것**을 기본으로 한다.
- **프로토타입:** Nexion·실데이터 없이도 검증할 수 있도록 **임시 액션 버튼·클릭 핸들러**를 두어 `nmapSnapshotStore`의 **actions**(및 요소별 GSAP 헬퍼)만 호출해도 닉시가 반응하게 만든다 (스토어 계약은 테스트 버전 명세와 동일).
- **물리 규격:** 뷰포트 **약 180×60 px**, 도트 **18×6(가변 가능)** — 테스트 버전 명세와 맞출 것.

### 방향 전환: Rive → GSAP (온라인 미니 닉시)

- **이전 가정(비전·아키텍처 문서에 남아 있는 표현):** 닉시를 **Rive** 벡터 캐릭터(표정·상태 머신)로 두고 N-MAP과 연동하는 경로.
- **플랫폼 온라인 HUD에서의 방향:** **도트·정보 그리드**를 **GSAP**으로 연주한다. **“캐릭터 일러스트”가 아니라 “정보·상태의 생동감·인격적 교감”**을 **DOM/SVG/Canvas + Timeline**으로 표현한다.
- **Rive와의 관계:** Rive는 다른 표면에서 유효할 수 있다. **본 GSAP UI 명세**에서는 **GSAP을 1차 런타임**으로 두고, Rive 의존은 필수로 두지 않는다.

### [NIXIE] GSAP 기반 지능형 표현 요소 (참고 목록)

아래 항목은 **구현 시 임시 액션 버튼과 매핑**하여 시뮬레이션한다(위 **「1차 진행 계획」** 참조).

#### 1. 기초 요소 (9)

1. **도트 상태 연출:** 점멸, 페이드, 색상 변화 등 기본 상태값 제어.
2. **도트 눈(Eyes):** 특정 좌표 도트의 깜빡임·시선·감정에 가까운 패턴.
3. **도트 텍스트:** 격자 밀도를 활용한 Identity ID(6자)·짧은 영문 IR 출력.
4. **도트 정보 그래프:** 높낮이·밀도로 실시간 데이터 차트화.
5. **인격적 갸우뚱:** 전체 컨테이너 가변 회전(예: `Back.out`)으로 혼란·질문 뉘앙스.
6. **탄성 반응 (Squash & Stretch):** 박스가 젤리처럼 튀는 느낌(예: `Elastic.out`).
7. **가변 밀도 LOD:** 줌·맥락에 따라 도트 밀도를 바꾸는 프랙탈적 시각화.
8. **도트 음파:** 모스·주파수와 동기화된 유기적 흐름.
9. **레이아웃 변형:** 사각 그리드 ↔ 원형·마름모 등 배치 전환.

#### 2. 시스템 아키텍처 기반 추가 요소 (8)

10. **지능적 맥박 (Intelligence Pulse):** 시스템 활력 지수(VI)와 동기화된 호흡.
11. **의도 중력 왜곡 (Intent Gravity Warp):** WILL·포커스 방향으로 도트가 끌리는 연출.
12. **신뢰도 지터 (Confidence Jitter):** 신뢰도 임계(예: 95 미만)에서의 비언어적 경고.
13. **시스템 체온 (Reddish Gradient):** 긴박도·부하에 따른 호박→붉은 그라데이션.
14. **프랙탈 폭발/함몰 (Singularity Sync):** 차원 전이 시 흩어짐·한 점으로 수렴.
15. **서사적 잔상 (Narrative Trace):** Why Chain 등 궤적의 느린 잔상.
16. **고스트 레이어 (Virtual Ghosting):** `is_virtual=true` 등 점선·반투명 환영.
17. **외부 자원 편입 (Nebula Influx):** 외부 API·프로젝트 연결 시 VOID에서 유입·정착.

### GSAP란 무엇인가 (본 프로젝트에서의 위치)

웹에서 **연속 상태의 수학적 보간**을 쓰기 쉬운 라이브러리로 이해하면 된다. DOM·SVG·Canvas 위 요소의 **A→B 전이(Tween)**, **Timeline**으로 순서 제어, **이벤트·포인터와 결합**이 강점이다. 수천 도트가 필요해지면 **Canvas + GSAP(좌표만 갱신)** 조합으로 논리는 Processing에 가까워진다.

---

### 렌더링 전략: SVG vs Canvas (요약)

| 방식       | 적합한 경우                            | 장점                                              | 주의                                                                                    |
| :--------- | :------------------------------------- | :------------------------------------------------ | :-------------------------------------------------------------------------------------- |
| **SVG**    | 도트 수백 개 수준, 개별 클릭·필터 실험 | 벡터 선명도, 요소 단위 이벤트, GSAP가 좌표만 제어 | `feGaussianBlur` 등을 전 도트에 실시간 적용하면 모바일에서 부담 → 그룹 단위·필요 순간만 |
| **Canvas** | 입자 수천·강한 혼합·역동적 블러        | 한 장 비트맵으로 그려 부담 분산 가능              | 직접 그리기/지우기 로직·HiDPI 스케일 처리 필요                                          |

**권장:** 도트 **300개 이하**·블러 실험이 많으면 **먼저 SVG**를 기준으로 두고, 부족하면 Canvas로 이전한다.

### 성능·구현 메모 (GSAP)

1. **RequestAnimationFrame** — 브라우저 페인트에 맞춤 (배터리·프레임).
2. **GPU:** 가능하면 `transform` / `x` / `y` / `scale` 중심(`top` / `left` 남용 자제). SVG에 `force3D: true` 등은 GPU 레이어 분리에 도움이 될 수 있으나 과용 금지.
3. **애니메이션 종료 후 정리** — 불필요 트윈·리스너 해제로 GC 압력 완화.

**시각 효과:**

- **CSS Filter**를 도트마다 겹치게 걸면 비용이 커진다. 블러가 필요하면 `<defs>` 필터·미리 블러 넣은 스프라이트·상호작용 순간만 블러 해제 등으로 나눈다.
- **심도(Depth of Field):** 뒤쪽 도트만 블러 등으로 입체감.
- **잔상:** 고속 이동 시에만 일시 블러, 정지 시 선명.

### 개발용 인터랙션 (프로토타입)

- **컨테이너:** 모든 시뮬 UI는 **`NixieDevControls.vue`** 에만 둔다. **Nexion 우측 패널 아코디언** 배치는 위 **「개발용 컨트롤」** 절.
- **스토어 강제 변경:** 상세 시나리오는 **「시뮬레이션 우선: N-MAP 스토어(Pinia) 강제 변경」** (로우-엔트로피·고스트·네뷸라·임계값).
- **임시 액션 버튼:** **지능형 표현 요소 목록**과 대응. 예) 「정상 FLOW」「저확신」「STUCK」「타임아웃」「맥박만」「갸우뚱만」 등. 클릭 시 `useNmapSnapshotStore`의 **action** 또는 **요소별 GSAP 헬퍼** 호출 → `NixieOnlineCharacter`는 구독으로 GSAP 트리거.
- **가시성:** 배포 포함 시 사용자에게 노출될 수 있음. 숨김이 필요하면 **NexionRightPanel**에서 아코디언 제거 또는 설정 플래그로 제어(팀 규칙).

### 정리

- 본 문서는 **GSAP·`NixieDevControls.vue`·Nexion 우측 아코디언·임시 액션 버튼 시뮬레이션**의 상세를 담는다. **N-MAP 필드·기본값·Pinia 경로**는 `심플 닉시(Simple NIXIE) 테스트 버전 구현 명세.md` 를 SSOT로 한다.
- **Rive 기반 캐릭터**는 본 경로의 필수 스택이 아니다.
- 세부 수치·프레임 예산·우선 구현 순서는 구현 중 확정한다.
