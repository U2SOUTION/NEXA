## TipTap 편집 시 Ollama로 구현하는 기능 (명시)

### 구현하는 기능 (v1·Nexion Extension이 보장하는 것)

| ID | 기능명 | 동작 | 입력 | 출력·반영 위치 | 비고 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **NXN-OLL-01** | **현재 문서 핵심 용어·설명 추출** | 사용자가 **「핵심 용어 추출」**(또는 동등 커맨드) 실행 | 그 시점 TipTap에 올라와 있는 **문자열 본문**(저장 여부와 무관하게 **에디터 스냅샷**) | **우측 `Terms Inspector`** 에 `term` + `description`(1~2문장) 목록. 사용자가 항목 선택 시에만 TipTap에 삽입 | API: `POST .../engines/term-extraction/v1/extract`(또는 동일 계약). 엔진 ID·계약은 SPEC §3·API §9 |

**정리:** TipTap 문서를 연 상태에서 Ollama(로컬)를 쓰는 **유일한 제품 기능**은 위 **NXN-OLL-01** 이다. 모델·프롬프트는 전역 엔진 쪽(SPEC §3.5), UI 자리는 우측 패널(Vue Flow 운영 규약 §6.3).

### 구현하지 않는 것 (Ollama 미사용·명시)

아래는 **본 기획·Extension SPEC v1 범위 밖**이며, Ollama를 TipTap **편집 파이프라인에 자동으로 붙이지 않는다.**

| 구분 | 비포함 기능 | 이유(한 줄) |
| :--- | :--- | :--- |
| 편집 보조 | 타이핑 **인라인** 자동완성·Copilot식 연속 생성 | `onUpdate`마다 추론 호출 금지, 지연·비용 |
| 편집 보조 | 맞춤법·문체 **실시간** 교정 | 동일 |
| 메타 | 열자마자 자동 태그·자동 요약·자동 제목 생성 | 트리거 없음·덮어쓰기 위험 |
| 저장 | AI가 대신 저장·자동 커밋 | 저장은 사용자·API 계약(SPEC 기능 1) |
| 캔버스 | 노드 라벨·Why Chain을 AI가 **연속** 갱신 | 캔버스는 §2 로컬/저장 정책 |
| 원장 | 추출 결과를 Glossary 원장에 **자동 승격** | 후보일 뿐, ④ Glossary·거버넌스 |

## 1. 두 층: 로컬 실시간 vs Ollama


| 층                           | 의미하는 “실시간”                                                 | 엔진                           | 비고                                             |
| --------------------------- | ---------------------------------------------------------- | ---------------------------- | ---------------------------------------------- |
| **A. 로컬**                   | 에디터 내 글자·선택·스크롤, 탭 제목의 `*` 표시, (정책에 따라) 캔버스 노드 라벨·좌측 목록 메타 | Vue 반응형 상태·TipTap `onUpdate` | **네트워크 불필요**. 60fps에 가깝게 처리 가능.                |
| **B. Ollama(및 백엔드 추출 API)** | “지금 글을 읽고 의미를 돌려준다”                                        | HTTP 추론                      | **매 키 입력 호출 금지**. 명시적 액션·스로틀·청크 정책(SPEC §3.4). |


**원칙:** “실시간 반영”이라는 말을 쓸 때 **A와 B를 혼동하지 않는다.** B는 **사용자 의도가 있는 순간**에만 돌리고, 결과는 **우측 Terms Inspector** 등에 두어 **자동 삽입 금지**(기존 UIUX 규약 §6.3).

## 2. 로컬 실시간 반영 — 범위와 책임

아래는 **구현 시 선택지를 좁히는 기본안**이다. 제품에서 수치(디바운스 ms 등)만 조정한다.


| 대상                                | 반영 시점 (기본안)                                                                                                    | 데이터 소스                                |
| --------------------------------- | -------------------------------------------------------------------------------------------------------------- | ------------------------------------- |
| **TipTap 본문**                     | 입력 즉시(에디터 내부)                                                                                                  | 에디터 문서 상태                             |
| **탭 제목·미저장 배지**                   | `onUpdate` 후 짧은 디바운스(예: 0~50ms)                                                                                | dirty 플래그                             |
| **중앙 캔버스 노드 `data.label`(문서 카드)** | **옵션 1:** 첫 줄 제목/H1 파싱 후 **디바운스**(예: 300~500ms). **옵션 2:** 저장 성공 후에만 반영(저장 부담↓, “실시간” 체감↓). MVP는 **옵션 2**도 허용. | 파싱 규칙은 PRD·N-PATH와 정합                 |
| **좌측 Explorer** 파일명·수정 시각         | **저장 성공 후** 또는 로컬 파일 watcher가 있을 때만                                                                            | `updated_at`·`source_hash`는 API 응답 기준 |
| **우측 속성 패널** (제목·Link ID·IR)      | 선택 필드는 편집 중 로컬 미러링 가능, **서버 권위**는 저장 응답                                                                        | §3                                    |


**정리:** “실시간”의 핵심은 **에디터와 탭 UI**이고, **파일·DB·캔버스 영구 상태**는 **저장·동기화 경로**를 탄다. 캔버스 라벨을 타이핑마다 바꾸면 성능·번쩍임 이슈가 생기므로 **디바운스 또는 저장 후 갱신** 중 하나를 문서·팀에서 고정한다.

## 3. 편집 세션·저장·해시

1. **세션 열기:** SPEC §2.1 — 동일 `anchor_id` 재클릭 시 탭 포커스만.
2. **서버/파일 권위:** API `GET .../content` 로 초기 본문 로드(또는 로컬 Phase에서는 파일 직접 읽기 — PRD Phase에 따름).
3. **저장:** `PUT .../content` + `expected_source_hash`(API §7.2). 충돌 시 `409` → UI는 Vue Flow 운영 규약 §3.3(ASK·재시도).
4. **자동 저장(선택):** 켤 경우 **디바운스(예: 2~5s)** + 백그라운드 저장 실패 시 배너. 코어 Tier와 Ext 중 어디에 넣을지는 PRD Phase로 분리.
5. **편집 중 `source_hash`:** 클라이언트는 **마지막으로 알려진 해시**를 들고 있다가 저장 시 전송. 타이핑할 때마다 서버 해시를 갱신하지 않는다.

## 4. Ollama 연동 — 트리거·제약·UI (NXN-OLL-01 상세)

위 **「TipTap 편집 시 Ollama로 구현하는 기능 (명시)」** 절과 동일하다. 요약만 반복한다.


| 항목              | 정책                                                                                    |
| --------------- | ------------------------------------------------------------------------------------- |
| **구현 범위**       | **NXN-OLL-01 한 가지** — 핵심 용어·설명 추출. 그 외 Ollama 기능은 § 위 표 “구현하지 않는 것”.        |
| **트리거**         | **명시적만** — “핵심 용어 추출” 버튼·커맨드 팔레트 등(SPEC §3.1). `onUpdate` 연동 **금지**.                  |
| **입력**          | 요청 시점의 **에디터 본문 스냅샷** 문자열. 길이 초과 시 SPEC §3.4 청크·병합.                                       |
| **출력**          | Terms Inspector 목록. **자동 삽입 금지** — 사용자가 항목 선택 후 삽입.                                   |
| **실패**          | SPEC §3.3 — 1회 재시도 후 ASK. 에러 토큰은 SPEC §5.                                             |
| **보안**          | 기본 로컬 Ollama(SPEC §3.4). 원격 모델은 별도 옵션·정책 문서.                                          |
| **5대 Glossary** | 추출 결과는 **후보**이며, `nexa_knowledge_definitions` 등 **원장 승격**은 Glossary UI·거버넌스 흐름(④ 문서). |

## 5. TipTap ↔ Ollama 상호작용

- 문서가 편집되면 **이전 추출 결과는 “오래된 스냅샷”**임을 UI에 표시(배지·타임스탬프 권장).
- 사용자가 **저장하지 않은 채** 추출만 반복할 수 있으므로, 추출 요청 페이로드에는 **현재 에디터 버전의 본문**을 넣고, 필요 시 **클라이언트만의 `draft_revision` 카운터**로 혼동을 방지한다(서버 필드는 API 확장 시 정의).
- 용어를 에디터에 삽입한 뒤에는 **일반 편집**과 동일하게 dirty·저장 흐름을 탄다.
