## 1. 공통 골격: 스택과 3패널

| 구성요소                        | 역할 (구현 시 고정)                                                                                                                                                                                                                                                                            |
| :------------------------------ | :--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **ExplorerTree**                | **좌측.** 물리 파일 트리·리소스 목록·**이름 변경**·**디렉터리 이동·부모 변경**(드래그로 이동, `mv`에 대응)·**북마크·즐겨찾기**·**새 파일·폴더·삭제·복제**(권한 범위 내)·트리 **확장/축소**·**정렬·필터**·고아(Orphaned) 필터·검색·**DnD 소스**로 중앙에 연결. **긴 목록·계층 탐색의 주 무대.** |
| **Vue Flow** (`@vue-flow/core`) | **중앙.** 노드·엣지·줌·팬·선택. 상단 **6탭**(§5)으로 ①~⑤ 모드와 **⑥ TipTap** 을 전환한다. 5대마다 **노드 타입·엣지 의미**만 바뀐다.                                                                                                                                                            |
| **Dagre**                       | **자동 레이아웃.** 계층·방향 그래프를 **초기 배치·재정렬**할 때 사용. 수동 드래그와 공존 가능(정책은 제품에서 단정).                                                                                                                                                                           |

**3패널:** 좌 ExplorerTree · 중앙(6탭·§5) · 우 **Attribute**. 우측은 **§5「우측 사이드바」** — 활성 탭별 도구 + **공통 패널 항상 유지**. Database·Narrative가 이 조합과 가장 강하게 맞고, Identity·Glossary는 **중앙을 표·폼·그래프 위주**로 바꿀 수 있으나 **골격은 동일**하게 유지한다(기초 SSOT §4).

## 3. 횡단: 앵커·노드·Late Anchoring

- **`node_id` (Vue Flow)** ↔ **`anchor_id` (문서/파일)** 연결 테이블·API는 `[NXN] [SCHM] NEXA Nexion 독립형 인덱스 및 자산 관리 스키마.md`, `[NXN] [API] NEXA Nexion API 및 통신 규약.md` 가 SSOT.
- **Late Anchoring:** 캔버스에 **논리 뼈대**를 먼저 두고, ExplorerTree에서 **실체를 뒤늦게 붙이는** 흐름 — Narrative·Capability와 직접 맞닿음(기초 SSOT §6).
- **고아(Orphaned):** 트리·필터에서 드러내 캔버스 선택과 연동 → 앵커 재연결 유도.

## 4. 캔버스 밀도·성능(요약)

**원칙:** **문서(파일) 수 ≠ 캔버스 노드 수.** 긴 이름·전체 트리는 **좌측 ExplorerTree**에 두고, 중앙 노드에는 **요약·상태 신호**만 두어 **지도가 읽히게** 한다. DOM/SVG(Vue Flow) 부하는 **LOD·접기·필터·가시 노드 수 제한**으로 나눈다.

**중첩 카드·줌:** 전역 뷰포트 줌은 **균일 스케일**이라 “프랙탈처럼 층마다 읽기 단위가 바뀌는 진입”과 체감이 다를 수 있다. **한 층 들어가기** 느낌은 우측 상세·선택 포커스·모드 전환과 **역할 분담**으로 보완하고, 노드 내부 **중첩 Vue Flow** 는 기본값으로 두지 않는다(특수 타입·후속 단계만 검토).

## 5. 중앙 6탭: 5대 + TipTap

**확정:** 중앙 **콘텐츠 영역** 상단에 **탭 6개**를 둔다 — **① Database · ② Identity · ③ Capability · ④ Glossary · ⑤ Narrative · ⑥ TipTap(문서 편집)**. **항상 6개 모두 표시**하며, 특정 탭을 **비활성·숨김 처리하지 않는다.**

| 탭           | 역할                                                                                                                                                                                                                             |
| :----------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **①~⑤**      | `_[NXN] NEXA Nexion 5대 지능 관리 시스템.md` 의 **Database → Identity → Capability → Glossary → Narrative** 순서와 대응. 좌 ExplorerTree·중앙 주 무대·우 Attribute의 **컨텍스트**가 탭에 맞게 바뀐다.                            |
| **⑥ TipTap** | **마크다운 문서 본문** 편집. 저장·해시·용어 추출은 `[NXN] [UIUX] Nexion TipTap 편집·실시간 반영 및 Ollama 연동 기획.md`, 중앙·우측 배치는 `[NXN] [UIUX] NEXA Nexion 인터페이스 레이아웃 및 Vue Flow 운영 규약.md` §6·§8 과 정합. |

**레이아웃:** 탭은 **가로 공간이 충분한 데스크톱**을 전제로 하며, 6개가 **한 줄에 좁지 않게** 배치 가능하다고 본다. **반응형**(좁은 뷰에서 스크롤·드로어)은 구현 세부에서 처리하되, **6탭 구조 자체는 변경하지 않는다.**

### 우측 사이드바(Attribute): 탭 연동 도구 + 공통 패널

**원칙:** 캔버스 **하단 타임라인**이 활성 탭에 따라 **시간축·스냅샷 종류**를 바꾸는 것과 **같은 구조**로, **우측 사이드바**는 **현재 활성 탭**에 따라 **필요한 도구·패널**을 디스플레이한다. 동시에 **공통으로 쓰는 기능 패널**은 **탭과 무관하게 항상 유지**한다.

| 구분              | 구현                                                                                                                                                                                                                                                                 |
| :---------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **탭 전용(가변)** | 활성 탭 **①~⑥**에 맞는 **속성·도구만** 표시한다. §2 표 **«우측 패널 / 저장·API»** 열과 1:1로 맞춘다. (예: ① 컬럼·Dry-run·DDL 승인, ② Identity·족보 메타, ③ Tier·Late Anchoring, ④ 용어·IR·Terms Inspector, ⑤ `anchor_id`·동기화·충돌 ASK, ⑥ 편집 보조·용어 삽입 등.) |
| **공통(고정)**    | Nexion 데스크 전역에서 반복 참조하는 **기능 패널**은 **항상 같은 영역**에 둔다. 예: 워크스페이스·프로젝트 전환, **선택 대상 요약**(노드·문서 선택 시), 동기화·알림·ASK, (정책에 따른) 설정·계정 등. **숨기거나 탭마다 사라지게 하지 않는다.**                        |

**한 줄:** 우측 = **공통 뼈대(항상)** + **활성 탭 전용 도구(가변)**.

## 6. NEXA NIXIE(닉시)와 통신·연출

**위상:** **NIXIE**는 Nexion과 **별도 프로세스·전용 API로 “대화”하는 에이전트**가 아니라, **지식 원장·API가 주는 메타**를 **비언어 시각(Lumina·Jitter 등)** 으로 **그리는 표현 주체**다. **NEXU/Vue Flow 캔버스 = 좌표 표면**, **NIXIE = 그 위(및 전역 오버레이)에서 연출을 그리는 주체** — `[NXN] [UIUX] NEXA Nexion 인터페이스 레이아웃 및 Vue Flow 운영 규약.md` **§7.4~§7.4.1, §7.5**, `docs/NIXIE ARCH 닉시 설계도.md`, `docs/NIXIE 지능형 서사 및 감각 처리 통합 규약.md`.

| 언제                                                                                            | 어디에                                                                            | 무엇을                                                                                                                 | 입력·데이터(통신의 실체)                                                                                                                                                                                                                 |
| :---------------------------------------------------------------------------------------------- | :-------------------------------------------------------------------------------- | :--------------------------------------------------------------------------------------------------------------------- | :--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **탭 ①~⑤** 에서 **캔버스(Vue Flow)** 가 보이고, **노드 선택·갱신·동기화·신뢰도** 이벤트가 올 때 | **캔버스 위 노드·엣지**                                                           | Lumina·Jitter·Reddish 등 **비언어 피드백**                                                                             | `nexa_knowledge_traceability_paths`, `nexa_knowledge_doc_sync_state`(가중)·`confidence` 임계, (Tier B) `nixie_lumina_profile` 등 — **SCHM·API**가 SSOT. Tier A에선 **클라이언트 파생**으로도 연출 시작 가능(Vue Flow 문서 §2 Tier 설명). |
| **동기화 불일치·고아·ASK** 가 UI에 떠야 할 때                                                   | 위와 동일 + **공통 패널**(§5 우측)                                                | 배너·ASK·상태 요약과 **연출 강도** 연동                                                                                | 같은 원장 + N-PATH·Late Anchoring UI 흐름(§3, Vue Flow §9~§10).                                                                                                                                                                          |
| **플랫폼 전역**(Nexion 외 도메인 포함)                                                          | **`NixieOnlineCharacter`** — `MainLayout` 등 **frame** 레이어, 캔버스와 **별 축** | 온라인 NIXIE **캐릭터 슬롯**(드래그·위치 `localStorage` 등)                                                            | **캔버스 NIXIE와 동일 개념·다른 레이어**; 향후 `confidence`·동기화 요약·ASK를 **동일 SSOT**에서 주입(Vue Flow §7.4.1).                                                                                                                   |
| **탭 ⑥ TipTap**                                                                                 | **문서 편집이 중앙 주역**일 때                                                    | 캔버스 노드 연출은 **우선순위 낮음** 또는 숨김; **저장 충돌·해시**는 기존 UI·NIXIE와 **충돌 없이** 같은 알림 채널 사용 | `[NXN] [UIUX] Nexion TipTap 편집·실시간 반영 및 Ollama 연동 기획.md`; 전역 오버레이 NIXIE는 **필요 시 그대로** 유지 가능.                                                                                                                |

**한 줄:** Nexion ↔ NIXIE “통신”은 **소켓 하나**가 아니라, **클라이언트가 API/구독으로 읽은 메타 → NIXIE 연출 레이어에 바인딩**하는 **데이터 파이프**다. **6탭 전환**은 **캔버스가 보이는 탭**에서만 노드 연출이 풀가동되고, **⑥** 에서는 **편집·저장 UX**가 앞에 선다.

## 추가 아이디어

EXA-OS의 핵심 철학인 **'의도 중력(Intent Gravity)'**, **'공감 엔진(Empathy)'**, 그리고 **'지능적 족보(Why Chain)'**를 시각적으로 극대화할 수 있는 **UI/UX 아이디어 모음**(아래 **1~6**).

### 1. ①~⑤ 탭별 **다중 렌더 모드** + **데이터 무게·가중치** 기반 노드 표현

**①~⑤** 탭을 렌더링할 때, 탭마다 **하나의 고정 뷰**만 두지 않고 **여러 표시 모드(프리셋)** 를 둔다. 사용자가 모드를 고르면 **같은 그래프 데이터**라도 **노드·엣지의 시각 언어**(크기, 두께, 라벨 밀도, LOD, 색·아이콘 계층)가 달라진다.

| 층                      | 내용                                                                                                                                                                                                                                                                   |
| :---------------------- | :--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **데이터 무게(입력)**   | SSOT·원장에서 오는 **정량 신호** — 예: 테이블 **행 수·FK 수**, 족보 **깊이·승계 단계**, Capability **Tier·게이트 상태**, Glossary **정의 길이·태그 수**, Narrative **앵커 연결 수·Doc Sync `confidence`** 등. **실제 데이터의 무게**를 0~1 또는 단계값으로 정규화한다. |
| **모드별 가중치(규칙)** | 모드마다 **어떤 신호를 얼마나 반영할지** 가중치 벡터를 둔다. (예: **요약 모드**는 연결 수·부하만, **감사 모드**는 동기화·신뢰도·최근 변경을 강조.)                                                                                                                     |
| **출력(표현)**          | 위 두 층을 합성해 **노드 반지름·엣지 두께·라벨 표시 단계·그룹 접기**를 결정한다. Dagre·줌·LOD와 **직교**하는 **표현 레이어**로 둔다.                                                                                                                                   |

**구 2번「의도 중력」과의 구분:** **의도 중력**은 **사용자 행동 로그·체류** 등 **인터랙션에서 오는 관심**으로 레이아웃·응집을 바꾸는 쪽에 가깝다. **본 항목**은 **도메인 원장·필드에서 오는 정량 무게**와 **모드별 가중 규칙**으로 **노드 표현**을 바꾼다. 둘을 **합성**할 수는 있으나 **데이터 소스와 책임**을 문서·코드에서 분리한다.

### 2. "의도 중력(Intent Gravity)" 기반 동적 레이아웃 스태킹

Dagre를 통한 정적 배치를 넘어, 사용자의 관심도에 따라 캔버스가 물리적으로 반응하는 방식입니다.

- **아이디어:** `project_logs`의 접근 빈도나 마우스 체류 시간을 **'X7 중력 축'** 에너지로 환산합니다. 사용자가 자주 탐색하는 노드 그룹은 캔버스 중앙으로 강하게 응집(Implosion)되고, 오랫동안 방치된 '고아 자산'이나 'VOID' 상태의 노드들은 캔버스 외곽의 '성운 영역'으로 밀려나며 흐릿하게 표현됩니다.
- **신선한 포인트:** 지도가 고정된 것이 아니라, **"사유의 무게"**에 따라 실시간으로 지형이 변하는 유기체적 인터페이스를 경험하게 합니다.

### 3. 타임라인 (활성 탭별 스냅샷·이력)

중앙 **6탭** 중 **어느 탭이 활성화되어 있느냐**에 따라, **같은 타임라인 UI**(캔버스 **하단** 바·핸들·눈금)가 **다루는 시간축·스냅샷 종류**를 바꾼다. 공통으로 `execution_steps`·`post_state_snapshot`·도메인별 **버전/감사 메타** 등 **SSOT에 정의된 스냅샷**을 불러온다(스키마·필드는 `[NXN] [SCHM]`·`[NXN] [API]`).

| 활성 탭          | 타임라인이 표시·스크럽하는 대상                                                                                         | 핸들을 특정 시점으로 옮겼을 때(대표 동작)                                                                                                             |
| :--------------- | :---------------------------------------------------------------------------------------------------------------------- | :---------------------------------------------------------------------------------------------------------------------------------------------------- |
| **① Database**   | ER·테이블 노드 배치, FK/관계 그래프의 **스냅샷 이력** — Dry-run 제출 전후, DDL **승인·반영** 시점 등                    | 해당 시점의 **ER 상태**를 캔버스에 **고스트 레이어**로 투영하거나, 현재와 **diff**(추가/삭제 테이블·엣지) 요약                                        |
| **② Identity**   | 족보 그래프·`Identity ID` 메타의 **승계·대체 체인** — `superseded_by_id`·Re-pointing·정제 작업이 남긴 **이벤트 시퀀스** | 선택 시점의 **노드·엣지(족보)** 상태 투영, 병합·별칭 **계열** 하이라이트                                                                              |
| **③ Capability** | `nexa.*` **Late Anchoring** 확정/대기, Tier·게이트·노드–기능 연결의 **변경 이력**                                       | 해당 시점의 **게이트·점선/실선 엣지** 상태 투영                                                                                                       |
| **④ Glossary**   | 용어 원장·HEXAGON·IR 규칙의 **개정 버전** — 정의·동의어·라우팅 규칙이 바뀐 시점                                         | 표/그래프 뷰를 **그 버전**으로 되돌려 읽기(편집은 현재 권한에 따름)                                                                                   |
| **⑤ Narrative**  | **논리 지도**(Vue Flow)·노드–`anchor_id`·Why Chain·**Doc Sync** 상태가 함께 찍힌 **설계 스냅샷**                        | `post_state_snapshot` 등으로 **과거 맵**을 고스트로 겹쳐 보이게 하고, 현재 편집과 **비교**(Vue Flow 운영 규약 §9 N-PATH 동기화 UI·가상 재구성과 정합) |
| **⑥ TipTap**     | 현재 편집 중 문서(`anchor_id`)의 **저장 시점**·`source_hash` 변경 이력, (구현 시) **로컬 리비전**                       | 선택 시점의 **본문 스냅샷** 읽기 전용 미리보기 또는 **문자열 diff**, 필요 시 그 시점으로 복원(ASK)                                                    |

**한 줄:** “타임라인”은 **하나의 시간 UI**이며, **활성 탭**이 바뀌면 그 안에 실리는 **이벤트 종류**만 바뀐다.

### 4. "Hot-Plug & Late Anchoring" 드래그 게이트 연출

외부 자산이 시스템의 '기능 자격(Capability)'으로 편입되는 순간을 드라마틱하게 연출합니다.

- **아이디어:** ExplorerTree에서 아직 연결되지 않은 외부 API나 문서를 중앙 Vue Flow의 '논리 뼈대 노드'로 드래그할 때, 노드 주변에 **'인증/검증 게이트'** 애니메이션(빛의 고리)이 나타납니다. 드롭 성공 시 점선(VOID) 엣지가 실선(WILL)으로 변하며 `identity_id`가 박제되는 시각적 '스파크'를 연출합니다.
- **신선한 포인트:** "파일 연결"이라는 무미건조한 작업을 **"영혼을 육체에 안착시키는 서사적 행위"**로 격상시킵니다.

### 5. "Empathy 기반 Low-Entropy" 캔버스 쓰로틀링

관리자의(사용자) 심리적 부하에 따라 인터페이스의 복잡도를 스스로 조절 또는 직접 조절 하는 공감형 UI입니다.

- **아이디어:** 공감 엔진이 감지한 사용자의 활력 지수(VI)가 임계값 미만으로 떨어지면 캔버스가 자동으로 **'Static UI' 모드**로 전환됩니다. 복잡한 Why Chain 연결선들이 생략되고, 현재 작업 중인 `Context Paging` 노드들만 Lumina(발광)를 유지하며 나머지는 어둡게 침묵(Silence) 모드로 들어갑니다.
- **신선한 포인트:** 시스템이 사용자의 피로를 이해하고 **"함께 쉬어가는 지능"**을 비언어적(Jitter/Lumina 제어)으로 증명합니다.

### 6. "4대 식별자" 기반의 '영혼의 여권(Passport)' 인스펙터

우측 상세 패널(Attribute)에 Identity의 근본 유래를 서사적으로 풀어서 보여주는 전용 섹션입니다.

- **아이디어:** 선택된 노드의 상단에 'Passport' 탭을 신설합니다. 이 노드가 어느 가문(`tenant_id`) 출신인지, 어느 산부인과(`mint_surface`)에서 태어났는지, 현재 거주지 주소(`anchor_id`)는 어디인지를 비유적 아이콘과 함께 카드 형태로 보여줍니다. 병합된 경우 `superseded_by_id`를 따라 과거의 이름(별칭)들을 '계승 족보' 형태로 나열합니다.
- **신선한 포인트:** 기술적인 메타데이터 나열이 아닌, **"하나의 인격체를 대면하는 듯한 서사적 정보"**를 제공하여 지능 자산에 대한 신뢰와 애착을 높입니다.

---

**결론적으로**, 이 아이디어들은 기존의 **ExplorerTree(물리)-Vue Flow(논리)-Attribute(상세)** 구조를 유지하면서도, 그 사이에 **시간(타임라인), 심리(공감), 중력(관심)** 같은 NEXA만의 변수를 주입하는 것입니다.

**'서사적 연출'**이나 **'데이터 연동'** — **탭별 렌더 모드·데이터 무게**, **의도 중력**, **타임라인** 등을 Dagre·표현 레이어·가중치 파라미터와 연동하는 로직을 구체화한다.

### 추가 아이디어와 Ollama 연동 (검토)

아래는 **§2의 Glossary·용어 추출(Ollama)** 과는 별도로, **추가 아이디어** 구간에서 **로컬 LLM을 붙일 만한 지점**만 가린다. 공통 원칙은 `[NXN] [UIUX] Nexion TipTap 편집·실시간 반영 및 Ollama 연동 기획.md` — **명시적 트리거·자동 덮어쓰기 금지·Extended 트랙**.

| #     | 아이디어                                           | Ollama(또는 LLM) 후보                                                                                                                                                                               | 비고 |
| :---- | :------------------------------------------------- | :-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :--- |
| **1** | **탭별 다중 렌더 모드·데이터 무게** 기반 노드 표현 | **약함.** **규칙·스케일링·SSOT 필드**가 본체. LLM은 **모드 설명·툴팁 문구** 보조, **가중치 자동 추천**은 비감사·비본증 경로에서만 검토.                                                             |
| **2** | 의도 중력·동적 레이아웃                            | **약함.** 핵심은 로그·체류 시간 → **가중치·레이아웃 수학**. LLM은 “이번 주 집중할 서브그래프 제안” 같은 **자연어 목표 → 노드 집합 후보** 정도의 **보조**에만 쓰기 쉬움(실시간 매 틱 호출은 부적합). |
| **3** | **타임라인**(§ 위, 탭별 스냅샷)·고스트 레이어      | **중간.** 스냅샷 diff는 **데이터 비교**가 본체. LLM은 **두 시점 차이 요약**, **변경 하이라이트 설명** 등 **사후 내러티브**에 유리(버튼·패널 한정).                                                  |
| **4** | Late Anchoring 게이트 연출                         | **약함(연출 우선).** “자격 적합 여부”를 LLM에 맡기면 **정책·감사 SSOT**와 충돌하기 쉬움. 설명 카피 생성 정도는 선택.                                                                                |
| **5** | Empathy·Low-Entropy                                | **분리 권장.** VI·피로 추정은 **공감 엔진·센서/휴리스틱** 쪽이 SSOT. Ollama **용어 추출**과 파이프라인·프라이버시가 다름 — 동일 “Ollama” 블록으로 묶지 않는다.                                      |
| **6** | Passport 인스펙터                                  | **중간.** 메타 표시는 **DB·Identity SSOT**. LLM은 **서사적 한 줄 요약·비유 카피** 생성 등 **선택적·승인 후** 삽입에 적합(기본은 규칙 기반 카피).                                                    |
