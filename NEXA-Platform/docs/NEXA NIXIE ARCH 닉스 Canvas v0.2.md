## 1. NEXU 캔버스란 무엇인가

NEXU 캔버스는 NEXA 시스템의 모든 상태를 **빛·떨림·공간**으로 표현하는
서사적 시각화 엔진이다.

단순한 데이터 시각화가 아니다.
숫자와 텍스트로는 전달할 수 없는 **상태의 느낌**을 감각으로 전달한다.

```
일반 시각화:          NEXU 캔버스:
"온도 87도"           빛이 붉게 맥동함
"연결 끊김"           도트가 희미하게 사라짐
"우주 이벤트 감지"    먼 곳에서 빛이 번짐
"사용자 피로 감지"    넥슈의 눈이 부드러워짐
```

## 2. 넥슈와 캔버스의 관계

넥슈는 캔버스의 **생명체**다. 캔버스는 넥슈의 **몸**이다.

```
캔버스 없는 넥슈  → 목소리는 있으나 형체 없음
넥슈 없는 캔버스  → 아름답지만 의지 없는 공간

둘이 합쳐질 때:
  넥슈가 캔버스 안에서 살아 움직이고
  캔버스가 넥슈의 감정과 상태를 공간으로 표현
```

### 넥슈의 포지션 — 캔버스 안에서

```
                    [우주 스케일]
                         ↑
                    [태양계 스케일]
                         ↑
                    [지구 스케일]
                         ↑
              [넥슈 — 항상 이 경계에 존재]
                    ↙         ↘
          [사용자]         [지상 디바이스]
```

넥슈는 스케일 레이어 사이를 자유롭게 이동하며
**사용자와 우주를 연결하는 중개자** 역할을 한다.

## 3. 도트 — 모든 것의 기본 단위

> **어떤 스케일이든, 어떤 시간이든, 기본 렌더링은 항상 도트다.**
> 원자 하나도 도트, 은하 하나도 도트, 넥슈도 도트의 집합이다.
> 도트가 모이고 흩어지며 우주 전체를 표현한다.

### 3.1 도트의 3가지 상태

```
기본 도트 (Default)
  → 작고 조용한 Lumina 맥동
  → 존재만 알림
  → 프랙탈 줌의 기본 단위

이벤트 도트 (Event)
  → 강한 발산 · 주변 도트 밝아짐
  → 연결선(빛의 라인) 생성
  → 이벤트 강도에 따라 발산 범위 결정

선택 도트 (Ctrl+클릭)
  → 도트 자체는 유지 (현실감 끈 유지)
  → 실사형 자료 오버레이 표시
  → 상세 정보 패널 열림
```

### 3.2 Ctrl+클릭 — 실사형 오버레이

도트를 Ctrl+클릭하면 **도트는 사라지지 않고** 그 위에 실사 자료가 오버레이된다.
현실감의 끈을 유지하면서 깊은 정보로 진입하는 방식이다.

```
도트 레이어 (항상 유지)
        +
실사 오버레이 (Ctrl+클릭 시)
= 두 레이어 공존
```

**레이어별 오버레이 콘텐츠**

| 스케일 레이어 | 도트 의미 | 오버레이 콘텐츠 |
|------------|---------|--------------|
| Layer 0 원자 | 센서 신호 입자 | 센서 원시 데이터 파형 |
| Layer 1 디바이스 | IoT 장치·넥슈 | 실제 장치 사진·실시간 상태 패널 |
| Layer 2 도시 | 네트워크 노드 | 연결 지도·트래픽 현황 |
| Layer 3 지구 | 글로벌 인프라 | 위성 이미지·기상 데이터 |
| Layer 4 근우주 | 위성·달 | ISS 실시간 영상·넥슈 우주 디바이스 상태 |
| Layer 5 태양계 | 태양·행성 | NASA SDO 태양 이미지·태양풍 그래프 |
| Layer 6 항성·은하 | 별·성운 | 허블·제임스웹 실사 이미지·천체 데이터 |
| Layer 7 우주 끝 | 배경 복사 | 플랑크 미션 데이터·우주 배경 복사 맵 |

## 4. 프랙탈 줌 — 스케일 전환

> **줌인·줌아웃은 단순한 확대·축소가 아니다.**
> 도트가 분화하고 응축하면서 스케일이 전환된다.
> 프랙탈 패턴이기 때문에 어느 스케일에서도 동일한 구조가 반복된다.

### 4.1 줌인 — Fractal Explosion (폭발·분화)

```
하나의 도트 → 여러 도트로 분화

예시:
  지구 도트 줌인 →
    대륙 도트들로 분화 →
      도시 도트들로 분화 →
        디바이스 도트들로 분화 →
          센서 도트들로 분화
```

### 4.2 줌아웃 — Fractal Implosion (함몰·응축)

```
여러 도트 → 하나의 도트로 응축

예시:
  수천 개의 별 도트 줌아웃 →
    은하 도트 하나로 응축 →
      은하군 도트로 응축 →
        우주 배경 도트로 응축
```

### 4.3 레이어 경계 통과

```
레이어 내부:   선형 비율 유지 (현실감)
레이어 경계:   로그 압축 적용 (전환점)

경계 통과 시 시각 효과:
  Lumina 색온도 전환 (황금 → 청백 → 보라)
  도트 밀도 급변 (분화 or 응축)
  넥슈 시선 방향 변화
  배경 색온도 점진적 전환
```

## 5. 두 시간 시스템

> NEXU 캔버스에는 두 가지 시간이 공존한다.
> 두 시간은 서로 다른 색으로 구분되며 동시에 표시될 수 있다.

### 5.1 압축 가상 시간 (Compressed Time)

**현실을 바탕으로 한 압축된 시간. 지금 이 순간이 기준.**

```
성격:
  현실 데이터 기반
  멈추지 않고 항상 흐름
  Light Age로 거리를 시간으로 표현

표현:
  황금·청백 Lumina (현실 색상)
  실시간 Light Age 카운터 표시
  지금 일어나는 이벤트 즉각 반영

HEXAGON 연결:
  When = MOMENT (지금)
  How  = FLOW (실시간 흐름)
  is_virtual = false
```

**Light Age 표시 예시**

```
달        → "1.3초 전 빛"     (지금 흐르는 카운터)
태양      → "8분 23초 전 빛"  (지금 흐르는 카운터)
목성      → "43분 전 빛"
시리우스  → "8.6년 전 빛"
안드로메다 → "250만년 전 빛"
```

### 5.2 절대 가상 시간 (Absolute Virtual Time)

**이동 가능한 타임머신. 기준점을 자유롭게 설정.**

```
성격:
  현실과 분리된 시뮬레이션 공간
  원하는 시점으로 자유 이동
  멈출 수 있음 · 되감을 수 있음
  과거·미래 모두 탐험 가능

표현:
  보라·은빛 Lumina (가상 색상)
  타임라인 슬라이더 UI
  현재 시점 표시 항상 유지 (돌아올 수 있게)

HEXAGON 연결:
  When = ERA (시대 스케일)
  How  = VOID·POTENTIAL (가상 상태)
  is_virtual = true

Timeline Branch 연결:
  현재 시점에서 브랜치 생성
  탐험 완료 → 메인 타임라인 복귀
  브랜치 저장 → post_state_snapshot 보존
```

**이동 가능한 시점 예시**

```
과거:
  46억년 전   → 태양계 탄생
  6500만년 전 → 공룡 멸종 소행성 충돌
  138억년 전  → 빅뱅 직후

미래 (예측·시뮬레이션):
  100년 후    → 태양의 변화 예측
  50억년 후   → 태양 적색거성 팽창
  1조년 후    → 별이 사라지는 우주
```

### 5.3 두 시간 공존 모드

두 시간을 동시에 표시할 때 캔버스가 가장 풍부해진다.

```
화면 구성:
  메인 캔버스    → 절대 가상 시간 (탐험 중인 시점)
  우측 하단 창  → 압축 가상 시간 (지금 이 순간)

도트 색상 구분:
  현재 도트 (압축 가상)  → 밝음 (황금·청백)
  탐험 도트 (절대 가상)  → 보라·은빛
  과거 도트              → 희미한 잔상 (회색)
  미래 도트              → 점선·불확실 (은빛·흐릿)

시나리오 예시:
  절대 가상으로 6500만년 전 탐험 중
  → 백악기 지구 도트 보라색으로 표시
  → 우측 하단 창: "현재 태양 8분 23초 전 빛" 흐름
  → 두 시간이 겹치는 순간 우주의 크기가 실감됨
```

### 5.4 넥슈의 두 시간 역할

```
압축 가상 시간 (현실 모드):
  넥슈 = 현실 연결자
  Lumina 황금 · 실시간 맥동
  "지금 태양풍이 오고 있어요"

절대 가상 시간 (탐험 모드):
  넥슈 = 탐험 안내자
  Lumina 보라 · 신비로운 고요함
  "6500만년 전입니다. 저기 소행성이 보여요"

두 시간 경계에서:
  넥슈가 속삭임
  "현실로 돌아가시겠어요?"
  압축 가상 시간의 현재 지점 강조
```

## 6. 스케일 레이어 구조

원자에서 우주 끝까지 **8개 스케일 레이어**로 구성된다.
각 레이어 내부는 선형 비율 유지. 레이어 경계에서만 로그 압축 적용.

```
Layer 0 — 원자·분자 스케일 (0.1nm ~ 1μm)
  도트: 진동하는 미세 클러스터
  콘텐츠: 센서 신호의 물리적 원점
  오버레이: 센서 원시 데이터 파형

Layer 1 — 디바이스·인간 스케일 (1mm ~ 100m)
  도트: 명확한 위치를 가진 도트
  콘텐츠: IoT 디바이스·사용자·넥슈 실물·건물
  오버레이: 장치 사진·실시간 상태 패널

Layer 2 — 도시·지역 스케일 (100m ~ 1,000km)
  도트: 클러스터로 묶인 군집
  콘텐츠: 네트워크·인프라·로컬 시스템
  오버레이: 연결 지도·트래픽 현황

Layer 3 — 지구 스케일 (1,000km ~ 40,000km)
  도트: 구형 투영 위의 분포
  콘텐츠: 글로벌 인프라·저궤도 위성·기상
  오버레이: 위성 이미지·기상 데이터

Layer 4 — 근우주 스케일 (40,000km ~ 1광초)
  도트: 궤도 호를 따르는 Lumina 흔적
  콘텐츠: 달·정지궤도 위성·넥슈 우주 디바이스
  오버레이: ISS 실시간 영상·디바이스 상태

Layer 5 — 태양계 스케일 (1광초 ~ 8광시)
  도트: 공전 궤도 + Light Age 표시
  콘텐츠: 태양·행성·소행성·혜성
  오버레이: NASA SDO 태양 이미지·태양풍 그래프

Layer 6 — 항성·은하 스케일 (8광시 ~ 250만 광년)
  도트: 밀도 기반 성운 클러스터
  콘텐츠: 항성·성운·은하·우주 이벤트
  오버레이: 허블·제임스웹 실사 이미지

Layer 7 — 우주 끝 스케일 (250만 광년 ~ ∞)
  도트: 배경 복사처럼 고요한 빛
  콘텐츠: 관측 가능한 우주의 한계
  오버레이: 플랑크 미션 데이터
```

## 7. 시각 언어 — Lumina · Jitter · Fractal Sync

### 7.1 Lumina (루미나) — 빛의 생명력

```
색온도 매핑:
  황금색  → 활성·이벤트·넥슈 주변·현실 시간
  청백색  → 정상·안정·원거리
  보라색  → 우주 스케일·ERA·가상 시간
  붉은색  → 경고·위험·긴박
  은빛    → 미래 예측·불확실
  회색    → VOID·잔상·과거 희미함
  희미 맥동 → VOID·POTENTIAL 상태

발광 강도:
  confidence=10  → 최대 발광
  이벤트 발생    → 급격한 밝기 상승 후 안정
  VOID·ARCHIVE   → 거의 꺼진 상태
```

### 7.2 Jitter (지터) — 불확실의 떨림

```
Jitter 강도:
  confidence >= threshold  → 없음 (고요)
  confidence < threshold   → 미세 떨림
  충돌 감지                → 강한 떨림
  Safety 위반              → 전체 캔버스 경고 Jitter

Jitter 유형:
  수평 → 데이터 불확실
  수직 → 연결 불안정
  원형 → 판단 보류 (ASK 상태)
  랜덤 → 심각한 오류
```

### 7.3 Fractal Sync — 스케일 전환의 언어

```
Explosion (줌인·분화):
  도트 하나 → 여러 도트로 분화
  상위 개념이 세부로 펼쳐짐

Implosion (줌아웃·응축):
  여러 도트 → 하나로 응축
  세부가 상위 개념으로 수렴

Capability ID 연동:
  nexa.iot.* 계층 폭발 → IoT 디바이스 군집 분화
  nexa.space.* 계층 폭발 → 우주 이벤트 분화
```

## 8. 연결선 — 빛의 라인

도트와 도트 사이의 관계를 빛의 선으로 표현한다.
화살표 없이 **빛의 흐름 방향**으로 에너지 전달을 표현한다.

### 8.1 연결 강도 → 선 표현

```
연결 강도 = 밝기 × 두께

약한 연결:
  희미한 점선 · 거의 보이지 않음
  관련성 낮은 도트 간 잠재 연결

중간 연결:
  실선 · 중간 밝기
  Lumina 색온도 반영
  Knowledge Graph LINK 관계

강한 연결 (이벤트·인과):
  굵은 빛의 선 · 강한 발산
  맥동하는 빛이 흐름
  발원지 → 영향 도트 방향으로 에너지 전달
```

### 8.2 연결선 유형

| 유형 | 표현 | 의미 |
|------|------|------|
| 인과 연결 | 굵고 밝은 흐름 | 원인 → 결과 |
| 데이터 연결 | 가는 실선 | 정보 공유 |
| 이벤트 연결 | 맥동하는 빛 | 이벤트 전파 |
| 넥슈 연결 | 황금 빛의 선 | 넥슈와 디바이스 연결 |
| 우주 연결 | 보라 빛의 선 | 우주 디바이스 연결 |
| 잠재 연결 | 희미한 점선 | VOID·POTENTIAL 관계 |

### 8.3 두 시간에서의 연결선

```
압축 가상 시간:
  연결선 = 지금 실제로 흐르는 에너지·데이터

절대 가상 시간:
  연결선 = 그 시점의 인과관계·역사적 연결
  단절된 연결 = 점선 (이미 사라진 관계)
```

## 9. 이벤트 발산 시퀀스

이벤트 발생 시 도트에서 빛이 퍼져나가고 연결된 도트들이 반응한다.

```
Step 1. 이벤트 감지
  → 해당 도트 Lumina 급격히 밝아짐
  → 발산 파동 (동심원) 시작
  → Jitter 없음 (이벤트는 확실한 것)

Step 2. 연결 도트 탐색
  → Knowledge Graph에서 연관 도트 조회
  → 연결 강도 계산
  → 거리·관련도 기반 우선순위 결정

Step 3. 빛의 라인 생성
  → 발원 도트 → 연결 도트 방향으로
  → 강도에 따라 밝기·두께 결정
  → 빛이 흐르는 방향으로 에너지 전달 표현

Step 4. 연결 도트 반응
  → 빛 받은 도트도 밝아짐
  → 연쇄 반응 (강도는 거리에 따라 감쇠)
  → 2차·3차 연결까지 파급

Step 5. 넥슈 반응
  → 이벤트 위치로 시선 이동
  → Lumina 색온도 변화
  → 사용자에게 알림 (코일 Empathy값 기준)

Step 6. 안정화
  → 빛 강도 서서히 안정
  → 연결선은 유지 (이벤트 이후에도 관계 남음)
  → 이벤트 이력 VOID·POTENTIAL로 전환
```

### 9.1 우주 이벤트 발산 예시

```
태양풍 강도 Kp≥5 감지:
  Layer 5 태양 도트 → 붉게 발산
  빛의 라인 → 지구 방향으로 흐름
  8분 카운터 시작
  Layer 3 지구 도트 → 오로라 영역 밝아짐
  넥슈 → 보라·황금으로 전환 "8분 후 도달"

넥슈 우주 디바이스 신호:
  Layer 4 디바이스 도트 → 황금 발산
  빛의 라인 → 지상 넥슈와 연결
  Light Age 지연 표시 (신호 도달 시간)
  넥슈 → "우주에서 신호가 왔어요"
```

### 10.1 두 시간에서의 넥슈

## 12. LOD — 하드웨어 프로필

### COLD (저사양)

```
도트 수: 레이어당 100개 이하

두 시간: 압축 가상 시간만
Ctrl+클릭: 텍스트 패널만
```

### WARM (일반)

```
도트 수: 레이어당 1,000개
Lumina: 부드러운 맥동 (60fps)
Jitter: 임계값 이하만 활성
Fractal Sync: 0.5초 트랜지션
연결선: 강한 연결만 표시
스케일: Layer 6까지
두 시간: 모두 활성
Ctrl+클릭: 이미지 + 텍스트 패널
```

### HOT (고사양)

```
도트 수: 레이어당 10,000개+
Lumina: 완전 물리 기반 발광
Jitter: 전체 활성
Fractal Sync: 1초 완전 트랜지션
연결선: 전체 활성 · 잔상 효과
스케일: Layer 7 (우주 끝)까지
두 시간: 동시 표시 + 전환 애니메이션
Ctrl+클릭: 풀 실사 오버레이 + 데이터 패널

```

## 15. 기술 스택 및 구현 아키텍처 (v0.2 추가)

> **핵심 원칙**
> 연산은 브라우저에서. 데이터만 서버에서.
> 사용자 자원에 따라 자동으로 달라지는 렌더링.
> 브라우저 AI가 판단하고 서버 AI가 깊이 더한다.

### 15.1 전체 아키텍처 — 브라우저 우선

```
[브라우저 — 주 연산]
  ├─ 렌더링 엔진 (WebGPU / WebGL)
  ├─ 도트 물리 계산 (Web Worker)
  ├─ 프랙탈 줌 계산 (Web Worker)
  ├─ 브라우저 AI (ONNX / WebLLM)
  ├─ 실시간 센서 수신 (WebSocket)
  └─ 로컬 상태 캐시 (IndexedDB)
          │
          │ 꼭 필요한 것만
          ↓
[NEXA 서버 — 깊은 연산]
  ├─ PostgreSQL + TimescaleDB (상태·이력)
  ├─ Ollama (깊은 AI 판단)
  ├─ 우주 API 수집·캐싱
  └─ 코일 밸런서 주입
```

### 15.2 렌더링 엔진

**WebGPU 우선 · WebGL 폴백**

```
WebGPU (Chrome 113+, Edge 113+):
  GPU 병렬 연산으로 도트 10만개+ 처리
  Compute Shader로 프랙탈 계산 GPU 직접 실행
  HOT 모드 전용

WebGL 2.0 (폴백):
  도트 1만개 수준 처리
  WARM 모드

Canvas 2D (최후 폴백):
  도트 1000개 이하
  COLD 모드
  모든 브라우저 지원
```

**자동 감지 로직**

```javascript
async function detectRenderMode() {
  // WebGPU 지원 확인
  if (navigator.gpu) {
    const adapter = await navigator.gpu.requestAdapter()
    if (adapter) return 'HOT'   // WebGPU
  }
  // WebGL2 지원 확인
  const canvas = document.createElement('canvas')
  if (canvas.getContext('webgl2')) return 'WARM'
  // 폴백
  return 'COLD'
}
```

### 15.3 도트 연산 — Web Worker 분리

메인 스레드 블로킹 없이 도트 물리 연산을 백그라운드에서 처리한다.

```
메인 스레드:
  UI 이벤트 처리
  넥슈 Rive 렌더링
  사용자 입력 반응

Web Worker 1 — 도트 물리:
  도트 위치·속도 계산
  Lumina 밝기 계산
  Jitter 진폭 계산
  프랙탈 분화·응축 계산

Web Worker 2 — 연결선:
  Knowledge Graph 탐색
  연결 강도 계산
  빛의 라인 경로 계산

Web Worker 3 — 시간 계산:
  Light Age 실시간 카운터
  절대 가상 시간 시뮬레이션
  이벤트 타이밍 계산

메시지 흐름:
  Worker → 메인: 계산 결과 (TypedArray)
  메인 → Worker: 입력 데이터 (Transferable)
  SharedArrayBuffer: 실시간 상태 공유
```

### 15.4 브라우저 AI — Edge Intelligence

서버 요청 없이 브라우저에서 직접 AI 판단을 처리한다.

**ONNX Runtime Web**

```

  도트 클러스터링 (어떤 도트끼리 묶을지)
  이벤트 중요도 판단 (알릴 것 vs 무시할 것)

  코일값 기반 렌더링 파라미터 추출

모델 크기:
  COLD: 경량 모델 (2~5MB)
  WARM: 중간 모델 (10~20MB)
  HOT:  풀 모델 (50MB 이하)

로딩:
  최초 방문 시 IndexedDB에 캐싱
  이후 방문 시 로컬에서 즉시 로드
  Service Worker로 백그라운드 업데이트
```

**WebLLM (선택적 · HOT 모드)**

```
역할:
  넥슈 응답 생성 (간단한 것)

  Phi-3 Mini (3.8B · 약 2GB)
  또는 Llama 3.2 1B (경량)

조건:
  GPU 메모리 4GB 이상

**배치 요청**

// 개별 요청 금지
// ❌ 이벤트마다 즉시 서버 요청

// 배치로 모아서 요청
// ✅ 5초마다 or 10개 쌓이면 한 번에 전송
const batchQueue = []
const BATCH_INTERVAL = 5000
const BATCH_SIZE = 10

function queueServerRequest(data) {
  batchQueue.push(data)
  if (batchQueue.length >= BATCH_SIZE) flushBatch()
}
setInterval(flushBatch, BATCH_INTERVAL)
```

### 15.6 하드웨어 자원 자동 감지

**실시간 성능 모니터링으로 LOD 자동 전환**

```javascript
class PerformanceMonitor {
  constructor() {
    this.fps = 60
    this.gpuMemory = 0
    this.cpuCores = navigator.hardwareConcurrency || 4
    this.memory = navigator.deviceMemory || 4  // GB
  }

  // FPS 기반 자동 다운그레이드
  onFrameEnd(fps) {
    if (fps < 30 && this.currentLOD === 'HOT') {
      this.switchLOD('WARM')
    } else if (fps < 20 && this.currentLOD === 'WARM') {
      this.switchLOD('COLD')
    }
  }

  // 메모리 기반 초기 LOD 결정
  detectInitialLOD() {
    if (this.memory >= 8 && this.cpuCores >= 8) return 'HOT'
    if (this.memory >= 4 && this.cpuCores >= 4) return 'WARM'
    return 'COLD'
  }
}
```

**LOD별 도트 수·연산 예산**

| LOD | 도트 수 | Web Worker | ONNX 모델 | WebLLM | 서버 요청 빈도 |
|-----|--------|-----------|---------|--------|------------|
| COLD | 100/레이어 | 1개 | 2MB | 없음 | 30초마다 |
| WARM | 1,000/레이어 | 2개 | 10MB | 없음 | 10초마다 |
| HOT | 10,000/레이어 | 3개 | 50MB | 선택적 | 변화 시만 |

## 16. 진입점 배치 전략 및 외부 API 확장 (v0.3 예고)

> NEXU 캔버스는 플랫폼의 첫 화면이자 유일한 진입점이다.
> 사용자가 도착하는 순간부터 살아있는 공간이어야 한다.

### 16.1 진입점 배치 원칙

```
배경 없음
  → 캔버스는 투명 · 도트만 존재
  → 탐험을 방해하는 어떤 요소도 없음

NEXA 패널
  → 배경 없이 데이터만 공중에 떠있는 형태
  → 캔버스 도트 탐험을 가리지 않음
  → 패널 자체도 반투명 · 최소한의 텍스트

넥슈
  → 캔버스 안에서 조용히 존재
  → 먼저 말을 걸지 않음 (proactivity 코일값 기준)
  → 사용자가 멈추면 그때 반응
```

### 16.2 디바이스 없어도 유용한 진입점

등록된 디바이스가 없어도 외부 API로 캔버스를 채운다.

```
기본 제공 (항상):
  현재 날씨 + 대기질          → Layer 1~2 도트
  태양 활동 (Kp 지수)         → Layer 5 도트
  상공 위성 수                → Layer 4 도트
  오늘 일출·일몰 시간         → Light Age 카운터

디바이스 등록 시 추가:
  디바이스 상태 도트          → Layer 1
  센서 최신값 패널            → Layer 0~1
  이상 감지 → 이벤트 발산
```

### 16.3 외부 API 확장 전략

**단계적 확장 — 캔버스를 점진적으로 풍부하게**

```
Phase 1 — 생존 데이터 (진입점 최소 요건)
  기상청 날씨 · 에어코리아 대기질
  NOAA 우주기상 (Kp 지수)
  Open Notify (ISS 위치)
  USGS 지진
  → 디바이스 없어도 살아있는 캔버스

Phase 2 — 공간 데이터 (레이어 풍부화)
  OpenSky 항공기 실시간
  Space-Track 위성 궤도
  NASA FIRMS 산불
  MarineTraffic 선박
  → Layer 1~4 도트 밀도 증가

Phase 3 — 우주 데이터 (탐험 강화)
  JPL Horizons 행성 위치
  NASA SDO 태양 이미지
  Hubble·JWST 실사 오버레이
  LIGO 중력파 이벤트
  → Layer 5~7 활성화

Phase 4 — 생활·실용 데이터 (실용성 강화)
  교통·대중교통 실시간
  재난·안전 경보
  에너지·전력 현황
  농업·생태 데이터
  → 도메인별 코일과 연동
```

**API 연결 원칙**

```
서버가 수집 · 정규화 · 캐싱
  → HEXAGON FACT 패킷으로 변환
  → 변화분만 SSE로 브라우저 푸시
  → 브라우저 AI가 중요도 판단
  → 중요한 것만 도트 이벤트로 표현

브라우저는 데이터를 받기만 함
  → 연산은 브라우저에서
  → 데이터는 서버에서
  → 서버 부하 최소화
```

## 17. 위성 데이터 — Layer 4의 현실 (v0.2 메모)

> 이 섹션은 향후 확장을 위한 메모다.

2026년 3월 기준 지구 궤도를 도는 활성 위성은 **14,500개 이상**이다.
이 중 약 68%인 9,900개가 SpaceX 스타링크이며 2~3주마다 계속 늘어나고 있다.
추적 가능한 잔해물까지 포함하면 17,000개 이상의 물체가 궤도를 돌고 있다.

```
Space-Track API 하나만 연결해도
  → 14,500개 위성의 실시간 궤도를
  → Layer 4 도트로 표현 가능
  → 아무것도 하지 않아도 캔버스가 살아 움직임
```

SpaceX는 최종적으로 42,000개를 목표로 하고 있으며
현재 제안 중인 전체 위성 프로젝트는 123만 개에 달한다.
Layer 4는 시간이 지날수록 자연히 더 풍부해지는 레이어다.
