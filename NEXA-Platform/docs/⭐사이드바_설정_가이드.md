# 사이드바 설정 가이드

## 📋 개요

`sidebarRegistry.js`에서 각 사이드바의 동작을 중앙에서 관리합니다. 상태 저장, 자동 열기, 모바일 대응 등을 모두 설정으로 제어할 수 있습니다.

---

## ⚙️ 설정 옵션

### `SidebarBehaviorConfig`

각 사이드바는 다음 설정을 가질 수 있습니다:

```typescript
{
  autoOpen: boolean,           // 컨텐츠에 따라 자동으로 열지 여부
  showMessage: boolean,        // 안내 메시지만 보여줄지 여부
  respectMobileHidden: boolean, // 모바일에서 숨김 상태를 유지할지 여부
  defaultOpen: boolean,        // 기본 열림 상태 (최초 진입 시)
  saveState: boolean,         // 열림/닫힘 상태를 저장할지 여부
  message: string | null,      // 안내 메시지 (showMessage가 true일 때)
}
```

## 📝 설정 예시

### 예시 1: 기본 사이드바 (상태 저장)

```javascript
'parts-management': {
  component: () => import('src/components/parts-management/PartsManagementSidebar.vue'),
  behavior: {
    autoOpen: false,              // 수동으로만 열기
    showMessage: false,           // 안내 메시지 없음
    respectMobileHidden: true,    // 모바일에서 숨김 상태 유지
    defaultOpen: true,            // 최초 진입 시 열림
    saveState: true,              // 상태 저장 (다음 방문 시 유지)
    message: null,
  },
}
```

### 예시 2: 자동 열기 + 안내 메시지

```javascript
'dev': {
  component: () => import('src/components/document-manager/DocumentListSidebar.vue'),
  behavior: {
    autoOpen: true,               // 문서가 없을 때 자동으로 열기
    showMessage: true,            // 문서가 없을 때 안내 메시지 표시
    respectMobileHidden: true,
    defaultOpen: true,
    saveState: true,
    message: '문서를 선택하거나 새로 만드세요.',
  },
}
```

### 예시 3: 모바일에서 항상 숨김

```javascript
'portfolio': {
  component: () => import('src/components/portfolio/PortfolioSidebar.vue'),
  behavior: {
    autoOpen: false,
    showMessage: false,
    respectMobileHidden: false,   // 모바일에서도 강제로 표시 (권장하지 않음)
    defaultOpen: false,
    saveState: true,
    message: null,
  },
}
```

### 예시 4: 상태 저장 안 함 (항상 기본값)

```javascript
'erp': {
  component: () => import('src/components/erp/ErpSidebar.vue'),
  behavior: {
    autoOpen: false,
    showMessage: false,
    respectMobileHidden: true,
    defaultOpen: true,
    saveState: false,             // 상태 저장 안 함 (항상 defaultOpen 사용)
    message: null,
  },

```

## 🔧 사용 방법

### MainLayout.vue에서 설정 읽기

```vue
<script setup>
import { 
  getLeftSidebarBehavior, 
  getRightSidebarBehavior 
} from 'src/config/sidebarRegistry.js'
import { useQuasar } from 'quasar'

const $q = useQuasar()
const currentMenu = computed(() => { /* ... */ })

// 왼쪽 사이드바 동작 설정 가져오기
const leftBehavior = computed(() => {
  return getLeftSidebarBehavior(currentMenu.value)
})

// 오른쪽 사이드바 동작 설정 가져오기
const rightBehavior = computed(() => {
  return getRightSidebarBehavior(currentMenu.value)
})

// 모바일 여부 확인
const isMobile = computed(() => $q.screen.width < 768)

// 사이드바 열림 상태 결정
const shouldOpenLeft = computed(() => {
  const behavior = leftBehavior.value
  if (!behavior) return false
  
  // 모바일에서 숨김 상태를 유지해야 하는 경우
  if (isMobile.value && behavior.respectMobileHidden) {
    // 저장된 상태 확인 (userSettings에서)
    const savedState = userSettings.settings.drawer.leftOpen
    return savedState ?? behavior.defaultOpen
  }
  
  // 자동 열기 설정이 있으면 컨텐츠 상태 확인
  if (behavior.autoOpen) {
    // 컨텐츠가 비어있으면 열기
    return isEmptyContent.value
  }
  
  // 저장된 상태 또는 기본값
  if (behavior.saveState) {
    const savedState = userSettings.settings.drawer.leftOpen
    return savedState ?? behavior.defaultOpen
  }
  
  return behavior.defaultOpen
})
</script>
```

## 📱 모바일 대응

### `respectMobileHidden: true` (권장)

- 모바일에서 사용자가 사이드바를 닫으면 그 상태를 유지
- 다음 방문 시에도 닫힌 상태 유지
- 데스크톱에서는 정상적으로 동작

### `respectMobileHidden: false`

- 모바일에서도 강제로 표시 (권장하지 않음)
- 작은 화면에서 공간 낭비

---

## 💾 상태 저장

### `saveState: true`

- 사용자가 사이드바를 열고 닫은 상태를 `userSettingsStore`에 저장
- 다음 방문 시 저장된 상태 복원
- `localStorage`에 자동 저장

### `saveState: false`

- 상태를 저장하지 않음
- 항상 `defaultOpen` 값 사용
- 세션 간 상태 유지 불가

---

## 🎯 자동 열기 (`autoOpen`)

### `autoOpen: true`

컨텐츠 상태에 따라 자동으로 사이드바를 엽니다.

**사용 예시:**
- 문서 목록이 비어있을 때 → 사이드바 자동 열기
- 부품이 선택되지 않았을 때 → 사이드바 자동 열기
- 검색 결과가 없을 때 → 사이드바 자동 열기

**구현 방법:**
```vue
<script setup>
const isEmptyContent = computed(() => {
  // 컨텐츠가 비어있는지 확인
  return files.value.length === 0
})

const shouldAutoOpen = computed(() => {
  const behavior = getLeftSidebarBehavior(currentMenu.value)
  if (!behavior?.autoOpen) return false
  return isEmptyContent.value
})
</script>
```

### `autoOpen: false`

수동으로만 열고 닫을 수 있습니다.

---

## 💬 안내 메시지 (`showMessage`)

### `showMessage: true`

사이드바 대신 안내 메시지만 표시합니다.

**사용 예시:**
- 문서가 없을 때: "문서를 선택하거나 새로 만드세요."
- 부품이 없을 때: "부품을 추가하세요."

**구현 방법:**
```vue
<template>
  <q-drawer v-model="leftDrawerOpen">
    <component v-if="leftSidebarComponent" :is="leftSidebarComponent" />
    
    <!-- 안내 메시지 표시 -->
    <div v-else-if="shouldShowMessage" class="message-container">
      <q-icon name="info" size="48px" />
      <p>{{ leftBehavior?.message }}</p>
    </div>
  </q-drawer>
</template>

<script setup>
const shouldShowMessage = computed(() => {
  const behavior = leftBehavior.value
  return behavior?.showMessage && isEmptyContent.value
})
</script>
```

## 🔄 마이그레이션 가이드

기존 사이드바를 새 구조로 마이그레이션:

1. `leftSidebarComponents` → `leftSidebarConfigs`로 변경
2. `component` 속성 추가
3. `behavior` 객체 추가 (기본값 사용 가능)

```javascript
// Before
'parts-management': () => import('...'),

// After
'parts-management': {
  component: () => import('...'),
  behavior: {
    autoOpen: false,
    showMessage: false,
    respectMobileHidden: true,
    defaultOpen: true,
    saveState: true,
    message: null,
  },
}
```

## 📋 등록 전략 및 시나리오

### 등록 수 추정

#### 최소 시나리오 (현재)
- 메인 메뉴: 12개
- 등록 수: **12개**

#### 중간 시나리오
- 메인 메뉴: 12개
- 서브 메뉴 평균 2개: 12 × 2 = 24개
- 등록 수: **24~30개**

#### 최대 시나리오
- 메인 메뉴: 20개
- 서브 메뉴 평균 3개: 20 × 3 = 60개
- 라우트 파라미터 조합: +20개
- 등록 수: **80~100개**

---

### 등록 전략

#### 1단계: 메인 메뉴만 등록 (권장 시작점)

**특징:**
- 메뉴당 1개 등록
- 서브 컨텍스트는 컴포넌트 내부에서 처리
- 등록 수: 10~20개

**예시:**
```javascript
const leftSidebarConfigs = {
  'parts-management': {
    component: () => import('...'),
    behavior: { ... },
  },
  'dev': {
    component: () => import('...'),
    behavior: { ... },
  },
}
```

**장점:**
- ✅ 등록 수가 적어 관리 용이
- ✅ 구조가 단순하고 명확
- ✅ 성능 저하 없음

**단점:**
- ⚠️ 서브 컨텍스트별 다른 사이드바가 필요하면 확장 어려움

---

#### 2단계: 서브 메뉴/컨텍스트별 등록 (필요 시)

**특징:**
- 메뉴:서브메뉴 형태의 키 사용
- 컨텍스트별 다른 사이드바 등록
- 등록 수: 20~50개

**예시:**
```javascript
const leftSidebarConfigs = {
  'parts-management': {
    component: () => import('...'), // 기본
    behavior: { ... },
  },
  'parts-management:physical': {
    component: () => import('...'), // 물리 공간 전용
    behavior: { ... },
  },
  'parts-management:parts-data': {
    component: () => import('...'), // 부품 데이터 전용
    behavior: { ... },
  },
  'dev': {
    component: () => import('...'),
    behavior: { ... },
  },
  'dev:editor': {
    component: () => import('...'), // 편집 모드 전용
    behavior: { ... },
  },
}
```

**MainLayout.vue에서 키 생성:**
```javascript
const sidebarKey = computed(() => {
  const menu = currentMenu.value
  const context = getContextFromStore(menu) // Store에서 컨텍스트 가져오기
  return context ? `${menu}:${context}` : menu
})
```

**장점:**
- ✅ 세밀한 제어 가능
- ✅ 컨텍스트별 다른 동작 설정

**단점:**
- ⚠️ 등록 수 증가
- ⚠️ 키 관리 복잡도 증가

---

#### 3단계: 동적 키 생성 (대규모, 50개 이상)

**특징:**
- 패턴 매칭 또는 함수 기반 키 생성
- 등록 수: 50개 이상

**예시:**
```javascript
// 패턴 기반 등록
const leftSidebarConfigs = {
  'parts-management': { ... },
  'parts-management:*': { ... }, // 와일드카드 패턴
}

// 함수 기반 키 생성
function getSidebarKey(menu, context) {
  if (context) return `${menu}:${context}`
  return menu
}
```

### 서브 메뉴 등록 여부 결정 가이드

#### 등록 불필요 (컴포넌트 내부 처리)

**조건:**
- 같은 컴포넌트 사용
- 내부 상태로 다른 UI 표시
- 사이드바 구조가 유사

**예시:**
```javascript
// parts-management: 하나의 사이드바로 충분
'parts-management': {
  component: () => import('PartsManagementSidebar.vue'),
  // 내부에서 sidebarMode로 분기 처리
  // - null: 대시보드
  // - 'physical': 물리 공간
  // - 'parts-data': 부품 데이터
}
```

---

#### 등록 필요 (서브 키로 분리)

**조건:**
- 완전히 다른 UI
- 다른 동작 설정 필요
- 독립적인 컴포넌트

**예시:**
```javascript
// dev: 문서 목록과 편집기는 완전히 다른 UI
'dev': {
  component: () => import('DocumentListSidebar.vue'),
  behavior: {
    autoOpen: true,
    showMessage: true,
    message: '문서를 선택하세요.',
  },
},
'dev:editor': {
  component: () => import('DocumentEditorSidebar.vue'),
  behavior: {
    autoOpen: false,
    showMessage: false,
    defaultOpen: true, // 편집 시 항상 열림
  },
}
```

### 라우트 파라미터 기반 등록

**시나리오:**
```
/parts-management → 'parts-management'
/parts-management/:id → 'parts-management:detail'
/parts-management/:id/edit → 'parts-management:edit'
```

**등록:**
```javascript
const leftSidebarConfigs = {
  'parts-management': { ... },
  'parts-management:detail': { ... },
  'parts-management:edit': { ... },
}
```

**MainLayout.vue에서 키 생성:**
```javascript
const currentMenu = computed(() => {
  const path = router.currentRoute.value.path
  if (path.startsWith('/parts-management')) {
    if (path.includes('/edit')) return 'parts-management:edit'
    if (path.match(/\/parts-management\/[^/]+$/)) return 'parts-management:detail'
    return 'parts-management'
  }
  // ...
})
```

## 🎯 최종 권장사항

### 등록 전략

1. **기본**: 메인 메뉴만 등록
   - 서브 컨텍스트는 컴포넌트 내부 처리
   - 등록 수: 10~20개

2. **확장**: 필요 시 서브 키 추가
   - 완전히 다른 UI가 필요할 때만
   - 등록 수: 20~50개

3. **대규모**: 동적 키 생성
   - 패턴 매칭 또는 함수 기반
   - 등록 수: 50개 이상

### 서브 메뉴 등록 여부

- ✅ **같은 컴포넌트, 다른 상태** → 등록 불필요 (내부 처리)
- ✅ **완전히 다른 UI** → 서브 키로 등록
- ✅ **라우트 기반** → 라우트 파라미터를 키에 포함

### 관리 복잡도

- **20개 이하**: 현재 구조 유지
- **20~50개**: 모듈화 고려
- **50개 이상**: 동적 키 생성 + 모듈화 필수
