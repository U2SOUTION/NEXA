### 1. 보안 및 권한 관리 체계 (Security & Governance)

## 1.1 목적과 범위

본 문서는 NEXIA `7개 탭 체계` 전반의 인증, 인가, 데이터 보호, 감사 추적 기준을 정의한다.

## 1.2 인증/세션 기준

- 인증 표준: OIDC/OAuth2 기반 토큰 인증.
- 세션 정책: Access Token 15분, Refresh Token 7일.
- 재인증 트리거: 고위험 명령, 권한 변경, 장치 변경 시 즉시 재인증.
- 멀티윈도우: SharedWorker 세션 상태를 기준으로 모든 창 동기 차단.

## 1.3 인가(RBAC) 모델

| 역할 | 읽기 | 편집 | 실행 | 권한 관리 |
| --- | --- | --- | --- | --- |
| Owner | 전체 | 전체 | 전체 | 가능 |
| Admin | 전체 | 전체 | 전체 | 제한적 가능 |
| Editor | 범위 내 | 범위 내 | 범위 내 | 불가 |
| Viewer | 범위 내 | 불가 | 불가 | 불가 |

- 고위험 작업(대량 변경, IoT 제어, 배포)은 Cockpit 승인 단계를 필수로 한다.

## 1.4 데이터 보호

- 전송 구간: TLS 1.2 이상.
- 저장 구간: 민감 데이터 AES-256 암호화.
- 프롬프트 보안: 입력 전 마스킹(개인정보/키/토큰), 출력 후 정책 필터링.
- 키 관리: 분기별 키 회전, 긴급 교체 Runbook 운영.

## 1.5 AI 가드레일

- 공통 정책 Subgraph를 모든 Rivet 그래프 선행 노드로 강제.
- 금지 동작: 비인가 파일 접근, 민감정보 출력, 승인 없는 자동 실행.
- 응답 검증: 정책 점수 미달 시 재생성 또는 사용자 승인 대기.

## 1.6 감사 및 대응

- 감사 로그 대상: 로그인, 권한 변경, 엔진 호출, 배포, 실패 이벤트.
- 보존 기간: 180일 이상.
- 사고 대응: 탐지(5분) -> 격리(15분) -> 복구(4시간 내) -> 사후 보고.

## 1.7 KPI

- 인증 실패 탐지율 99% 이상.
- 권한 오남용 사고 0건 목표.
- 고위험 작업 승인 누락 0건 목표.
