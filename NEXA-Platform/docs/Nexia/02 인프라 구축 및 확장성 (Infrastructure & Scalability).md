### 2. 인프라 구축 및 확장성 (Infrastructure & Scalability)

## 2.1 목적과 범위

본 문서는 NEXIA `7개 탭`을 안정적으로 운영하기 위한 배포, 확장, 성능 기준을 정의한다.

## 2.2 배포 아키텍처 기준

- 앱 계층: Vue/Quasar 프론트 + Node.js 오케스트레이터.
- 엔진 계층: Ollama, ComfyUI, ESPHome를 외부 서비스로 분리.
- 상태 계층: Yjs 협업 상태 + 서버 영속 저장소.
- 권장 형태: 초기 단일 리전, 성장 후 멀티 AZ 전환.

## 2.3 확장 전략

- 수평 확장: API 서버/워커를 무상태로 유지.
- 비동기 처리: 장시간 작업은 큐 기반으로 분리.
- 캐싱: 자주 호출되는 모델/워크플로우 결과 캐시 적용.
- Kafka 도입 조건: 이벤트 처리량이 임계치를 넘을 때 단계적 전환.

## 2.4 성능 목표(SLO)

| 항목 | 목표 |
| --- | --- |
| API 응답 시간 | P95 300ms 이하 |
| 탭 전환 UI 지연 | P95 150ms 이하 |
| 상태 전파 지연 | 평균 50ms 이하 |
| 에러율 | 월 0.5% 이하 |
| 가용성 | 월 99.9% 이상 |

## 2.5 용량 계획

- 기준 단위: 동시 세션, 초당 요청, 엔진 호출량, 스트림 이벤트량.
- 최소 운영 기준: 프로젝트당 동시 20세션.
- 스케일 아웃 트리거: CPU 70% 이상 10분 지속 또는 큐 대기 임계치 초과.

## 2.6 관측성(Observability)

- 메트릭: 응답시간, 에러율, 큐 지연, 엔진 가용성.
- 로그: 요청 추적(traceId), 정책 검증 결과, 장애 이벤트.
- 알림: SEV1 즉시, SEV2 10분 내, SEV3 일괄 보고.

## 2.7 운영 체크리스트

- 주간 부하 점검(트래픽/리소스/비용).
- 월간 DR 리허설(백업 복원/장애 전환).
- 분기별 아키텍처 리뷰(병목/교체 후보/기술부채).
