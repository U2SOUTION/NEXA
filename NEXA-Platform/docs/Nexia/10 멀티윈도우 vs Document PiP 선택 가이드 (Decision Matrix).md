### 10. 멀티윈도우 vs Document PiP 선택 가이드 (Decision Matrix)

## 10.1 목적

본 문서는 NEXIA 기능 설계 시 멀티윈도우와 Document PiP 중 어떤 방식을 선택할지 결정 기준을 제공한다.

## 10.2 한 줄 정의

- 멀티윈도우: `병렬 작업/전문 생산성` 최적화
- Document PiP: `상시 보조/경량 제어` 최적화

## 10.3 비교 매트릭스

| 기준 | 멀티윈도우 | Document PiP |
| --- | --- | --- |
| 주 목적 | 작업 공간 분할/병렬 처리 | 항상 위 보조 제어 |
| 복잡 편집 | 강함 | 약함 |
| 지속성 | 작업 세션 중심 | 메인 탭 종속 |
| 제어권 충돌 위험 | 중간~높음 | 중간 |
| 구현 난이도 | 높음 | 중간 |
| UX 성격 | 전문가형 | 앰비언트형 |

## 10.4 선택 규칙

- 아래 조건이면 멀티윈도우 선택:
  - 탭 2개 이상 동시 편집이 필요
  - 대형 캔버스/코드/그래프를 병렬로 봐야 함
  - 레이아웃 복원과 멀티 모니터 활용이 핵심
- 아래 조건이면 PiP 선택:
  - 핵심 상태 표시와 짧은 명령만 필요
  - 타 애플리케이션 작업 중 보조 비서가 필요
  - 음성 대기와 빠른 인터럽트가 핵심

## 10.5 혼합 전략(권장)

- 기본 정책: 작업은 멀티윈도우, 상시 제어는 PiP.
- 제어권 정책: "한 시점 한 STT 엔진".
- 승인 정책: 고위험 작업은 항상 Cockpit 경유.

## 10.5.1 탭 증감 판단 기준

- 탭을 늘릴 때:
  - 독립된 책임/워크플로우가 기존 탭과 명확히 분리될 때
  - 별도 KPI와 운영 책임자(owner)가 정의될 때
  - 보안/권한/장애 대응 정책이 독립적으로 성립할 때
- 탭을 줄일 때:
  - 기능 중복으로 인지 부하가 증가할 때
  - 사용 빈도/성과 지표가 임계치 이하일 때
  - 운영 비용 대비 가치가 낮고 기존 탭에 흡수 가능할 때
- 원칙:
  - "탭 수 고정"이 아니라 "책임 경계 명확화"를 우선한다.

## 10.6 모드별 권장안

| 모드 | 권장 기술 | 설명 |
| --- | --- | --- |
| Deep Work | 멀티윈도우 | Synapse/Glos/Physis 병렬 작업 |
| Ambient Assistant | PiP | 상시 대기/빠른 전송/중단 |
| Hybrid Control | 둘 다 | 메인 작업 + 보조 음성 인터페이스 |
| Mobile Light | PiP 유사 경량 패널 | 모니터링/승인 중심 |

## 10.7 의사결정 체크리스트

- 이 기능은 복잡 편집이 필요한가?
- 메인 창 외부에서 상시 표시가 필요한가?
- 창 종료/복구 시 데이터 손실 리스크가 있는가?
- 제어권 충돌을 자동 해결할 수 있는가?
- 접근성/프라이버시 요구를 충족하는가?

## 10.8 KPI 선택 기준

- 멀티윈도우 선택 시 필수 KPI:
  - 상태 전파 지연, 레이아웃 복원 성공률, 충돌 해결률
- PiP 선택 시 필수 KPI:
  - 제어권 전환 지연, 상태 불일치율, 음성 루프 재개 성공률
