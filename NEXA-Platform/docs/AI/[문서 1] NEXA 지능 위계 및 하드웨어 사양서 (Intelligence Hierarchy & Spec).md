## 목적

넥사(NEXA) 시스템 구축을 위한 첫 번째 단계로, 시스템의 물리적 뼈대와 지능의 체급을 결정하는 **'지능 위계 및 하드웨어 사양서'**를 작성합니다. 이 문서는 '반사 신경'인 센티널과 '전략적 뇌'인 인디케이터가 각자의 역할에 최적화된 하드웨어에서 구동되도록 설계하여, 연산 부하를 분산하고 실시간 반응성을 확보하는 데 목적이 있습니다.

### NEXA AI 지능 위계 및 하드웨어 사양서 (Intelligence Hierarchy & Spec)

#### 1. 지능 계층별 역할 및 배치 전략

**명명 규칙:** 하위 하드웨어·지능에는 **Sentinel**을 공통으로 붙이고(나노 센티널, 마이크로 센티널), 상위 고성능·맥락 해석 계층에는 **Vista Indicator**로 통일한다. [NEXA-STACK-01] §8.2와 동일.

넥사 시스템은 데이터를 생성하고 해석하는 주체를 **반사·인식 계층(Sentinel)**과 **전략 계층(Vista Indicator)**으로 이분화하여 연산 효율을 극대화한다.

| 체급 (공식 명칭)                        | 역할      | 핵심 임무                                                | 배치 환경                 |
| :-------------------------------------- | :-------- | :------------------------------------------------------- | :------------------------ |
| **나노 센티널** (Nano Sentinel)         | 반사 신경 | 로우 데이터 감시, 노이즈 제거, 5W1H 단편 사실(Fact) 추출 | 현장 최전방 (ESP32 등)    |
| **마이크로 센티널** (Micro Sentinel)    | 인식 지능 | 객체 탐지 및 사건(Event) 식별, 데이터 비식별화           | 엣지 허브 (라즈베리 파이) |
| **비스타 인디케이터** (Vista Indicator) | 전략적 뇌 | 맥락(Why) 해석, 코일 벨렌서 기반 전략 수립, 사용자 조언  | 중앙 서버 (NAS)           |

#### 2. 하드웨어 세부 사양 (Hardware Specification)

**① Nano Sentinel (ESP32)**

- **하드웨어 사양:** ESP32-S3 또는 동급의 독립형 센서 모듈.
- **주요 지능:** TinyML, Rule-based 패턴 매칭.
- **특성:** **10ms~50ms 이내의 즉각적 반응**을 수행하며, 하드(Hard) 도메인에서 위험 감지 시 인디케이터를 거치지 않는 **'로컬 선조치(Reflex)'**를 담당합니다.

**② Micro Sentinel (Raspberry Pi)**

- **하드웨어 사양:** **라즈베리 파이 5 (NPU 탑재 권장)** 또는 고성능 엣지 PC.
- **주요 지능:** YOLOv10(객체 탐지), SLM(Phi-3, Gemma 2B급).
- **특성:** 영상/오디오를 분석하여 특정 사건을 식별하며, 개인정보가 포함된 데이터를 즉시 비식별화된 텍스트(5W1H)로 변환하여 보안 게이트 역할을 수행합니다.

**③ Vista Indicator (AI NAS Server)**

- **하드웨어 사양:**
    - **CPU:** Intel Core i5/i7 또는 AMD Ryzen 5/7 이상 (x86 64비트 필수).
    - **RAM:** **32GB 이상** (중형 모델 상주 및 병렬 처리용).
    - **GPU:** **NVIDIA RTX 3060 (VRAM 12GB) 이상** (AI 추론 가속 필수).
- **주요 지능:** 7B~14B LLM (Llama 3 등), 코일 벨렌서 엔진, RAG 가속기.
- **배치 환경:** Docker 및 Ollama 기반의 서버 환경.

#### 3. 연산 부하 분산 및 반응 속도 최적화 로직

- **계층적 필터링 (Hierarchical Filtering):** 나노 센티널이 로우 데이터를 5W1H 문장으로 요약하여 전달함으로써, 상위 계층인 비스타 인디케이터의 **연산 부하를 90% 이상 경감**시킵니다.
- **에너지 효율 관리:** 나노 센티널이 유의미한 변화를 포착했을 때만 마이크로와 비스타를 깨워 시스템 전체의 에너지 효율을 높입니다.
- **도메인별 분리 대응:**
    - **하드 도메인 (보안/안전):** 센티널 단에서 **0.1초 미만**의 선조치를 우선하여 지연 시간을 최소화합니다.
    - **소프트 도메인 (기획/아트):** 인디케이터의 추론(약 1~3초 소요)을 거쳐 부드럽고 풍성한 조언을 제공합니다.

#### 4. 배치 계획 및 연결 (Deployment & Connectivity)

- **통신 방식:** ESP32와 라즈베리 파이는 **로컬 WiFi/MQTT**를 통해 NAS와 연결되어 지연 시간을 10ms~30ms 내외로 유지합니다.
- **보안 게이트:** 모든 외부 클라우드와의 연결은 비스타(NAS) 계층에서 통합 관리하며, 엣지 단의 마이크로 센티널은 비식별화된 데이터만 상향 전송합니다.

**결론:** 센티널의 정직한 사실 보고와 비스타 인디케이터의 지혜로운 맥락 해석이 최적의 하드웨어 밸런스 위에서 작동하도록 보장한다. 이를 통해 NEXA는 단순 자동화를 넘어 실시간으로 인간과 공감하는 **살아있는 지능 체계**의 물리적 토대를 갖춘다. 아래는 3단계 지능 위계(나노 센티널, 마이크로 센티널, 비스타 인디케이터)에 따른 Hugging Face 활용 권장 모델 목록이다.

### 💡 모델 선택 및 운용 전략 (NEXA 가이드라인)

1.  **지능적 분업:** 나노 센티널은 **"추측하지 말고 관찰"**하여 사실(Fact)만 보고하고, 비스타 인디케이터가 외부 API와 협력하여 **"지혜로운 조언(Why)"**을 내리도록 모델을 배치하십시오.
2.  **보안 게이트:** 음성 및 영상 데이터 처리는 가급적 **마이크로 센티널**(라즈베리 파이)에서 처리하여 비식별화된 텍스트(5W1H)로 변환한 후 비스타 인디케이터로 전송하십시오.
3.  **RAG 활용:** 모든 모델의 결과물은 **아카이브(Archive)**에 기록되며, 비스타 인디케이터는 RAG 가속기를 통해 이 과거 데이터를 현재 맥락의 필터로 사용해야 한다.

### 6. 참고 및 보충 (개념·분산 엣지·RAG·반사/인지·하이브리드·피지컬 동향)

#### 6.1 개념: 텐서(Tensor) 및 코딩 패러다임

- **텐서:** 1차원 벡터, 2차원 행렬을 넘어 3차원 이상의 입체적 수치 구조. 컬러 이미지는 R·G·B 행렬이 쌓인 3차원 텐서로 표현된다.
- **코딩 패러다임 전환 (AI 도입 시):**
    - **How → What:** 동작 과정(How)의 나열 대신 목적(What)·상황 정의에 집중. "이 데이터가 정상/이상인지 알려줘" 수준의 요청으로 전환.
    - **예외 처리:** AI는 확률적 판단으로 노이즈·예외에 유연 대응; 수천 개 if문 방어 대신 데이터·모델 갱신으로 대체(Software 2.0).
    - **엣지 코드 구조 (2026년 권장):** 상단=센서·전처리, 중간=AI 모델 호출·결과 수신, 하단=액션(모터·MQTT). 설계적 코딩 비중 확대.

#### 6.2 계층적 연합 추론(분산 엣지 AI)

- **ESP32(말단) + 메인 AI(중앙):**
    - 하위: 2·3차원 데이터·특징 추출로 부하 감소. 중앙: 시공간 텐서 완성 후 최종 판단.
    - 이점: 데이터 압축, 멀티모달 정확도, 비용 효율. 구현 시 NTP/PTP 동기화, MQTT/gRPC, 엣지 임베딩 활용.
- **ESP32에서 RAG(Tiny-RAG):** SRAM(520KB 내외) 제약으로 엣지 최적화형 설계. SQLite Micro/LittleFS, Ring Buffer로 최신 맥락 유지. 임베딩 엣지화·상태 태그 저장·플랫폼 협업 이원화. 내부 저장은 CBOR/MessagePack 권장(전송은 JSON). 엣지 RAG는 "평소와 다른 데이터"만 선별해 플랫폼으로 전송하는 스마트 전송이 핵심 가치.
- **외부 메모리 사용 시:** Tiered Storage(SRAM=인덱스·최근 벡터, 외부=상세 데이터), 고정 크기 레코드·바이너리 검색으로 인덱싱 최적화. 즉각 제어는 RAG 배제, 상태 추론·맥락 파악(0.5~1초)에는 RAG 필수. PSRAM 8MB 이상·LittleFS 권장.

#### 6.3 반사적 제어 vs 인지적 판단 (즉각 vs 생각)

- **즉각 모드(Fast Path):** 임계치 초과·위험 패턴. RAG·통신 없이 TinyML이 1ms 이내 제어. 근거는 로그만 남김.
- **생각 모드(Slow Path):** 서서히 변하는 수치·모호한 상황. RAG로 과거 데이터 조회 후 결론. 4차원·맥락으로 정확도 향상.
- **구현 가이드 요약:**

| 구분      | 즉각 (Reflex)                         | 생각 (Reasoning)       |
| :-------- | :------------------------------------ | :--------------------- |
| 처리 위치 | ESP32 내부                            | 웹 플랫폼              |
| 핵심 기술 | 하드코딩 루틴 / TensorFlow Lite Micro | Vector DB + RAG        |
| 저장 매체 | SRAM                                  | 외부 메모리 / Cloud DB |
| 통신      | 없음(즉시 제어)                       | MQTT + JSON            |

- **하이브리드 엣지단:** 오프라인 캐싱(플랫폼이 요약본·Lightweight Policy를 엣지에 주기 동기화), 비상용 MVI(Minimum Viable Intelligence)·sLLM/TinyML 탑재. Critical 판단은 로컬, Non-critical은 복구 시까지 로컬 적재. 온라인 시 압축본 수시 동기화, 오프라인 시 "엣지는 웹의 생각을 학습해 두었다가 비상 시 대신 생각"하는 구조 권장. Edge Impulse 등으로 엣지용 소형 모델 사전 설계.

#### 6.4 엣지단 RAG 대안 (압축 지침)

- **Look-up Table:** 플랫폼이 "A 상황 → B 행동" 시나리오를 미리 계산해 엣지에 전달; 단절 시 유사 항목 즉시 실행.
- **가중치 동기화:** TinyML 판단 기준(가중치)을 플랫폼이 수시 튜닝해 엣지에 반영; 단절 시에도 최신화된 판단 유지.
- **상태 기반 조건부(FSM+AI):** "위험 단계 2 → 로직 세트 #5 활성화" 등 상황 모드를 코드로 내려보내 단절 시에도 유연 대응.
- **원칙:** "엣지는 생각 안 한다"를 유지하되, 인터넷 단절 대비 비상용 판단 로직을 내부 메모리에 수시 갱신. TensorFlow Lite Micro 배포 전략과 정합.

#### 6.5 피지컬 로봇 동향 (2026년)

- **완전 자체 연산(On-device):** 테슬라 옵티머스·보스턴 다이내믹스 등. 지연 불가(0.001초) 환경에서 반사+기본 인지는 로봇 내부(NVIDIA Jetson 등)·수백 GB급 가중치 내장.
- **클라우드 협력형:** 경로 최적화·LLM·RAG는 클라우드; 단절 시 동작 제한.
- **트렌드:** 엣지 지능 상향 평준화 — SLM 탑재, 월드 모델(압축된 공간·물리 법칙) 내장.
- **NEXA(ESP32) 시사점:** 모든 데이터를 엣지에 둘 수 없으나 "자주 발생하는 상황에 대한 해답"은 내장. 근육(모터 제어)=엣지 즉시, 철학/전략=플랫폼+RAG, 비상 전략 세트=엣지 수시 캐싱. [즉각-생각] 분리는 Fast-Slow 파이프라인과 일치하며, NVIDIA ISAAC 등에서 표준으로 제시되는 아키텍처와 부합한다.
