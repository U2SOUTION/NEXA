아길이님, 이번에는 **IoT 플랫폼을 설계할 때 반드시 개념이 정리되어야 하는 핵심 요소들**을 단계적으로 정리해 보겠습니다.
이건 단순 용어 문제가 아니라 **플랫폼 구조를 단순하게 만드는 핵심 개념 정리**라고 보시면 됩니다.

제가 실제 플랫폼 설계에서 자주 사용하는 **핵심 개념 12개**를 기준으로 설명하겠습니다.

---

# 1️⃣ 장치 (Device)

플랫폼에서 가장 기본 단위입니다.

**정의**

> 시스템에 연결되어 데이터를 보내거나 동작을 수행하는 물리 장비

예

- 온도 센서
- 수분 센서
- 릴레이
- 캠핑카 배터리 모니터

---

# 2️⃣ 센서 (Sensor)

장치 중에서도 **데이터를 측정하는 역할**입니다.

**정의**

> 환경이나 상태를 측정하여 데이터를 생성하는 장치

예

- 온도
- 습도
- CO₂
- 토양수분

---

# 3️⃣ 제어장치 (Actuator)

센서와 반대 역할입니다.

**정의**

> 전기 신호를 받아 실제 동작을 수행하는 장치

예

- 펌프
- 밸브
- 조명
- 팬

---

# 4️⃣ 연결장치 (Gateway)

IoT 시스템에서는 거의 항상 등장합니다.

**정의**

> 여러 장치에서 데이터를 받아 서버로 전달하는 중간 장치

예

- 라즈베리파이
- ESP 게이트웨이
- 산업용 게이트웨이

---

# 5️⃣ 데이터 (Data)

센서가 만들어내는 가장 중요한 자산입니다.

**정의**

> 장치가 측정하거나 생성하여 시스템으로 보내는 정보

예

- 온도 23.4℃
- 배터리 전압
- GPS 위치

---

# 6️⃣ 데이터 흐름 (Data Flow)

아길이님이 고민한 **Lifecycle 대체 개념**이 여기에 해당합니다.

**정의**

> 데이터가 생성되고 이동하고 사용되는 과정

예

```
센서 → 게이트웨이 → 서버 → 저장 → 분석
```

---

# 7️⃣ 상태 (State)

IoT 플랫폼에서 매우 중요한 개념입니다.

**정의**

> 장치나 시스템이 현재 어떤 상태인지 나타내는 정보

예

- 장치 연결됨
- 장치 오프라인
- 펌프 작동중

---

# 8️⃣ 이벤트 (Event)

플랫폼 자동화에서 핵심입니다.

**정의**

> 시스템에서 발생한 특정 상황

예

- 온도 30도 초과
- 장치 연결 끊김
- 배터리 부족

---

# 9️⃣ 규칙 (Rule)

자동화를 만드는 요소입니다.

**정의**

> 특정 조건이 발생하면 실행되는 동작 규칙

예

```
온도 > 30도 → 팬 켜기
```

---

# 🔟 자동동작 (Automation)

사용자가 직접 제어하지 않아도 동작하는 시스템입니다.

**정의**

> 규칙에 따라 시스템이 자동으로 수행하는 동작

예

- 자동 환기
- 자동 급수
- 자동 충전

---

# 11️⃣ 알림 (Notification)

사용자와 시스템을 연결합니다.

**정의**

> 시스템 상태나 이벤트를 사용자에게 전달하는 메시지

예

- 온도 경고
- 장치 오류
- 배터리 부족

---

# 12️⃣ 상황판 (Dashboard)

사용자가 보는 대표 화면입니다.

**정의**

> 시스템 상태와 데이터를 한눈에 보여주는 화면

예

- 온도 그래프
- 장치 상태
- 알림 목록

---

# 아길이님 플랫폼에서의 개념 구조

이 12개 개념을 연결하면 구조가 이렇게 됩니다.

```
장치
 ├ 센서
 └ 제어장치

센서 → 데이터 생성

데이터 → 데이터 흐름

데이터 → 이벤트 발생

이벤트 → 규칙 실행

규칙 → 자동동작

자동동작 → 제어장치 동작

모든 상태 → 상황판 표시

이벤트 → 알림 발생
```

이렇게 정리하면 **플랫폼 구조가 매우 단순해집니다.**

# 실제 IoT 플랫폼들이 실패하는 이유

많은 플랫폼이 아래처럼 복잡해집니다.

```
Device
Node
Endpoint
Channel
Telemetry
Asset
Thing
Component
```

개념이 많아질수록 **사용자가 이해 못합니다.**

그래서 저는 보통 **12개 이하 개념**으로 플랫폼을 설계합니다.
