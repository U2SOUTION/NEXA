# SYS GLOSSARY 문서 네이밍 규칙

> NEXA 플랫폼 문서 관리 표준 — 파일명 구성 규칙 및 코드 참조표
> 작업 순서 관리는 별도 문서 `SYS PLAN` 시리즈로 관리

---

## 파일명 구조

```
{Context} {DocType} {한글 제목 (필요시 영문 혼합)} v{N}.md
```

| 구성 요소 | 규칙                                                           |
| --------- | -------------------------------------------------------------- |
| 구분자    | 공백만 사용. 언더바·하이픈 없음                                |
| Context   | 맨 앞. 대문자 코드                                             |
| DocType   | Context 다음. 대문자                                           |
| 제목      | 한글 중심, 고유명사·전문용어는 영문 병기                       |
| 버전      | 개정이 예상되는 문서만 끝에 v1, v2... 붙임. 단발성 문서는 생략 |
| 진행 중   | 파일명 맨 앞에 `_` 하나. 탐색기 상단 고정 + 미완료 표시        |
| 수정 금지 | 파일명 맨 앞에 `@` 하나. 탐색기 상단 고정 + 수정 금지 표시     |

### 예시

```
NEXA VISION 넥사는 무엇인가 v0.2.md
NEXA REF Master Design v0.4.md
SYS ARCH NEXA 전체 아키텍처 v1.md
SYS GLOSSARY 기술 스택 통합 가이드.md
AIS SPEC AI 협업 TS 타입 스키마.md
AIS RFC ASK VOID 처리 설계.md
NOD DESIGN ESP32 베이스라인 펌웨어.md
NEXU REQ JAB5 멀티앰프 스피커 지능 선택 설계 v0.8.md
SYS PLAN NEXA 전체 작업 순서.md          ← 작업 순서 전용
_ AIS RFC 진행 중인 기획.md              ← 진행 중, 상단 고정
@ SYS GLOSSARY 문서 네이밍 규칙.md       ← 수정 금지, 상단 고정
```

## Context 계층 구조

```
NEXA  플랫폼 정체성 (최상위)
  └── SYS  기술 기반 및 표준 (전체 적용)
        ├── 서비스 영역        AIS NOD BRD ARC TRC PRT
        ├── 인프라 영역        INF NET ERP
        ├── 관리·운영 영역     ADM MYP HLP DEV
        ├── 횡단 관심사        PRJ AUTH DDL Nexnap
        └── 하드웨어·특수      NEXA NIXIE
```

## NEXA vs SYS 분리 기준

핵심 질문: **"NEXA가 없어지면 이 문서도 의미 없어지는가?"**

```
YES  →  NEXA   플랫폼 정체성, 비전, 존재 이유
NO   →  SYS    다른 플랫폼에서도 쓸 수 있는 기술 원칙, 아키텍처, 표준
```

| 구분      | NEXA                                              | SYS                               |
| --------- | ------------------------------------------------- | --------------------------------- |
| 성격      | 플랫폼 정체성, 비전, 존재 이유                    | 기술 설계 원칙, 아키텍처, 표준    |
| 질문      | "NEXA는 무엇인가?"                                | "NEXA를 어떻게 만드는가?"         |
| 변경 빈도 | 거의 안 바뀜                                      | 자주 업데이트됨                   |
| 예시      | NEXA VISION, NEXA CONCEPT, NEXA REF Master Design | SYS ARCH, SYS GLOSSARY, SYS GUIDE |

## DocType 코드표

> 표준 약어는 변형하지 않습니다. Context 코드만 NEXA 플랫폼 전용으로 정의합니다.
> DocType 순서 자체가 개발 워크플로우를 반영합니다.

### 탐색 / 아이디어 단계

| #   | 코드      | 풀 네임             | 선택 가이드                                         |
| --- | --------- | ------------------- | --------------------------------------------------- |
| 01  | `NOTE`    | Note                | 단편 메모, 아이디어 조각. 구조 없어도 됨            |
| 02  | `SPIKE`   | Spike / Exploration | "이게 가능한가" 기술 탐색. 결과가 방향을 바꿔도 됨  |
| 03  | `VISION`  | Vision Document     | 왜 만드는가. 목적과 방향의 최초 정의                |
| 04  | `CONCEPT` | Concept Document    | 핵심 개념과 용어 정의. VISION보다 구체적인 아이디어 |

### 요구사항 / 기획 단계

| #   | 코드  | 풀 네임                       | 선택 가이드                                        |
| --- | ----- | ----------------------------- | -------------------------------------------------- |
| 05  | `PRD` | Product Requirements Document | 제품 전체 요구사항. 기능·정책·사용자 요구사항 통합 |
| 06  | `REQ` | Requirements                  | PRD보다 범위가 작은 단위 요구사항                  |

### 제안 / 결정 단계

| #   | 코드  | 풀 네임                      | 선택 가이드                                   |
| --- | ----- | ---------------------------- | --------------------------------------------- |
| 07  | `RFC` | Request for Comments         | 아직 결정 전. 방향 제안·검토 요청·초안        |
| 08  | `ADR` | Architecture Decision Record | 결정 완료. 이유와 맥락 기록. RFC 확정 후 전환 |

### 설계 단계

| #   | 코드     | 풀 네임               | 선택 가이드                                 |
| --- | -------- | --------------------- | ------------------------------------------- |
| 09  | `ARCH`   | Architecture Document | 전체 구조. 기술 스택, 컴포넌트 관계         |
| 10  | `DESIGN` | Design Document       | 세부 설계. UI 흐름, 모듈 내부, 화면 구성    |
| 11  | `SPEC`   | Specification         | 동작 명세. 입출력·조건·예외, API 엔드포인트 |
| 12  | `SCHEMA` | Schema Document       | 데이터 구조. DB 테이블, 엔티티 관계         |
| 13  | `FLOW`   | Flow Document         | 업무·데이터·상태 흐름 중심 설계             |

### 운영 / 참조 단계

| #   | 코드       | 풀 네임   | 선택 가이드                                     |
| --- | ---------- | --------- | ----------------------------------------------- |
| 14  | `GUIDE`    | Guide     | 사용 방법·설치·설정 등 절차 중심                |
| 15  | `RUNBOOK`  | Runbook   | 반복 운영 절차. 배포, 장애 대응                 |
| 16  | `LOG`      | Log       | 작업 기록, 변경 이력, 실험 결과                 |
| 17  | `GLOSSARY` | Glossary  | 용어 정의 모음. 시스템 내 공통 언어             |
| 18  | `REF`      | Reference | 확정된 기준 자료. 다른 문서들이 참조하는 마스터 |

### 관리 전용 (작업 순서·계획)

| #   | 코드   | 풀 네임       | 선택 가이드                            |
| --- | ------ | ------------- | -------------------------------------- |
| 19  | `PLAN` | Plan Document | 작업 순서, 실행 계획. 별도 문서로 관리 |

> PLAN은 표준 DocType은 아니지만 1인 개발 환경에서 작업 순서 관리를 위해 NEXA 플랫폼 전용으로 추가

## DocType 선택 흐름

```
탐색·아이디어 단계인가?
  단편 메모, 구조 없음          → NOTE
  기술 가능성 탐색              → SPIKE
  왜 만드는가, 목적·방향        → VISION
  핵심 개념과 용어 정의         → CONCEPT

요구사항·기획 단계인가?
  제품 전체 요구사항            → PRD
  특정 기능·모듈 요구사항       → REQ

제안·결정 단계인가?
  아직 검토 중, 방향 제안       → RFC
  결정 완료, 이유와 맥락 기록   → ADR

설계 단계인가?
  전체 구조, 컴포넌트 관계      → ARCH
  UI 흐름, 모듈 내부 설계       → DESIGN
  동작 명세, 입출력·예외 조건   → SPEC
  데이터 구조, DB 테이블        → SCHEMA
  업무·데이터·상태 흐름         → FLOW

운영·참조 단계인가?
  사용 방법, 설치 절차          → GUIDE
  반복 운영 절차                → RUNBOOK
  작업 기록, 변경 이력          → LOG
  용어 정의 모음                → GLOSSARY
  확정된 기준 자료              → REF

작업 순서·계획인가?
  다음에 무엇을 해야 하는가     → PLAN
```

## NEXA 축약 세트 (현재 단계 기준)

40개 전체 DocType 중 현재 NEXA 플랫폼 단계에서 실질적으로 필요한 세트

| 코드       | 통합 대상                | 사용 시점                  |
| ---------- | ------------------------ | -------------------------- |
| `NOTE`     | NOTE                     | 단편 메모                  |
| `SPIKE`    | SPIKE                    | 기술 가능성 탐색           |
| `VISION`   | VISION                   | 목적·방향 최초 정의        |
| `CONCEPT`  | CONCEPT                  | 개념·철학 정의             |
| `PRD`      | PRD + BRD + MRD          | 제품 전체 요구사항         |
| `REQ`      | REQ                      | 단위 요구사항              |
| `RFC`      | RFC + PROPOSAL           | 검토 중 제안·초안          |
| `ADR`      | ADR                      | 결정 완료 기록             |
| `ARCH`     | ARCH + HLD               | 전체 구조 설계             |
| `DESIGN`   | DESIGN + LLD + WIREFRAME | 세부 설계                  |
| `SPEC`     | SPEC + API               | 동작 명세                  |
| `SCHEMA`   | SCHEMA + ERD             | 데이터 구조                |
| `GUIDE`    | GUIDE + SOP              | 절차·운영                  |
| `LOG`      | LOG + CHANGELOG + IMPL   | 기록                       |
| `GLOSSARY` | GLOSSARY + REF           | 용어·기준 자료             |
| `PLAN`     | PLAN                     | 작업 순서·계획 (별도 문서) |
