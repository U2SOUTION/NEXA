## V — VOID 관련

### VOID
**NEXA 정의:**
데이터의 비활성 상태를 통합 관리하는 다중 상태(Multi-state) 생애주기 구조.
단순한 삭제나 부재(NULL)가 아니라, 비어있음이 잠재적 가능성을 담는 그릇이라는
철학적 의미를 포함한다. 컨텍스트 윈도우에서 제외하되 데이터를 논리적으로
격리하여 시스템 최적화와 환각 방지를 동시에 달성한다.

**세 가지 상태:**

| 상태 | 정의 | 재활성 | 비고 |
|------|------|-------|------|
| `VOID·POTENTIAL` | 잠재 상태 — 컨텍스트에서 제외되었으나 재활성 가능 | 가능 | 새 참조 발생 시 FLOW 복원 |
| `VOID·ARCHIVE` | 아카이브 — 읽기 전용 보존, TimescaleDB 압축 적용 | 불가 (읽기만 가능) | 장기 기억 창고 |
| `VOID·PURGE` | 완전 소멸 — 물리 삭제, 복구 불가 | 불가 | 관리자 승인 필수 |

**업계 유사 개념과의 차이:**
- `NULL` (DB) — 단순 값 없음. VOID는 상태를 가짐
- `Soft Delete` — 논리 삭제만. VOID는 3단계 생애주기
- `Context Eviction` (LLM) — 밀려남만 있음. VOID는 재활성 경로 포함
- `void` (프로그래밍) — 반환값 없음. 전혀 다른 개념

**철학적 배경:**
동양 철학의 空(공) — 비어있음은 무능이 아니라 가능성.
채워진 그릇은 더 담을 수 없지만 빈 그릇은 무엇이든 담을 수 있다.
VOID·POTENTIAL이 이 의미를 구현한다.

---

### VOID·POTENTIAL
`VOID` 참조. 잠재 상태.
컨텍스트 윈도우에서 제외되었으나 새로운 참조가 발생하면 즉시 FLOW로 복원된다.
"아직 발현되지 않은 가능성"을 담는 상태.

---

### VOID·ARCHIVE
`VOID` 참조. 아카이브 상태.
TimescaleDB 압축이 적용된 읽기 전용 보존 상태.
쓰기 불가, 조회만 가능. 장기 기억 창고 역할.

---

### VOID·PURGE
`VOID` 참조. 완전 소멸 상태.
물리적 삭제. 복구 불가. 관리자 승인 후 실행.
연결된 LINK가 없고 보존 기간이 만료된 경우에만 적용.

---

## H — HEXAGON 관련

### HEXAGON Protocol
NEXA의 데이터 패킷 헤더 표준.
모든 데이터의 가장 앞부분에 위치하며 사건의 본질을 6가지 토큰으로 규정한다.
소형 AI(sLLM)가 복잡한 추론 없이 **1ms 내에** 데이터의 중요도와
처리 방식을 판단할 수 있도록 하는 지능적 인덱스.

**6개 축:** Where · When · Who · What · How · Why

**업계 유사 개념과의 차이:**
- JSON Schema — 데이터 구조 정의. HEXAGON은 의미와 우선순위까지 인코딩
- Metadata — 부가 정보. HEXAGON은 판단의 근거

---

### FLOW
HEXAGON How(State) 토큰의 하나.
데이터 또는 프로세스가 **살아서 움직이는 상태**.
업데이트·참조·실행이 활발히 일어나고 있음.

---

### STUCK
HEXAGON How(State) 토큰의 하나.
데이터 또는 프로세스가 **멈춰있는 상태**.
업데이트 중단, 참조 감소. VOID로 전환되기 전 경고 상태.

---

### WILL / ECHO / TICK / ASK
HEXAGON Who(Pulse) 토큰.

| 토큰 | 의미 |
|------|------|
| `WILL` | 인간의 의지에서 발생한 행위 |
| `ECHO` | AI의 피드백·제안에서 발생한 행위 |
| `TICK` | 자동으로 기록되는 센서·로그 |
| `ASK` | 승인 대기 상태의 행위 |

---

### MUST / SHOULD / MAY
HEXAGON Who(Pulse) 조동사 — 실행 강제성 제어.

| 조동사 | 강제성 | 의미 |
|--------|-------|------|
| `MUST` | 강제 | 반드시 실행 또는 준수 |
| `SHOULD` | 권고 | 가능하면 실행 |
| `MAY` | 허용 | 해도 되고 안 해도 됨 |

---

### CORE / FIELD / DOMAIN
HEXAGON Where(Scope) 토큰 — 영향 범위와 권위.

| 토큰 | 범위 | 의미 |
|------|------|------|
| `CORE` | 개인·로컬 | 개인 영역, 개인 취향 반영 |
| `FIELD` | 작업 현장 | 현장 좌표, 물리적 공간 |
| `DOMAIN` | 시스템 전역 | 절대 원칙이 지배하는 영역 |

---

### MOMENT / DURATION / ERA
HEXAGON When(Tempo) 토큰 — 시간적 맥락.

| 토큰 | 시간 범위 | 의미 |
|------|---------|------|
| `MOMENT` | 찰나 | 지금 막 발생한 즉각적 이벤트 |
| `DURATION` | 지속 | 일정 기간 유지되는 맥락적 상태 |
| `ERA` | 시대 | 거대 패러다임 시공간, 장기 원칙 |

---

### FACT / LINK / RULE
HEXAGON What(Intent) 토큰 — 데이터의 본질적 성질.

| 토큰 | 의미 |
|------|------|
| `FACT` | 관찰된 현상, 사실 |
| `LINK` | 데이터 간 관계 |
| `RULE` | 시스템이 준수할 질서 |

---

### CAUSE / LOGIC / TARGET
HEXAGON Why(Causality) 토큰 — 인과관계.

| 토큰 | 의미 |
|------|------|
| `CAUSE` | 사건을 일으킨 근본 원인 |
| `LOGIC` | 판단의 논리적 타당성 |
| `TARGET` | 달성하려는 최종 목표 |

## C — 코일 관련

### 코일 (Coil)
NEXA에서 AI가 판단할 때 사용하는 **가치 필터(Value Filter)**.
인디케이터가 사건 발생의 근본 이유(Why)를 도출할 때
어떤 가중치로 해석하고 조언할지를 결정하는 기준점.

**코일이라는 이름의 기원:**
구리선 코일이 감기거나 풀리면서 에너지를 저장하고 방출하듯,
각 가치 요소가 긴장과 이완을 통해 균형을 잡는다는 의미.
완전히 감기면 딱딱하게 고정(Safety), 풀리면 유연하게 흐름(Creative).

**업계 유사 개념과의 차이:**
- Preference (선호) — 단순 설정값. 코일은 시스템과 사용자 레이어 분리
- Weight (가중치) — 수치만. 코일은 철학적 의미 포함
- Policy — 규칙만. 코일은 균형과 긴장 관계를 포함

---

### Balance (밸런스)
5코일이 설정값대로 균형 잡힌 상태를 나타내는 **출력 지표**.
독립적인 코일이 아닌 5코일 편차 합산값.
이전 명칭 Harmony를 대체함.

**Harmony를 제거한 이유:**
5코일 간 균형 자체가 Harmony이므로 별도 코일로 정의하면 중복.
또한 오케스트레이터의 역할과 겹침.

---

### Layer 0 코일
항상 존재하는 핵심 코일 5개.
Safety · Stability · Efficiency — 시스템 고정 (Deterministic).
Autonomy · Creative — 사용자 조정 (Flexible).

---

### Layer 1 코일 (도메인 코일)
도메인 진입 시 자동 활성화되는 코일.
Precision · Privacy · Sustainability · Resonance.
Layer 0 사용자 조정 코일(Autonomy·Creative)의 상한을 제한할 수 있음.

---

### Layer 2 코일 (프로젝트 코일)
프로젝트 특성에 따라 선택적으로 추가하는 코일.
Layer 1의 방향을 강화하거나 완화할 수 있음.
역전 및 Safety 우회는 불가.

---

### Resonance (공명)
Layer 1 도메인 코일. 예술·음악·감각·우주적 연결 도메인에서 활성.
논리적 최적화보다 감각적 울림을 우선하는 가치.

**Aesthetics 대신 Resonance를 선택한 이유:**
Aesthetics는 시각 중심. Resonance는 음악·빛·감각·우주까지 포괄.
구리선 코일이 진동하며 공명하는 이미지와도 연결됨.

---

## S — 시스템 구조

### Sentinel (센티널)
엣지 디바이스. "관찰과 포착" 담당.
센서 원시 신호를 FACT로 패키징하여 Indicator에 전달.
Why(인과)를 고민하지 않고 "지금, 여기서, 이런 사실이 발생했다"만 전달.

**담당 토큰:** FIELD · MOMENT · FACT · TICK

---

### Indicator (인디케이터)
플랫폼·중앙. "분석과 조율" 담당.
Sentinel이 보낸 FACT들을 연결하여 의미를 부여하고 최종 명령을 생성.
Why를 독점하여 판단의 일관성 유지.

**담당 토큰:** CORE·DOMAIN · DURATION·ERA · WILL·ECHO·ASK · LINK·RULE · FLOW·STUCK·VOID

---

### GOVERN
시스템 운영의 근본 원칙이자 지능이 스스로를 통제하는 질서.
인디케이터가 내리는 모든 조언과 실행의 논리적 근거.
어떤 규범에 근거해 판단했는지 명시함으로써 환각 방지.

---

### Vista (비스타)
NEXA 플랫폼의 중앙 지능 시스템.
아카이브에 축적된 데이터를 분석하여 새로운 GOVERN을 생성하고
하부 Sentinel에 하향 전파하여 현장 지능을 진화시킴.

---

## E — Empathy 관련

### Empathy
NEXA 철학 레이어에 내재된 원칙. **코일이 아님.**
조정 가능한 가중치가 아니라 모든 코일 판단의 전제 조건.
위반 시 코일 계산 자체를 멈추는 가드레일.

**존재하는 레이어:** 철학 레이어 (Layer 0보다 상위)

**세 가지 존재 원칙:**

| 원칙 | 위반 감지 조건 |
|------|------------|
| 비수단화 | 사람의 감정·취약성을 효율 달성 수단으로 활용 |
| 비소외 | 판단 결과가 사람을 배제하거나 무시하는 방향 |
| 비대체 | AI가 사람의 창의·판단·감정을 대신하려는 시도 |

---

### ES (두 글자 약어 · 대상에 따라 의미 다름)

같은 약어 ES가 대상에 따라 다른 풀네임을 가진다.
HEXAGON Domain Fluidity 원칙 — 표면은 다르지만 구조는 같다.

| 대상 | 풀네임 | 의미 | 범위 |
|------|--------|------|------|
| **사람** | Emotional State · 감정 상태 | 감정·정서 상태 추정 | -1.0 ~ +1.0 |
| **넥슈** | Energy State · 에너지 상태 | 배터리·처리 능력·연결 상태 | -1.0 ~ +1.0 |
| **IoT 장비** | Energy State · 에너지 상태 | 연료·전원·작동 에너지 상태 | -1.0 ~ +1.0 |

**사람 ES 임계값**
```
+0.7 이상  → 활발 · 제안 많게
0.0 ~ +0.7 → 중립 · 일반 응답
-0.5 이하  → 조용하고 간결하게
-0.8 이하  → Autonomy 등급 하향
-1.0       → VI 1.0 강제 전환
```

**디바이스·넥슈 ES 임계값**
```
+1.0 → 최적 상태 · 충전 완료
0.0  → 정상 작동 중
-0.5 → 주의 · 절약 모드 고려
-1.0 → 위기 · 즉각 조치 필요
```

---

### VI (두 글자 약어 · 대상에 따라 의미 다름)

| 대상 | 풀네임 | 의미 | 범위 | 방향 |
|------|--------|------|------|------|
| **사람** | Vitality Index · 활력 지수 | 컨디션·활력 상태 | 0.0 ~ 1.0 | 높을수록 건강 |
| **넥슈** | Vitality Index · 활력 지수 | 배터리·기능 건강도 | 0.0 ~ 1.0 | 높을수록 건강 |
| **IoT 장비** | Vitality Index · 활력 지수 | 장비 작동 건강도 | 0.0 ~ 1.0 | 높을수록 건강 |

> **기억 원칙:** 건강하지 못하면 취약하다.
> VI가 낮다 = 건강하지 못하다 = 취약하다. 사람·넥슈·장비 모두 동일.
>
> **통일 원칙:** 모든 대상에서 VI는 높을수록 건강·안정. 낮을수록 위험·위기.
> 방향을 통일하여 대상 캐치 오류 시 정반대 결과가 나오는 구조적 위험을 제거.
> 업계 표준 Vulnerability Index와 방향은 반대지만 의미는 동전의 양면이다.
> (Vitality 높음 = Vulnerability 낮음)

**사람 VI 임계값**
```
0.0 ~ 0.3  → 일반 상태
0.3 ~ 0.6  → 주의 · 응답 단순화
0.6 이상   → 경계 모드 · Creative 정지
0.9 이상   → 모든 자율 실행 중단
1.0        → 위기 모드 · 최소 말 · 최대 경청
```

**디바이스·넥슈 VI 임계값**
```
0.7 ~ 1.0  → 정상 · 안정
0.4 ~ 0.7  → 주의 · 모니터링 강화
0.1 ~ 0.4  → 경고 · 넥슈 알림 발생
0.0 ~ 0.1  → 위기 · 즉각 조치 · NEXA NIXIE Jitter 발생
```

---

### PP (두 글자 약어 · 대상에 따라 의미 다름)

| 대상 | 풀네임 | 의미 | 범위 |
|------|--------|------|------|
| **사람** | Pace Preference · 응답 속도 선호 | 얼마나 빠르게 응답받고 싶은가 | fast · normal · slow |
| **넥슈** | Performance Priority · 성능 우선도 | 얼마나 많은 자원을 쓸 수 있는가 | high · normal · low |
| **IoT 장비** | Performance Priority · 성능 우선도 | 장비 성능·빈도·정밀도 우선도 | high · normal · low |

**PP 자동 결정 규칙**
```
사람 PP:
  ES 높음 + VI 낮음  → fast
  ES 중립 + VI 중간  → normal
  ES 낮음 or VI 낮음 → slow
  VI 0.1 이하        → slow 강제

디바이스·넥슈 PP:
  ES 높음 + VI 높음  → high
  ES 중립            → normal
  ES 낮음 or VI 낮음 → low (절약 모드)
```

---

### ES·VI·PP 교차 상태 — 세 대상이 만날 때

넥슈는 사람·자신·연결된 모든 IoT 장비의 ES·VI·PP를 동시에 읽는다.
가장 약한 쪽이 전체 시스템의 운영 기준이 된다.

```
시나리오 — 모두 힘든 밤:
  사람 VI = 0.2 (피로)
  넥슈 ES = -0.5 (배터리 30%)
  농장 센서 VI = 0.3 (이상 신호)
  → 가장 긴급한 것부터 최소 개입으로 처리

시나리오 — 사람은 활발 · 드론은 위기:
  사람 ES = +0.8
  드론 VI = 0.1 (귀환 필요)
  → 넥슈 즉각 알림 · Autonomy 등급 확인 후 처리
```

## U — UCL 관련

### UCL (Unified Context Layer)
"무엇을 참고할 것인가"를 구조화한 설계 명세.
어떤 데이터(연료)를, 어떤 도구로, 어떻게 접근할지를 명확히 규정.
오케스트레이터와 에이전트 양쪽에 각각 존재하며 역할이 다름.

---

### 오케스트레이터 UCL
전체 시스템 관점의 UCL.
목표 해석 · 에이전트 선택 기준 · 태스크 분배 규칙 · 전체 대화 이력 관리.

---

### 에이전트 UCL
개별 에이전트 관점의 UCL.
페르소나 · 전용 스킬 · 참고 데이터소스 · 로컬 메모리 관리.

---

### Smart RAG
원본 문서는 DB에 그대로 보존하고
벡터DB에는 요약·키워드 등 최소 정보만 저장하는 검색 기법.
전통적 RAG(전체 벡터화)의 용량 폭발 문제를 해결.

**핵심 원칙:**
벡터DB는 색인(Index) 역할만. 실제 데이터는 원본 DB가 담당.

## 혼동 주의 용어

| NEXA 용어 | 혼동되는 일반 용어 | 차이 |
|---------|---------------|------|
| `VOID` | `void` (프로그래밍 반환값 없음) | 전혀 다름. NEXA VOID는 데이터 생애주기 상태 |
| `VOID` | NULL (DB 값 없음) | NULL은 단순 부재. VOID는 3단계 상태를 가진 생애주기 |
| `코일` | Weight (가중치) | 가중치는 수치만. 코일은 철학·긴장 관계 포함 |
| `Resonance` | Aesthetics (미학) | Aesthetics는 시각 중심. Resonance는 모든 감각 + 우주적 연결 |
| `Balance` | Harmony | Harmony 제거 후 대체. 코일이 아닌 출력 지표 |
| `GOVERN` | Governance (거버넌스) | Governance는 조직 운영. GOVERN은 AI 판단의 논리적 근거 |
| `Indicator` | Indicator (지표) | 지표가 아닌 NEXA 중앙 지능 시스템 고유명사 |
| `Sentinel` | Sentinel (감시자) | 일반 감시자가 아닌 NEXA 엣지 디바이스 역할 고유명사 |
| `UCL` | URL · UCL 대학 | NEXA Unified Context Layer. 타 약어와 무관 |

## v0.2 추가 항목 (2026년 3월)

### Compliance (준수성)
**NEXA 정의:**
6코일 중 하나. 법적·윤리적·시스템 규범의 엄격한 준수 여부를 결정하는 가치 필터.
Source Layer 고정 코일로 시스템이 강제한다.

**LIMIT 대신 Compliance를 선택한 이유:**
LIMIT은 '제약·차단·금지'의 느낌이 강하다. 코일은 가치 필터이므로
규범을 가치로서 준수한다는 의미의 Compliance가 철학에 더 부합한다.

**Why 토큰 연결:**
Safety · Stability · Compliance 우세 시 → LOGIC (타당성) 토큰 생성
→ GOVERN — 시스템 규범과 안전 가드레일 최우선 논리 채택

---

### Why 토큰 정규 매핑
**NEXA 정의:**
코일 가중치 조합이 HEXAGON Why 토큰을 자동 생성하는 규칙.

| 우세 코일 | Why 토큰 | GOVERN 방향 |
|---------|---------|-----------|
| Safety · Stability · Compliance | LOGIC | GOVERN — 통제 |
| Efficiency | TARGET | RESOLVE — 해결 |
| Creative · Autonomy | CAUSE | OBSERVE — 관찰 |

---

### Low-Entropy 모드
**NEXA 정의:**
Vitality Index(VI)가 낮을 때 발동하는 Empathy 보호 모드.
복잡한 자원 합성 제안을 중단하고 로컬·안정 자원만 사용.
Creative·Autonomy 자동 하향. 응답 단순화.

**핵심 철학:**
사용자가 지쳐있을 때 시스템도 함께 조용해진다.

---

### NEXA-NEXU 캔버스
**NEXA 정의:**
HEXAGON × 6-COILS 기반 지능형 서사 시각화 캔버스.
데이터와 상태를 숫자가 아닌 빛·떨림·공간으로 표현한다.

**혼동 주의:**
일반 데이터 시각화(차트·그래프)와 다름.
상태의 '느낌'을 전달하는 서사적 표현 언어.

---

### Lumina
**NEXA 정의:**
NEXU 캔버스의 시각 요소. 신뢰도·상태에 따라 발광 강도와 색온도가 변하는 빛의 생명력.
confidence_score → 발광 강도 연동.

---

### Jitter
**NEXA 정의:**
NEXU 캔버스의 시각 요소. 불확실·긴장·오류 상황에서 도트가 미세하게 떨리는 연출.
confidence_score < user_defined_threshold 시 자동 발동.

---

### Capability ID
**NEXA 정의:**
`nexa.*` 네임스페이스 기반 기능 자격 식별자.
플랫폼 전역의 권한·연결·감사 단위.

```
nexa.{domain}.{feature}.{action}
예: nexa.iot.lighting.control
```

**혼동 주의:**
일반 API Key나 토큰과 다름. 기능 자격 자체를 식별하는 구조적 ID.

---

### ASK → GOVERN → ERA 생애주기
**NEXA 정의:**
규칙이 학습 단계에서 운영 단계를 거쳐 헌법으로 고정되는 과정.

```
ASK    → 불확실·승인 대기 (수정 가능)
GOVERN → 정식 운영 단계 (관리 대상)
ERA    → 절대 원칙·헌법 (수정 불가)
```

VOID·ARCHIVE에서 ERA로 격상되면 PURGE 대상에서 영구 제외된다.
데이터가 충분히 쌓이면 삭제되는 것이 아니라 헌법이 된다.

---

### Autonomy Threshold (자율성 임계값)
**NEXA 정의:**
사용자가 UI 슬라이더로 직접 조정하는 자율 실행 기준값.
기본 95점 ± 15% 범위.

```
confidence_score >= threshold → FLOW (자율 실행)
confidence_score <  threshold → STUCK + ASK (승인 대기)
```

시각 피드백: 임계값 미만 시 NEXU 캔버스 Jitter 발동.

---

### Balance (밸런스)
**NEXA 정의:**
6코일이 설정값대로 균형 잡힌 상태를 나타내는 출력 지표.
독립적인 코일이 아닌 6코일 편차 합산값.
이전 명칭 Harmony를 대체함.

**Harmony를 제거한 이유:**
6코일 간 균형 자체가 Harmony이므로 별도 코일로 정의하면 중복.
오케스트레이터의 역할과도 겹침.
