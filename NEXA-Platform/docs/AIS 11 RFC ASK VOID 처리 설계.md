# AIS 11 RFC ASK VOID 처리 설계

> AI 협업 중 발생하는 ASK(질문 요청)에 대한 대기·소멸·기록 처리 설계안

---

## 배경

AI가 사람에게 판단을 요청(ASK)할 때 무한 대기는 현실적이지 않다.
1인 개발 환경에서 사람의 집중도, 신체 컨디션, 외부 상황에 따라 ASK가 무시되는 경우가 많으므로
**VOID(소멸) 처리 + 기록 보존** 구조가 필요하다.

---

## ASK 상태 흐름

```
ASK 발행
  └→ UNREAD        알림 미확인
       └→ READ          알림 확인 (열람 시각 기록)
            └→ ANSWERED     답변 완료
            └→ DEFERRED     의도적 미룸 (버튼 클릭)
                 └→ ANSWERED
                 └→ VOID     유예기간 × 2 초과
       └→ VOID          timeout 초과
            └→ VOID_BOX     미결 목록 보존
                 └→ ARCHIVE  폐기 유예기간 초과 시 아카이브 이동
```

---

## 1. 대기시간 가변 계산식

고정값 대신 질문의 긴급도와 복잡도에 따라 동적으로 계산한다.

```
timeout = 기본값 × 긴급도 계수 × 복잡도 계수
```

### 기본값

```
기본값: 10분
```

### 긴급도 계수

| 긴급도 | 계수  | 결과 (기본값 기준) |
| ------ | ----- | ------------------ |
| 낮음   | × 3.0 | 30분               |
| 보통   | × 1.0 | 10분               |
| 높음   | × 0.3 | 3분                |

### 복잡도 계수

| 복잡도 | 계수  | 설명                           |
| ------ | ----- | ------------------------------ |
| 단순   | × 0.5 | 예/아니오 수준, 빠른 판단 가능 |
| 보통   | × 1.0 | 짧은 검토 필요                 |
| 복잡   | × 2.0 | 맥락 파악 및 사고 시간 필요    |

### 적용 예시

```
"이 파일 삭제할까요?"            단순 + 보통  →  5분
"아키텍처 방향을 바꿀까요?"      복잡 + 높음  →  6분
"로그 정리 주기 설정할까요?"     단순 + 낮음  →  15분
```

### DEFERRED 상태의 timeout

```
DEFERRED timeout = 일반 timeout × 2
```

의도적으로 미룬 것이므로 더 긴 유예를 부여한다.

## 2. 읽음 확인 및 무시 추정

사람의 내면 상태(봤는지, 귀찮았는지)는 직접 파악 불가능하다.
행동 데이터를 누적해 **간접 추정**한다.

### 상태 정의

| 상태       | 의미                          |
| ---------- | ----------------------------- |
| `UNREAD`   | 알림 미확인                   |
| `READ`     | 알림 클릭, 열람 시각 기록     |
| `DEFERRED` | 봤고 의도적으로 나중으로 미룸 |
| `VOID`     | timeout 초과 소멸             |

### 간접 추정 방법

**재알림 반응 분석**

```
1차 알림 무반응
  → 재알림 발송
    → 그래도 무반응  →  BURIED  (묻혔을 가능성)
    → 그때 반응함   →  DELAYED_ATTENTION  (타이밍 문제)
```

**시간대 패턴 학습**

```
사용자 반응률이 높은 시간대를 누적 학습
  → 반응률 낮은 시간대 발행 ASK는 재알림 타이밍 자동 조정
```

**VOID 유형 구분**

```
UNREAD_VOID   →  알림 자체를 못 봤을 가능성
READ_VOID     →  봤는데 넘어간 가능성
DEFERRED_VOID →  의도적으로 미뤘으나 결국 처리 안 됨
```

### 한계 인정

완벽한 구분은 불가능하다. 최종 안전망은 **VOID_BOX를 사람이 주기적으로 검토**하는 것이다.

---

## 3. VOID_BOX 자동 폐기 기준

### 폐기 유예기간

```
폐기 유예기간 = 긴급도 기준

낮음   →  7일
보통   →  3일
높음   →  1일

DEFERRED 상태  →  유예기간 × 2 적용
```

### 폐기 처리 방식

```
1단계  VOID_BOX에서 제거
2단계  ARCHIVE로 이동 (완전 삭제 아님)
```

완전 삭제하지 않고 아카이브로 이동하는 이유:
나중에 "왜 이 결정이 내려졌는가"를 추적할 수 있어야 한다.

```json
  "voided_at": "2026-03-22T14:36:00",
  "resolved": false,
  "archive_after": "2026-03-25T14:36:00"
}
```

---

## VOID_BOX 큐 구조

```
ACTIVE      현재 실행 중인 ASK
VOID_BOX    사람이 주기적으로 확인해야 할 미결 목록
ARCHIVE     폐기 유예기간 초과 후 이동. 추적용으로 보존
```
