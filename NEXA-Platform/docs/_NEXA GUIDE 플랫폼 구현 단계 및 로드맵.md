# NEXA GUIDE 플랫폼 구현 단계 및 로드맵

**범위:** NEXA 플랫폼 전체(Knowledge OS, UI 셸, 오케스트레이션 DB, AI·도메인 협업).  
**성격:** `_KNOWLEDGE`  문서에 한정되지 않는 **상위 구현 순서** 가이드다.

**관련 문서:**

- Knowledge 전용 실행 순서: `_KNOWLEDGE GUIDE 시스템 구축 순서 및 로드맵.md`
- Knowledge DDL SSOT: `_KNOWLEDGE DDL 통합 스키마 및 물리 설계(SSOT).md`
- 오케스트레이션 스키마: `__NEXA 오케스트레이션 스키마 DDL v5.md` 등(명세·DDL v5 문서군)

---

## 구현 단계 (요약)


| 단계    | 내용                                                            |
| ----- | ------------------------------------------------------------- |
| **1** | `_KNOWLEDGE` 관련 기능을 먼저 구현한다. (스키마·Admin·라우팅 등, 세부는 준비에 따라 확장) |
| **2** | AI/도메인 UI 등 **레이아웃 기초**(탭·패널)와 **UX**를 정리·점검한다.               |
| **3** | **오케스트레이션 DB**를 구축한다.                                         |
| **4** | AI/도메인에서 **각종 모델**을 적용하고, 오케스트레이션을 붙여 **통합 테스트**한다.           |
| **5** | 이후 **도메인별 AI 협업 툴**을 순차적으로 만든다.                               |


**Knowledge 문서군·REF의 마무리 수준:** 1단계에서 **Knowledge DDL·경로·감사·게이트 규약**까지 맞추면 `_KNOWLEDGE*`·`_KNOWLEDGE REF *` 기준의 **지식층 계약**은 1차 완료로 본다. **오케스트레이션·AI 고도화**는 **3~5단계**에서 본격하며, REF는 **경로·경계 SSOT**로 유지하고 세부 런타임·모델 규범은 해당 계층에서 확장한다 — `_KNOWLEDGE REF *` **§1-B** 참고.

## 단계별 메모 (의존·주의)

### 1단계 — Knowledge 우선

- 지식 계층(`nexa_knowledge_`)·승인·감사·라우팅 최소 루프가 있으면, 이후 단계에서 “UI만 앞서가는” 상황을 줄일 수 있다.
- Knowledge DDL이 `project_assets` 등 **프로젝트 귀속 테이블**을 참조한다면, **같은 PostgreSQL 인스턴스에 최소 스키마**를 두거나, **스키마/DB 분리 전략**을 3단계 이전에 한 줄이라도 확정해 두는 것이 안전하다.

### 2단계 — 레이아웃·UX

- Knowledge Admin·NIXIE·도메인 화면이 **공통 탭/패널 패턴**을 공유하면 4·5단계에서 재사용 비용이 줄어든다.

### 3단계 — 오케스트레이션 DB

- UCL·`project_`·NIXIE 쉘 등은 4단계 모델·실행과 직접 맞물린다. 3단계에서는 **스키마 + RLS + API 경계**까지 열어두면 4단계가 수월하다.

### 4단계 — 모델·오케스트레이션·테스트

- 1단계 Knowledge와 **Capability·로그·임계(STUCK/ASK 등)** 규약을 맞추는 것이 통합 품질의 핵심이다.

### 5단계 — 도메인별 AI 협업 툴

- 2단계 UI 셸과 4단계 파이프라인을 **그대로 재사용**할지 여부가 속도와 일관성을 가른다.

---

## 이 문서의 위치

- **본 문서:** 플랫폼 전체의 **선후 관계**만 담는다. 세부 체크리스트는 각 도메인 GUIDE·DDL 명세에 둔다.
- **변경 시:** 단계 번호보다 **의존 관계**(Knowledge ↔ 오케스트레이션 ↔ UI)가 깨지지 않게 수정한다.

# 별도의 개발 로드맵

**Knowledge OS 구축 가이드**와 **오케스트레이션 설계**를 통합하여, **6단계 상세 보강 로드맵**.

### 1단계: 인프라 준비 및 지식(Knowledge) 기반 구축

가장 먼저 시스템의 '언어'와 '규칙'을 정의하는 지식 계층을 만듭니다. 지능형 시스템에서 지식은 단순한 데이터가 아니라 AI가 상황을 판단하는 지도가 됩니다.

- **할 일:** PostgreSQL 설치 및 필수 확장(pgvector, TimescaleDB) 활성화, `nexa_knowledge_`* 핵심 테이블 10개 생성.
- **이유:** 지식 계층이 먼저 구축되어야 AI가 "UI만 앞서가는" 환각 현상을 방지하고, 5W1H(육하원칙)에 기반한 정교한 라우팅이 가능해지기 때문입니다.
- **초보자 팁:** `uuid_generate_v7()` 함수를 통해 시간순 정렬이 가능한 고유 ID 체계를 먼저 확보하세요.

### 2단계: 관리 도구(Admin) 및 언어적 라우팅 구현

시스템이 이해할 수 있는 '표준 악보'를 만드는 단계입니다.

- **할 일:** 용어/토큰 CRUD API 구현, 불변 토큰 승인 큐(Change Request) 제작, 한국어 입력을 영문 IR로 변환하는 라우팅 엔진 프로토타입 개발.
- **이유:** NEXA는 내부적으로 **영어 커널(English Kernel)**을 사용하여 토큰 효율을 2~3배 높이고 논리적 일관성을 확보하기 때문입니다.
- **체크포인트:** 사용자가 한국어로 질문하면 시스템이 내부적으로 `term_key`와 5W1H 토큰으로 변환할 수 있는지 확인하세요.

### 3단계: 오케스트레이션 엔진 및 실행 트랙 설계

이제 정의된 지식을 바탕으로 실제 기기를 움직이거나 서비스를 실행하는 '두뇌'를 만듭니다.

- **할 일:** `execution_chains`(실시간 사슬), `execution_steps`(원자 단계) 테이블 구축 및 RLS(행 수준 보안) 적용.
- **이유:** 단순 로그 저장을 넘어 **타임머신 복구**와 **가상 시뮬레이션(Dry-run)**을 가능하게 하여, 실제 장비에 영향을 주지 않고 안전하게 테스트하기 위함입니다.
- **핵심 규칙:** 신뢰도 점수(`confidence_score`)가 95점 미만이면 실행을 멈추고 사용자에게 묻는(ASK) 가드레일을 이때 심어야 합니다.

### 4단계: AI 모델 연동 및 시각화(NEXU Canvas) 기초

로컬 AI(Ollama 등)를 붙여 실제로 생각하고 그 과정을 화면에 그리는 단계입니다.

- **할 일:** Ollama 임베딩 모델 연동, `nexa_self_`* 기반 다중 자아(Self facet) 테이블 구축, **NEXU 캔버스**의 족보(Why Chain) 시각화 기초 구현.
- **이유:** 사용자가 현재 '작업하는 나'인지 '창작하는 나'인지에 따라 시스템의 코일 가중치를 실시간으로 변경하여 최적의 환경을 제공하기 위함입니다.
- **주의 사항:** 고정 UCL(페르소나 등)은 항상 **500토큰 이내**로 유지하여 모델의 기억 공간을 아껴야 합니다.

### 5단계: 문서 동기화 및 지능 위계 배포

기획 문서와 시스템 지능을 하나로 묶고, 다양한 장치에 지능을 배포합니다.

- **할 일:** `src/docs/` 기획 문서 크롤러 구현, Nano(ESP32)·Micro(라즈베리파이)·Vista(서버) 위계별 차등 배포 패키저 제작.
- **이유:** 기획 문서가 수정되면 시스템의 용어 정의와 참조가 자동으로 갱신되어, 개발 문서와 실제 동작이 일치하는 **지능적 족보(Traceability)**를 완성하기 위함입니다.
- **배포 규칙:** 저사양 장치(COLD 프로필)에는 10KB 미만의 필수 데이터만 배포하고 벡터 데이터는 금지합니다.

### 6단계: 자가 회복 및 공감(Empathy) 정책 고도화

시스템이 스스로 오류를 배우고 사용자의 상태를 배려하는 마지막 단계입니다.

- **할 일:** 오류 패턴 집계(`error_patterns`), 활력 지수(`vi_threshold`) 기반 **Low-Entropy 모드**(응답 단순화) 전환 로직 구현.
- **이유:** 사용자가 피로할 때는 복잡한 제안 대신 안정적인 로컬 자원만 사용하는 등 '사람을 닮은 운영체제'로서의 완성도를 높이기 위함입니다.
- **최종 인수 기준:** 모든 실행의 유래를 기획 문서까지 역추적할 수 있고, 장애 발생 시 자동으로 롤백 제안이 뜨는지 확인하십시오.

**초보자를 위한 요약:** "먼저 **Postgres**에 지식 테이블을 만들고(1~~2단계), 그 다음 **실행 명령**을 관리하는 테이블을 만든 뒤(3단계), 마지막으로 **AI 모델**을 붙여서 시뮬레이션하세요(4~~6단계)." 이 순서를 지켜야 시스템의 근본이 흔들리지 않습니다.
