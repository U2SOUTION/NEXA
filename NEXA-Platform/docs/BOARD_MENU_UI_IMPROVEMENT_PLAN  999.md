# 넥사보드 메뉴 관리 UI 개선 계획

**작성일**: 2024년  
**목적**: 넥사보드 메뉴 관리 UI의 문제점 해결 및 사용자 경험 개선

---

## 1. 핵심 문제점 요약

- **편집 모드 불명확**: 편집 모드 진입 시 시각적 피드백 부족, 사이드바와의 연결 불명확 (해결: 편집 모드 제거)
- **복잡한 3단계 프로세스**: 단순 작업에 6단계 필요, 컨텍스트 전환 빈번
- **레이아웃 선택 중복**: 생성 시와 편집 시 경험이 분리됨
- **개념 설명 복잡**: 그룹/보드 구분이 직관적이지 않음, 탐색기 스타일 인터랙션 부족
- **삭제 기능 미정**: 삭제 UI 위치, 휴지통 적용 여부, 하위 항목 처리 방법 미정

---

## 1.1 결정 사항

- ✅ **상단 버튼 동작**: 옵션 1 (현재 선택된 항목의 하위에 추가) - 결정
- ✅ **우클릭 메뉴**: 추가 개선 사항으로 포함 - 결정
- ✅ **편집 모드**: 제거 결정
- ✅ **설정 아이콘**: 우측 대시보드 창 상단에 배치 - 결정
- ✅ **그룹/보드 추가**: 모달창으로 간단하게 처리 - 결정
- ✅ **이름 수정**: 더블클릭으로 수정 - 결정

## 2. 해결 방안

### 2.1 사이드바 중심 편집 기능 구현

**목표**: 사이드바 내에서 모든 편집 작업 수행 (편집 모드 개념 제거)

#### 구현 방안: 설정 아이콘 방식 (결정)

**개념**:

- 편집 모드라는 별도 모드를 없애고, 우측 대시보드 창 상단에 설정 아이콘 배치
- 해당 보드의 전체 설정을 변경할 수 있도록 함

```
[사이드바 (왼쪽)]
┌─────────────────────┐
│ U2 SOLUTION         │
│ [ADD DEVICE]        │
│                     │
│ [+ 그룹 추가]       │ ← 항상 표시
│ [+ 보드 추가]       │ ← 항상 표시
│                     │
│ 📁 그룹 1           │
│   📊 보드 1         │
└─────────────────────┘

[우측 대시보드 창]
┌─────────────────────────┐
│ [⚙️ 설정] ← 상단 우측   │ ← 설정 아이콘
├─────────────────────────┤
│                         │
│   대시보드 내용...      │
│                         │
└─────────────────────────┘

[설정 아이콘 클릭 시]
┌─────────────────────────┐
│ [⚙️ 설정]               │
├─────────────────────────┤
│ 보드 설정                │
│ 이름: [보드 이름]        │
│ 설명: [설명 입력]        │
│                         │
│ 대시보드 레이아웃:       │
│ [○] Single  [ ] Split-LR│
│ [ ] L-Shape [ ] Split-TB│
│                         │
│ 연결 디바이스:          │
│ [ ] Device 1            │
│ [ ] Device 2            │
│                         │
│ [저장] [취소]           │
└─────────────────────────┘
```

**장점:**

- 편집 모드 전환 불필요
- 보드 확인 중 바로 설정 변경 가능
- 더 직관적이고 간단한 UX
- 일반 모드/편집 모드 구분 불필요

**그룹/보드 추가 프로세스**

**그룹 추가:**

1. 상단 "[+ 그룹 추가]" 버튼 클릭
2. 모달창 표시: 이름 입력 필드
3. 위치 지정:
   - 현재 선택된 항목이 있으면 → 해당 항목의 하위에 추가
   - 현재 선택된 항목이 없으면 → 위치 선택 요구 또는 최상위에 추가
4. 확인 클릭 → 저장
5. 더블클릭으로 이름 수정 가능

**보드 추가:**

1. 상단 "[+ 보드 추가]" 버튼 클릭
2. 모달창 표시: 이름 입력 필드
3. 위치 지정:
   - 현재 선택된 항목이 있으면 → 해당 항목의 하위에 추가
   - 현재 선택된 항목이 없으면 → 위치 선택 요구 또는 최상위에 추가
4. 확인 클릭 → 저장
5. 신규 보드인 경우: 레이아웃 선택, 기기 선택 등 (이미 작동 중)
6. 더블클릭으로 이름 수정 가능

**우클릭 메뉴 (추가 개선)**

- 각 항목에 우클릭 시 컨텍스트 메뉴 표시
- 해당 항목의 컨텍스트에 맞는 작업 제공
- 상단 버튼과 함께 사용하여 더욱 직관적인 작업 흐름 제공

**주요 기능**

- 상단 "[+ 그룹 추가]", "[+ 보드 추가]" 버튼 항상 표시
- 모달창으로 간단한 추가 프로세스
- 우측 대시보드 창 상단에 설정 아이콘(⚙️) 배치
- 설정 아이콘 클릭 시 해당 보드의 전체 설정 변경 가능
- 더블클릭으로 이름 수정
- 우클릭 컨텍스트 메뉴 제공
- 편집 모드 전환 불필요

**구현 파일**

- `src/layouts/MainLayout.vue`: 상단 추가 버튼 항상 표시
- `src/components/TreeNavItem.vue`: 더블클릭 이름 수정, 우클릭 메뉴
- `src/components/AddGroupDialog.vue`: 그룹 추가 모달 (신규)
- `src/components/AddBoardDialog.vue`: 보드 추가 모달 (신규)
- `src/pages/NexaBoardPage.vue`: 우측 대시보드 상단에 설정 아이콘 추가
- `src/components/BoardSettingsPanel.vue`: 보드 설정 패널 (신규)

**목표**: 우측 대시보드 창 상단에 설정 아이콘을 배치하여 해당 보드의 전체 설정 변경 가능

**설정 아이콘 클릭 시**

```
[설정 패널 (우측 또는 오버레이)]
┌─────────────────────────┐
│ 보드 설정                │

│                         │

│ [ ] L-Shape [ ] Split-TB│

│ 연결 디바이스:          │

```

**주요 기능**

- 우측 대시보드 창 상단 우측에 설정 아이콘(⚙️) 배치
- 설정 아이콘 클릭 시 보드 전체 설정 패널 표시
- 레이아웃 선택과 편집을 함께 수행
- 레이아웃 변경 시 즉시 미리보기 업데이트
- 신규 보드 생성 시 레이아웃 선택은 기존 프로세스 유지 (이미 작동 중)

**데이터베이스 연동:**

- 설정 패널에서 수정 가능한 항목과 해당 DB 테이블:
  - **보드 기본 정보** (이름, 설명): `board_menu_nodes`
  - **대시보드 레이아웃** (Single, Split-LR, L-Shape, Split-TB): `board_windows`
  - **연결 디바이스**: `board_devices` (N-N 관계)
- 저장 시 해당 테이블들에 변경사항 반영

**구현 파일**

- `src/pages/NexaBoardPage.vue`: 우측 대시보드 상단에 설정 아이콘 추가
- `src/components/BoardSettingsPanel.vue`: 보드 설정 패널 (신규)
- `src/board/NexaBoardSetup.vue`: 신규 보드 생성 시 레이아웃 선택 (기존 유지)

### 2.3 탐색기 스타일 인터페이스

**목표**: 일반 탐색기처럼 직관적인 인터랙션 제공

#### 구현 내용

**시각적 구분 강화**

- **그룹**: 📁 폴더 아이콘 (노란색), 약간 다른 배경색 또는 테두리
- **보드**: 📊 대시보드 아이콘 (파란색), 기본 배경색
- 확장/축소 화살표 버튼 명확히 표시

**드래그 앤 드롭**

- 항목을 드래그하여 다른 그룹으로 이동
- 순서 변경을 위한 드래그 앤 드롭
- 드롭 존 시각적 표시 (그룹 위에 호버 시 하이라이트)

**키보드 네비게이션**

- ↑↓ 화살표: 항목 간 이동
- Enter: 선택/확장
- Delete: 삭제 (확인 다이얼로그)
- F2: 이름 변경

**컨텍스트 메뉴**

```
[그룹 우클릭 메뉴]
┌─────────────────────┐
│ 새 그룹 추가        │ ← 이 그룹 하위에 추가
│ 새 보드 추가        │ ← 이 그룹 하위에 추가
│ ─────────────────── │
│ 이름 변경           │
│ 복제                │
│ 이동                │
│ ─────────────────── │
│ 삭제                │
└─────────────────────┘

[보드 우클릭 메뉴]
┌─────────────────────┐
│ 새 그룹 추가        │ ← 같은 레벨에 추가
│ 새 보드 추가        │ ← 같은 레벨에 추가
│ ─────────────────── │
│ 이름 변경           │
│ 복제                │
│ 이동                │
│ ─────────────────── │
│ 🗑️ 삭제            │ ← 빨간색 강조
└─────────────────────┘

[빈 공간 우클릭 메뉴]
┌─────────────────────┐
│ 새 그룹 추가        │ ← 최상위에 추가
│ 새 보드 추가        │ ← 최상위에 추가
└─────────────────────┘
```

**동작 방식 정리**

1. **상단 버튼 클릭**: 현재 선택된 항목의 하위에 추가 (선택 없으면 최상위)
2. **우클릭 메뉴**: 해당 항목의 컨텍스트에 따라 적절한 위치에 추가
3. **드래그 앤 드롭**: 생성 후 위치 변경 가능

**구현 파일**

- `src/components/TreeNavItem.vue`: 드래그 앤 드롭, 키보드 네비게이션
- `src/components/ContextMenu.vue`: 우클릭 메뉴 (신규)
- `src/stores/boardMenuStore.js`: 순서 변경, 이동 기능 추가

### 2.4 단계 수 감소

**목표**: 3단계 프로세스를 1-2단계로 단순화

#### 구현 내용

**새 보드/그룹 생성**

- **기존**: 6단계 (BOARD EDIT 클릭 → 페이지 이동 → 디렉토리 선택 → 타입 선택 → 정보 입력 → 저장)
- **개선**: 2단계 (우클릭 또는 [+] 버튼 → 다이얼로그에서 정보 입력 및 저장)

**편집**

- **기존**: 4단계 (BOARD EDIT 클릭 → 항목 클릭 → 정보 수정 → 저장)
- **개선**: 2단계 (우측 대시보드 상단 설정 아이콘 클릭 → 설정 패널에서 수정 및 저장)

**삭제**

- **기존**: 4단계 (BOARD EDIT 클릭 → 항목 클릭 → 삭제 버튼 → 확인)
- **개선**: 2단계 (우클릭 메뉴 또는 키보드 Delete → 확인 다이얼로그)

**구현 파일**

- `src/components/AddBoardDialog.vue`: 통합 생성 다이얼로그 (신규)
- `src/components/AddGroupDialog.vue`: 통합 생성 다이얼로그 (신규)
- `src/pages/BoardAdminPage.vue`: 단순화 또는 제거 고려

### 2.5 삭제 기능 상세 설계

**목표**: 안전하고 직관적인 삭제 프로세스 구현

#### 삭제 UI 위치

**1. 우클릭 컨텍스트 메뉴 (주요 방법)**

```
[그룹/보드 우클릭 메뉴]
┌─────────────────────┐
│ 새 그룹 추가        │
│ 새 보드 추가        │
│ ─────────────────── │
│ 이름 변경           │
│ 복제                │
│ 이동                │
│ ─────────────────── │
│ 🗑️ 삭제            │ ← 빨간색 강조
└─────────────────────┘
```

**2. 우측 설정 패널 (보드만)**

```
[보드 설정 패널]
┌─────────────────────────┐
│ 보드 설정                │
├─────────────────────────┤
│ 이름: [보드 이름]        │
│ 설명: [설명 입력]        │
│ ...                     │
│                         │
│ [저장] [취소]           │
│ ─────────────────────── │
│ 🗑️ 보드 삭제            │ ← 하단, 빨간색 강조
└─────────────────────────┘
```

**3. 키보드 Delete 키**

- 항목 선택 상태에서 Delete 키 입력
- 확인 다이얼로그 표시
- Enter로 확인, Esc로 취소

#### 휴지통 개념 적용

**옵션 1: 휴지통 적용 (권장)**

**장점:**

- 실수로 삭제한 항목 복원 가능
- 데이터 손실 방지
- 사용자 안심

**구현 방식:**

- 삭제 시 `deleted_at` 타임스탬프 저장
- 휴지통에서 30일 후 자동 영구 삭제 (또는 수동 영구 삭제)
- 휴지통 메뉴에서 복원 가능

**데이터 구조:**

```javascript
{
  id: '...',
  name: '...',
  type: 'board' | 'group',
  deleted_at: '2024-01-15T10:30:00Z', // 삭제 시 설정
  deleted_by: 'user_id', // 선택사항
  // ... 기타 필드
}
```

**옵션 2: 즉시 삭제 (현재 방식)**

**장점:**

- 구현 단순
- 저장 공간 절약

**단점:**

- 복원 불가능
- 실수 시 데이터 손실

**결정 필요**: 휴지통 적용 여부

#### 그룹 삭제 시 하위 보드 처리

**옵션 1: 함께 삭제 (현재 구현)**

**동작:**

- 그룹 삭제 시 모든 하위 보드와 그룹도 재귀적으로 삭제
- 확인 다이얼로그에 하위 항목 개수 표시

**확인 다이얼로그 예시:**

```
┌─────────────────────────────────┐
│ 삭제 확인                        │
├─────────────────────────────────┤
│ '그룹 1' 그룹을 삭제하시겠습니까?│
│                                 │
│ ⚠️ 다음 항목들도 함께 삭제됩니다:│
│   • 보드 1                       │
│   • 보드 2                       │
│   • 하위 그룹 1                  │
│     - 보드 3                     │
│                                 │
│ 총 4개 항목이 삭제됩니다.        │
│                                 │
│ [취소] [삭제]                   │
└─────────────────────────────────┘
```

**옵션 2: 상위로 이동**

**동작:**

- 그룹 삭제 시 하위 보드들을 삭제된 그룹의 상위로 이동
- 하위 그룹도 상위로 이동

**확인 다이얼로그 예시:**

```
┌─────────────────────────────────┐
│ 삭제 확인                        │
├─────────────────────────────────┤
│ '그룹 1' 그룹을 삭제하시겠습니까?│
│                                 │

```

**옵션 3: 사용자 선택**

**동작:**

- 그룹 삭제 시 하위 항목 처리 방법 선택
- 라디오 버튼으로 선택

**확인 다이얼로그 예시:**

```
┌─────────────────────────────────┐
│ 삭제 확인                        │
├─────────────────────────────────┤
│ '그룹 1' 그룹을 삭제하시겠습니까?│
│                                 │
│ 하위 항목 처리 방법:             │
│ ( ) 함께 삭제                    │
│ ( ) 상위로 이동                  │
│                                 │
│ [취소] [삭제]                   │
└─────────────────────────────────┘
```

**권장**: 옵션 1 (함께 삭제) - 현재 구현과 일치, 단순하고 명확

#### 보드 삭제 시 데이터 처리

**삭제되는 데이터:**

1. **보드 메뉴 노드**

   - **DB 테이블**: `board_menu_nodes`
   - `boardMenuStore`에서 노드 제거
   - 하위 그룹이 있으면 함께 삭제

2. **대시보드 레이아웃 설정**

   - **DB 테이블**: `board_windows` (창 구조 - 화면 분할/병합 구조)
   - `dashboardLayoutStore`에서 해당 보드의 레이아웃 설정 제거
   - 패널 구성 정보 제거

3. **패널 데이터**

   - **DB 테이블**: `board_panels` (패널 인스턴스)
   - 각 패널의 설정 및 데이터
   - 패널 내 위젯/차트 설정

4. **디바이스 연결 정보**

   - **DB 테이블**: `board_devices` (보드-디바이스 연결 정보, N-N 관계)
   - 보드에 연결된 디바이스 목록
   - 디바이스별 설정

5. **기타 설정**
   - 보드별 사용자 설정
   - 권한 정보 (향후 구현 시)
     - **DB 테이블**: `shares_boards` (보드 공유 설정 - 향후)

**휴지통 적용 시:**

- 모든 데이터를 `deleted_at`과 함께 보관
- 복원 시 모든 설정과 데이터 복구
- 영구 삭제 시 모든 데이터 완전 제거

**즉시 삭제 시:**

- 모든 관련 데이터 즉시 제거
- 복원 불가능
- 확인 다이얼로그 강조

**확인 다이얼로그 예시 (보드 삭제):**

```
┌─────────────────────────────────┐
│ 보드 삭제 확인                    │
├─────────────────────────────────┤
│ '보드 1' 보드를 삭제하시겠습니까? │
│                                 │
│ ⚠️ 다음 데이터가 삭제됩니다:      │
│   • 대시보드 레이아웃 설정        │
│     (board_windows)              │
│   • 패널 구성 (3개 패널)          │
│     (board_panels)               │
│   • 디바이스 연결 정보            │
│     (board_devices)              │
│                                 │
│ 이 작업은 되돌릴 수 없습니다.    │
│                                 │
│ [취소] [삭제]                   │
└─────────────────────────────────┘
```

**참고**: 사용자에게는 테이블명을 표시하지 않고, 개발자 콘솔/로그에만 표시 가능

#### 삭제 프로세스 흐름

**1. 삭제 요청**

- 우클릭 메뉴 → "삭제" 선택
- 또는 키보드 Delete 키
- 또는 설정 패널에서 "삭제" 버튼

**2. 확인 다이얼로그**

- 삭제 대상 정보 표시
- 하위 항목 개수 표시 (그룹인 경우)
- 삭제될 데이터 목록 표시 (보드인 경우)
- 경고 메시지 표시

**3. 삭제 실행**

- 사용자 확인 시 `boardMenuStore.removeNode()` 호출
- 관련 데이터 정리
  - `board_menu_nodes`: 보드 노드 삭제 (CASCADE로 하위 그룹/보드 자동 삭제)
  - `board_windows`: 보드의 창 구조 삭제
  - `board_panels`: 보드의 모든 패널 인스턴스 삭제
  - `board_devices`: 보드-디바이스 연결 정보 삭제
- 성공 알림 표시

**4. 휴지통 적용 시 (옵션)**

- 삭제된 항목을 휴지통으로 이동
- 휴지통 메뉴에서 복원 가능
- 30일 후 자동 영구 삭제 또는 수동 영구 삭제

## 5. 사용자 시나리오 (개선 후)

### 시나리오 1: 새 보드 생성

**방법 A: 상단 버튼 사용**

1. 원하는 그룹 선택 (또는 선택 안 함 = 최상위)
2. "[+ 보드 추가]" 버튼 클릭
3. 모달창에서 보드 이름 입력
4. 확인 클릭 → 저장
5. 신규 보드인 경우: 레이아웃 선택, 기기 선택 등 (기존 프로세스)
6. 저장 → 선택한 위치에 즉시 표시

**방법 B: 우클릭 메뉴 사용**

1. 그룹 또는 빈 공간 우클릭
2. "새 보드 추가" 선택
3. 모달창에서 보드 이름 입력
4. 확인 클릭 → 저장
5. 신규 보드인 경우: 레이아웃 선택, 기기 선택 등 (기존 프로세스)
6. 저장 → 우클릭한 위치에 즉시 표시

### 시나리오 2: 기존 보드 편집

1. 보드를 클릭하여 우측 대시보드 창에 표시
2. 우측 대시보드 창 상단의 설정 아이콘(⚙️) 클릭
3. 설정 패널에서 모든 설정 수정 (이름, 설명, 레이아웃, 디바이스)
4. 저장 → 즉시 반영

**또는**

1. 보드 항목 더블클릭 → 이름 수정
2. 보드 항목 우클릭 → 컨텍스트 메뉴에서 "설정" 선택

### 시나리오 3: 그룹 간 이동

1. 보드 항목을 드래그 (편집 모드 불필요)
2. 대상 그룹 위에 드롭
3. 자동으로 이동 완료

### 시나리오 4: 순서 변경

1. 항목을 드래그하여 원하는 위치로 이동 (편집 모드 불필요)
2. 자동으로 순서 저장
