# NEXA NIXIE 실물 하드웨어 설계 문서 v0.1
## 실물 닉시의 구성요소 · 센서 리스트 · 플랫폼 연동

> **설계 철학**
> 닉시는 단순한 스마트 스피커가 아니다.
> 공간을 감지하고, 사람을 이해하고, 우주와 연결된 존재다.
> 카메라에 의존하지 않고 다층 센서로 프라이버시를 보호한다.
> 센서는 거부감 없는 위치에. 설치는 천장·벽면 중심으로.

## 1. 닉시 하드웨어 등급

닉시는 사용 환경과 예산에 따라 세 가지 등급으로 구성된다.
모든 등급은 동일한 NEXA 플랫폼 소프트웨어와 연동된다.

| 등급 | 코어 | 특징 | 대상 |
|------|------|------|------|
| **Lite** | ESP32-S3 단독 | 초저전력 · 배터리 운용 가능 | 서브 허브 · 각 방 배치 |
| **Standard** | Raspberry Pi 4/5 | 균형 잡힌 성능 · 로컬 AI | 거실 메인 닉시 |
| **Pro** | Raspberry Pi 5 + Hailo-8 | 고성능 로컬 AI · 풀 센서 | 홈 오피스 · 프리미엄 |

| **RPi CM4** | Cortex-A72 · 4코어 | 1~8GB | 커스텀 보드 내장 | 🔜 커스텀 PCB 시 |

```

  13 TOPS AI 연산

  → CPU 부하 없이 AI 추론
```

### 4.2 스피커

```
자체 스피커:
  소형 앰프 모듈 (MAX98357A · I2S)
  + 3W~5W 패시브 스피커
  → RPi 또는 ESP32 직접 연결

WiFi 앰프 연결:
  Snapcast 서버 → 멀티룸 오디오
  기존 WiFi 스피커·앰프에 스트리밍
  → 집 전체 오디오 시스템 활용

Bluetooth 오디오:
  RPi BT → 블루투스 스피커 연결
  → 고음질 but 지연 있음
```

### 4.3 디스플레이 — 닉시관 스타일 설계 방향

> **닉시관(Nixie Tube)** 은 1950~60년대 숫자 표시 진공관이다.
> 따뜻한 주황·황금빛 글로우가 NEXA 시각 언어의 원형이다.
> 닉시의 얼굴은 LCD보다 이 빛의 언어를 메인으로 삼는다.

---

#### 방향 1 — 아크릴 레이어 + 도트매트릭스 베이스

```
구성:
  투명 아크릴판 여러 겹을 수직으로 쌓음
  각 레이어에 WS2812B LED 배치
  바닥에 도트매트릭스 (8×8 or 16×16) 깔기

효과:
  레이어를 통과하는 빛의 산란 → 깊이감
  닉시관 특유의 "글로우" 느낌 현대적 재현
  아래서 올라오는 빛 + 위에서 내려오는 빛 교차
  Lumina 색온도 표현의 가장 자연스러운 형태
  Jitter(떨림)가 층별 빛 차이로 입체 표현

LCD 배치:
  아크릴 레이어 뒤에 LCD 배치
  → LED가 앞면 메인 얼굴
  → LCD는 아크릴 틈새로 비치는 정보

구현:
  WS2812B 스트립 · 도트매트릭스 (MAX7219)
  아크릴 두께: 3~5mm 권장
  레이어 간격: 5~10mm
```

#### 방향 2 — 3D LED 매트릭스 (LED Cube · Voxel Display)

```
구성:
  LED를 3차원 공간에 배치 (예: 8×8×8 = 512개)
  X·Y·Z 좌표로 개별 도트 제어

효과:
  NEXU 캔버스의 도트 개념을 물리 공간으로 구현
  Lumina 맥동이 3D 공간에서 퍼져나감
  Jitter가 입체적으로 표현 (수평·수직·원형 모두)
  사람이 가까워질 때 도트가 반응 (ToF 연동)

NEXA 철학 연결:
  소프트웨어 NEXU 캔버스와 하드웨어가
  같은 도트 철학을 공유하는 것
  → 화면과 실물이 하나의 언어를 씀

구현:
  WS2812B 단일 LED 어레이
  3D 프레임 (아크릴 or 금속 와이어)
  ESP32로 직접 제어 (DMA 출력)

난이도: 높음 · 납땜 집약적 · 최고의 시각적 임팩트
```

#### 방향 3 — LCD + 앰비언트 라이트 연동

```
구성:
  LCD가 정보 전면에 배치
  LCD 뒤·주변에 WS2812B LED 스트립

역할 분담:
  LCD  → 수치·텍스트·아이콘 (읽는 것)
  LED  → 감정·분위기·상태  (느끼는 것)

비트겐슈타인 연결:
  "말할 수 없는 것은 보여줄 수 있을 뿐"
  LCD는 말하고 LED는 보여주는 구조

앰비언트 효과:
  LCD 화면 색상 → 주변 LED로 번짐 (Ambilight)
  오디오 분석 BPM → LED 리듬 동기화
  Lumina 색온도 → LCD 백라이트와 연동
  → 화면과 공간이 하나의 감각 레이어로

LCD 옵션:
  2.4" TFT (SPI) · 3.5" TFT · 작은 OLED
  → LCD 크기가 클수록 앰비언트 효과 강해짐

난이도: 낮음 · 가장 실용적 · Standard 등급 권장
```

#### 방향 4 — 올노출 회로 예술 (Open Hardware Art)

```
구성:
  PCB · 센서 · 배선 · 회로 모두 외부 노출
  케이스 없음 or 투명 케이스

철학:
  기능 자체가 미학
  데이터가 흐르는 물리적 증거가 보임
  스팀펑크 · 바우하우스 · 디오게네스 스타일

NEXA 철학 연결 (푸코):
  "구조를 숨기지 않음"
  투명성이 신뢰의 물리적 표현

구성 요소 배치 미학:
  ESP32 · 센서 · LED 배선이 아트워크
  PCB 색상 선택 (청색·녹색·블랙)
  점퍼선 색상 코딩 (기능별 컬러)
  투명 아크릴 받침으로 공중 부양 느낌

난이도: 낮음 (케이스 불필요) · 디자인 감각 필요
```

#### 방향 5 — 개방형 도킹 스타일 (구형 스마트폰 연동)

```
구성:
  ESP32 메인보드가 노출된 베이스
  스마트폰이 자연스럽게 도킹되는 슬롯 존재
  스마트폰 연결 시 자동으로 NEXA 앱 실행

역할 분담:
  ESP32 단독:  Lite 모드 · 센서 · MQTT
  스마트폰 추가: 디스플레이 · 카메라 · AI 보강

Lumina 연동:
  스마트폰 화면 하단 → LED 앰비언트
  스마트폰이 없을 때 → ESP32 LED만

모듈화 철학:
  스마트폰이 꽂히면 Standard로 업그레이드
  빠지면 Lite로 자동 다운그레이드
  사용자가 점진적으로 확장 가능

난이도: 중간 · 도킹 슬롯 설계 필요 · 미해결 과제
```

#### 공통 LED 구성 요소

```

  → 감정 상태 · Lumina 색온도

  단일 WS2812B or APA106

  황금·주황 색온도 기본값

간접 조명 모드 (실물 전용):
  주변 공간을 물들이는 간접 조명
  ES·VI 낮을 때 따뜻한 황금 간접광
  수면 모드 → 극소 앰버 → 소등
```

## 6. 센서 레이어별 역할

### 6.1 단계적 각성 구조

```
[Layer 0 — 상시 극저전력]   소비: ~0.5mA
  PIR (AM312)              → 움직임 있으면 깨움
  마이크 (wake word 회로)   → "닉시야" 감지
  BLE 스캔                  → 등록 디바이스 감지
  RTC                       → 시간 유지

[Layer 1 — 경각성]          소비: ~25mA
  VL53L0X ToF              → 1m 이내 근접 확인
  조도 센서 (BH1750)        → 주변 밝기 확인
  환경 센서 (BME280)        → 온습도 기본값

[Layer 2 — 활성]            소비: ~150mA
  mmWave (LD2410C)          → 정지·호흡 감지
  WiFi MQTT                 → 데이터 송수신
  Ollama SLM               → 응답 생성

[Layer 3 — 풀 활성]         소비: ~400mA
  WiFi CSI                  → 공간 전체 감지
  카메라 (조건부)            → 표정·시선 분석
  공기질 센서 (BME680·SCD41) → 상세 환경 분석
```

### 6.2 Empathy Engine 신호 매핑

| 센서 입력 | Empathy 신호 | 임계값 |
|---------|-----------|------|
| PIR 감지 | Human Presence = 1 | 즉각 |
| VL53L0X 0.5m 이내 | ES 계산 시작 | 즉각 |
| LD2410C 정지 감지 | VI 안정 확인 | 30초 지속 |
| LD2410C 호흡 이상 | VI 하락 | 5회 연속 이상 |
| 기상 이벤트 감지 | ES 상승 | 에너지 급변 |
| CO₂ 1500ppm+ | VI 하락 | 5분 지속 |
| 소음 급증 | ES 변화 | 즉각 |
| WiFi CSI 공간 비움 | Human Presence = 0 | 60초 지속 |

## 7. 전력 관리

### 7.1 등급별 전력 소비

| 등급 | 대기 (Deep Sleep) | 일반 활성 | 풀 활성 | 권장 전원 |
|------|----------------|---------|--------|---------|
| **Lite (ESP32-S3)** | 0.1mA | 100mA | 300mA | 배터리 3000mAh+ or USB |
| **Standard (RPi 4)** | — | 600mA | 1200mA | 5V 3A 유선 전용 |
| **Pro (RPi 5)** | — | 800mA | 2000mA | 5V 5A 유선 전용 |

### 7.2 배터리 전략 (Lite 등급)

```
3000mAh 배터리 기준:

Deep Sleep 유지:         ~3년
Layer 1 경각성 유지:     ~5일
Layer 2 활성 유지:       ~20시간
Layer 3 풀 활성 유지:    ~10시간

혼합 사용 (현실적 시나리오):
  8시간 Deep Sleep
  14시간 Layer 1~2
  30분 CSI Active
  → 약 3~5일

권장: 5000mAh 이상 + Qi 무선 충전 도킹
```

### 7.3 배터리 VI 연동

```
VI 0.7 이상:   모든 센서 정상 운용
VI 0.4~0.7:    CSI 활성 시간 절반 제한
VI 0.1~0.4:    CSI 비활성 · 경보 발송
VI 0.1 이하:   Layer 0만 · 충전 알림 1회
```

## 9. 구형 스마트폰 닉시 가능성

> **개념:** 서랍에 잠든 구형 스마트폰을 닉시 하드웨어로 활용한다.

### 9.1 스마트폰이 이미 갖춘 것들

```
카메라 (전·후면)
마이크 (고품질)
스피커
배터리 + 충전 관리
WiFi + Bluetooth
GPS
가속도·자이로·지자기 센서
조도·근접 센서
디스플레이 (터치)
강력한 AP 칩 (AI 추론 가능)
```

### 9.2 활용 시나리오

```
시나리오 A — 웹앱 닉시:
  Chrome 브라우저에서 NEXA 플랫폼 접속
  Web Bluetooth · Web Serial 활용
  → 가장 간단 · 추가 개발 없음
  → 카메라·마이크·스피커 즉시 활용
  → 단: 백그라운드 실행 제한

시나리오 B — 전용 앱 닉시:
  Android 전용 앱 개발
  → 상시 백그라운드 실행
  → 카메라·센서 완전 제어
  → Ollama 경량 모델 온디바이스 실행
  → 단: Android 전용 · 앱 개발 필요

시나리오 C — ADB 브리지:
  PC와 ADB 연결 후 제어
  → 개발자 전용 · 프로토타이핑 용도
```

### 9.3 한계와 미해결 과제

```
한계:
  mmWave 센서 없음 → 외부 ESP32 노드 필요
  iOS는 백그라운드 실행 심각하게 제한
  장시간 충전 연결 → 배터리 열화 가속
  케이스 설계 없음 → 거치 방법 비표준

미해결 과제:
  ① 배터리 상시 충전 열화 최소화 방법
  ② iOS 상시 실행 우회 방법 (있는가?)
  ③ NEXA Android 앱 개발 범위 결정
  ④ 외부 mmWave 노드와의 통합 프로토콜
  ⑤ 스마트폰 CSI 활용 가능성
     (Wi-Fi CSI는 Android에서 일부 접근 가능 — 연구 필요)
```
