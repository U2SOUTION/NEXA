# KNOWLEDGE RULE 지식 자산 관리 표준 계약 및 규약

이 문서는 `_KNOWLEDGE *` 문서군의 상위 기준 문서다.

> 핵심 정의: `nexa_knowledge_*`는 NEXA 전 도메인이 공유하는 Knowledge OS 계층이며, `project_knowledge`는 그 위에서 생성/진화하는 프로젝트 단위 지식 계층이다.

**지식 스펙트럼(참고):** 엣지 관측·실행 로그·대화·Self 상태 등은 **다른 스키마**에도 “지식에 가까운” 자산으로 존재한다. `_KNOWLEDGE *` 문서군은 **공통/프로젝트 용어·규범·RAG 원천**에 집중한다. 플랫폼 전체 개괄 표는 `_KNOWLEDGE ARCH 지식 운영체제(K-OS) 운영 아키텍처.md` **§0**을 본다.

## 1) 문서 역할

- `_KNOWLEDGE REF 디렉토리 책임 및 기획 자원 경로.md`: 디렉토리·뷰 경로 SSOT·**§1-B** 마무리 수준·후속 고도화 위치
- `_KNOWLEDGE SPEC CRUD 테이블 및 필드 명세서.md`: 테이블/컬럼/승인큐/배포프로파일 기준
- `_KNOWLEDGE DDL 통합 스키마 및 물리 설계(SSOT).md`: 실행 가능한 DDL(SSOT) 기준
- `_KNOWLEDGE ARCH 지식 운영체제(K-OS) 운영 아키텍처.md`: Knowledge OS 운영 아키텍처 기준(§0 지식 스펙트럼·§1-D LLM 입문)
- `_KNOWLEDGE GUIDE 시스템 구축 순서 및 로드맵.md`: 단계별 구현 순서 기준
- `_NEXA GUIDE 플랫폼 구현 단계 및 로드맵.md`: 플랫폼 전체(Knowledge 외 오케스트레이션·UI·도메인 AI) 구현 순서
- `_KNOWLEDGE ARCH 언어적 라우팅 및 지능형 정규화.md`: 라우팅/중의성/역로컬라이제이션 기준

## 1-B) 계약 범위·후속 고도화

`_KNOWLEDGE*` 상위 계약은 **데이터·승인·배포·감사·DDL·경로**에 초점을 둔다. **오케스트레이션 실행 규범의 전부**와 **AI·도메인 추론 고도화**는 **오케스트레이션 SSOT·도메인/AI 층**에서 확장하며, 본 문서군은 그때까지 **식별자·게이트·소프트 삭제 등 계약을 깨지 않는 인터페이스**만 유지한다. 상세한 “어디까지 REF·SPEC에서 끊고 어디서 고도화하는지”는 `_KNOWLEDGE REF *` **§1-B**를 본다.

---

## 2) 공통 강제 규칙

- 물리 삭제 금지(Soft Delete)
- 불변 토큰 즉시 반영 금지(반드시 승인 큐)
- 원본 문서 저장소(`NEXA-Documentation/` 또는 운영 기준 경로) 변경은 crawler로 자동 동기화
- EN 내부 사유, KO 사용자 출력 원칙 유지
- Nano 대상은 전체 DB 배포 금지(차등 배포 필수)
- DDL 적용은 DBeaver SQL Editor에서 수동 순차 실행을 기본 원칙으로 한다.

## 3) 계층 책임

- `frame`: 렌더링/UI

- `system`: 스키마/자산/잡(crawler/packager)

## 5) Knowledge OS 명칭 사용 시 안전 축 (필수)

용어·파일 관리에서 출발한 체계가 **「지식 운영체제(OS)」**까지 확장될수록, 단일 실패·과자동화 위험이 커진다. **OS적 은유**(인터럽트·페이징·드라이버·NFS·쓰로틀 등)는 서사·온보딩·런타임 정책에 쓰되, 아래 **네 축**은 **DDL·실행 규약**으로 우선한다. 상세·5가지 보강 아이디어는 `_KNOWLEDGE ARCH 지식 운영체제(K-OS) 운영 아키텍처.md` **§1-B · §1-C**를 본다.

| 축 | 내용 |
| :-- | :-- |
| **생애주기** | 모든 지식(및 이를 반영하는 정책·규칙)은 **[ASK(검토) → GOVERN(운영) → ERA(헌법)]**를 거친다. GOVERN/ERA에 오르기 전 상태를 시스템이 단독으로 「확정」하지 않는다. |
| **정규화** | **HEXAGON(5W1H)** 프로토콜에 따라 관측·로그·지식의 저장 단위를 **6개 정수 토큰(SMALLINT)**으로 정규화한다. 은유는 이 뼈대 위의 해석 계층에 둔다. |
| **신뢰도 게이트** | `confidence_score`가 `user_defined_threshold` **미만**이면 **STUCK(고착)** 을 선언하고 **ASK(승인 대기) 펄스**를 발생시킨다. 즉시 바이패스·선점류 동작은 이 게이트와 충돌하지 않도록 정의한다(긴급 경로는 **감사 이벤트 + 사후 검토** 전제). |
| **실물 비침해** | 오케스트레이션 **UCL** 경로에서는 `execution_steps.is_virtual = true`와 `post_state_snapshot` 등으로 **드라이 런·시뮬레이션**을 실물 장비에 영향 없이 수행한다. Time-travel·분기 실험은 이 **가상 경계** 안에서 우선 검증한다. |

**은유와 구현의 분리:** 스키마에는 생애주기·HEXAGON·STUCK/ASK·가상 스텝처럼 **검증 가능한 제약**을 두고, OS 은유는 스케줄러·캐시·API 뷰·문서에 두어 **스키마 전체가 은유에 종속되지 않게** 한다.
