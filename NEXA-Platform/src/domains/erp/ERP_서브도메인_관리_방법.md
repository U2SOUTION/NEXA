# ERP 하위 기능 네임스페이스(라우팅/메뉴) 전략

- ERP-Scoped Navigation Grouping

##

- 폴더/도메인은 독립 유지(재사용 가능성 확보).
- 앞으로 프로젝트, 문서작성, 일정관리, 협업, 참고자료, 제무관리, 로그북.... 등은 독립적인 도메인을 유지하되 메뉴 네비개이션만 ERP에 통합한다.
- ERP 하위 도메인의 좌측 네비에는 별도 헤더를 넣지 말고 ERP 헤더와 중복되지 않도록 한다

- 도메인 분리 + 통합 네비: 부품관리처럼 독립 도메인 폴더(스토어/뷰/좌우 패널)를 그대로 유지하면서 ERP 좌측 아코디언으로 통합해 진입점만 그룹화. 기능별 개발·배포·테스트를 독립적으로 진행하면서도 사용자 동선은 ERP 안에서 일원화.

- 확장 용이성: 앞으로 ERP 하위 기능을 추가할 때, 새로운 도메인 폴더(erp-<sub>)를 만들고 라우트만 /erp/<sub>로 연결하면 좌우 패널/헤더를 ERP 공통으로 재사용하면서도 각 기능의 코드베이스는 격리 유지 가능.
- 유지보수 단순화: 메뉴·탭·현재 도메인 판별을 ERP 하나로 묶어 상단 탭을 슬림하게 유지. 사이드바 아코디언만 확장하면 기능을 추가할 수 있어 MainLayout 비대화를 막음.
- 충돌/리스크 감소: 부품관리 로직을 그대로 두고 네비게이션만 ERP 그룹으로 묶었으므로 기존 기능 영향 최소. 회귀 위험을 낮추면서 구조 개선 효과 확보.
- 일관된 UX: ERP 헤더/우측 패널을 공유하고, 좌측은 아코디언 패턴으로 통일하여 정보구조가 명료해짐. LOGISTICS를 최상단에 배치해 ERP 내 주요 기능을 강조.
- 향후 추가 기능 시
- 새 기능은 별도 도메인 폴더(스토어/좌우 패널/콘텐츠)로 개발 → 라우트 /erp/<sub> 추가 → 도메인 레지스트리에서 <erp-sub> 서브도메인 등록(ERP 좌/우 패널 공유하거나 필요 시 덮어쓰기) → - ERP 좌측 아코디언에 섹션/하위 메뉴 추가.
- 상단 탭은 ERP 하나만 유지, ERP 내부 메뉴로 세분화해도 상단 UI가 비대해지지 않음.
