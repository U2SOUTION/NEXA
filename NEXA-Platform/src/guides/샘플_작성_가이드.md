# 샘플 작성 가이드

## 📋 개요

개발 가이드의 샘플 파일을 작성할 때 따라야 할 원칙과 가이드라인입니다.

---

## 🎨 핵심 원칙

### 1. 배경색/테마 전환 테스트 가능성

**원칙**: 샘플 컴포넌트는 배경색을 최소화하거나 제거하여, 샘플 뷰 페이지에서 배경색 변경이나 테마 전환을 테스트할 수 있어야 합니다.

**이유**:

- 샘플 뷰 페이지에서 다양한 배경색으로 테스트할 수 있어야 함
- 다크/라이트 테마 전환 시 샘플의 가시성을 확인할 수 있어야 함
- 샘플 자체의 배경색이 테스트를 방해하지 않아야 함

**권장 사항**:

- ❌ 샘플 섹션에 고정된 배경색 사용 금지
- ✅ 테두리(`border`)와 패딩(`padding`)만으로 섹션 구분
- ✅ 필요시 투명하거나 최소한의 배경색만 사용
- ✅ 배경색이 필요하다면 `var(--nexa-surface)` 같은 테마 변수 사용 (고정 색상 금지)

**예시**:

```scss
// ❌ 나쁜 예: 고정 배경색
.sample-section {
  background-color: #f5f5f5; // 테마 전환 테스트 불가
}

// ✅ 좋은 예: 테두리만 사용
.sample-section {
  border: 1px solid var(--nexa-border-color);
  border-radius: 8px;
  padding: 24px;
  // 배경색 없음 또는 최소한의 투명 배경
}
```

---

### 2. 중첩 구조 최소화

**원칙**: 가능하면 중첩 구조를 지니지 않는 평면적인 구조를 유지해야 합니다.

**이유**:

- DOM 구조가 단순할수록 스타일링이 쉬움
- 불필요한 래퍼 요소는 레이아웃 문제를 야기할 수 있음
- CSS 선택자가 단순해져 유지보수가 쉬움
- 성능상 이점 (렌더링 최적화)

**권장 사항**:

- ❌ 불필요한 래퍼 `div` 요소 사용 금지
- ✅ 직접적인 부모-자식 관계 유지
- ✅ CSS로 해결 가능한 경우 래퍼 추가 금지
- ✅ 구조적으로 필수인 경우에만 중첩 허용

**예시**:

```vue
<!-- ❌ 나쁜 예: 불필요한 중첩 -->
<template>
  <div class="sample-container">
    <div class="wrapper">
      <div class="content">
        <q-btn>버튼</q-btn>
      </div>
    </div>
  </div>
</template>

<!-- ✅ 좋은 예: 평면적 구조 -->
<template>
  <div class="sample-container">
    <q-btn>버튼</q-btn>
  </div>
</template>
```

## 📐 구조 가이드

### 샘플 파일 기본 구조

```vue
<template>
  <!-- 샘플 컨테이너 (메인 타이틀/설명 제거 - 중첩 방지) -->
  <div class="sample-container">
    <!-- 섹션 1 -->
    <div class="sample-section">
      <div class="section-header">
        <h4 class="section-title">섹션 제목</h4>
        <p class="section-subtitle">섹션 설명</p>
      </div>
      <div class="section-content">
        <!-- 샘플 콘텐츠 -->
      </div>
    </div>

    <!-- 섹션 2 -->
    <div class="sample-section">
      <!-- ... -->
    </div>
  </div>
</template>
```

### 스타일 가이드

```scss
.sample-container {
  display: flex;
  flex-direction: column;
  gap: 24px;
}

.sample-section {
  // ❌ 고정 배경색 사용 금지
  // background-color: #f5f5f5;

  // ✅ 테두리와 패딩만으로 구분
  border: 1px solid var(--nexa-border-color);
  border-radius: 8px;
  padding: 24px;

  // 호버 효과 (선택사항)
  &:hover {
    box-shadow: 0 2px 8px rgba(0, 0, 0, 0.1);
  }
}
```

## ✅ 체크리스트

샘플 파일 작성 시 다음 사항을 확인하세요:

### 구조

- [ ] 불필요한 래퍼 요소가 없는가?
- [ ] 중첩 구조가 최소화되어 있는가?
- [ ] 메인 타이틀/설명이 제거되어 있는가? (섹션별 제목만 사용)

### 스타일

- [ ] 고정 배경색을 사용하지 않았는가?
- [ ] 테두리와 패딩만으로 섹션 구분이 가능한가?
- [ ] 테마 변수(`var(--nexa-*)`)를 사용하고 있는가?
- [ ] 다크/라이트 테마에서 모두 잘 보이는가?

### 기능

- [ ] 샘플 뷰 페이지에서 배경색 변경 테스트가 가능한가?
- [ ] 테마 전환 시 샘플이 정상적으로 보이는가?

## 🎯 예시: 좋은 샘플 vs 나쁜 샘플

### ✅ 좋은 샘플

```vue
<template>
  <div class="sample-container">
    <div class="sample-section">
      <div class="section-header">
        <h4 class="section-title">기본 버튼</h4>
      </div>
      <div class="section-content">
        <q-btn label="클릭" />
      </div>
    </div>
  </div>
</template>

<style lang="scss" scoped>
.sample-section {
  border: 1px solid var(--nexa-border-color);
  border-radius: 8px;
  padding: 24px;
}
</style>
```

### ❌ 나쁜 샘플

```vue
<template>
  <div class="sample-header">
    <h3>샘플 제목</h3>
    <p>설명</p>
  </div>
  <div class="sample-container">
    <div class="wrapper">
      <div class="content">
        <div class="sample-section" style="background-color: #f5f5f5;">
          <q-btn label="클릭" />
        </div>
      </div>
    </div>
  </div>
</template>
```

**문제점**:

1. 메인 타이틀/설명으로 인한 중첩
2. 불필요한 `wrapper`, `content` 래퍼
3. 고정 배경색 사용
4. 테마 전환 테스트 불가

## 🔄 재사용 가능한 컴포넌트 자동 감지

### 개요

시스템이 자동으로 샘플 컴포넌트의 재사용 가능성을 감지하여, 재사용 가능한 컴포넌트에만 "사용 예제" 섹션을 표시합니다.

### 자동 감지 기준

시스템은 다음 조건들을 확인하여 재사용 가능 여부를 판단합니다:

#### 1. 실제 프로젝트 컴포넌트 참조

샘플이 실제 프로젝트의 컴포넌트를 import하는 경우:

```javascript
// ✅ 재사용 가능으로 감지됨
import NexaChart from 'src/charts/NexaChart.vue'
import ConfirmModal from 'src/components/modals/ConfirmModal.vue'
```

**감지 경로**:

- `src/charts/`
- `src/components/`
- `src/modules/`
- `src/renderers/`
- `src/block/`
- `src/board/`
- `src/panel/`

#### 2. Props/Emits 정의

재사용을 위한 인터페이스가 정의된 경우:

```vue
<script setup>
// ✅ Props 정의 - 재사용 가능으로 감지됨
const props = defineProps({
  data: Array,
  options: Object,
})

// ✅ Emits 정의 - 재사용 가능으로 감지됨
const emit = defineEmits(['update', 'change'])
</script>
```

#### 3. 실제 로직 존재

단순 샘플 헤더가 아닌 실제 기능이 구현된 경우:

```vue
<script setup>
// ✅ 실제 로직 존재 - 재사용 가능으로 감지됨
import { ref, computed } from 'vue'

const data = ref([])
const processedData = computed(() => {
  // 실제 처리 로직
})
</script>
```

#### 4. 실제 프로젝트 경로 위치

`guides/` 폴더가 아닌 실제 프로젝트 경로에 있는 경우:

```
✅ src/charts/NexaChart.vue
✅ src/components/modals/ConfirmModal.vue
❌ guides/styles/charts/bar/NexaChartBar.vue (샘플 전용)
```

### 감지 로직

재사용 가능으로 판단되는 경우:

1. **실제 프로젝트 경로에 위치** 또는
2. **실제 프로젝트 컴포넌트를 import하고 샘플 전용이 아닌 경우** 또는
3. **Props/Emits를 정의하고 있고 샘플 전용이 아닌 경우**

### 사용 예제 섹션

재사용 가능한 컴포넌트로 감지되면 자동으로 "사용 예제" 섹션이 표시됩니다:

```vue
<!-- 자동 생성되는 사용 예제 -->
<template>
  <div>
    <h3>NexaChart 사용 예제</h3>
    <NexaChart :data="chartData" />
  </div>
</template>

<script setup>
import NexaChart from 'src/charts/NexaChart.vue'
</script>
```

### 예시

#### ✅ 재사용 가능한 컴포넌트

```vue
<!-- guides/styles/charts/bar/NexaChartBar.vue -->
<template>
  <div class="chart-container">
    <NexaChart type="bar" :data="chartData" />
  </div>
</template>

<script setup>
import NexaChart from 'src/charts/NexaChart.vue' // 실제 프로젝트 컴포넌트 참조

const chartData = ref([...])
</script>
```

**결과**: "사용 예제" 섹션 자동 표시 ✅

#### ❌ 샘플 전용 컴포넌트

```vue
<!-- guides/styles/buttons/ToggleButton.vue -->
<template>
  <div class="sample-container">
    <q-btn-toggle v-model="value" :options="options" />
  </div>
</template>

<script setup>
// 실제 프로젝트 컴포넌트 참조 없음
// Props/Emits 정의 없음
const value = ref('option1')
</script>
```

**결과**: "사용 예제" 섹션 표시 안 됨 ❌

### 주의사항

- **명시적 플래그 불필요**: `@reusable: true` 같은 플래그를 추가할 필요 없음
- **자동 감지**: 코드 분석을 통해 자동으로 판단
- **샘플 작성 시 고려**: 재사용 가능한 컴포넌트를 만들 때는 실제 프로젝트 컴포넌트를 참조하거나 Props/Emits를 정의
