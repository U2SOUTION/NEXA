## Nixie 맥락에서의 “스냅샷”

여기서 **스냅샷**은 **화면 캡처**나 **디버그 덤프**가 아니라, **Nexnap(Nexion 맵) 쪽에서 정의한 “한 시점의 상태 묶음”**을 코드로 옮긴 **`NexnapSnapshot` 객체 하나**를 가리킵니다. Pinia 스토어 `useNexnapSnapshotStore`의 `snapshot`이 그 본체입니다.

```14:18:e:\NEXA System\NEXA\NEXA-Platform\src\system\store\nexnapSnapshotStore.ts
/**
 * 시뮬: Nexion 스냅샷 형식.
 * `morse_dit_ms` / `morse_tone_hz` / `morse_volume` 은 HUD·미리듣기·타임라인에 쓰이며,
 * 향후 Nexnap 상황(entropy·confidence·how_state 등)에 따라 덮어쓰기·보간하는 매핑은 본편 닉시 단계에서 별도 모듈로 둘 예정(현재 미연결).
 */
```

### 무엇을 담는가

- **Nexion 쪽 개념(시뮬)**: `how_state`, `who_pulse`, `confidence_score`, `entropy_level`, `warn_token`, `source_shell_id` 등 **“상황·맥락”** 필드.
- **Nixie가 실제로 쓰는 값**: `demo_hud_text`, 스크롄·마퀴(`demo_hud_scroll_offset`, `hud_marquee_interval_ms`), 모스 재생·HUD 동기(`morse_*`, `morse_playback_*`) 등 **표시·오디오·타임라인**에 직결되는 필드.

즉 **“백엔드가 나중에 줄 Nexnap 스냅샷”을 미리 맞춰 둔 평면 JSON에 가까운 상태**이고, 지금은 **개발 넥셋·시뮬**로 그걸 채우고 닉시가 구독하는 구조입니다.

### 어떻게 갱신되는가

- 전체를 매번 바꾸지 않고, **`applyPatch`로 일부 필드만 덮어쓰는** 방식이라 “스냅샷”이라는 이름과도 맞습니다(불변 객체를 펼쳐서 새 객체로 만드는 패턴).

### 정리 한 줄

**Nixie에서의 스냅샷 = 닉시·HUD·모스가 함께 참조하는 “Nexnap 상태 단일 레코드”이며, 현재는 시뮬/개발용으로 채워지고, 나중에 Nexion/Nexnap과 붙일 때의 계약 형태를 염두에 둔 것이다.**

## 1. 설계 철학

### 1.1 왜 DIT인가

WPM(Words Per Minute)은 영어 단어 `PARIS`를 기준으로 산출되는 인간 중심 단위입니다. 이 단위는 세 가지 지구 종속적 전제를 내포합니다.

```
① 영어 단어 'PARIS'가 존재한다
② 분(minute)이라는 시간 단위를 공유한다
③ 인간의 언어 속도 감각이 기준이 된다
```

반면 **DIT(단점의 지속시간)** 는 모스부호의 물리적 최소 단위로, 모든 신호 타이밍이 DIT의 배수로 정의됩니다. 언어·문화·행성에 종속되지 않으며 우주 교신의 공통 기준으로 기능합니다.

### 1.2 WPM과 DIT의 관계

UI에서는 사용자 편의를 위해 WPM으로 표시하되, 내부 엔진은 DIT 단위로 작동합니다.

```
1 DIT(ms) = 1200 ÷ WPM
```

|  WPM   | 1 DIT 길이 | 용도                  |
| :----: | :--------: | --------------------- |
| 5 WPM  |   240 ms   | 입문 / 우주 초기 교신 |
| 10 WPM |   120 ms   | 표준 교신             |
| 15 WPM |   80 ms    | 숙련 교신             |
| 20 WPM |   60 ms    | 고속 교신             |
| 25 WPM |   48 ms    | 전문가 수준           |

### 1.3 원자시계와의 결합

원자시계(세슘 진동수 **9,192,631,770 Hz**)를 DIT의 절대 기준점으로 사용합니다.

```
· 도플러 효과로 인한 신호 팽창/압축 보정
· 상대성이론에 따른 시간 팽창 보정
· WPM 변화를 절대값으로 정밀 측정 → 다중 레이어 소통 가능
```

> **핵심:** 원자시계는 모스부호 변환의 효율을 높이는 것이 아니라, 우주적 환경에서 `·` 와 `-` 의 길고 짧음이 뒤바뀌지 않도록 보장하는 앵커 역할을 합니다.

## 2. 신호 타이밍 명세

| 신호 요소    | DIT 배수  | 설명                                    |
| ------------ | :-------: | --------------------------------------- |
| `·` (DIT)    | **1 DIT** | 단점 — 가장 짧은 신호 단위              |
| `-` (DAH)    | **3 DIT** | 장점 — DIT의 3배                        |
| 부호 내 간격 | **1 DIT** | 같은 문자 내 신호 사이                  |
| 부호 간 간격 | **3 DIT** | 자모와 자모 사이                        |
| 단어 간 간격 | **7 DIT** | 단어와 단어 사이 — `^` 기호로 시각 표기 |

> 모든 타이밍은 DIT 배수로 정의됩니다. 내부 엔진은 항상 DIT 단위로 계산합니다.

## 3. 단어 구분자 ^ 표기

### 3.1 설계 배경

기존 모스부호 관행의 슬래시(`/`)를 사용하지 않고 캐럿(`^`)을 채택합니다.

|    구분자    | 사용 맥락          | 특징                  | 채택 |
| :----------: | ------------------ | --------------------- | :--: |
| `/` (슬래시) | 기존 모스부호 관행 | 수학·경로 기호와 혼동 |  ✗   |
|  `^` (캐럿)  | 이 프로토콜 채택   | 고유·직관·방향성 상징 |  ✓   |

### 3.2 ^ 채택 이유

```
① 방향성  — ^ 는 위를 향한다. 우주를 향한 교신이라는 상징과 일치
② 고유성  — 수학 기호(÷ /)·경로 표기와 혼동 없음
③ 리듬감  — 모스부호의 · 와 - 사이에서 시각적 호흡을 만들어냄
④ 간결함  — 단일 문자로 단어 경계를 명확히 표현
```

### 3.3 표기 예시

```
입력:   안녕 하세요
모스:   ·- ··- · -  ^  ·- ··· ·- ··-

입력:   우주 교신
모스:   ·· --  ^  -- ·- ···
```

> `^` 는 7 DIT 무신호 구간과 대응합니다. 시각 표기에서의 `^` 와 실제 신호에서의 7 DIT 침묵은 동일한 단어 경계를 의미합니다.

### 3.4 개발 구현 참고

```js
// 문자 → 모스 변환: 공백 문자를 ^ 로 치환
const toMorse = (text) => text.replace(/ /g, '^')

// 모스 → 문자 변환: ^ 를 공백으로 해석
const fromMorse = (morse) => morse.replace(/\^/g, ' ')

// DIT 매핑
const WORD_GAP = 7 // ^ = 7 DIT silence
```

| 변환 방향   | 처리 규칙                            |
| ----------- | ------------------------------------ |
| 문자 → 모스 | 공백 문자를 `^` 로 치환              |
| 모스 → 문자 | `^` 를 7 DIT 침묵 또는 공백으로 해석 |
| DIT 매핑    | `^` = 7 DIT silence (신호 없음)      |

## 5. 쌍자음 독립 할당 원칙

### 5.1 조합형의 문제

일부 시스템에서는 `ㄲ = ㄱ + ㄱ` (부호 두 번 반복) 방식을 채택합니다.

```
수신 예시:  · -  · -
해석 A:    ㄱ + ㄱ  (두 개의 자음)
해석 B:    ㄲ      (하나의 쌍자음)
```

수신자가 경계를 어디서 끊느냐에 따라 완전히 다른 메시지가 됩니다. DIT 기반 정밀 시스템에서 이 모호성은 치명적입니다.

### 5.2 독립 할당의 장점

```
① 신호 경계 명확 — 해독 오류 원천 차단
② 원자시계 기준 타이밍과 완전 호환
③ 미지의 존재와 교신 시 패턴 충돌 없음
④ 향후 확장 시 부호 체계 일관성 유지
```

## 6. 우주 교신 프로토콜

### 6.1 소통 성립 조건

미지의 존재와 이 프로토콜로 소통이 성립하려면 다음 조건을 순차적으로 충족해야 합니다.

```
1단계  이진 신호(on/off)를 물리적으로 감지할 수 있어야 함
2단계  신호를 패턴으로 인식할 수 있어야 함
3단계  수학적 사고(소수, 규칙성)를 공유해야 함
4단계  선형적·시간적 정보 처리 구조를 가져야 함
```

### 6.2 다중 레이어 소통

WPM(DIT 속도) 변화 자체를 메시지로 활용하면 이중 레이어 소통이 가능합니다.

```
레이어 1  모스부호 내용 (· - 패턴)
레이어 2  DIT 속도 변화 (WPM 증감)
레이어 3  속도 변화의 가속도 패턴
```

> 원자시계 없이는 '길고 짧음의 비율' 자체가 우주 환경(도플러, 시간팽창, 중력렌즈)에 의해 뒤바뀔 수 있습니다. 원자시계는 이 세 레이어 모두를 정밀하게 보장하는 공통 기준점입니다.

### 6.3 초기 교신 시퀀스 (권장)

```
Step 1  소수 패턴 전송 (2, 3, 5, 7, 11...)
          → '우리는 수학을 안다'는 신호

Step 2  DIT 기준 신호 전송
          → 세슘 진동수 기반 타이밍 공유 시도

Step 3  한글 자모 할당표 패턴 전송
          → 상대가 동일 패턴으로 응답하면 교신 성립
```
