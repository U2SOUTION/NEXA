# 에러 의존성 다이어그램 문제 분석

> **분석 일자**: 2024년 12월
> **문제**: 다이어그램에 노드가 하나만 표시되고 중앙에 고정되어 있음

---

## 문제 현상

에러 의존성 다이어그램에서 다음과 같은 현상이 발생:

1. **노드가 하나만 표시됨**: 파란색 원형 노드 하나만 중앙에 표시
2. **"unknown" 레이블**: 노드 아래에 "unknown" 텍스트 표시
3. **숫자 "13" 표시**: 노드 내부에 숫자 "13" 표시 (에러 개수)
4. **연결선 없음**: 노드 간 연결선(edge)이 전혀 없음
5. **고정 위치**: 노드가 중앙에 고정되어 움직이지 않음

---

## 원인 분석

### 1. 노드가 하나만 생성되는 이유

**코드 위치**: `ErrorTrackingContent.vue` 468-492줄

```javascript
// 파일별로 에러 그룹화
const fileErrors = {};
errors.value.forEach((error) => {
    const file = error.file || "unknown"; // ⚠️ 문제 지점
    if (!fileErrors[file]) {
        fileErrors[file] = [];
    }
    fileErrors[file].push(error);
});

// 노드 생성 (파일별, 최대 20개)
const fileEntries = Object.entries(fileErrors).slice(0, 20);
const nodes = fileEntries.map(([file, fileErrorList], index) => ({
    id: `file-${index}`,
    label: file.split("/").pop() || file, // ⚠️ 'unknown'이 그대로 표시됨
    type: "file",
    count: fileErrorList.length,
    file: file,
}));
```

**원인**:

-   모든 에러의 `error.file` 값이 `undefined` 또는 `null`
-   모든 에러가 동일한 파일에서 발생 (모두 'unknown'으로 처리)
-   결과적으로 `fileErrors` 객체에 'unknown' 키 하나만 존재
-   노드가 하나만 생성됨

**확인 방법**:

```javascript
// 디버깅 코드 추가
console.log(
    "에러 파일 정보:",
    errors.value.map((e) => ({
        message: e.message,
        file: e.file,
    }))
);
console.log("파일별 그룹화:", fileErrors);
console.log("생성된 노드:", nodes);
```

### 2. 에지(연결선)가 없는 이유

**코드 위치**: `ErrorTrackingContent.vue` 494-523줄

```javascript
// 에지 생성 (파일 간 연관성 - 같은 에러 메시지를 가진 파일들)
const edges = []
const messageToFiles = {}
errors.value.forEach((error) => {
  const message = error.message || 'unknown'
  const file = error.file || 'unknown'
  if (!messageToFiles[message]) {
    messageToFiles[message] = new Set()
  }
  messageToFiles[message].add(file)
})

Object.values(messageToFiles).forEach((fileSet) => {
  const fileArray = Array.from(fileSet)
  if (fileArray.length > 1) {  // ⚠️ 파일이 2개 이상이어야 에지 생성
    // 같은 메시지를 가진 파일들을 연결
    for (let i = 0; i < fileArray.length - 1; i++) {
      const sourceNode = nodes.find((n) => n.file === fileArray[i])
      const targetNode = nodes.find((n) => n.file === fileArray[i + 1])
      if (sourceNode && targetNode) {
        edges.push({ ... })
      }
    }
  }
})
```

**원인**:

-   노드가 하나만 있으면 `fileArray.length > 1` 조건이 항상 `false`
-   에지 생성 로직이 실행되지 않음
-   결과적으로 `edges` 배열이 비어있음

### 3. 노드가 중앙에 고정되는 이유

**코드 위치**: `ErrorTrackingContent.vue` 549-560줄

```javascript
// 시뮬레이션 생성
diagramSimulation = d3
    .forceSimulation(diagramData.value.nodes)
    .force(
        "link",
        d3
            .forceLink(diagramData.value.edges)
            .id((d) => d.id)
            .distance(100)
    )
    .force("charge", d3.forceManyBody().strength(-300))
    .force("center", d3.forceCenter(width / 2, height / 2)); // ⚠️ 중앙으로 강제 배치
```

**원인**:

-   **노드가 하나만 있을 때**:
    -   `forceLink`: 에지가 없어서 작동하지 않음
    -   `forceManyBody`: 노드 간 상호작용이 없어서 효과 없음
    -   `forceCenter`: 중앙으로 강제 배치만 작동
-   결과적으로 노드가 중앙에 고정됨

**D3 Force Simulation 동작 원리**:

-   `forceLink`: 에지의 길이를 유지하려고 노드 위치 조정
-   `forceManyBody`: 노드 간 반발력으로 분산
-   `forceCenter`: 중앙으로 끌어당김
-   노드가 하나면 `forceCenter`만 작동하여 중앙 고정

### 4. "unknown" 레이블이 표시되는 이유

**코드 위치**: `ErrorTrackingContent.vue` 488줄

```javascript
label: file.split('/').pop() || file,  // 'unknown'이 그대로 표시됨
```

**원인**:

-   `file` 값이 'unknown'이면
-   `'unknown'.split('/').pop()` = `'unknown'`
-   결과적으로 레이블이 'unknown'으로 표시됨

## 근본 원인 요약

### 데이터 문제

1. **에러 데이터에 파일 정보 부재**:

    - `error.file` 값이 대부분 `undefined` 또는 `null`
    - 에러 수집 시 파일 정보가 제대로 저장되지 않음

2. **데이터 구조 문제**:
    - 모든 에러가 동일한 파일('unknown')로 그룹화됨
    - 노드가 하나만 생성되어 다이어그램의 의미가 없음

### 로직 문제

1. **노드가 하나일 때 처리 부재**:

    - 노드가 하나일 때의 특별한 처리 로직 없음
    - 에지 생성 조건이 노드 2개 이상을 전제로 함

2. **에지 생성 기준의 한계**:

    - 같은 에러 메시지를 가진 파일들만 연결
    - 노드가 하나면 에지 생성 불가능

3. **Force Simulation 설정 문제**:
    - 노드가 하나일 때 의미 있는 배치 불가능
    - 중앙 고정만 작동

---

## 해결 방안

### 즉시 해결 (임시)

1. **노드가 하나일 때 메시지 표시**:

    ```javascript
    if (nodes.length === 1) {
        // 다이어그램 대신 안내 메시지 표시
        return { nodes: [], edges: [] };
    }
    ```

2. **에러 데이터 확인 및 디버깅**:
    ```javascript
    // 에러 데이터 구조 확인
    console.log("에러 샘플:", errors.value.slice(0, 3));
    console.log("파일 정보:", errors.value.map((e) => e.file).filter(Boolean));
    ```

### 근본 해결 (장기)

1. **에러 수집 시 파일 정보 저장**:

    - 에러 수집기에서 `error.file` 정보를 제대로 추출
    - 스택 트레이스에서 파일 경로 파싱
    - 파일 정보가 없을 때의 대체 정보 제공

2. **다이어그램 데이터 구조 개선**:

    - 파일 정보가 없을 때 다른 기준으로 그룹화 (에러 타입, 메시지 등)
    - 노드 생성 기준 다양화

3. **에지 생성 로직 개선**:

    - 파일 간 연결 외에 다른 연결 기준 추가
    - 에러 타입, 발생 시간, 스택 트레이스 등으로 연관성 파악

4. **Force Simulation 개선**:
    - 노드가 적을 때의 배치 전략
    - 노드가 하나일 때의 특별 처리
