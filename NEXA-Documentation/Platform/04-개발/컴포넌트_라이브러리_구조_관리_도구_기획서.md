## 📋 문서 개요

컴포넌트 라이브러리 구조 관리 도구는 NEXA 플랫폼의 컴포넌트 구조를 **관리하고 규칙을 단속**하는 도구입니다. 이 도구는 단순히 정보를 보여주는 것이 아니라, **구조 규칙 위반을 감지하고, 구조를 개선하며, 안전하게 디렉토리를 이동**할 수 있도록 지원합니다.

### 핵심 목표

1. **구조 규칙 단속**: 컴포넌트가 난잡하게 아무 디렉토리에 규칙 없이 즉흥적으로 만들어지는 것을 방지
2. **구조 통합/분리 관리**: 통합할 것 통합, 분리할 것 분리하여 전체 구조 틀을 단단하게 유지
3. **디렉토리 이동 관리**: 컴포넌트 이동 시 영향도 분석 및 안전한 이동 지원
4. **지속적인 구조 모니터링**: 프로젝트가 커져도 구조가 무너지지 않도록 지속적으로 관리

### 사용 목적

-   **규칙 위반 방지**: Vue 초보자도 규칙에 맞는 구조를 유지할 수 있도록 지원
-   **구조 개선**: 비슷한 컴포넌트 통합, 분리 필요 컴포넌트 분리 제안
-   **안전한 리팩토링**: 디렉토리 이동 시 영향도 분석 및 자동 경로 변경
-   **장기 유지보수**: 프로젝트가 커져도 구조가 무너지지 않도록 지속 관리

## 🎯 프로그램 목적 (재정의)

### 1차 목표: 구조 규칙 단속 및 관리

**핵심 문제:**

-   Vue 초보자로서 디렉토리 구조 관리가 어려움
-   컴포넌트가 난잡하게 아무 디렉토리에 규칙 없이 즉흥적으로 만들어지는 것 방지
-   각 모듈 간 재사용이나 통신 관계가 중요한데 구조가 무너지면 감당 불가
-   현재도 약간 달라진 디렉토리 구조를 단속해야 할 부분이 느껴지는데 엄두를 못 내고 있음

**해결 방안:**

1. **규칙 위반 감지**: 컴포넌트가 잘못된 위치에 있는지 자동 감지
2. **구조 통합/분리 제안**: 통합할 것 통합, 분리할 것 분리 제안
3. **디렉토리 이동 관리**: 컴포넌트 이동 시 영향도 분석 및 안전한 이동 지원
4. **전체 구조 틀 강화**: 지속적인 모니터링으로 구조 틀을 단단하게 유지

### 2차 목표: 구조 파악 및 리팩토링 지원

-   전체 구조 파악: 프로젝트의 컴포넌트 구조를 한눈에 파악
-   의존성 분석: 컴포넌트 간 의존성 관계를 파악하여 리팩토링 시 영향도 분석
-   코드 탐색: 특정 컴포넌트를 빠르게 찾고 관련 파일을 탐색

## 🏗️ 프로그램 구성

### 전체 레이아웃

컴포넌트 라이브러리 구조 관리 도구는 **3단계 계층 구조**로 구성됩니다.

```
┌─────────────────────────────────────────────────────────┐
│                    툴바 (상단)                          │
├──────────────┬──────────────────────┬───────────────────┤
│              │                      │                   │
│  왼쪽 사이드바 │   중간 컨텐츠 영역    │  오른쪽 사이드바   │
│  (뼈대/구조)  │   (상세 정보)         │  (관리/액션)      │
│              │                      │                   │
│  - 카테고리   │  - 컴포넌트 상세 정보  │  - 규칙 위반 경고 │
│  - 컴포넌트   │  - 규칙 위반 상세     │  - 이동 관리      │
│    목록       │  - 구조 개선 제안     │  - 통합/분리 제안 │
│  - 규칙 위반  │  - 디렉토리 구조     │  - Props/Emits    │
│    목록 ⚠️    │  - 파일 구조 상세    │  - 빠른 액션       │
│  - 파일 구조  │  - 의존성 관계       │  - 관련 문서       │
│    (하위메뉴) │  - 사용 위치         │                   │
│              │  - 파일 관계         │                   │
│              │                      │                   │
└──────────────┴──────────────────────┴───────────────────┘
```

### 3단계 계층 구조

1. **왼쪽 사이드바**: 뼈대, 구조 선택
    - 왼쪽에서 항목 선택 → 중간에 상세 정보 표시
    - **규칙 위반 목록** (⚠️) 추가: 위반 항목 즉시 확인 가능
2. **중간 컨텐츠 영역**: 선택한 항목의 상세 정보
    - 중간에서 아이템 선택 → 오른쪽에 관리 기능 표시
    - **구조 개선 제안** 섹션 추가
3. **오른쪽 사이드바**: 관리 기능 및 액션
    - 규칙 위반 경고 및 수정 제안
    - 이동 관리, 통합/분리 제안 등 구조 관리 기능

## 🔍 핵심 기능 (구조 관리 중심)

### 1. 규칙 위반 감지 및 경고 ⚠️ (최우선)

**목적**: 컴포넌트 조직화 가이드라인(`[STRUCTURE] 컴포넌트ㅡ 조직화 가이드.md`) 기준으로 자동 검사

**기능:**

-   **자동 검사**: 프로젝트 전체 컴포넌트를 스캔하여 규칙 위반 감지
-   **실시간 모니터링**: 새 컴포넌트 생성 시 즉시 규칙 검사
-   **위반 목록 표시**: 왼쪽 사이드바에 "⚠️ 규칙 위반" 섹션으로 표시
-   **상세 정보**: 위반 항목 클릭 시 중간 영역에 문제점 및 해결 방법 표시

**검사 항목:**

1. **디렉토리 위치 검사**

    - `src/components/`에 있어야 할 컴포넌트가 독립 디렉토리에 있는지
    - 독립 디렉토리에 있어야 할 컴포넌트가 `src/components/`에 있는지
    - 판단 플로우차트 기준으로 자동 판단

2. **네이밍 규칙 검사**

    - 베이스 컴포넌트에 `Nexa` 접두어가 있는지
    - 하위 디렉토리 컴포넌트에 `Nexa` 접두어가 없는지
    - 디렉토리명과 파일명의 일관성

3. **카테고리 분류 검사**
    - 컴포넌트가 올바른 카테고리에 분류되어 있는지
    - 비슷한 기능의 컴포넌트가 올바른 위치에 있는지

**표시 방법:**

-   왼쪽 사이드바: "⚠️ 규칙 위반 (3)" 같은 배지 표시
-   위반 항목 클릭 시 중간 영역:
    -   문제점 설명
    -   올바른 위치 제안
    -   이동 계획 및 영향도 분석
    -   "올바른 위치로 이동" 버튼

**활용 위치:**

-   왼쪽 사이드바: 규칙 위반 목록 (항상 상단에 표시)
-   중간 컨텐츠 영역: 위반 항목 상세 정보
-   오른쪽 사이드바: 이동 관리 기능

### 2. 구조 통합/분리 제안

**목적**: 비슷한 컴포넌트 통합, 분리 필요 컴포넌트 분리 제안

**통합 제안:**

-   **비슷한 기능 감지**: 비슷한 기능의 컴포넌트가 여러 곳에 분산되어 있는지 감지
-   **통합 가능 목록**: 통합 가능한 컴포넌트 목록 제시
-   **영향도 분석**: 통합 시 영향받는 파일 목록 표시
-   **통합 계획**: 통합 후 구조 및 import 경로 변경 계획

**분리 제안:**

-   **과도한 집중 감지**: 하나의 디렉토리에 너무 많은 컴포넌트가 있는지 감지
-   **카테고리별 분리**: 카테고리별로 분리 제안
-   **독립 디렉토리 이동**: 독립 디렉토리로 이동이 필요한 컴포넌트 제안

**활용 위치:**

-   중간 컨텐츠 영역: "구조 개선 제안" 섹션
-   오른쪽 사이드바: 통합/분리 실행 기능

### 3. 디렉토리 이동 관리

**목적**: 컴포넌트 이동 시 안전하게 이동하고 영향도를 최소화

**기능:**

1. **이동 전 검증**

    - 이동하려는 컴포넌트의 의존성 관계 확인
    - 이동 시 영향받는 파일 목록 표시
    - import 경로 변경 필요 여부 확인
    - 순환 참조 위험 확인

2. **안전한 이동 지원**

    - 이동 계획 수립 (어떤 파일을 어디로 이동할지)
    - import 경로 자동 변경 제안
    - 관련 파일 (`.vue`, `.js`, `.scss`) 함께 이동 제안
    - 이동 전 백업/스냅샷 생성

3. **이동 후 검증**
    - 모든 import 경로가 올바르게 변경되었는지 확인
    - 빌드 오류 확인
    - 테스트 실행 제안

**활용 위치:**

-   컴포넌트 선택 시 오른쪽 사이드바: "이동 관리" 섹션
-   파일 구조 메뉴: 드래그 앤 드롭으로 이동 제안
-   규칙 위반 항목: "올바른 위치로 이동" 버튼

### 4. 컴포넌트 조직화 가이드라인 연동

**목적**: `[STRUCTURE] 컴포넌트ㅡ 조직화 가이드.md`의 규칙을 자동으로 검사

**연동 기능:**

1. **판단 플로우차트 자동화**

    - 새 컴포넌트 생성 시 플로우차트에 따라 올바른 위치 제안
    - 컴포넌트 라이브러리에서 직접 위치 확인 가능
    - 질문 기반 위치 결정 지원

2. **규칙 기반 검증**

    - 컨텍스트 의존적 vs 독립적 시스템 자동 판단
    - 디렉토리 위치 자동 검증
    - 네이밍 규칙 자동 검증

3. **가이드라인 표시**
    - 컴포넌트 선택 시 관련 가이드라인 자동 표시
    - 규칙 위반 시 가이드라인 링크 제공
    - 판단 기준 설명 표시

## 💡 실제 사용 시나리오

### 시나리오 1: 규칙 위반 컴포넌트 발견 및 수정 (가장 중요!)

**상황**: 개발 중 컴포넌트를 만들었는데 규칙에 맞는지 확인하고 싶음

**절차:**

1. 컴포넌트 라이브러리 열기

    - 디렉토리 위치 자동 검증
    - 네이밍 규칙 자동 검증

3. **가이드라인 표시**
    - 컴포넌트 선택 시 관련 가이드라인 자동 표시
    - 규칙 위반 시 가이드라인 링크 제공
    - 판단 기준 설명 표시

### 검사 규칙

**디렉토리 위치 규칙:**

-   `src/components/`: 컨텍스트 의존적 컴포넌트
-   독립 디렉토리 (`src/block/`, `src/charts/`, `src/panel/` 등): 독립적 시스템

**네이밍 규칙:**

-   베이스 컴포넌트: `Nexa` 접두어 사용 (예: `NexaPanel.vue`)

**판단 플로우차트:**

4. 수십~수백 개로 확장 예정이고 종류별 분류가 필요한가? → 독립 디렉토리
5. 특정 페이지/모듈/기능에 종속되어 있는가? → `src/components/`
6. 범용 UI 컴포넌트인가? → `src/components/ui/`

```javascript
// src/utils/componentScanner.js

import { structureRules } from "@/config/componentStructureRules";

/**
 * 프로젝트 전체 Vue 컴포넌트 스캔
 * Vite의 import.meta.glob을 활용하여 모든 .vue 파일 수집
 */
export async function scanAllComponents() {
    // Vite의 import.meta.glob 사용
    const allVueFiles = import.meta.glob(["/src/**/*.vue", "!**/node_modules/**", "!**/dist/**"], { eager: false });

    const components = [];

    for (const path in allVueFiles) {
        const component = {
            path: path,
            name: extractComponentName(path),
            directory: extractDirectory(path),
            isBaseComponent: isBaseComponent(path),
            depth: calculateDepth(path),
            metadata: await extractMetadata(path),
        };

        components.push(component);
    }

    return components;
}

function extractComponentName(path) {
    return path.split("/").pop().replace(".vue", "");
}

function extractDirectory(path) {
    // 'src/block/time/TimeBlock.vue' → 'src/block/'
    const parts = path.split("/");
    return parts.slice(0, -1).join("/") + "/";
}

function isBaseComponent(path) {
    const fileName = extractComponentName(path);
    return fileName.startsWith("Nexa");
}

function calculateDepth(path) {
    // src/block/time/TimeBlock.vue → depth: 3
    return path.split("/").length - 1;
}

async function extractMetadata(path) {
    // 파일 내용을 읽어서 추가 메타데이터 추출
    // (import 문, props, emits 등)
    // 실제 구현 시 파일 시스템 API 사용
    return {};
```

#### 2-2. 규칙 위반 검사 엔진

```javascript
// src/utils/ruleValidator.js

import { structureRules } from "@/config/componentStructureRules";

/**
 * 컴포넌트가 올바른 위치에 있는지 검사
 * @param {Object} component - 검사할 컴포넌트 정보
 * @returns {Array} 위반 사항 목록
 */
export function validateComponentLocation(component) {
    const violations = [];

    // 1. 독립 디렉토리 컴포넌트 검사
    const independentDir = structureRules.independentDirectories.find((dir) => component.path.startsWith(dir.path));

    if (independentDir) {
        // 베이스 컴포넌트 검사 (직접 자식)
        if (isDirectChild(component.path, independentDir.path)) {
            if (structureRules.validationOptions.checkNaming) {
                if (!component.name.startsWith("Nexa")) {
                    violations.push({
                        type: "NAMING_VIOLATION",
                        severity: "ERROR",
                        message: `베이스 컴포넌트는 'Nexa' 접두어가 필요합니다.`,
                        currentName: component.name,
                        suggestedName: `Nexa${component.name}`,
                        rule: "namingRules.baseComponentPrefix",
                        fixable: true,
                    });
                }
            }
        }
        // 하위 컴포넌트 검사
        else {
            if (structureRules.validationOptions.checkNaming) {
                if (component.name.startsWith("Nexa")) {
                    violations.push({
                        type: "NAMING_VIOLATION",
                        severity: "WARNING",
                        message: `하위 디렉토리 컴포넌트는 'Nexa' 접두어를 제거해야 합니다.`,
                        currentName: component.name,
                        suggestedName: component.name.replace("Nexa", ""),
                        rule: "namingRules.subComponentPrefix",
                        fixable: true,
                    });
                }
            }
        }
    }

    // 2. 컨텍스트 의존성 검사
    if (structureRules.validationOptions.checkLocation) {
        const isInComponents = component.path.startsWith("src/components/");
        const shouldBeIndependent = analyzeIndependence(component);

        if (isInComponents && shouldBeIndependent) {
            violations.push({
                type: "LOCATION_VIOLATION",
                severity: "ERROR",
                message: `이 컴포넌트는 독립 디렉토리에 있어야 합니다.`,
                currentLocation: component.path,
                suggestedLocation: shouldBeIndependent.targetDirectory,
                reason: shouldBeIndependent.reason,
                confidence: shouldBeIndependent.confidence,
                rule: "decisionFlow",
                fixable: true,
            });
        }

        // 반대 경우도 검사 (독립 디렉토리에 있지만 컨텍스트 의존적)
        const isInIndependent = structureRules.independentDirectories.some((dir) => component.path.startsWith(dir.path));
        const shouldBeContextDependent = analyzeContextDependency(component);

        if (isInIndependent && shouldBeContextDependent) {
            violations.push({
                type: "LOCATION_VIOLATION",
                severity: "ERROR",
                message: `이 컴포넌트는 src/components/에 있어야 합니다.`,
                currentLocation: component.path,
                suggestedLocation: structureRules.contextDependentDirectory,
                reason: shouldBeContextDependent.reason,
                rule: "decisionFlow",
                fixable: true,
            });
        }
    }

    return violations;
}

/**
 * 컴포넌트의 독립성 분석 (키워드 및 import 분석)
 */
function analyzeIndependence(component) {
    const content = component.metadata?.content || "";
    const componentName = component.name.toLowerCase();
    const path = component.path.toLowerCase();

    // 판단 플로우차트 기반 분석
    for (const rule of structureRules.decisionFlow) {
        // 키워드 매칭
        const hasKeywords = rule.keywords.some((keyword) => componentName.includes(keyword) || path.includes(keyword) || content.includes(keyword));

        if (hasKeywords && rule.targetDirectory.startsWith("src/") && !rule.targetDirectory.startsWith("src/components/")) {
            return {
                targetDirectory: rule.targetDirectory,
                reason: rule.question,
                confidence: calculateConfidence(component, rule),
            };
        }
    }

    return null;
}

/**
 * 컴포넌트의 컨텍스트 의존성 분석
 */
function analyzeContextDependency(component) {
    const imports = component.metadata?.imports || [];

    // Pinia store 사용 → 컨텍스트 의존적
    const hasPiniaStore = imports.some((imp) => imp.includes("stores/") || imp.includes("pinia"));

    // Vue Router 사용 → 컨텍스트 의존적
    const hasRouter = imports.some((imp) => imp.includes("vue-router") || imp.includes("router"));

    // 특정 페이지/모듈 import → 컨텍스트 의존적
    const hasPageSpecificImport = imports.some((imp) => imp.includes("pages/") || imp.includes("modules/"));

    if (hasPiniaStore || hasRouter || hasPageSpecificImport) {
        return {
            reason: "Pinia store, Router, 또는 페이지/모듈 의존성 발견",
            confidence: 0.8,
        };
    }

    return null;
}

function isDirectChild(componentPath, directoryPath) {
    const relativePath = componentPath.replace(directoryPath, "");
    return !relativePath.includes("/");
}

function calculateConfidence(component, rule) {
    // 키워드 매칭 개수에 따라 신뢰도 계산
    let matches = 0;
    const total = rule.keywords.length;

    const componentName = component.name.toLowerCase();
    const path = component.path.toLowerCase();

    rule.keywords.forEach((keyword) => {
        if (componentName.includes(keyword) || path.includes(keyword)) {
            matches++;
        }
    });

    return matches / total;
}
```

#### 2-3. 실시간 검사 및 알림 (Composable)

```javascript
// src/composables/useRuleValidation.js

import { ref, computed, onMounted } from "vue";
import { scanAllComponents } from "@/utils/componentScanner";
import { validateComponentLocation } from "@/utils/ruleValidator";

export function useRuleValidation() {
    const components = ref([]);
    const violations = ref([]);
    const isScanning = ref(false);
    const lastScanTime = ref(null);

    // 전체 스캔 및 검증
    async function scanAndValidate() {
        isScanning.value = true;

        try {
            // 1. 모든 컴포넌트 스캔
            components.value = await scanAllComponents();

            // 2. 각 컴포넌트 검사
            const allViolations = [];
            for (const component of components.value) {
                const componentViolations = validateComponentLocation(component);
                if (componentViolations.length > 0) {
                    allViolations.push({
                        component,
                        violations: componentViolations,
                    });
                }
            }

            violations.value = allViolations;
            lastScanTime.value = new Date();
        } catch (error) {
            console.error("[RuleValidation] 스캔 실패:", error);
        } finally {
            isScanning.value = false;
        }
    }

    // 규칙 위반 통계
    const violationStats = computed(() => ({
        total: violations.value.length,
        errors: violations.value.filter((v) => v.violations.some((vio) => vio.severity === "ERROR")).length,
        warnings: violations.value.filter((v) => v.violations.some((vio) => vio.severity === "WARNING")).length,
        fixable: violations.value.filter((v) => v.violations.some((vio) => vio.fixable)).length,
    }));

    // 규칙 위반 타입별 그룹화
    const violationsByType = computed(() => {
        const grouped = {
            NAMING_VIOLATION: [],
            LOCATION_VIOLATION: [],
        };

        violations.value.forEach((item) => {
            item.violations.forEach((vio) => {
                if (!grouped[vio.type]) {
                    grouped[vio.type] = [];
                }
                grouped[vio.type].push({ ...item, violation: vio });
            });
        });

        return grouped;
    });

    return {
        components,
        violations,
        violationStats,
        violationsByType,
        isScanning,
        lastScanTime,
        scanAndValidate,
    };
}
```

## 🎯 규칙 관리의 핵심 가치

1. **중앙화된 규칙 정의**: 한 곳에서 모든 규칙 관리
2. **즉시 반영**: 규칙 변경 시 전체 프로젝트 자동 재검사

이 방식으로 **규칙을 명확히 정의하고, 변경 시 즉시 반영하여 모든 문제점을 빠르게 찾을 수 있습니다**.

## 📊 컴포넌트 분류 체계 (Component Taxonomy)

컴포넌트를 **6가지 차원**으로 분류하여 모호함을 제거하고 명확한 기준을 제공합니다.

### 분류 차원 개요

```
컴포넌트 분류
├── 1. 기능별 (Functional Role) - 컴포넌트가 수행하는 기능
├── 2. 위치별 (Layout Position) - 화면에서의 위치
├── 3. 용도별 (Purpose) - 사용 목적 및 범위
├── 4. 관계별 (Dependency) - 의존성 관계
├── 5. 범위별 (Scope) - 재사용 범위
└── 6. 계층별 (Hierarchy) - 구조적 계층
```
