# D3.js 레이아웃 및 차트 시스템 종합 분석

## 📋 개요

NEXA Platform에서 사용하는 D3.js 기반 레이아웃 및 차트 시스템의 종합 분석 문서입니다. 다양한 레이아웃 방식의 특징, 구현 방법, 사용 사례를 정리하여 올바른 선택과 구현을 지원합니다.

---

## ❓ 핵심 질문에 대한 답변

### 1. 일관성 있는 표현: dagre-d3-es vs Force-Directed Graph

**답변: 네, dagre-d3-es가 더 정확하고 일관성 있습니다.**

#### dagre-d3-es (계층적 레이아웃)

-   ✅ **결정적 알고리즘**: 같은 데이터면 항상 같은 위치
-   ✅ **예측 가능**: 렌더링마다 동일한 결과
-   ✅ **계층적 구조**: 방향성에 따라 명확한 레벨/랭크 배치
-   ✅ **정적 레이아웃**: 계산 후 위치 고정

**사용 사례:**

-   파일 간 의존성 그래프 (DependencyDiagram.js)
-   ERD 다이어그램 (ERDDiagram.js)
-   플로우차트, 조직도
-   계층적 구조가 명확한 경우

#### Force-Directed Graph (물리 시뮬레이션)

-   ⚠️ **비결정적 알고리즘**: 시뮬레이션 결과가 매번 다를 수 있음
-   ⚠️ **동적 레이아웃**: 시뮬레이션이 진행되며 위치가 변함
-   ✅ **자연스러운 분산**: 노드가 균형 있게 분산
-   ✅ **클러스터 시각화**: 밀집 관계가 시각적으로 드러남

**사용 사례:**

-   패키지 의존성 분석 (DependencyAnalysisDiagram.js)
-   소셜 네트워크
-   복잡한 관계망
-   인터랙티브 탐색이 중요한 경우

### 2. Force-Directed Graph의 렌더링 일관성

**답변: 네, 렌더링할 때마다 노드 위치가 달라질 수 있습니다.**

#### 원인

1. **물리 시뮬레이션**: 노드 간 인력/반발력으로 위치 결정
2. **초기 위치**: 랜덤 또는 원형 배치로 시작
3. **시뮬레이션 진행**: 매 틱마다 위치 업데이트
4. **수렴 시점**: 시뮬레이션이 안정화되는 시점이 다를 수 있음

#### 해결 방법

```javascript
// 1. 초기 위치 고정
packages.forEach((pkg, i) => {
    const angle = (i / packages.length) * 2 * Math.PI;
    pkg.x = centerX + radius * Math.cos(angle);
    pkg.y = centerY + radius * Math.sin(angle);
});

// 2. 시뮬레이션 파라미터 고정
simulation.force("charge", d3.forceManyBody().strength(-300)).force("link", d3.forceLink().distance(100));

// 3. 시뮬레이션 완료 후 위치 저장
simulation.on("end", () => {
    // 위치를 localStorage에 저장하여 다음 렌더링 시 재사용
});
```

### 3. 인터랙티브 응용에 유리한 방식

**답변: Force-Directed Graph가 더 유리합니다.**

#### Force-Directed Graph의 인터랙티브 장점

-   ✅ **자연스러운 드래그**: 노드를 드래그하면 주변 노드가 자동으로 반응
-   ✅ **실시간 피드백**: 시뮬레이션이 즉시 반영
-   ✅ **동적 업데이트**: 노드 추가/제거 시 자연스러운 재배치
-   ✅ **줌/팬**: 시뮬레이션과 독립적으로 작동

#### dagre-d3-es의 인터랙티브 제한

-   ⚠️ **드래그 후 재계산**: 노드를 드래그하면 레이아웃 재계산 필요
-   ⚠️ **정적 구조**: 레이아웃이 고정되어 있어 동적 변화에 불리
-   ✅ **줌/팬**: 가능하지만 레이아웃은 고정

## 📊 현재 프로젝트의 D3.js 사용 현황

### 1. 다이어그램 시스템 (`src/diagram/`)

#### 계층적 레이아웃 (dagre-d3-es)

-   **ERDDiagram.js**: 데이터베이스 테이블 관계 시각화
-   **DependencyDiagram.js**: 파일 간 의존성 그래프
-   **FlowDiagram.js**: 프로세스 흐름도

**특징:**

-   `dagre.layout()`: 한 번에 레이아웃 계산
-   `dagre-d3-es render()`: 자동 SVG 렌더링
-   계층적 구조, 방향성 설정 가능 (LR, TB, RL, BT)

#### 물리 시뮬레이션 (Force-Directed)

-   **DependencyAnalysisDiagram.js**: 패키지 의존성 분석

**특징:**

-   `d3.forceSimulation()`: 물리 시뮬레이션
-   `d3.forceLink()`: 링크 힘
-   `d3.forceManyBody()`: 노드 간 반발력
-   `d3.forceCenter()`: 중앙 정렬
-   `d3.forceCollide()`: 노드 충돌 방지

#### 트리 레이아웃 (D3 Tree)

-   **FileTreeDiagram.js**: 파일 구조 트리

**특징:**

-   `d3.hierarchy()`: 계층 구조 생성
-   `d3.tree()`: 트리 레이아웃 계산
-   `d3.tree().nodeSize()`: 노드 크기 설정
-   수직/수평 방향 지원

### 2. 차트 시스템 (`src/charts/`)

#### D3.js 직접 사용 (스케일 기반)

-   **BarChart.js**: 막대 차트
-   **LineChart.js**: 선 차트
-   **AreaChart.js**: 영역 차트
-   **PieChart.js**: 파이 차트
-   **ScatterChart.js**: 산점도

**특징:**

-   `d3.scaleLinear()`: 선형 스케일

-   `d3.axisBottom()`, `d3.axisLeft()`: 축 렌더링
-   `d3.line()`, `d3.area()`, `d3.arc()`: 경로 생성

**구조:**

## 🎨 D3.js 레이아웃 및 차트 방식 종합 정리

### 1. 레이아웃 방식 (Graph/Network)

#### 1.1 계층적 레이아웃 (Hierarchical Layout)

**라이브러리:** dagre-d3-es

**특징:**

-   결정적 알고리즘
-   계층적 구조 표현
-   방향성 설정 (LR, TB, RL, BT)
-   정적 레이아웃

**구현:**

```javascript
const graph = new graphlib.Graph().setGraph({ rankdir: "LR", nodesep: 200, ranksep: 120 }).setNode(id, { label, width, height }).setEdge(from, to, { label });

dagre.layout(graph);
renderer(svgGroup, graph);
```

**사용 사례:**

-   ERD 다이어그램
-   파일 의존성 그래프
-   플로우차트
-   조직도

**장점:**

-   일관성 있는 레이아웃
-   예측 가능한 결과
-   계층적 구조 명확

**단점:**

-   인터랙티브 기능 제한
-   커스터마이징 어려움
-   복잡한 관계 표현 어려움

#### 1.2 물리 시뮬레이션 (Force-Directed Graph)

**라이브러리:** D3.js 내장

**특징:**

-   비결정적 알고리즘
-   동적 레이아웃
-   자연스러운 분산
-   인터랙티브

**구현:**

```javascript
const simulation = d3.forceSimulation(nodes)
  .force('link', d3.forceLink(links).id(d => d.id))
  .force('charge', d3.forceManyBody().strength(-300))
  .force('center', d3.forceCenter(width/2, height/2))
  .force('collision', d3.forceCollide().radius(40))

simulation.on('tick', () => {
  link.attr('x1', d => d.source.x)...
  node.attr('cx', d => d.x)...
})
```

**사용 사례:**

-   패키지 의존성 분석
-   소셜 네트워크
-   복잡한 관계망
-   인터랙티브 탐색

**장점:**

-   자연스러운 레이아웃
-   인터랙티브 기능
-   동적 업데이트
-   커스터마이징 용이

**단점:**

-   렌더링마다 위치 다를 수 있음
-   성능 이슈 (대량 노드)
-   시뮬레이션 안정화 시간 필요

#### 1.3 트리 레이아웃 (Tree Layout)

**라이브러리:** D3.js 내장

**특징:**

-   계층적 구조
-   부모-자식 관계
-   확장/축소 가능
-   방향 설정 가능

**구현:**

```javascript
const hierarchy = d3.hierarchy(data, (d) => d.children);
const tree = d3.tree().nodeSize([width, height]);
const treeData = tree(hierarchy);

// 링크 렌더링
treeData.links().forEach((link) => {
    // path 그리기
});

// 노드 렌더링
treeData.descendants().forEach((node) => {
    // 노드 그리기
});
```

**사용 사례:**

-   파일 구조 트리
-   조직도
-   디렉토리 구조
-   계층적 데이터

**장점:**

-   계층적 구조 명확
-   확장/축소 기능
-   직관적인 표현

**단점:**

-   단일 루트만 지원
-   순환 구조 표현 불가

#### 1.4 클러스터 레이아웃 (Cluster Layout)

**라이브러리:** D3.js 내장

**특징:**

-   트리와 유사하지만 리프 노드가 같은 레벨
-   원형 배치 가능

**구현:**

```javascript
const cluster = d3.cluster().nodeSize([width, height]);
const clusterData = cluster(hierarchy);
```

**사용 사례:**

-   계층적 데이터 (리프 노드 정렬)
-   원형 트리

#### 1.5 파티션 레이아웃 (Partition Layout)

**라이브러리:** D3.js 내장

**특징:**

-   계층적 데이터를 직사각형으로 분할
-   트리맵, 선버스트 차트에 사용

**구현:**

```javascript
const partition = d3.partition().size([2 * Math.PI, radius]);
const partitionData = partition(hierarchy);
```

**사용 사례:**

-   트리맵
-   선버스트 차트
-   계층적 데이터 시각화

### 2. 차트 방식 (Chart)

#### 2.1 스케일 기반 차트 (Scale-Based Charts)

**라이브러리:** D3.js 내장

**특징:**

-   데이터를 시각적 속성으로 매핑
-   스케일 함수 사용
-   축 렌더링

**구현:**

```javascript
// 스케일 생성
const xScale = d3
    .scaleBand()
    .domain(data.map((d) => d.x))
    .range([0, width])
    .padding(0.1);

const yScale = d3
    .scaleLinear()
    .domain([0, d3.max(data, (d) => d.y)])
    .range([height, 0]);

// 축 렌더링
const xAxis = d3.axisBottom(xScale);
const yAxis = d3.axisLeft(yScale);

// 데이터 렌더링
svg.selectAll("rect")
    .data(data)
    .join("rect")
    .attr("x", (d) => xScale(d.x))
    .attr("y", (d) => yScale(d.y))
    .attr("width", xScale.bandwidth())
    .attr("height", (d) => height - yScale(d.y));
```

**사용 사례:**

-   막대 차트 (BarChart.js)
-   선 차트 (LineChart.js)
-   영역 차트 (AreaChart.js)
-   산점도 (ScatterChart.js)

**장점:**

-   완전한 커스터마이징
-   유연한 데이터 매핑
-   다양한 차트 타입 지원

**단점:**

-   많은 코드 필요
-   직접 구현 필요

#### 2.2 기하학적 생성기 (Geometric Generators)

**라이브러리:** D3.js 내장

**특징:**

-   경로 생성 함수
-   SVG path 데이터 생성

**구현:**

```javascript
// 선 생성기
const line = d3
    .line()
    .x((d) => xScale(d.date))
    .y((d) => yScale(d.value))
    .curve(d3.curveMonotoneX);

// 영역 생성기
const area = d3
    .area()
    .x((d) => xScale(d.date))
    .y0(height)
    .y1((d) => yScale(d.value));

// 호 생성기 (파이 차트)
const arc = d3.arc().innerRadius(0).outerRadius(radius);

const pie = d3.pie().value((d) => d.value);
```

**사용 사례:**

-   선 차트 (line)
-   영역 차트 (area)
-   파이 차트 (arc, pie)
-   곡선 차트

### 3. 기타 레이아웃 방식

#### 3.1 히스토그램 (Histogram)

**라이브러리:** D3.js 내장

**특징:**

-   데이터를 빈(bin)으로 그룹화
-   분포 시각화

**구현:**

```javascript
const histogram = d3
    .histogram()
    .value((d) => d.value)
    .domain(x.domain())
    .thresholds(x.ticks(20));

const bins = histogram(data);
```

#### 3.2 Voronoi 다이어그램

**라이브러리:** D3.js 내장

**특징:**

-   점 집합을 영역으로 분할
-   가장 가까운 점 찾기

**구현:**

```javascript
const voronoi = d3
    .voronoi()
    .x((d) => d.x)
    .y((d) => d.y)
    .extent([
        [0, 0],
        [width, height],
    ]);

const polygons = voronoi.polygons(data);
```

#### 3.3 덴드로그램 (Dendrogram)

**라이브러리:** D3.js 내장

**특징:**

-   계층적 클러스터링 결과 시각화
-   트리와 유사하지만 리프 노드가 같은 레벨

**구현:**

```javascript
const cluster = d3.cluster().size([height, width - 160]);

const root = d3.hierarchy(data);
const clusterData = cluster(root);
```

## 🔧 구현 및 다루기 입장에서의 특징

### 1. 코드 복잡도

#### 간단한 구현

1. **dagre-d3-es**: 자동 렌더링으로 코드가 간단
2. **D3 스케일 기반 차트**: 표준 패턴으로 구현 용이
3. **트리 레이아웃**: D3 내장으로 구현 간단

#### 복잡한 구현

1. **Force-Directed Graph**: 시뮬레이션 관리 필요
2. **커스텀 레이아웃**: 직접 알고리즘 구현 필요
3. **복잡한 인터랙션**: 이벤트 처리 복잡

### 2. 성능

#### 고성능

1. **dagre-d3-es**: 한 번 계산 후 정적 렌더링
2. **트리 레이아웃**: O(n) 계산 복잡도
3. **스케일 기반 차트**: 효율적인 데이터 바인딩

#### 성능 이슈 가능

1. **Force-Directed Graph**: 매 틱마다 계산, 대량 노드 시 느림
2. **실시간 업데이트**: DOM 조작 빈번
3. **복잡한 경로**: 많은 SVG 요소

### 3. 커스터마이징

#### 높은 커스터마이징

1. **Force-Directed Graph**: 모든 요소 직접 제어
2. **스케일 기반 차트**: 완전한 스타일 제어
3. **트리 레이아웃**: 노드/링크 스타일 자유롭게

#### 제한적 커스터마이징

1. **dagre-d3-es**: render 함수 내부 동작 제어 어려움
2. **자동 렌더링**: 구조 변경 어려움

### 4. 인터랙티브 기능

#### 강력한 인터랙션

1. **Force-Directed Graph**: 드래그, 동적 업데이트
2. **트리 레이아웃**: 확장/축소, 노드 클릭
3. **스케일 기반 차트**: 줌, 브러시, 필터

#### 제한적 인터랙션

1. **dagre-d3-es**: 줌/팬만 가능, 드래그 시 재계산 필요

### 5. 데이터 구조 요구사항

#### 유연한 데이터 구조

1. **Force-Directed Graph**: 노드/링크 배열만 필요
2. **스케일 기반 차트**: 다양한 데이터 형식 지원

#### 특정 데이터 구조 필요

1. **트리 레이아웃**: 계층적 구조 (children 속성)
2. **dagre-d3-es**: 그래프 구조 (노드/엣지)

### 6. 학습 곡선

#### 쉬운 학습

1. **스케일 기반 차트**: 직관적, 많은 예제
2. **트리 레이아웃**: 간단한 API

#### 어려운 학습

1. **Force-Directed Graph**: 시뮬레이션 이해 필요
2. **dagre-d3-es**: 라이브러리 특성 이해 필요

## 📈 선택 가이드

### 레이아웃 선택 기준

#### dagre-d3-es (계층적 레이아웃)를 선택할 때

-   ✅ 계층적 구조가 명확할 때
-   ✅ 일관성 있는 레이아웃이 필요할 때
-   ✅ 빠른 정적 렌더링이 필요할 때
-   ✅ 코드를 단순하게 유지하고 싶을 때
-   ✅ 방향성이 중요한 경우 (LR, TB 등)

**현재 사용:**

-   `ERDDiagram.js`: 데이터베이스 테이블 관계
-   `DependencyDiagram.js`: 파일 간 의존성 그래프

#### Force-Directed Graph를 선택할 때

-   ✅ 복잡한 관계망을 표현할 때
-   ✅ 인터랙티브 기능이 중요할 때
-   ✅ 동적 레이아웃이 필요할 때
-   ✅ 커스터마이징이 중요할 때
-   ✅ 클러스터 시각화가 필요할 때

**현재 사용:**

-   `DependencyAnalysisDiagram.js`: 패키지 의존성 분석

#### 트리 레이아웃을 선택할 때

-   ✅ 단일 루트 계층 구조
-   ✅ 부모-자식 관계 명확
-   ✅ 확장/축소 기능 필요
-   ✅ 파일 시스템, 조직도 등

**현재 사용:**

-   `FileTreeDiagram.js`: 파일 구조 트리

### 차트 선택 기준

#### 스케일 기반 차트

-   ✅ 완전한 커스터마이징 필요
-   ✅ 다양한 차트 타입
-   ✅ 복잡한 데이터 변환

**현재 사용:**

-   모든 차트 타입 (Bar, Line, Area, Pie, Scatter)
