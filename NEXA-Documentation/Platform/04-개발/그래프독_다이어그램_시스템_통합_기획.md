# 그래프독 다이어그램 시스템 통합 기획

## 📋 개요

그래프독(GraphDoc) 기능 구현과 동시에 D3.js 기반 다이어그램 시스템을 전역 모듈로 재구성하여, 시스템 전역에서 다양한 형태와 옵션으로 다이어그램을 사용할 수 있도록 하는 통합 기획 문서입니다.

---

## 🎯 목표

### 1. 그래프독 기능 구현

-   의존성 그래프 시각화
-   의존성 분석 결과 표시
-   파일 구조 트리 시각화
-   코드 검색 결과 시각화

### 2. D3 다이어그램 시스템 전역화

-   현재 데이터베이스 뷰어의 ERD 설정 패널을 참고하여 전역 다이어그램 설정 시스템 구축
-   다양한 다이어그램 타입 지원 (ERD, Flow, Network, Dependency Graph, File Tree 등)
-   사용자 커스터마이징 가능한 설정 시스템
-   재사용 가능한 모듈 구조

### 3. 정확도 및 사용성 향상

-   D3 렌더링 정확도 향상
-   실시간 설정 변경 반영
-   부분 업데이트 vs 전체 재렌더링 최적화

### 4. 렌더링 캔버스 최적화 ⚠️ **핵심 과제**

-   부모 컨테이너 크기에 맞춘 자동 최적화
-   가로폭 100% 활용 및 스크롤 없는 초기 렌더링
-   동적 캔버스 크기 조정
-   전체창 보기 기능 및 최적화

    - 축소 등을 수동으로 해야 하는 불편함
    - 컨테이너 크기와 실제 그래프 크기의 불일치
    - 높이가 지정되지 않았을 때 브라우저 크기에 맞춘 최적화 부재

## 🎯 렌더링 캔버스 최적화 (핵심 해결 과제)

### 현재 문제점

1. **초기 렌더링 크기 불일치**

    - 부모 창에 최적화된 크기가 초기에 렌더링되지 않음
    - 빈 공간이 너무 많거나 브라우저가 커지면 과도하게 노드들이 커지면서 스크롤 필요
    - 사용자가 수동으로 축소/확대를 조정해야 함

2. **컨테이너 크기 관리 부재**

    - 컨테이너 크기와 실제 그래프 크기의 불일치
    - 높이가 지정되지 않았을 때 브라우저 크기에 맞춘 최적화 부재
    - 최소 크기 지정 시 보장되지 않음

3. **사용자 경험 저하**
    - 초기 로드 시 스크롤이 필요한 경우가 많음
    - 확대 후 탐색 시 불필요한 스크롤 발생
    - 전체 노드 공간 활용도가 낮음

### 해결 방안

#### 1. 자동 캔버스 크기 최적화

**원칙**:

-   **가로폭**: 항상 100% 활용 (부모 컨테이너 기준)
-   **높이**: 지정되지 않았다면 브라우저 크기에 맞춰 스크롤 없이 최적화
-   **최소 크기**: 지정된 경우 보장, 아니면 자동으로 캔버스 크기 조정
-   **상대적 크기**: 가로폭이 상대적으로 작아야 함 (세로 스크롤 최소화)

**구현 방법**:

```javascript
// 1. 컨테이너 크기 감지
function getOptimalCanvasSize(container, graphBounds) {
    const containerWidth = container.clientWidth;
    const containerHeight = container.clientHeight || window.innerHeight * 0.8;

    // 그래프 실제 크기 계산
    const graphWidth = graphBounds.width;
    const graphHeight = graphBounds.height;

    // 최적 스케일 계산 (가로폭 100% 활용, 스크롤 없이)
    const scaleX = containerWidth / graphWidth;
    const scaleY = containerHeight / graphHeight;
    const optimalScale = Math.min(scaleX, scaleY) * 0.95; // 5% 여유 공간

    return {
        width: containerWidth,
        height: graphHeight * optimalScale,
        scale: optimalScale,
    };
}

// 2. 초기 렌더링 시 자동 최적화
async function renderDiagram(container, data, options) {
    // ... 그래프 레이아웃 계산 ...

    // 그래프 바운드 계산
    const graphBounds = graph.graph().width && graph.graph().height ? { width: graph.graph().width, height: graph.graph().height } : calculateGraphBounds(graph);

    // 최적 캔버스 크기 계산
    const optimalSize = getOptimalCanvasSize(container, graphBounds);

    // SVG 크기 설정
    svg.attr("viewBox", `0 0 ${optimalSize.width} ${optimalSize.height}`);

    // 초기 줌 설정 (최적 스케일)
    fitToScreen(svg, svgGroup, optimalSize.width, optimalSize.height, zoom);
}
```

#### 2. 동적 크기 조정

**ResizeObserver 활용**:

```javascript
// 컨테이너 크기 변경 감지
const resizeObserver = new ResizeObserver((entries) => {
    for (const entry of entries) {
        const { width, height } = entry.contentRect;
        // 캔버스 크기 재계산 및 재렌더링
        recalculateCanvasSize(width, height);
    }
});

resizeObserver.observe(container);
```

#### 3. 전체창 보기 기능

**기능**:

-   별도 아이콘 버튼으로 전체창 모드 전환
-   전체창에서도 최적화된 전체 노드들의 공간을 최대한 활용
-   모달 또는 전체 화면 오버레이로 표시

**구현**:

```vue
<template>
    <div class="diagram-container">
        <!-- 전체창 보기 버튼 -->
        <q-btn flat dense round icon="fullscreen" class="fullscreen-btn" @click="toggleFullscreen">
            <q-tooltip>전체창 보기</q-tooltip>
        </q-btn>

        <!-- 다이어그램 -->
        <NexaDiagram :type="diagramType" :data="diagramData" />

        <!-- 전체창 모달 -->
        <q-dialog v-model="isFullscreen" maximized>
            <div class="fullscreen-diagram-container">
                <NexaDiagram :type="diagramType" :data="diagramData" :options="fullscreenOptions" />
            </div>
        </q-dialog>
    </div>
</template>
```

**전체창 최적화**:

```javascript
// 전체창 옵션
const fullscreenOptions = computed(() => ({
    ...defaultOptions,
    // 전체창에서는 더 넓은 공간 활용
    layout: {
        ...defaultOptions.layout,
        nodesep: calculateOptimalNodeSep(window.innerWidth),
        ranksep: calculateOptimalRankSep(window.innerHeight),
    },
    // 자동 맞춤 활성화
    autoFit: true,
}));
```

#### 4. 최소 크기 보장

```javascript
// 최소 크기 설정
const MIN_CANVAS_WIDTH = 800;
const MIN_CANVAS_HEIGHT = 600;

function ensureMinimumSize(calculatedSize) {
    return {
        width: Math.max(calculatedSize.width, MIN_CANVAS_WIDTH),
        height: Math.max(calculatedSize.height, MIN_CANVAS_HEIGHT),
        scale: calculatedSize.scale,
    };
}
```

### 구현 우선순위

1. **높은 우선순위**: 초기 렌더링 최적화

    - 자동 스케일 계산
    - fitToScreen 최적화

2. **중간 우선순위**: 동적 크기 조정

    - ResizeObserver 통합
    - 브라우저 크기 변경 대응

3. **중간 우선순위**: 전체창 보기
    - 전체창 모달 구현
    - 전체창 최적화 옵션

### 현재 ERD 다이어그램 분석

**현재 구현** (`ERDDiagram.js`):

```javascript
// 컨테이너 크기 확인
const containerWidth = container.clientWidth || 800;
const containerHeight = container.clientHeight || 600;

// SVG 생성
const svg = d3.select(container).append("svg").attr("width", "100%").attr("height", "100%").attr("viewBox", `0 0 ${containerWidth} ${containerHeight}`);
```

**문제점**:

-   고정된 기본값 사용 (800x600)
-   컨테이너 높이가 0일 때 처리 부족
-   그래프 실제 크기와 컨테이너 크기 불일치
-   초기 줌 최적화 부재

**개선 방향**:

1. ResizeObserver로 컨테이너 크기 실시간 감지
2. 그래프 바운드 계산 후 최적 스케일 계산
3. fitToScreen 함수 개선 (여유 공간 고려)
4. 높이 미지정 시 브라우저 크기 기반 계산

### 4. 렌더링 캔버스 최적화 원칙 ⚠️ **핵심 과제**

-   **가로폭 100% 활용**: 부모 컨테이너의 가로폭을 항상 100% 활용

-   **상대적 크기**: 가로폭이 상대적으로 작아 세로 스크롤 최소화
-   **전체창 최적화**: 전체창 모드에서도 전체 노드 공간 최대한 활용

```javascript
// 설정 변경 시 변경 타입 감지
function detectChangedTypes(oldSettings, newSettings) {
    const changedTypes = [];

    if (oldSettings.nodeSize !== newSettings.nodeSize) {
        changedTypes.push("nodeSize");
    }
    if (oldSettings.layout !== newSettings.layout) {
        changedTypes.push("layout");
    }
    if (oldSettings.theme !== newSettings.theme) {
        changedTypes.push("theme");
    }

    return changedTypes;
}
```

현제 시스템에서 다이어그램별 D3 기능 사용 현황

1. Force-Directed Graph (PackageDependencyDiagram, FileTreeDiagram)
   D3 Force Simulation API:
   d3.forceSimulation(packages): Force 시뮬레이션 생성
   d3.forceLink(links): 링크(엣지) 힘 설정
   .distance(): 링크 거리
   .strength(): 링크 강도
   d3.forceManyBody(): 노드 간 반발력 (charge)
   .strength(): 반발력 강도 (음수)
   d3.forceCenter(): 중심점으로 끌어당기는 힘
   d3.forceCollide(): 노드 간 충돌 방지
   .radius(): 충돌 반경
   simulation.on('tick'): 시뮬레이션 틱 이벤트 (위치 업데이트)
   simulation.alpha() / .restart(): 시뮬레이션 제어
   simulation.alphaTarget(): 시뮬레이션 목표 값
2. Hierarchical Layout (FileDependencyDiagram, ERDDiagram)
   Dagre-d3-es + D3:
   dagre-d3-es.graphlib.Graph: 그래프 구조 생성
   dagre.layout(): 레이아웃 계산 (계층형)
   dagre-d3-es.render(): D3로 렌더링
3. 공통 D3 기능
   DOM 조작:
   d3.select() / d3.selectAll(): 요소 선택
   .append(): 요소 생성
   .attr(): 속성 설정
   .style(): 스타일 설정
   .classed(): CSS 클래스 추가/제거
   .text() / .html(): 텍스트/HTML 설정
   .raise(): 요소를 DOM 최상위로 이동
   이벤트:
   d3.drag(): 드래그 핸들러
   .on('start') / .on('drag') / .on('end')
   d3.zoom(): 줌/팬 핸들러
   .scaleExtent(): 줌 범위
   .on('zoom'): 줌 이벤트
   .on(): 일반 이벤트 리스너 (click, mouseenter, mouseleave 등)
   .call(): 함수 체이닝
   Transform & Animation:
   d3.zoomIdentity: 줌 변환 매트릭스
   .transition(): 애니메이션
   .duration(): 지속 시간
   .ease(): 이징 함수 (d3.easeCubicInOut, d3.easeElasticOut 등)
   svgGroup.attr('transform'): SVG 변환 적용
   기타:
   d3.pointer(): 포인터 위치 (드래그 이벤트에서 사용)
   .node().getBBox(): SVG 요소의 바운딩 박스
