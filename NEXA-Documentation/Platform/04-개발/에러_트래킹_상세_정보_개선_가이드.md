## 현재 구현 상태

### ✅ 구현 완료된 항목

#### 1. 에러 기본 정보 섹션 (`error-header`)

-   ✅ 에러 메시지 (큰 제목)
-   ✅ 에러 유형 및 레벨 (아이콘 + 칩)
-   ✅ 발생 횟수 및 시간 범위
-   ✅ 상태 (새 에러, 해결됨, 무시됨)
-   ✅ 액션 버튼 (해결, 무시, 삭제, 복사)
-   ✅ 전체 적용 옵션 (일괄 처리)

#### 2. 발생 통계 섹션 (`error-statistics`)

-   ✅ 발생 횟수
-   ✅ 에러 타입 (Lint 등)
-   ✅ 유사 에러 개수
-   ✅ 최초/최근 발생 시간 (상대 시간 + 절대 시간)
-   ✅ 발생 기간
-   ✅ 에러 레벨 (Error, Warning, Unhandled)
-   ✅ 상태 (신규, 해결, 무시)

#### 3. 에러 위치 정보 (`error-location`)

-   ✅ 파일 경로
-   ✅ 라인/컬럼 번호
-   ✅ 파일 열기 버튼 (VS Code)

#### 4. 스택 트레이스 (`error-stack`)

-   ✅ 스택 트레이스 전체 표시 (기본 텍스트)

#### 5. 네트워크 정보 (`error-network`)

-   ✅ 요청 URL
-   ✅ HTTP 메서드
-   ✅ 상태 코드
-   ✅ 요청/응답 헤더

#### 6. 린트 정보 (`error-lint`)

-   ✅ 규칙 ID
-   ✅ 자동 수정 가능 여부
-   ✅ 심각도
-   ⚠️ 린트 에러 자동 수집 (부분적 작동, 개선 필요)

#### 7. 컨텍스트 정보 (`error-context`)

-   ✅ 페이지 URL
-   ✅ User Agent
-   ✅ 발생 시간

## 추가해야 할 상세 정보 항목

### 1. 스택 트레이스 섹션 개선 ⚠️ (우선순위: 높음)

**현재 상태**: 스택 트레이스 전체만 텍스트로 표시

**추가 필요**:

-   **클릭 가능한 파일명/라인 번호**

    -   VS Code에서 해당 파일 열기
    -   `vscode://file/{filePath}:{line}:{column}` 프로토콜 사용

-   **스택 프레임별 상세 정보**

    -   각 스택 프레임을 개별 카드로 표시
    -   함수명, 파일명, 라인/컬럼 번호 구분 표시
    -   접기/펼치기 기능

-   **코드 스니펫 표시**
    -   에러 발생 라인 ±5~10줄 코드 표시
    -   구문 강조 (Syntax Highlighting)
    -   에러 라인 강조 표시

**구현 예시**:

```vue
<div class="error-stack-enhanced q-pa-md q-mb-md">
  <h5 class="section-title q-mb-sm">
    <q-icon name="code" />
    스택 트레이스
  </h5>

  <div v-for="(frame, index) in parsedStackFrames" :key="index" class="stack-frame q-mb-sm">
    <q-expansion-item>
      <template #header>
        <div class="stack-frame-header">
          <q-icon name="place" />
          <span class="stack-function">{{ frame.function }}</span>
          <q-btn
            flat
            dense
            icon="open_in_new"
            size="sm"
            @click.stop="openInVSCode(frame.file, frame.line, frame.column)"
          />
        </div>
      </template>

      <div class="stack-frame-details">
        <div class="stack-file">{{ frame.file }}:{{ frame.line }}:{{ frame.column }}</div>
        <div v-if="frame.codeSnippet" class="code-snippet">
          <pre><code>{{ frame.codeSnippet }}</code></pre>
        </div>
      </div>
    </q-expansion-item>
  </div>
</div>
```

## 에러 원인/해결법 메모 기능 방법론

### 목적

에러 발생 원인과 해결 방법을 기록하여 **학습 효과를 극대화**하는 것이 목적입니다.

-   동일한 에러 재발 시 빠른 해결
-   에러 패턴 학습 및 코드 품질 향상
-   팀 내 지식 공유 및 협업 효율성 증대

### 방법론 비교

#### 방법 1: 구조화된 메모 필드 (권장) ⭐

**데이터 구조**:

```javascript
{
  id: string,
  // ... 기존 에러 필드 ...
  notes: {
    cause: string,        // 원인 분석
    solution: string,      // 해결 방법
    learned: string,       // 학습 내용
    references: string[],  // 참고 자료 링크
    updatedAt: number,     // 마지막 수정 시간
    updatedBy: 'user' | 'ai'  // 작성자 구분
  }
}
```

**장점**:

-   ✅ 구조화되어 검색/필터링 용이
-   ✅ AI와 사용자 작성 구분 가능
-   ✅ 학습 효과 극대화 (원인/해결/학습 내용 분리)
-   ✅ 구현 단순

**단점**:

-   ❌ 유연성 제한 (고정된 필드 구조)

#### 3. AI 요청 이벤트 처리

**`ErrorTrackingContent.vue` 스크립트**:

```javascript
import { ref, computed, watch } from "vue";
import { useErrorTracking } from "@/composables/dev-tools/useErrorTracking";

const { selectedError, updateErrorNotes } = useErrorTracking();

const notesTab = ref("cause");
const isAnalyzing = ref(false);
const errorNotes = computed({
    get: () =>
        selectedError.value?.notes || {
            cause: null,
            solution: null,
            learned: null,
            references: [],
            updatedAt: null,
            updatedBy: null,
        },
    set: (value) => {
        if (selectedError.value) {
            selectedError.value.notes = value;
        }

                    stack: selectedError.value.stack,

                    line: selectedError.value.line,
                    column: selectedError.value.column,
                    level: selectedError.value.level,
                    url: selectedError.value.url,
                    userAgent: selectedError.value.userAgent,
                    timestamp: selectedError.value.timestamp,
                },
            },
        })
    );
}

    const { errorId, analysis } = event.detail;

    if (selectedError.value?.id === errorId) {
        // AI 분석 결과를 메모에 저장

            cause: analysis.cause,
            solution: analysis.solution,
            learned: analysis.learned,
            references: analysis.references || [],
            updatedBy: "ai",
        });
    }

    isAnalyzing.value = false;
});

// 메모 저장
function saveNotes() {
    if (!selectedError.value) return;

    updateErrorNotes(selectedError.value.id, {
        ...errorNotes.value,
        updatedBy: "user",
    });
}

function addReference() {
    if (!errorNotes.value.references) {
        errorNotes.value.references = [];
    }
    errorNotes.value.references.push("");
}

    errorNotes.value.references.splice(index, 1);
```

### AI 분석 결과 저장 프로세스

#### 1. Cursor에서 AI 분석 요청

사용자가 Cursor에서 에러 컨텍스트를 붙여넣고 AI에게 분석 요청:

#### 2. AI 응답 형식

AI가 다음 형식으로 응답:

```
@error-analysis-result
ERROR_ID: 1234567890abcdef
CAUSE: undefined 상태의 배열에 map 메서드를 호출하려고 시도했습니다. userList가 초기화되지 않았거나 API 응답이 실패했을 가능성이 있습니다.
SOLUTION:
1. userList를 초기화: const userList = ref([])
2. API 호출 전 로딩 상태 확인
3. 옵셔널 체이닝 사용: userList.value?.map(...)
LEARNED: Vue 3의 ref는 초기값이 없으면 undefined입니다. 항상 초기값을 설정하거나 옵셔널 체이닝을 사용해야 합니다.
REFERENCES:
- https://vuejs.org/api/reactivity-core.html#ref
- https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Operators/Optional_chaining
```

### 개요

에러 분석 결과를 마크다운 문서로 저장하여, 문서 뷰어와 에러 트래킹 시스템 모두에서 활용하는 방식입니다.

**핵심 원칙**:

-   문서 자체가 가치 있는 이름을 가짐 (에러 ID는 숨김)
-   프론트매터에 에러 ID 포함 (파서용)
-   문서 내용에도 에러 ID 포함 (검색용)
-   문서 뷰어와 에러 트래킹 모두에서 접근 가능

### 문서 구조

#### 1. 파일명 규칙

**원칙**: 의미 있는 이름 사용, 에러 ID는 파일명에 포함하지 않음

**예시**:

```
✅ 좋은 예:
- Vue_ref_초기화_에러_분석.md
- Cannot_read_property_map_해결방법.md
- 네트워크_요청_타임아웃_분석.md

❌ 나쁜 예:
- 에러_분석_1234567890abcdef.md
- error_1234567890abcdef.md
```

**파일명 생성 가이드**:

1. 에러 메시지의 핵심 키워드 추출
2. 발생 위치 정보 활용 (컴포넌트명, 함수명 등)
3. 에러 유형 포함 (선택적)
4. 한글 또는 영문 사용 가능

#### 2. 프론트매터 (YAML) 구조

**위치**: 문서 최상단, 보이지 않는 메타데이터

**구조**:

```yaml

errorId: "1234567890abcdef"
```

**필수 필드**:

-   `errorId`: 에러 고유 ID (파서가 이 값을 읽어서 필터링)

-   `errorFile`, `errorLine`, `errorColumn`: 발생 위치
-   `errorLevel`: 에러 레벨 (error, warning 등)
-   `errorStatus`: 에러 상태 (new, resolved, ignored)
-   `createdAt`, `updatedAt`: 생성/수정 시간
-   `tags`: 태그 목록 (검색 및 분류용)

#### 인덱스 관리 시스템

**위치**: `NEXA-Platform/src/utils/error-tracking/errorAnalysisIndex.js` (신규)

**기능**:

1. 인덱스 파일 읽기/쓰기
2. 문서 추가/수정/삭제 시 인덱스 업데이트
3. 인덱스 검증 및 재구성

**구현 예시**:

```javascript
/**
 * 에러 분석 문서 인덱스 관리
 */
export class ErrorAnalysisIndex {
    constructor(project = "Platform") {
        this.project = project;
        this.indexPath = `Error/${project}/.error-analysis-index.json`;
        this.cache = null;
        this.lastModified = null;
    }

    /**
     * 인덱스 파일 로드
     */
    async loadIndex() {
        try {
            const response = await fetch(`http://localhost:3000/api/docs/${encodeURIComponent(this.indexPath)}`);
            if (!response.ok) {
                // 인덱스 파일이 없으면 빈 인덱스 생성
                return this.createEmptyIndex();
            }

            const content = await response.text();
            const index = JSON.parse(content);

            this.cache = index;
            return index;
        } catch (error) {
            console.error("인덱스 로드 실패:", error);
            return this.createEmptyIndex();
        }
    }

    /**
     * 빈 인덱스 생성
     */
    createEmptyIndex() {
        return {
            version: "1.0",
            lastUpdated: new Date().toISOString(),
            index: {},
            fileMap: {},
        };
    }

    /**
     * 에러 ID로 문서 검색 (인덱스 사용)
     */
    async findDocumentsByErrorId(errorId) {
        const index = await this.loadIndex();
        return index.index[errorId] || [];
    }

    /**
     * 문서 추가/업데이트 시 인덱스 업데이트
     */
    async updateIndex(documentPath, metadata) {
        const index = await this.loadIndex();
        const errorId = metadata.errorId;

        if (!errorId) {
            console.warn("에러 ID가 없어 인덱스에 추가할 수 없습니다:", documentPath);
            return;
        }

        // 기존 항목 제거 (같은 파일이면)
        if (index.fileMap[documentPath]) {
            const oldErrorId = index.fileMap[documentPath];
            if (index.index[oldErrorId]) {
                index.index[oldErrorId] = index.index[oldErrorId].filter((doc) => doc.path !== documentPath);
                if (index.index[oldErrorId].length === 0) {
                    delete index.index[oldErrorId];
                }
            }
        }

        // 새 항목 추가
        if (!index.index[errorId]) {
            index.index[errorId] = [];
        }

        const docEntry = {
            path: documentPath,
            fileName: metadata.fileName || documentPath.split("/").pop(),
            title: metadata.title || metadata.fileName,
            createdAt: metadata.createdAt || new Date().toISOString(),
            updatedAt: metadata.updatedAt || new Date().toISOString(),
            tags: metadata.tags || [],
            errorMessage: metadata.errorMessage,
        };

        // 중복 체크
        const existingIndex = index.index[errorId].findIndex((doc) => doc.path === documentPath);
        if (existingIndex >= 0) {
            index.index[errorId][existingIndex] = docEntry;
        } else {
            index.index[errorId].push(docEntry);
        }

        // 파일 맵 업데이트
        index.fileMap[documentPath] = errorId;
        index.lastUpdated = new Date().toISOString();

        // 인덱스 파일 저장
        await this.saveIndex(index);
    }

    /**
     * 문서 삭제 시 인덱스 업데이트
     */
    async removeFromIndex(documentPath) {
        const index = await this.loadIndex();
        const errorId = index.fileMap[documentPath];

        if (errorId && index.index[errorId]) {
            index.index[errorId] = index.index[errorId].filter((doc) => doc.path !== documentPath);
            if (index.index[errorId].length === 0) {
                delete index.index[errorId];
            }
        }

        delete index.fileMap[documentPath];
        index.lastUpdated = new Date().toISOString();

        await this.saveIndex(index);
    }

    /**
     * 인덱스 파일 저장
     */
    async saveIndex(index) {
        try {
            const content = JSON.stringify(index, null, 2);
            await fetch(`http://localhost:3000/api/docs/${encodeURIComponent(this.indexPath)}`, {
                method: "PUT",
                headers: {
                    "Content-Type": "application/json",
                },
                body: content,
            });
            this.cache = index;
        } catch (error) {
            console.error("인덱스 저장 실패:", error);
        }
    }

    /**
     * 인덱스 재구성 (모든 문서 스캔)
     */
    async rebuildIndex() {
        console.log("인덱스 재구성 시작...");

        const index = this.createEmptyIndex();

        try {
            // 에러 분석 폴더의 모든 파일 가져오기
            const response = await fetch(`http://localhost:3000/api/docs/Error/${this.project}`);
            const files = await response.json();

            for (const file of files) {
                // 인덱스 파일 자체는 제외
                if (file.name === ".error-analysis-index.json") continue;

                try {
                    const contentResponse = await fetch(`http://localhost:3000/api/docs/${encodeURIComponent(file.path)}`);
                    const content = await contentResponse.text();

                    const metadata = parseErrorAnalysisFrontmatter(content);

                    if (metadata?.errorId) {
                        await this.updateIndex(file.path, {
                            ...metadata,
                            fileName: file.name,
                        });
                    }
                } catch (error) {
                    console.error(`문서 처리 실패: ${file.path}`, error);
                }
            }

            console.log("인덱스 재구성 완료");
            return index;
        } catch (error) {
            console.error("인덱스 재구성 실패:", error);
            return index;
        }
    }
}

// 프로젝트별 인스턴스 (기본은 Platform)
export const errorAnalysisIndex = new ErrorAnalysisIndex("Platform");

// 다른 프로젝트용 인스턴스 생성 함수
export function createErrorAnalysisIndex(project) {
    return new ErrorAnalysisIndex(project);
}
```

#### 1. 프론트매터 파서 구현

**위치**: `NEXA-Platform/src/utils/error-tracking/errorAnalysisParser.js` (신규)

**기능**:

-   마크다운 파일에서 프론트매터 추출
-   YAML 파싱
-   에러 ID 추출

**구현 예시**:

```javascript
/**
 * 에러 분석 문서 프론트매터 파서
 */
export function parseErrorAnalysisFrontmatter(content) {
    // 프론트매터 패턴: ---로 시작하고 끝나는 YAML 블록
    const frontmatterRegex = /^---\s*\n([\s\S]*?)\n---\s*\n/;
    const match = content.match(frontmatterRegex);

    if (!match) {
        return null;
    }

    const yamlContent = match[1];

    // 간단한 YAML 파서 (복잡한 경우 js-yaml 라이브러리 사용)
    const metadata = {};
    const lines = yamlContent.split("\n");

    for (const line of lines) {
        const colonIndex = line.indexOf(":");
        if (colonIndex === -1) continue;

        const key = line.substring(0, colonIndex).trim();
        let value = line.substring(colonIndex + 1).trim();

        // 따옴표 제거
        if ((value.startsWith('"') && value.endsWith('"')) || (value.startsWith("'") && value.endsWith("'"))) {
            value = value.slice(1, -1);
        }

        // 배열 처리 (간단한 경우)
        if (value.startsWith("[") && value.endsWith("]")) {
            value = value
                .slice(1, -1)
                .split(",")
                .map((v) => v.trim().replace(/^["']|["']$/g, ""));
        }

        metadata[key] = value;
    }

    return metadata;
}

/**
 * 문서에서 에러 ID 추출
 */
export function extractErrorIdFromDocument(content) {
    const metadata = parseErrorAnalysisFrontmatter(content);
    return metadata?.errorId || null;
}

/**
 * 문서 목록에서 특정 에러 ID에 해당하는 문서 필터링
 */
export function filterDocumentsByErrorId(documents, errorId) {
    return documents.filter((doc) => {
        const metadata = parseErrorAnalysisFrontmatter(doc.content);
        return metadata?.errorId === errorId;
    });
}
```

```
SAVE_PATH: Error/Platform/

**요구사항**:

   ---
   errorId: "1234567890abcdef"

   errorLine: 45
   errorColumn: 12

   createdAt: "2024-12-20T10:30:00Z"
   tags: ["vue", "ref", "초기화"]

4. 저장 위치: 반드시 SAVE_PATH에 지정된 경로에 저장

   - 다른 위치에 저장하지 마세요!
```

### 주의사항

1. **로컬 스토리지 제한**: 메모 데이터가 많아지면 로컬 스토리지 용량 제한 고려
2. **인덱스 동기화**: 문서 저장 시 인덱스 자동 업데이트 방법 결정 필요
3. **프로젝트 식별**: 현재는 Platform 고정, 향후 동적 식별 필요
4. **에러 처리**: 모든 비동기 작업에 에러 처리 필수
5. **성능 최적화**: 인덱스 사용으로 성능 저하 방지
6. **마이그레이션**: 기존 에러 데이터에 notes 필드 추가 시 호환성 유지
7. **린트 에러 수집**: 현재 `console.error` 오버라이드 방식으로 부분적으로 작동하지만, 일부 린트 에러를 놓칠 수 있음. 향후 사용 패턴을 관찰하여 개선 방안 결정 필요 (과도한 수집 방지 고려)
