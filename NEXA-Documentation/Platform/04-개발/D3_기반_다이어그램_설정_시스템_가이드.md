# D3 기반 다이어그램 설정 시스템 가이드

## 📋 개요

이 문서는 NEXA 플랫폼의 D3.js 기반 시각화 시스템에서 다양한 다이어그램/차트 타입을 포괄적으로 지원하고, 각 타입별 설정 기능을 체계적이고 범용적으로 제작하기 위한 가이드입니다.

### 타입 분류 (총 8가지)

NEXA 플랫폼의 D3 기반 시각화는 다음과 같이 **총 8가지 타입**으로 분류됩니다:

1. **다이어그램 타입** (7가지): 네트워크/계층 구조 시각화

    - Force-Directed Graph, Hierarchical Layout, Tree Layout, Sankey, Chord, Cluster, Pack

2. **Chart 타입** (1가지, 세부 타입 5개): 데이터 통계 시각화
    - Bar Chart, Line Chart, Area Chart, Pie Chart, Scatter Plot

**참고**: Chart 타입(8번)은 모두 순수 D3.js를 직접 사용하여 구현되었으며, 별도의 레이아웃 라이브러리 없이 D3.js의 표준 API만을 사용합니다. 현재 `NexaChart.vue` 컴포넌트로 통합 관리됩니다.

---

## 🎯 목표

1. **포괄적인 시각화 타입 지원**: D3.js로 구현 가능한 다양한 다이어그램 및 차트 타입 정리
2. **범용 설정 시스템**: 타입별 설정을 일관된 방식으로 관리하는 범용 시스템 구축
3. **확장 가능한 구조**: 새로운 다이어그램/차트 타입 추가 시 최소한의 변경으로 통합 가능
4. **재사용 가능한 설정 UI**: 타입별 설정 컴포넌트를 체계적으로 구성하여 재사용성 극대화
5. **현재 사용 현황 반영**: NEXA 플랫폼에서 실제 구현 및 사용 중인 타입과 라이브러리 관계 명확화

> **참고**: 이 문서에서는 "다이어그램"은 네트워크/계층 구조 시각화를, "차트"는 데이터 통계 시각화를 의미합니다. 두 가지 모두 D3.js 기반으로 구현되지만, 사용 목적과 레이아웃 알고리즘이 다릅니다.

## 🎯 다이어그램 타입 (7가지)

### 1. Force-Directed Graph (Force 시뮬레이션 기반)

**특징:**

-   물리적 힘을 시뮬레이션하여 노드 위치 자동 계산
-   노드 간 반발력(charge), 링크 힘(link force), 중심력(center force), 충돌 감지(collision) 등을 조합
-   대규모 네트워크 관계 시각화에 적합
-   인터랙티브한 노드 드래그 가능

**D3 API:**

-   `d3.forceSimulation()`: 시뮬레이션 생성
-   `d3.forceLink()`: 링크 힘 (거리, 강도)
-   `d3.forceManyBody()`: 반발력 (charge)
-   `d3.forceCenter()`: 중심점 힘
-   `d3.forceCollide()`: 충돌 감지
-   `simulation.on('tick')`: 틱 이벤트로 위치 업데이트

**주요 설정 파라미터:**

-   `charge`: 노드 간 반발력 강도 (-1000 ~ 0, 음수 값)
-   `linkDistance`: 링크의 목표 거리 (픽셀)
-   `linkStrength`: 링크 힘의 강도 (0.0 ~ 1.0)
-   `center`: 중심점 좌표 (x, y)
-   `collision.radius`: 충돌 감지 반경 (함수 또는 상수)

**사용 사례:**

-   패키지 의존성 그래프 (PackageDependencyDiagram)
-   파일 구조 그래프 (FileTreeDiagram - Force 버전)
-   소셜 네트워크 시각화
-   웹 페이지 링크 구조

**라이브러리 관계:**

-   **순수 D3.js**: `d3-force` 모듈 사용
-   **대안 라이브러리**: vis.js (Network), Cytoscape.js (고급 네트워크 시각화)

---

### 2. Hierarchical Layout (계층형 레이아웃)

**특징:**

-   계층적 구조를 명확하게 표현
-   dagre 알고리즘 사용으로 최적 레이아웃 자동 계산
-   방향 설정 가능 (LR, TB, RL, BT)
-   엣지 교차 최소화

**D3 API:**

-   `dagre-d3-es`: dagre 레이아웃 + D3 렌더링
-   `dagre.layout()`: 레이아웃 계산
-   `dagre-d3-es.render()`: D3로 렌더링

**주요 설정 파라미터:**

-   `nodesep`: 같은 레벨 노드 간 간격
-   `ranksep`: 레벨 간 간격
-   `rankdir`: 레이아웃 방향 (LR, TB, RL, BT)
-   `marginx`, `marginy`: 여백

**사용 사례:**

-   ERD 다이어그램 (ERDDiagram)
-   파일 의존성 그래프 (FileDependencyDiagram)
-   조직도
-   UML 클래스 다이어그램

**라이브러리 관계:**

-   **dagre-d3-es**: dagre (레이아웃) + D3 (렌더링) 통합
-   **dagre**: 순수 레이아웃 알고리즘 (렌더링 없음)

---

### 3. Tree Layout (트리 레이아웃)

**특징:**

-   계층 구조를 트리 형태로 표현
-   루트에서 시작하여 자식으로 분기
-   수직/수평 방향 선택 가능
-   노드 접기/펼치기 지원

**D3 API:**

-   `d3.tree()`: 트리 레이아웃 생성
-   `tree.size()`: 트리 크기 설정
-   `tree.separation()`: 노드 간 간격
-   `d3.hierarchy()`: 계층 데이터 구조 생성

**주요 설정 파라미터:**

-   `size`: 트리 크기 [width, height]
-   `separation`: 노드 간 간격 (함수)
-   `orientation`: 방향 (vertical/horizontal)

**사용 사례:**

-   파일 디렉토리 구조
-   조직도
-   디렉토리 트리

**라이브러리 관계:**

-   **순수 D3.js**: `d3-hierarchy` 모듈 사용
-   **대안**: react-d3-tree, vis.js (Network - hierarchical layout)

---

### 4. Sankey Diagram (상키 다이어그램)

**특징:**

-   흐름량을 시각화
-   노드 간 흐름의 양을 링크 두께로 표현
-   레이어 구조 표현

**D3 API:**

-   `d3.sankey()`: 상키 레이아웃 생성
-   `sankey.nodeWidth()`: 노드 너비
-   `sankey.nodePadding()`: 노드 간 패딩
-   `sankey.size()`: 다이어그램 크기

**주요 설정 파라미터:**

-   `nodeWidth`: 노드 너비
-   `nodePadding`: 노드 간 패딩
-   `iterations`: 레이아웃 반복 횟수

**사용 사례:**

-   데이터 흐름 시각화
-   에너지 흐름
-   재무 흐름

**라이브러리 관계:**

-   **d3-sankey**: 공식 D3 플러그인
-   **d3-sankey-circular**: 원형 상키 다이어그램

---

### 5. Chord Diagram (코드 다이어그램)

**특징:**

-   원형 레이아웃에서 관계 표현
-   노드는 원주에 배치
-   관계는 내부 호로 표현

**D3 API:**

-   `d3.chord()`: 코드 레이아웃 생성
-   `d3.ribbon()`: 리본(호) 생성

**주요 설정 파라미터:**

-   `padAngle`: 패드 각도
-   `sortGroups`: 그룹 정렬
-   `sortSubgroups`: 하위 그룹 정렬

**사용 사례:**

-   관계 매트릭스 시각화
-   상호 의존성 표현

---

### 6. Cluster Layout (클러스터 레이아웃)

**특징:**

-   계층 구조를 클러스터 형태로 표현
-   노드를 그룹으로 묶어 표현

**D3 API:**

-   `d3.cluster()`: 클러스터 레이아웃 생성
-   `cluster.size()`: 클러스터 크기
-   `cluster.separation()`: 노드 간 간격

**주요 설정 파라미터:**

-   `size`: 클러스터 크기
-   `separation`: 노드 간 간격

---

### 7. Pack Layout (팩 레이아웃)

**특징:**

-   원형 노드를 중첩된 원 형태로 배치
-   노드 크기가 데이터 값에 비례

**D3 API:**

-   `d3.pack()`: 팩 레이아웃 생성
-   `pack.size()`: 팩 크기
-   `pack.padding()`: 패딩

**주요 설정 파라미터:**

-   `size`: 팩 크기
-   `padding`: 노드 간 패딩

---

## 🏗️ 다이어그램/차트 타입별 라이브러리 관계

### 타입 분류 체계 (총 8가지)

NEXA 플랫폼의 D3 기반 시각화는 다음과 같이 **총 8가지 타입**으로 분류됩니다:

1. **다이어그램 타입** (7가지): 네트워크/계층 구조 시각화

    - Force-Directed Graph
    - Hierarchical Layout
    - Tree Layout
    - Sankey Diagram
    - Chord Diagram
    - Cluster Layout
    - Pack Layout

2. **Chart 타입** (1가지, 세부 타입 5개): 데이터 통계 시각화 (순수 D3.js 직접 구현)

    - Line Chart (선 차트)
    - Area Chart (영역 차트)
    - Pie Chart (파이 차트)

-   차트 타입들은 모두 **순수 D3.js**를 직접 사용하며, 별도의 레이아웃 라이브러리 없이 `d3.scaleBand()`, `d3.scaleLinear()`, `d3.pie()`, `d3.line()` 등의 D3 API를 직접 호출합니다.
-   차트 타입들은 현재 **NexaChart.vue** 컴포넌트로 통합 관리되며, `type` prop으로 세부 차트 타입을 선택합니다 (`bar`, `line`, `area`, `pie`, `scatter`).

### 라이브러리 선택 기준

1. **순수 D3.js 사용 권장:**

    - 완전한 커스터마이징 필요
    - 특정 레이아웃/스타일 요구사항
    - 학습 목적

2. **통합 라이브러리 사용 권장:**

    - 빠른 프로토타이핑
    - 표준 레이아웃 충분
    - 외부 의존성 최소화 (예: dagre-d3-es)

3. **대안 라이브러리 고려:**
    - 매우 대규모 데이터 (수천 노드 이상)
    - 특수 기능 필요 (예: Cytoscape.js의 고급 네트워크 분석)
    - 다른 프레임워크와의 통합 (예: react-d3-tree)

#### Chart 타입 (8번) 선택 기준

**현재 NEXA 구현 방식: 순수 D3.js 직접 구현**

현재 NexaChart는 모든 차트 타입을 순수 D3.js로 직접 구현하고 있습니다:

-   **장점**:

    -   완전한 커스터마이징 가능
    -   NEXA 테마 시스템과 완벽 통합
    -   외부 의존성 없음
    -   일관된 코드 스타일 및 구조

-   **구현 방식**:
    -   Bar Chart: `d3.scaleBand()`, `d3.scaleLinear()` 사용
    -   Line Chart: `d3.line()`, `d3.scaleTime()` 사용
    -   Area Chart: `d3.area()` 사용
    -   Pie Chart: `d3.pie()`, `d3.arc()` 사용
    -   Scatter Plot: `d3.scaleLinear()` 사용

**대안: 레이아웃 라이브러리 활용 가능**

차트 구현 시 레이아웃 라이브러리를 활용할 수도 있습니다:

-   **예시 1: d3-force를 활용한 레이아웃된 산점도**

    -   `d3-force`로 노드 위치 계산
    -   엣지(링크) 제거 → 순수 데이터 포인트 레이아웃
    -   노드 크기/색상으로 데이터 값 표현
    -   클러스터링 효과 또는 자동 분산 레이아웃

-   **예시 2: d3-hierarchy를 활용한 계층형 차트**

    -   `d3.pack()` → 원형 버블 차트 (데이터 비율 시각화)
    -   `d3.tree()` → 계층 구조 차트
    -   `d3.cluster()` → 클러스터 차트

-   **예시 3: Sankey Diagram**
    -   데이터 흐름 차트로도 활용 가능
    -   노드 간 흐름량을 링크 두께로 표현

**선택 기준:**

1. **순수 D3.js 사용 (현재 방식)**

    - ✅ 표준 차트 타입 (Bar, Line, Area, Pie, Scatter)
    - ✅ 고정된 좌표계가 필요한 경우
    - ✅ 커스터마이징이 많은 경우

2. **레이아웃 라이브러리 사용 고려**
    - ✅ 자동 레이아웃이 필요한 경우 (예: 대량 데이터 클러스터링)
    - ✅ 네트워크/계층 구조가 데이터에 포함된 경우
    - ✅ 동적 레이아웃 조정이 필요한 경우
    - ⚠️ 다이어그램과 차트의 경계가 모호한 경우

**참고: 다이어그램 vs 차트의 경계**

-   **다이어그램**: 관계/구조를 표현 (네트워크, 계층, 흐름)
-   **차트**: 수량/통계를 표현 (비교, 추이, 분포)

하지만 실제로는:

-   Force-Directed Graph에서 링크 제거 → 레이아웃된 산점도
-   Sankey Diagram → 데이터 흐름 차트
-   Pack Layout → 원형 비율 차트

따라서 구현 방식보다는 **사용 목적과 데이터 특성**에 따라 선택하는 것이 중요합니다.

-   **대안 라이브러리 고려 시점**:
    -   매우 복잡한 차트 기능 필요 시 (예: 3D 차트, 고급 애니메이션)
    -   빠른 프로토타이핑이 우선일 때 (예: Chart.js, ECharts)

```javascript
// 다이어그램 렌더러에서
function updateSettings(newSettings) {
    const changedTypes = detectChangedTypes(currentSettings, newSettings);

    // 변경 타입별 업데이트 전략 선택
    changedTypes.forEach((changedType) => {
        switch (changedType) {
            case "layout.force.charge":
            case "layout.force.linkDistance":
            case "layout.force.linkStrength":
                // Force 파라미터만 업데이트 (부분 업데이트)
                updateForceParameters(renderResult, newSettings.layout.force);
                break;
            case "nodeSize":
                // 노드 크기만 업데이트 (부분 업데이트)
                updateNodeSizes(renderResult, newSettings.nodeSize);
                break;
            case "layout":
                // 레이아웃 전체 재계산 (전체 재렌더링)
                rerenderDiagram(renderResult, newSettings);
                break;
            default:
                // 스타일만 업데이트
                updateStyles(renderResult, newSettings);
        }
    });
}
```

```javascript
// diagramSettings.js
export function loadDiagramSettings(type) {
    const storageKey = `nexa-diagram-${type}-settings`;
    const stored = localStorage.getItem(storageKey);

    if (stored) {
        const parsed = JSON.parse(stored);
        const defaults = getDefaultDiagramSettings(type);
        return deepMerge(defaults, parsed); // 기본값과 병합
    }

    return getDefaultDiagramSettings(type);
}

export function saveDiagramSettings(type, settings) {
    const storageKey = `nexa-diagram-${type}-settings`;
    const validated = validateDiagramSettings(type, settings);
    localStorage.setItem(storageKey, JSON.stringify(validated));
}
```

```javascript
// diagramSettingsConfig.js
export function validateDiagramSettings(type, settings) {
    const schema = diagramSettingsSchemas[type];
    if (!schema) {
        console.warn(`알 수 없는 다이어그램 타입: ${type}`);
        return settings;
    }

    // 스키마 기반 검증 로직
    const validated = {};
    for (const [key, value] of Object.entries(settings)) {
        if (schema[key]) {
            validated[key] = validateSettingValue(key, value, schema[key]);
        }
    }

    return validated;
}
```

### Chart 타입 (8번) 설정

Chart 타입은 5가지 세부 차트 타입으로 구성되며, 각각 다른 설정을 가집니다:

| 세부 차트 타입 | 레이아웃 타입 | 주요 설정 항목                        | 전용 설정                 | NEXA 구현 상태 |
| -------------- | ------------- | ------------------------------------- | ------------------------- | -------------- |
| Bar Chart      | `cartesian`   | width, height, margin, xField, yField | barWidth, colorScale      | ✅ 사용 중     |
| Line Chart     | `cartesian`   | width, height, margin, curve          | strokeWidth, showPoints   | ✅ 사용 중     |
| Area Chart     | `cartesian`   | width, height, margin, curve          | fillOpacity, showOutline  | ✅ 사용 중     |
| Pie Chart      | `polar`       | radius, innerRadius, padAngle         | sort, showLabels          | ✅ 사용 중     |
| Scatter Plot   | `cartesian`   | width, height, margin                 | pointRadius, pointOpacity | ✅ 사용 중     |

**참고:**

-   Chart 타입들은 현재 별도의 설정 시스템이 없으며, `NexaChart.vue` 컴포넌트의 props로 설정을 전달합니다.

-   향후 차트 설정 시스템을 구축할 경우, 위 표의 주요 설정 항목을 기반으로 설정 스키마를 정의할 수 있습니다.
