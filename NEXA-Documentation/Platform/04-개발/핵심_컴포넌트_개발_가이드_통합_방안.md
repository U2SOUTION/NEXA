# 핵심 컴포넌트 개발 가이드 통합 방안

**작성일**: 2024년 12월  
**목적**: NEXA Platform의 핵심 컴포넌트(노드, 보드, 차트, 블록, 패널, 티치, 다이어그램)를 개발 가이드 기능에 통합하는 방법 및 유효성 검토  
**버전**: 1.0

---

## 📋 개요

현재 개발 가이드는 **스타일 가이드 중심**으로 구성되어 있으나, 핵심 컴포넌트를 통합하여 **개발 전체 가이드**로 확장할 수 있습니다. 이 문서는 핵심 컴포넌트를 개발 가이드에 통합하는 구체적인 방법과 유효성을 검토합니다.

---

## 🎯 통합 목적 및 가치

### 1. AI 규정 체계화
- **표준 계약 문서화**: 각 핵심 컴포넌트의 표준 계약을 샘플로 제공하여 AI가 참조 가능
- **일관성 보장**: AI가 핵심 컴포넌트를 생성할 때 표준 계약을 자동으로 따르도록 유도

### 2. 개발 표준 정립
- **사용 예시 제공**: 각 핵심 컴포넌트의 실제 사용 예시를 샘플로 제공
- **베스트 프랙티스**: 표준 계약을 준수한 올바른 사용법 문서화

### 3. AI 대화 최적화
- **키워드 기반 참조**: `@넥사차트`, `@넥사보드`, `@넥사다이어그램` 등으로 AI가 참조 가능
- **컨텍스트 제공**: AI가 핵심 컴포넌트를 생성할 때 필요한 컨텍스트 자동 제공

### 4. 개발자 교육
- **학습 자료**: 신규 개발자가 핵심 컴포넌트를 빠르게 학습
- **비교 기능**: 실제 프로젝트 컴포넌트와 샘플을 비교하여 차이점 확인

## 🔄 통합 방법

### 방법 1: 샘플 파일 기반 통합 (권장)

**개념**: 각 핵심 컴포넌트의 샘플을 `src/guides/` 폴더에 생성하고, 실제 컴포넌트와 연결

#### 1단계: 샘플 파일 구조 생성

```
src/guides/
├── styles/                    # 기존 스타일 샘플
│   └── ...
└── cores/           # 새 카테고리: 핵심 컴포넌트
    ├── charts/                # 차트 샘플
    │   ├── bar/
    │   │   └── NexaChartBarSample.vue
    │   ├── line/
    │   │   └── NexaChartLineSample.vue
    │   └── pie/
    │       └── NexaChartPieSample.vue
    ├── boards/                 # 보드 샘플
    │   ├── dashboard/
    │   │   └── NexaBoardDashboardSample.vue
    │   └── split-layout/
    │       └── NexaBoardSplitLayoutSample.vue
    ├── diagrams/               # 다이어그램 샘플
    │   ├── erd/
    │   │   └── NexaDiagramERDSample.vue
    │   ├── flow/
    │   │   └── NexaDiagramFlowSample.vue
    │   └── network/
    │       └── NexaDiagramNetworkSample.vue
    ├── blocks/                 # 블록 샘플
    │   ├── time/
    │   │   └── NexaBlockTimeSample.vue
    │   └── weather/
    │       └── NexaBlockWeatherSample.vue
    ├── panels/                 # 패널 샘플
    │   ├── gauge/
    │   │   └── NexaPanelGaugeSample.vue
    │   └── card/
    │       └── NexaPanelCardSample.vue
    └── nodes/                  # 노드 샘플 (향후)
        └── ...
```

#### 2단계: 샘플 파일 작성

각 샘플 파일은 다음을 포함:

```vue
<!-- NexaChartBarSample.vue -->
<template>
  <div class="nexa-chart-bar-sample">
    <NexaChart
      type="bar"
      :data="chartData"
      :options="chartOptions"
    />
  </div>
</template>

<script setup>
import NexaChart from 'src/charts/NexaChart.vue'

// 표준 계약 준수 예시
const chartData = {
  labels: ['A', 'B', 'C', 'D'],
  datasets: [{
    label: '데이터',
    data: [10, 20, 30, 40],
    backgroundColor: 'var(--nexa-primary)'
  }]
}

const chartOptions = {
  responsive: true,
  maintainAspectRatio: false
}
</script>

<style scoped>
.nexa-chart-bar-sample {
  padding: 16px;
}
</style>
```

#### 3단계: 메타데이터 자동 추출

현재 시스템은 파일 시스템에서 자동으로 샘플을 로드하므로, 샘플 파일만 생성하면 자동으로 등록됩니다.

**카테고리 자동 추출**:
- `src/guides/cores/charts/bar/NexaChartBarSample.vue` → 카테고리: `charts`
- `src/guides/cores/diagrams/erd/NexaDiagramERDSample.vue` → 카테고리: `erd`

#### 4단계: referencePath 설정 (선택적)

샘플 파일에 메타데이터 주석으로 실제 컴포넌트 경로 지정:

```vue
<!--
@referencePath: src/charts/NexaChart.vue
@category: charts
@tags: 넥사차트, 막대그래프, Bar, Chart, 데이터시각화
@description: NexaChart 컴포넌트를 사용한 막대 그래프 샘플
-->
```

또는 `useDevGuide.js`에서 자동으로 매핑:

```javascript
// useDevGuide.js에서 referencePath 자동 설정
const referencePathMap = {
  'charts': 'src/charts/NexaChart.vue',
  'diagrams': 'src/diagrams/NexaDiagram.vue',
  'boards': 'src/board/NexaBoardSetup.vue',
  'blocks': 'src/block/NexaBlock.vue',
  'panels': 'src/panel/NexaPanel.vue',
}
```

### 방법 2: 메타데이터 기반 통합

**개념**: 샘플 파일 없이 메타데이터만으로 핵심 컴포넌트를 등록 (실제 컴포넌트를 직접 참조)

#### 장점
- 샘플 파일 생성 불필요
- 실제 컴포넌트를 직접 참조하여 항상 최신 상태 유지

#### 단점
- 실제 프로젝트 코드에 의존
- 샘플과 실제 컴포넌트 비교 기능 제한

#### 구현 방법

```javascript
// src/domains/dev/modules/dev-guide/services/coreComponentRegistry.js
export const coreComponentSamples = [
  {

    name: '넥사차트',
    displayName: 'NexaChart',

      type: 'Chart',
```

## ✅ 유효성 검토

### 1. 개발 가이드 목적과의 부합성

| 개발 가이드 목적 | 핵심 컴포넌트 통합 가치 | 부합도 |
|----------------|---------------------|--------|
| **AI 규정 체계화** | 표준 계약 문서화, AI 참조 가능 | ⭐⭐⭐⭐⭐ |
| **개발 표준 정립** | 핵심 컴포넌트 사용 표준 정립 | ⭐⭐⭐⭐⭐ |
| **AI 대화 최적화** | `@넥사차트` 등 키워드 참조 | ⭐⭐⭐⭐⭐ |
| **단계적 확장** | Phase 2+ 확장 계획과 일치 | ⭐⭐⭐⭐⭐ |

### 2. 기술적 유효성

#### ✅ 현재 시스템과 호환
- **파일 시스템 기반 로드**: `useDevGuide.js`가 `src/guides/` 폴더를 자동 스캔
- **카테고리 자동 추출**: 폴더 구조에서 자동으로 카테고리 추출
- **동적 컴포넌트 로드**: `import.meta.glob`로 샘플 파일 동적 로드
- **비교 기능**: `referencePath`로 실제 컴포넌트와 비교 가능

#### ✅ 확장 가능성
- **새 카테고리 추가**: `cores` 카테고리 추가로 기존 시스템과 분리
- **점진적 통합**: 하나씩 추가하여 점진적으로 통합 가능
- **기존 샘플과 공존**: 스타일 샘플과 핵심 컴포넌트 샘플 공존 가능

### 3. 실용적 가치

#### ✅ 개발자 경험 향상
- **빠른 학습**: 신규 개발자가 핵심 컴포넌트를 빠르게 학습
- **표준 준수**: 표준 계약을 준수한 예시 제공
- **실제 사용 예시**: 실제 프로젝트에서 사용되는 패턴 제공

#### ✅ AI 협업 향상
- **키워드 참조**: `@넥사차트` 등으로 AI가 정확히 참조
- **컨텍스트 제공**: AI가 핵심 컴포넌트 생성 시 필요한 컨텍스트 자동 제공
- **표준 자동 적용**: 표준 계약을 자동으로 적용

## 🚀 구현 단계

### Phase 1: 기본 구조 설정 (1주)

1. **샘플 파일 구조 생성**
   - `src/guides/cores/` 디렉토리 생성
   - 각 핵심 컴포넌트별 서브 디렉토리 생성

2. **샘플 파일 작성 (우선순위 높음)**
   - 차트 샘플 (3-5개)
   - 다이어그램 샘플 (3개: ERD, Flow, Network)
   - 블록 샘플 (2-3개)

3. **카테고리 인식 확인**
   - 개발 가이드에서 `cores` 카테고리 자동 인식 확인
   - 필터링 및 검색 기능 확인

### Phase 2: 표준 계약 문서화 (1주)

1. **표준 계약 정보 추가**
   - 각 샘플에 표준 계약 정보 메타데이터 추가
   - `designDecisions`에 표준 계약 준수 사항 추가

2. **코드 스니펫 작성**
   - 표준 계약을 준수한 코드 스니펫 작성
   - 실제 사용 예시 포함

### Phase 3: 실제 컴포넌트 연결 (1주)

1. **referencePath 설정**
   - 각 샘플에 실제 컴포넌트 경로 설정
   - 비교 기능 테스트

2. **AI 참조 키워드 설정**
   - 각 핵심 컴포넌트에 한글명 설정
   - `@넥사차트`, `@넥사보드` 등 키워드 등록

### Phase 4: 확장 (지속적)

1. **나머지 핵심 컴포넌트 추가**
   - 보드 샘플
   - 패널 샘플
   - 노드 샘플 (향후)
   - 티치 샘플 (향후)

2. **고급 기능 추가**
   - 번역기 시스템 예시
   - 컴포넌트 간 변환 예시

## ⚠️ 주의사항

### 1. 샘플 파일 관리
- **실제 컴포넌트와 동기화**: 실제 컴포넌트 변경 시 샘플도 업데이트 필요

- **점진적 통합**: 모든 핵심 컴포넌트를 한 번에 통합하지 않고 점진적으로 추가
- **우선순위**: 자주 사용되는 컴포넌트부터 우선 통합
