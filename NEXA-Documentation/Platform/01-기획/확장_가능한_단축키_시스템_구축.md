# 확장 가능한 단축키 시스템 구축

## 목표

1. **단기**: 미리 정의된 액션 목록에서 선택하여 단축키를 생성
2. **장기**: 모든 기능에 동적으로 단축키를 부여할 수 있는 확장 가능한 시스템
3. **실제 사용 시나리오**:
   - 넥사 보드의 패널 레이아웃 (패널 보이기/숨기기)
   - 패널의 반복 액션/이벤트 트리거 (값 올리기/내리기)
   - 수백 개의 패널에 대한 동적 단축키 관리

## 설계 원리

### 1. 액션 레지스트리 시스템

- **중앙 집중식 액션 관리**: 모든 액션을 하나의 레지스트리에서 관리
- **액션 메타데이터**: ID, 설명, 카테고리, 파라미터 등 저장
- **핸들러 분리**: 액션 정의와 실행 핸들러를 분리하여 유연성 확보

### 2. 액션 타입 분류

```javascript
// 액션 타입 예시
- navigation: 라우터 네비게이션 (goToHome, goToSettings 등)
- toggle: 토글 기능 (toggleLeftSidebar, toggleTheme 등)
- store-action: Pinia store 액션 호출
- panel: 패널 관련 액션 (show, hide 등)
- panel-action: 패널 커스텀 액션 (increment, decrement 등)
- custom: 커스텀 핸들러 함수
```

### 3. 동적 액션 등록

- 각 모듈/컴포넌트에서 자체 액션을 등록 가능
- 런타임에 액션 추가/제거 가능
- 플러그인 시스템과 통합 가능
- **패널 생성 시 자동 액션 등록**: 패널이 생성되면 자동으로 관련 액션 등록

### 4. 단축키-액션 연결

- 단축키는 액션 ID를 참조
- 액션 ID로 핸들러를 찾아 실행
- 액션이 변경되어도 단축키는 유지

## 구현 단계

### 단계 1: 액션 레지스트리 시스템 구축

**파일**: `src/composables/useActionRegistry.js` (신규 생성)

```javascript
// 액션 레지스트리 구조
const actionRegistry = new Map()

// 액션 등록
function registerAction(actionId, {
  description,      // 액션 설명
  category,         // 카테고리 (navigation, toggle, store-action, panel, panel-action, custom)
  handler,          // 실행 핸들러
  params = {},      // 파라미터 스키마
  icon,             // 아이콘 (선택)
  enabled = true    // 활성화 여부
})

// 액션 목록 가져오기
function getAvailableActions(category = null)

// 액션 실행
function executeAction(actionId, params = {})
```

**기본 액션 등록**: `src/composables/actionRegistry.js` (신규 생성)

- 네비게이션 액션 (router.push 기반)
- 토글 액션 (store 메서드 호출)
- 기본 유틸리티 액션

### 단계 2: 단축키-액션 연결 시스템

**파일**: `src/composables/useGlobalShortcuts.js` (수정)

```javascript
// 단축키에 액션 ID 연결
function registerShortcut(shortcutId, {
  combo,
  description,
  actionId,        // 액션 ID 참조 (handler 대신)
  actionParams,    // 액션 실행 시 전달할 파라미터
  handler,         // 직접 핸들러 (기존 방식 유지)
  ...
})

// 액션 ID로 핸들러 자동 생성
function createHandlerFromAction(actionId, params)
```

**변경 사항**:

- `handler` 대신 `actionId` 사용 가능
- `actionId`가 있으면 액션 레지스트리에서 핸들러 가져와서 실행
- 기존 `handler` 방식도 유지 (하위 호환성)

### 단계 4: 패널 기반 동적 액션 시스템

**파일**: `src/composables/useActionRegistry.js` (확장)

**패널 액션 패턴**:

```javascript
// 패널별 동적 액션 생성
function registerPanelActions(panelId, panelType, panelActions) {
  // 패널별 기본 액션 (show, hide)
  registerAction(`panel:${panelId}:show`, {
    description: `패널 "${panelId}" 표시`,
    category: 'panel',
    handler: () => showPanel(panelId),
    params: { panelId },
  })

  registerAction(`panel:${panelId}:hide`, {
    description: `패널 "${panelId}" 숨기기`,
    category: 'panel',
    handler: () => hidePanel(panelId),
    params: { panelId },
  })

  // 패널별 커스텀 액션 (increment, decrement 등)
  panelActions.forEach((action) => {
    registerAction(`panel:${panelId}:${action.id}`, {
      description: `패널 "${panelId}" - ${action.label}`,
      category: 'panel-action',
      handler: () => executePanelAction(panelId, action.id, action.params),
      params: { panelId, actionId: action.id, ...action.params },
    })
  })
}

// 패널 제거 시 액션 해제
function unregisterPanelActions(panelId) {
  // panel:{panelId}:* 패턴의 모든 액션 제거
  const actionIds = Array.from(actionRegistry.keys()).filter((id) => id.startsWith(`panel:${panelId}:`))

  actionIds.forEach((id) => {
    actionRegistry.delete(id)
  })
}
```

**패널 액션 자동 등록**:

- 패널이 생성될 때 자동으로 액션 등록
- 패널이 제거될 때 자동으로 액션 해제
- 패널 타입별 기본 액션 템플릿

**컨텍스트 기반 단축키**:

- 현재 선택된 패널에 대한 단축키 자동 활성화
- 패널 선택 시 해당 패널의 액션만 단축키로 사용 가능

## 데이터 흐름

```
사용자가 단축키 생성
  ↓
액션 선택 (드롭다운)
  ↓
액션 ID 저장
  ↓
단축키 등록 시 액션 ID로 핸들러 생성
  ↓
단축키 실행 시 액션 레지스트리에서 핸들러 찾아 실행
```

## 실제 사용 시나리오 대응

### 시나리오 1: 패널 레이아웃 제어

- 패널 생성 시 자동으로 `panel:{id}:show`, `panel:{id}:hide` 액션 등록
- 사용자가 단축키 설정에서 패널 선택 → show/hide 액션 선택
- 단축키 실행 시 해당 패널만 표시/숨김

### 시나리오 2: 패널 반복 액션 트리거

- 패널이 `increment`, `decrement` 같은 액션을 제공하는 경우
- 패널 생성 시 해당 액션들도 자동 등록
- 사용자가 단축키 설정에서 패널 선택 → 액션 선택 (increment/decrement)
- 단축키 실행 시 해당 패널의 액션 트리거

### 시나리오 3: 수백 개 패널 관리

- 패널 ID 기반 동적 액션 생성으로 확장성 확보
- 패널 검색/필터링 기능으로 원하는 패널 빠르게 찾기
- 패널 그룹별 단축키 설정 (예: "온도 센서 패널들" 그룹)

## 장점

1. **확장성**: 새로운 기능 추가 시 액션만 등록하면 단축키로 사용 가능
2. **유지보수성**: 액션과 단축키가 분리되어 관리 용이
3. **일관성**: 모든 액션이 동일한 방식으로 관리됨
4. **재사용성**: 하나의 액션을 여러 단축키에 연결 가능
5. **하위 호환성**: 기존 handler 방식도 계속 지원
6. **동적 관리**: 패널 생성/제거 시 자동으로 액션 관리

## 구현 우선순위

1. **1단계**: 액션 레지스트리 기본 구조 + 기본 액션 등록
2. **2단계**: 단축키-액션 연결 시스템
3. **3단계**: UI 개선 (액션 선택 드롭다운)
4. **4단계**: 패널 기반 동적 액션 시스템 (핵심 시나리오)
5. **5단계**: 동적 액션 등록 메커니즘 (일반)
6. **6단계**: Store 액션 자동 등록 (선택사항)
