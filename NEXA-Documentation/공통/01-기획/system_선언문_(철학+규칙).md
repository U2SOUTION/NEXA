# 🧠 SYSTEM MANIFESTO

### ― 플랫폼의 신경망을 위한 선언 ―

---

## 0️⃣ 선언 (Declaration)

> 이 프로젝트에서 **system은 기능을 수행하지 않는다.**
> system은 **흐름을 만들고, 경계를 지키며, 상태를 연결한다.**
>
> **system은 ‘뇌’가 아니라 ‘신경망’이다.**

---

## 1️⃣ System의 존재 이유

System은 다음을 위해 존재한다.

-   도메인이 **서로를 몰라도** 협력할 수 있도록
-   상태가 **UI에 종속되지 않도록**
-   확장이 **기존 코드를 흔들지 않도록**
-   사람이 아닌 **구조가 실수를 막도록**

---

## 2️⃣ System의 정체성 정의

> **System은 중립적이어야 한다.**
> 특정 도메인의 편도, UI의 하수인도 아니다.

| 항목          | System의 입장   |
| ------------- | --------------- |
| 도메인        | 모른다          |
| UI            | 관여하지 않는다 |
| 비즈니스 규칙 | 판단하지 않는다 |
| 상태 흐름     | 전달한다        |
| 계약          | 강제한다        |

---

## 3️⃣ System이 담당하는 것 (Responsibility)

### ✅ System이 **반드시** 책임지는 영역

| 영역           | 설명                           |
| -------------- | ------------------------------ |
| 전역 상태 중계 | 선택된 대상, 활성 컨텍스트     |
| 계약 정의      | schema, interface              |
| 통신 허브      | eventBus, MQTT, socket wrapper |
| 진입 초기화    | router 진입 시 상태 세팅       |
| 관찰자         | 로그인, 연결, 권한 변화        |

---

### ❌ System이 **절대** 해서는 안 되는 것

| 금지 항목        | 이유        |
| ---------------- | ----------- |
| 도메인 로직 구현 | 책임 침범   |
| UI 제어          | 결합도 증가 |
| 데이터 가공      | 소유권 위반 |
| 도메인 조건 분기 | 중립성 붕괴 |
| 특정 도메인 의존 | 시스템 오염 |

> **System에 if (domain === 'infra') 가 등장하는 순간,
> 설계는 실패했다.**

---

## 4️⃣ Domain ↔ Domain 통신 원칙

> **Domain은 고립된다.
> System을 통해서만 연결된다.**

### 공식 규칙

-   ❌ Domain → Domain 직접 접근 금지
-   ✅ Domain → system → Domain 허용

### 허용되는 통신 수단

| 수단               | 용도          |
| ------------------ | ------------- |
| system/store       | 상태 공유     |
| system/composables | 기능 계약     |
| system/eventBus    | 느슨한 이벤트 |
| system/schema      | 데이터 표준   |

---

## 5️⃣ 상태(State)에 대한 철학

> **상태는 소유자만 수정한다.
> 나머지는 구독만 한다.**

| 상태 종류          | 소유자 |
| ------------------ | ------ |
| 전역 맥락          | system |
| 도메인 가공 데이터 | domain |
| UI 토글            | layout |
| URL 진입 조건      | router |

---

## 6️⃣ Router는 System의 일부다

> **라우터는 이동기가 아니다.
> 상태 진입 정의서다.**

Router는 다음을 담당한다.

-   어떤 상태로 진입하는가
-   어떤 layout을 사용하는가
-   system에 어떤 초기 신호를 주는가

---

## 7️⃣ System Composable 규칙

> **Composable은 로직이 아니라 계약이다.**

### system/composables 작성 기준

| 기준             | 설명              |
| ---------------- | ----------------- |
| 상태 최소화      | 소유 ❌           |
| 도메인 중립      | infra/erp 구분 ❌ |
| 명확한 네이밍    | use + 역할        |
| side-effect 명시 | watch / emit      |

---

## 8️⃣ Schema는 법이다

> **Schema는 문서가 아니라 법이다.**

-   모든 도메인은 system/schema를 따른다
-   도메인 내부에서 schema 재정의 금지
-   schema 변경은 **파급을 의도한 행위**다

---

## 9️⃣ System을 변경하기 전 체크리스트

변경 전에 반드시 자문한다.

-   이 로직의 **소유자는 누구인가?**
-   이 상태는 **공유되어야 하는가?**
-   이 기능이 **도메인에 있어도 되는가?**
-   system이 이걸 알 필요가 있는가?

> **의심되면 system에 넣지 않는다.**

---

## 🔟 핵심 문장 요약 (암기용)

-   **System은 기능을 만들지 않는다. 흐름을 만든다.**
-   **System은 판단하지 않는다. 전달한다.**
-   **System은 뇌가 아니라 신경망이다.**
-   **도메인은 고립되고, system을 통해서만 만난다.**
